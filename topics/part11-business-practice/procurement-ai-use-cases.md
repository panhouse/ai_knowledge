# 購買・調達職における生成AI活用事例

## これは何か

購買・調達の仕事は「複数のサプライヤーから見積を取り、条件を比較し、交渉し、発注・契約する」という一連の流れの中に、RFP(提案依頼書)・RFQ(見積依頼書)のドラフト作成、見積書の条件整理、支出データの集計・レポート化など、文章化・表への構造化・要約の作業が大量に発生する職種である。Deloitteの「2026 Global CPO Survey」では、RFP/RFQの自動生成が調達部門における生成AI活用の2番目に一般的な用途(42.3%)として挙がっており、スペンド分析(支出分析)ダッシュボードの構築が最優先の投資分野(53%)になっている([Deloitte](https://www.deloitte.com/us/en/services/consulting/blogs/business-operations-room/generative-ai-in-procurement-cpo-survey.html))。一方で、購買はサプライヤーの財務情報・与信情報・見積単価という「取引先の機微な commercial情報」を扱う職種でもあり、法務職([法務職における生成AI活用事例](legal-ai-use-cases.md))が契約の**法的リスク**を見るのに対し、本ページは購買職が担う**商流条件・価格・サプライヤー管理**の側面に焦点を当てる。両者は同じ契約書を扱う場面でも見る観点が異なるため、実務では併用が前提になる。

## 仕組み・背景

購買・調達における生成AI活用は、大きく3つの技術要素の組み合わせで進んでいる。

1. **文書生成・要約(汎用LLM)**: ChatGPT・Claude・GeminiなどのLLM(大規模言語モデル)は、過去のRFP/RFQのひな形や調達条件を渡すことで、案件ごとのドラフトを短時間で組み立てられる。見積書の条件を表形式に構造化する用途にも強い。
2. **スペンド分析・カテゴリ分類(AI-OCR+機械学習)**: 請求書・発注データを読み取り、勘定科目やカテゴリに自動分類する技術。分類精度はフィードバックループ(過去の修正履歴の学習)によって継続的に向上する仕組みが一般的になっている。
3. **サプライヤーリスクの継続モニタリング**: 財務データ・規制情報・ESG(環境・社会・ガバナンス)情報・地政学リスクなどをAIが常時スキャンし、異常があれば早期に警告する仕組み。調達関連の生成AIユースケースの中では「サプライヤーリスク評価・モニタリング」が本番導入率58%と最も進んでいる領域とされる([aimultiple](https://aimultiple.com/ai-procurement))。

2026年に入り、SAP AribaはAIエージェント「Joule Bid Analysis Agent」を一般提供開始し、価格・総所有コスト(TCO)・納期条件・コンプライアンス要件などRFXで指定した評価軸に沿って複数サプライヤーの入札内容を自動比較する機能を実装した([SAVIC Technologies](https://www.savictech.com/insights/next-gen-sap-ariba-ai-source-to-pay-joule-agents-2026/))。日本国内でも、intra-mart Procurement Cloudが「部品Xを1,000個、納期2か月で調達したい」といった自然文の入力からRFQドラフトを自動生成し、見積回答を自動で比較表化する機能を提供している([intra-mart Procurement Cloud](https://procurement.intra-mart.jp/column/procurement/procurement-with-generative-ai))ほか、Leaner(リーナー)の「AI見積査定」は見積書のPDFからのデータ入力、複数サプライヤー見積の横並び比較、過去データとの照合、価格の妥当性チェックまでの作業の約8〜9割を自動化するとしている([Leaner](https://leaner.jp/ax))。いずれも「AIが候補・比較表・下書きを作り、人が最終判断する」という役割分担が現状の主流であり、次の段階として、AIエージェントが購買実務の複数ステップ(見積依頼→比較→交渉→発注)を自律的に連鎖させる「エージェント型調達」への移行が2026年の焦点になっている([Supply Chain Management Review](https://www.scmr.com/article/doing-more-with-less-practical-ai-moves-for-procurement-teams-in-2026))。

## 使いどころ・使い分け

購買・調達業務は「AIが候補・下書き・一次比較を作る」領域と「人が最終確定すべき」領域の線引きが特に重要になる。金額・契約条件・取引先の信用情報を扱うため、誤りの影響が直接コストや取引関係に跳ね返る点は経理・法務と共通する。

| 活用シーン | AIが担う範囲 | 人が必ず担う範囲 |
|---|---|---|
| RFP・RFQのドラフト作成 | 過去案件を土台にした条件整理・文書構成のたたき台作成 | 調達戦略・予算上限・必達要件の最終決定 |
| 見積書の比較・条件整理 | 複数見積のPDF・Excelを表形式に構造化し、差分を要約 | 単価以外の定性的な取引条件(信頼関係・実績)を踏まえた最終選定 |
| サプライヤーリスク評価・与信情報の要約 | 公開されている財務情報・ニュース記事の要約、注目度の一次判定 | 反社会的勢力チェック・与信の最終判断、与信枠の決定 |
| 契約書の一次レビュー(発注契約・NDA等) | 商流条件(支払条件・納期・違約金等)の抽出・要点整理 | 契約締結の可否、法的リスクの最終判断(法務が担当) |
| 価格交渉の準備(シミュレーション・想定問答) | 交渉材料の整理、想定される相手の反論とその再反論の下書き | 実際の交渉方針の決定、相手との関係性を踏まえた駆け引き |
| 支出分析・カテゴリ別コスト可視化 | 大量の取引データのカテゴリ分類、レポートの初稿作成 | 分類結果の妥当性確認、コスト削減施策の意思決定 |
| サプライヤーとの定型連絡(発注確認・納期調整依頼) | 定型文面のドラフト作成 | 例外対応・クレーム対応など関係性に関わるやり取り |

判断の軸は他の職種と同様に「大量の候補・下書きを人が選ぶ・確認する仕事」はAIに任せやすく、「取引先との関係・与信・契約締結という一つの結論を確定する仕事」は人が主導する。特に**反社チェック・与信情報のような機微情報は、AIの要約結果だけで判断せず、信用調査会社(帝国データバンク・東京商工リサーチ等)の正式な調査結果や社内の与信管理規程に基づいて人が最終確認する**ことが必須になる。

## 実務での使い方

### 1. RFP・RFQのドラフト作成(コピペ用プロンプト例)

```
あなたは調達・購買部門の担当者です。以下の条件から、サプライヤー向けの
見積依頼書(RFQ)のドラフトを作成してください。

# 調達条件
- 調達品目: [例: 業務用ノートPC]
- 数量: [例: 50台]
- 希望納期: [例: 発注確定から6週間以内]
- 予算感: [例: 1台あたり15万円以内(税抜)]
- 必須要件: [例: メモリ16GB以上、3年保守サポート付き]
- 評価軸: [例: 価格40%、納期20%、保守条件20%、実績20%]

# 出力条件
- 「調達背景」「仕様要件」「見積回答条件(様式・提出期限)」
  「評価基準」「留意事項(機密保持等)」の見出しで構成する
- 数量・納期・予算などの数値は入力した内容のみを使い、新しい数値を作らない
- サプライヤーに開示すべきでない社内事情(予算の上限や競合サプライヤー名など)は
  本文に含めない
```

出力後は、必達要件に抜けがないか、予算感を開示する範囲が適切かを必ず人が確認してから送付する。

### 2. 複数サプライヤーの見積書比較(コピペ用プロンプト例)

見積書をPDFのままAIに読み込ませて構造化すると、条件の見落としを防ぎやすい。表データを扱えるChatGPT・Claude・Copilot等いずれでも使える。

```
以下は3社(A社・B社・C社)から届いた見積書です。各社の見積内容を
比較できるよう、表形式で整理してください。

# 抽出項目
- 単価・数量・合計金額(税込・税抜の別)
- 納期
- 支払条件(締め日・支払サイト)
- 保証・保守条件
- 有効期限(見積の有効期間)
- 通常の見積書と比べて特異な条件(あれば)

# 出力形式
項目 | A社 | B社 | C社

# 注意
- 各社の見積書に記載がない項目は「記載なし」と明記し、推測で埋めない
- 金額・日付は見積書の原文の表記をそのまま引用する
- 3社の内容から「価格は最安だが納期が長い」のような一次的な傾向コメントを
  末尾に3行以内で添える(最終的な選定判断ではなく気づきの提示に留める)
```

抽出結果は選定の一次材料として使い、最終的な発注先の決定は、単価だけでなく取引実績・関係性を踏まえて人が行う。

### 3. サプライヤーリスク評価・与信情報の要約(コピペ用プロンプト例)

**反社チェック・正式な与信判定はAIの要約では代替できない**という前提のうえで、公開情報の一次整理にAIを使う場合の例。

```
以下は取引検討先企業に関する公開情報(ニュース記事・企業サイトの記載)です。
この情報のみを根拠に、リスク確認の観点で要点を整理してください。

# 出力条件
- 「事業内容」「資本関係・株主構成」「直近の業績・話題になったニュース」の3項目で要約する
- 記載されている情報のみを使い、憶測で財務健全性や信用度を判定しない
- 「反社会的勢力に該当するか」「与信を供与してよいか」という最終判断は行わず、
  「信用調査会社の調査結果と社内与信管理規程に基づき別途確認が必要」と明記する

# 資料
[ここに公開情報のテキストを貼付]
```

正式な反社チェック・与信判断は、帝国データバンク・東京商工リサーチなどの信用調査会社の調査結果や、自社の与信管理規程に基づいて行う。AIは「大量の公開情報を素早く一次整理する」役割にとどめる。

### 4. 契約書(発注契約・NDA等)の一次レビュー(コピペ用プロンプト例)

購買職が見るのは主に「商流条件」であり、法的リスクの最終判断は法務に委ねる。

```
あなたは調達・購買部門の担当者です。以下の発注基本契約書について、
購買実務の観点から商流条件を抽出してください。

# 抽出項目
- 支払条件(締め日・支払サイト・振込手数料の負担者)
- 納期・検収条件(検収期間、不合格品の扱い)
- 価格改定条項(値上げ・値下げの協議条件)の有無
- 違約金・遅延損害金の条項の有無
- 契約期間・自動更新条項・解約予告期限
- 通常の発注契約と比べて自社に不利な特記事項

# 出力形式
項目 | 契約書の記載内容 | 気になる点(あれば)

# 注意
- 記載がない項目は「記載なし」と明記する
- 法的な有効性の判断はせず、「法務への確認が必要な論点」として整理するに留める
```

抽出結果は購買側の一次チェックとして使い、契約締結の可否・法的リスクの最終判断は法務部門([法務職における生成AI活用事例](legal-ai-use-cases.md)を参照)に確認を依頼する。

### 5. 価格交渉の準備(シミュレーション・想定問答)

生成AIは「交渉相手になりきらせて想定問答を作らせる」使い方が効果的。実際の自動交渉AIの事例として、Walmartはサプライヤーとの価格交渉にPactum AI社のチャットボットを導入し、対象となった発注先(消費者向けではない業務用資材・サービス)との交渉で平均1.5〜3%程度のコスト削減と、支払条件で平均35日の延長を引き出したと報告されている。交渉対象となったサプライヤーの約7割がチャットボットとの交渉を「人間より好ましい」と回答した点も注目される(交渉は数週間ではなく数日で完了、対象は消費者向け商品ではない運用資材・サービス調達)([Bloomberg](https://www.bloomberg.com/news/articles/2023-04-26/walmart-uses-pactum-ai-tools-to-handle-vendor-negotiations)、[PYMNTS](https://www.pymnts.com/news/artificial-intelligence/2023/walmart-finds-75-percent-vendors-prefer-negotiating-with-chatbot/partial/))。日本企業の多くはまだ自動交渉AIの本格導入段階ではなく、交渉前の準備(想定問答づくり)にチャットAIを使う段階が中心。

```
あなたは調達・購買部門のバイヤーです。以下の条件でサプライヤーとの
価格交渉に向けた準備をサポートしてください。

# 交渉条件
- 現行単価: [例: 1個あたり1,200円]
- 目標単価: [例: 1個あたり1,080円(10%減)]
- 交渉材料: [例: 発注数量を年間20%増やす見込み、支払サイトの短縮に応じる用意あり]
- 相手との関係: [例: 3年取引継続、納期遵守率は高いが値上げ要請が続いている]

# 依頼内容
1. 値下げを切り出す際の切り出し方の案を2パターン(強気・協調的)提示
2. サプライヤー側から想定される反論を3つ挙げ、それぞれへの再反論の案を作成
3. 値下げ以外に代替できる交渉カード(支払サイト・発注量・複数年契約等)を提案
```

出力はあくまで交渉準備の材料であり、実際の交渉の場では相手との関係性・自社の調達戦略を踏まえてバイヤー自身が判断する。

### 6. 支出分析・カテゴリ別コスト可視化のレポート作成支援(コピペ用プロンプト例)

```
アップロードした購買データ(発注日・品目・金額・サプライヤー名・カテゴリ)を基に、
経営会議向けの支出分析レポートの下書きを作成してください。

# 出力条件
- 「カテゴリ別支出額の上位5項目」「前年同期比で増減が大きいカテゴリとその要因の仮説」
  「集中購買・複数サプライヤー活用余地がありそうなカテゴリ」の3部構成
- 数値はアップロードしたデータのみを使い、記載のない数値を推測で補わない
- 要因や削減余地の記述は「〜の可能性がある」という仮説の書き方に留め、
  断定的な結論(「〜が原因である」等)は避ける
```

ChatGPT・Gemini・ClaudeのいずれもCSV・Excelの読み込みに対応しており、社内システムから抽出した購買データをそのまま貼り付けて分析できる。継続的にカテゴリ分類を自動化したい場合は、intra-mart Procurement CloudのようなBSM(ビジネス・スペンド・マネジメント)ツールの組み込み機能を使う選択肢もある。

### 7. サプライヤーとの定型連絡文面の自動化(コピペ用プロンプト例)

```
以下の条件で、サプライヤー宛ての発注確認メールの文面を作成してください。

- 発注内容: [例: 型番XYZ-100を200個]
- 納期: [例: 8月末までに指定倉庫へ]
- 確認したいこと: [例: 納期厳守の可否、分納の可否]
- トーン: 丁寧だが事務的、長期取引先向け

出力は日本のビジネスメールの定型構成(宛名・挨拶・本題・結びの挨拶・署名)に沿い、
本文は簡潔にする。
```

納期調整の依頼・支払条件変更の打診など、関係性に影響する可能性がある内容は、AIが作った下書きをそのまま送らず、担当者が文面のトーンを最終確認してから送付する。

### 主要調達プラットフォームのAI機能(2026年7月時点)

| ツール | 位置づけ | 特徴 |
|---|---|---|
| SAP Ariba(Joule Bid Analysis Agent) | 海外大手の調達・購買基盤 | 2026年第1四半期に一般提供開始。RFXで指定した評価軸(価格・TCO・納期・コンプライアンス等)に沿って複数サプライヤーの入札を自動比較するAIエージェント |
| Coupa | 海外大手の統合的な支出管理(Spend Management)プラットフォーム | 調達・財務・サプライヤーネットワークを横断するAI機能を拡充中、大企業・中堅企業向け |
| intra-mart Procurement Cloud | 国内のクラウド型調達・購買管理システム | 自然文からのRFQドラフト自動生成、見積回答の自動比較表化、BSM(ビジネス・スペンド・マネジメント)による支出可視化 |
| Leaner(リーナー見積・リーナー購買) | 国内の調達・購買部門向けクラウドサービス | 「AI見積査定」が見積書PDFのデータ化・複数社比較・過去データ照合・価格妥当性チェックの作業の約8〜9割を自動化すると謳う。ITreview Grid Award購買管理システム部門でリーダー評価を4期連続で獲得 |
| ChatGPT / Claude / Gemini / Copilot(汎用AI) | ドラフト作成・比較・要約の汎用エージェント | 専用ツールほどの自動化・監査ログはないが、RFQドラフト・見積比較・交渉準備・レポート下書きなど幅広い用途に安価に使える。機密情報の入力ルールを事前に確認する必要がある |

専用調達プラットフォームは「見積比較の自動化・監査ログ・サプライヤーマスタとの連携」を重視する場合に、汎用AIは「ドラフト作成・交渉準備・レポート下書きなど裾野の広い業務」に向く。中小規模の購買部門では汎用AIだけで多くの用途をカバーし、取引量が多い企業では専用プラットフォームのAI機能と併用するのが実務的な線引きになる。

## 注意点・よくある誤解

- **反社チェック・与信判断はAIの要約で完結させない**: AIは公開情報の一次整理・注目度判定には向くが、反社会的勢力チェックや与信枠の決定は、信用調査会社(帝国データバンク・東京商工リサーチ等)の正式な調査結果や自社の与信管理規程に基づいて人が最終判断する。AIの要約に含まれない非公開情報(業界の評判、過去の取引トラブル等)が判断を左右することも多い。
- **サプライヤーの見積単価・取引条件は機微な commercial情報である**: 見積書に記載された単価・数量・支払条件は、他のサプライヤーとの比較材料として悪用されると自社の交渉力を損なう。無料プランや学習利用がオプトインされたAIサービスにそのまま貼り付けず、法人契約プラン(学習利用オプトアウトが既定)を使う。詳細は[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md)を参照。
- **「AIが作った比較表・交渉準備」は最終判断の代わりにならない**: 見積比較の数値抽出やリスク評価の要約に誤り(存在しない条件の補完、金額の読み違え等)が起きることがある(ハルシネーション、詳細は[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md))。発注先の決定・契約締結・与信供与という「最終確定」の場面では、必ず原本(見積書・契約書)と突き合わせる。
- **法務レビューとの役割分担を曖昧にしない**: 発注契約書の「商流条件(支払条件・納期・価格改定等)」は購買が、「法的リスク(損害賠償の範囲、準拠法、知的財産権の帰属等)」は法務がレビューするという役割分担を明確にしておく。両者が同じ契約書の別々の観点をAIでレビューする場合、レビュー結果の食い違いが起きたときの調整ルールも事前に決めておくとよい。
- **自動交渉AI(Pactum AI等)は「対消費者取引ではない業務用資材・サービス」から導入が進んでいる**: Walmartの事例でも対象は運用資材・サービス調達が中心であり、価格弾力性や関係性の重要度が異なる主力商材の調達にそのまま適用できるとは限らない。自動交渉AIの導入は、対象カテゴリを絞ったパイロットから始めるのが実務的。

## 最初の一歩

直近取得した複数サプライヤーの見積書(匿名化またはサンプルデータ)を上記の「見積書比較」プロンプトに貼って表を作らせ、自分が手作業で比較した結果と照らし合わせて、抜け漏れや誤読がなかったかを確認してみる。
