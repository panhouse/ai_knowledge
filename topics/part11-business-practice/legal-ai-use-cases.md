# 法務職における生成AI活用事例

## これは何か

事業会社の法務部門(社内弁護士・法務担当者)は、契約書レビュー・法令調査・社内問い合わせ対応など「読む・調べる・書く」量が非常に多い職種であり、生成AIによる時間短縮効果が大きい一方、誤りが契約トラブルや訴訟リスクに直結しやすい分野でもある。日経の調査では主要企業の76%が法務業務で生成AIを活用していると回答しており、もはや「使うかどうか」ではなく「どこまで・どう使うか」を設計する段階に入っている。本ページは、法律事務所という**業種**としての事例([Part 13 士業・専門サービス](../part13-industry-cases/_index.md)で扱う範囲)ではなく、事業会社に所属する**職種としての法務**が生成AIをどう使うかに焦点を当てる。

## 仕組み・背景

法務でのAI活用が広がった背景には2つの技術的な流れがある。

- **契約書特化のLegalTech AI**: LegalOn Cloud(旧LegalForce)やGVA assist(現OLGA)のような日本発の契約書レビューSaaSは、大量の契約書・判例・自社の過去レビュー履歴を学習させたAIに、あらかじめ弁護士監修の「レビュー基準(プレイブック)」を組み込んでいる。アップロードした契約書を基準と照合し、抜け漏れ・不利な条項をハイライトする仕組みで、汎用AIより「見落としを減らす」ことに特化している。
- **汎用LLMのエージェント化**: ChatGPT・Claude・GeminiなどはWeb検索・ファイル読み込み・複数ステップの推論を組み合わせられるようになり、契約書ドラフトの初稿作成や社内FAQ対応など、契約審査以外の幅広い法務タスクをカバーできるようになった。米国のHarveyのように、汎用LLM(Anthropic Claude・OpenAI GPTなど)を基盤に法務特化のエージェント機能を載せるプレイヤーも急成長している。

いずれの方式でも、AIは「条文パターンの類似性」や「学習データ上の頻出表現」から出力を組み立てているのであり、個別契約の商慣習上の妥当性やその会社固有の交渉方針までは判断できない。最終的な法的判断は依然として人間の弁護士・法務担当者が担う、という前提を理解しておく必要がある。

## 使いどころ・使い分け

法務の業務は「AIに任せてよい範囲」と「必ず人が最終確認すべき範囲」の差が大きい。主な活用シーンごとに整理する。

| 活用シーン | AIが担う範囲 | 人が必ず担う範囲 |
|---|---|---|
| 契約書レビュー・リスク条項の抽出 | 抜け漏れ・不利条項の一次スクリーニング、社内基準との照合 | 商慣習上の妥当性判断、修正条文の最終確定、締結の意思決定 |
| 契約書ドラフト作成 | 定型契約のたたき台生成、条項の言い回し候補出し | 取引固有のリスク条件の設定、相手方との交渉方針 |
| 法令調査・社内問い合わせ対応 | 一般的な法令・社内規程の要約、FAQへの一次回答 | 個別事案への当てはめ、最新の法改正・判例の裏取り |
| コンプライアンス研修資料作成 | 研修スライドのたたき台、Q&A形式の設問生成 | 事例の正確性チェック、自社の実際の違反事例の扱い方 |
| 契約書の平易な日本語要約 | 現場の事業部門向けにリスクをかみ砕いて説明する下書き | 要約に法的に重要な留保・例外が漏れていないかの確認 |

使い分けの判断基準はシンプルに「この出力を鵜呑みにして進めた場合、誤りがあったら誰にどんな損害が出るか」。契約締結の可否・金額・違約条件に関わる最終判断は必ず人が行い、AIは「一次ドラフト・見落とし防止のダブルチェック役」と位置づけるのが実務的な線引きになる。

## 実務での使い方

### 1. 契約書レビュー・リスク条項の抽出

汎用AIに直接契約書全文を貼ってレビューさせる方法と、LegalTech AIのように事前にプレイブックが組み込まれた専用ツールを使う方法がある。汎用AIを使う場合はプレイブック(自社の許容範囲)をプロンプトで明示すると精度が上がる。

```
あなたは企業法務担当者です。以下の業務委託契約書(甲=当社、乙=委託先)を、
次の自社基準に沿ってレビューしてください。

【自社基準】
- 損害賠償の上限が契約金額の範囲内に収まっているか
- 秘密保持義務の期間が契約終了後も存続する条項になっているか
- 再委託の可否と当社への事前承諾義務の有無
- 契約解除条項に当社が一方的に不利な条件がないか

【出力形式】
1. リスクが高い条項を条番号付きで列挙し、なぜ問題かを1〜2行で説明
2. 各条項について修正案の文言を提示
3. 上記基準に抵触しない一般的な条項は「問題なし」として省略

契約書本文:
(ここに契約書のテキストを貼付)
```

### 2. 契約書ドラフト作成

```
以下の条件で秘密保持契約(NDA)のドラフトを作成してください。

- 契約形態: 相互型(甲乙双方が秘密情報を開示する)
- 目的: 新規事業の業務提携検討のための情報交換
- 秘密保持期間: 契約終了後3年間
- 準拠法・管轄: 日本法、東京地方裁判所を第一審の専属的合意管轄
- 当社は「甲」、相手方は「乙」とする

一般的なNDAの条項(定義、目的外利用禁止、除外情報、返還・破棄、損害賠償、
存続条項)を漏れなく含め、口語ではなく契約書らしい文体で出力してください。
出力後に、法令上または実務上とくに確認が必要な条項があれば、その理由とあわせて
別途注記してください。
```

### 3. 法令調査・社内問い合わせ対応(FAQボット)

社内向けには、汎用AIの記憶だけに頼らせず、自社の規程集や過去のFAQをRAG(検索拡張生成、外部・社内の文書を検索してから回答させる方式)で読み込ませたチャットボットが有効。日本ペイントホールディングスは社内専用の生成AI「NP ASSISTANT」を導入し、稟議規程や契約書ひな形に関する定型的な問い合わせに自動回答させることで、法務担当者の一次対応の負荷を減らしている。

```
あなたは当社の法務部が管理する社内問い合わせ対応AIです。
添付した社内規程集・契約書ひな形集の内容のみを根拠に回答してください。
資料に記載がない、または資料からは判断できない質問については、
推測で答えず「規程集に記載がないため法務部への確認が必要です」と回答してください。

質問: 取引先との覚書に押印ではなく電子署名を使ってよいか。
```

### 4. コンプライアンス研修資料作成

```
新入社員向けの下請法(下請代金支払遅延等防止法)に関する社内研修スライドの
構成案を作成してください。

- 対象: 営業部門の新入社員(法律の専門知識なし)
- 時間: 30分の研修を想定した10スライド程度
- 各スライドには「タイトル」「本文の要点(3行程度)」「理解確認用の一問一答クイズ」を含める
- 実際の違反事例は抽象化した架空のケースとして扱い、断定的な事実として書かない
```

### 5. 契約書の平易な日本語要約

事業部門の担当者が契約の法的な言い回しを読みこなせない場合、リスクをかみ砕いて説明する下書きとして使う。

```
以下の契約条項を、法律の知識がない事業部門の担当者向けに、
平易な言葉で3行以内に要約してください。
「結局、自社にとって何をしてはいけないか・何のリスクがあるか」を中心に書き、
法律用語を使う場合は必ずかっこ書きで一言説明を加えてください。

条項: (ここに条文を貼付)
```

### 法務特化AIツールと汎用AIの使い分け

| ツール | 位置づけ | 特徴・2026年7月時点の動向 |
|---|---|---|
| LegalOn Cloud(旧LegalForce) | 契約書レビュー・契約管理の国内シェア最大手 | 弁護士監修のレビュー基準を標準搭載。ISMS/ISMSクラウドセキュリティ認証(ISO/IEC 27001・27017)を取得し、入力データを外部AIモデルの学習に使わない方針を明示。料金は要問い合わせ制 |
| GVA assist(現OLGA) | 契約書レビューSaaS、法務OSへ機能拡張中 | 月額7.5万円(税別)程度からの1アカウント制。NDAに限定した無料チェック機能もあり、まず試したい場合の入口になる |
| Harvey | 海外の法律事務所・企業法務向け汎用法務AIエージェント | 2026年3月に200億円規模(2億ドル)の資金調達を実施し、企業価値1兆円超(110億ドル)。AmLaw100の大半、500以上の企業内法務部門が導入。契約分析・デューデリジェンス・訴訟対応まで幅広くカバー |
| Robin AI | 契約書レビュー特化の新興ツールとして注目されたが経営破綻 | 2025年末に資金調達failed後に事業が分割され、マネージドサービス部門はScisseroへ売却、エンジニアリング人材は2026年1月にMicrosoftへ移り、Wordの法務AI機能強化に活用される見通し。**法務AI新興ツールは変化が速く、乗り換えコストの高い基盤に据える前にベンダーの継続性も確認する必要がある**という教訓的な事例 |
| ChatGPT / Claude / Gemini(汎用AI) | ドラフト作成・要約・アイデア出しの汎用エージェント | 法務特化ツールほど契約審査の網羅性は保証されないが、社内規程FAQ・研修資料・平易な要約など幅広い用途に安価に使える。機密情報の入力ルールを個別に確認する必要がある |

法務特化ツールは「契約書レビューの網羅性・監査ログ・社内基準との一貫性」を重視する場合に、汎用AIは「ドラフト作成・要約・研修資料など裾野の広い業務」に向く。両者は排他ではなく、契約審査は専用ツール、それ以外の法務タスクは汎用AIという併用が一般的になっている。

## 注意点・よくある誤解

- **法律分野はハルシネーション(事実と異なる情報をもっともらしく生成する現象)のリスクが特に高い**: スタンフォード大学の研究では、法律に関する質問でChatGPT-4が58%、Llama 2が88%の割合で何らかの法的な幻覚(存在しない判例・誤った判示内容など)を含む回答をしたと報告されている。米国では架空の判例を裁判所に提出して弁護士が制裁を受けた事例が2023年以降200件以上報告されており、日本でも同種のリスクは同じ理屈で当てはまる。詳細は[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md)を参照。
- **AIの出力は「一次ドラフト」であり「最終判断」ではない**: 契約審査AIも汎用AIも、条文パターンの類似性から出力しているだけで、個別取引の背景事情・自社の交渉力・業界の商慣習までは判断できない。契約締結の可否・修正条文の最終確定・重要な法令解釈は、必ず社内弁護士・法務担当者が確認する体制を明文化する。
- **契約情報を外部AIに入力する情報漏洩リスクを軽視しない**: 取引先の名称・金額・独自の契約条件は、相手方との秘密保持契約(NDA)上の秘密情報に該当することが多い。汎用AIの無料プランやAPI設定によっては入力内容がモデルの学習に使われる場合があるため、法務部門が最初に「どのAIに、どの機密度の情報まで入力してよいか」をルール化する必要がある。LegalOn Cloudのように「入力データを外部AIモデルの学習に使わない」ことを明示しているサービスを選ぶ、または法人向け・API契約のプラン(学習利用オプトアウトが標準の契約形態)を使うのが基本線になる。詳しくは[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md)を参照。
- **法務特化AIベンダーの事業継続性も選定基準に入れる**: Robin AIのように資金調達に失敗して事業が分割されるケースが実際に起きている。契約審査の基準・レビュー履歴・ナレッジを蓄積する基盤ツールほど、乗り換えコストが高くなる。ベンダーの資金状況・データのエクスポート可否を事前に確認しておく。
- **「AIが76%活用されている」=「AIが法的判断をしている」ではない**: 日経調査が示す高い活用率も、多くは調査・ドラフト作成・リスク条項の一次抽出といった支援業務での利用であり、最終的な法的責任判断はあくまで人間が担っている前提であることを社内で誤解させないようにする。

## 最初の一歩

直近でレビューした契約書の一部を上記の「契約書レビュー」プロンプトに貼って試し、AIが指摘した条項と自分が気づいていた条項を比較して、見落としがなかったかを確認してみる(社外秘の実データではなく、匿名化した条文やサンプル契約書で試すこと)。
