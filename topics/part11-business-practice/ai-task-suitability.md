# 生成AIに向く業務・向かない業務の切り分け

## これは何か

「AIを使えば何でも効率化できる」という期待だけで導入すると、かえって業務の質が落ちることがある。ハーバード・ビジネス・スクールとボストン・コンサルティング・グループ(BCG)による実証実験(2026年3月に学術誌Organization Scienceで正式published)では、AIが得意な範囲の業務にAIを使うと品質が40%以上向上した一方、不得意な範囲で使うと平均で約23%パフォーマンスが低下することが確認されている。

2026年時点では、この見極めは「1回の生成をAIに任せてよいか」だけでなく、「複数ステップの作業を人の確認なしに自律実行させてよいか(=AIエージェントへの委任)」という論点にまで広がっている。生成の巧拙だけでなく、行動の自律性・不可逆性まで含めてAIに向く/向かない業務を切り分ける判断軸を持つことが、生成AI活用の出発点になる。

## 仕組み・背景

BCGとハーバード・ビジネス・スクールの研究者らは、AIの得意・不得意の境界を「ジャギッド・フロンティア(でこぼこした技術の境界線)」と呼んでいる。AIの能力は人間の直感的な「タスクの難易度」とは一致しない、でこぼこした境界を持っており、同じ業務フローの中でもAIが助けになるタスクと悪化させるタスクが混在する。厄介なのは、フロンティアの外側でAIを使った場合の出力は一見もっともらしく見えるため、誤りに気づきにくいという点だ。

生成AIが根本的に苦手とする「ハルシネーション」(事実と異なる情報をもっともらしく生成する現象)も、この境界線を見誤らせる要因になる。存在しない論文を出典として提示したり、架空の人物のプロフィールを作り出したりすることがあり、しかも誤りが自然な文章で提示されるため発見が難しい。

**2026年時点の変化: 境界線は「平準化」しつつあるが消えてはいない**

推論モデル(回答前に内部で段階的思考を行うモデル)・長いコンテキストウィンドウ・外部ツール呼び出し・AIエージェント(目標を与えると複数ステップの作業を自律的に計画・実行するAI)といった技術の進歩により、2023年頃には境界線の外側にあった業務の多くが内側に取り込まれてきた。実際、AI開発を計測する非営利団体METRの調査によれば、AIエージェントが50%の確率でやり遂げられる作業の長さ(タスク完了時間ホライズン)は、2023年以降おおよそ4か月強(約130日)で倍増するペースで伸びており、2026年1月時点の最新モデルでは十数時間規模の作業をこなせるまでになっている。

一方で、境界線そのものがなくなったわけではない。むしろ「AIエージェントが大量の作業を自律的に処理する」場面では、境界線の外側に落ちる割合がわずか数%であっても、処理件数が多いために失敗が高頻度で表面化するという新しい問題が指摘されている。つまり判断の重心は「AIにできるかどうか」から「どのくらいの精度で・どの範囲まで自律実行を任せ、どこで人が止めるか」に移ってきている。

## 使いどころ・使い分け

**向くタスクの特徴**

| 特徴 | 具体例 |
|---|---|
| 大量の非構造化データの要約 | 議事録・レポートの要約 |
| 定型文書のドラフト作成 | メール・提案書・企画書の初稿 |
| アイデア出し・選択肢の生成 | 企画のたたき台、コピー案の複数案作成 |
| パターン化・反復性の高い作業 | 毎日同じフォーマットで大量に発生する定型処理 |
| コードのドラフト生成・レビュー支援 | 既存コードを踏まえた実装案、テストコードの自動生成 |
| 社内で完結し、対外的な影響がない複数ステップ作業 | 複数ファイルの横断集計、社内ナレッジの一次整理 |

**向かない・注意が必要なタスクの特徴**

| 特徴 | 具体例 |
|---|---|
| 個人の人生や企業の命運に直結する最終判断 | 与信審査、人事評価、医療診断、契約書の最終リーガルチェック |
| 正確な数値計算・最新の確定情報が必須 | 財務諸表の確定数値、最新の法令解釈 |
| 判断基準が曖昧で属人的、例外処理が多い業務 | ケースバイケースの交渉、個別事情の多いクレーム対応 |
| 誤りが致命的な結果につながる領域 | 安全に関わる設計判断、公表前の重要発表 |
| 対外的・不可逆的な行動を伴う自律実行 | 顧客への自動メール送信、契約締結、外部システム・DBへの書き込み、SNS投稿の自動公開 |

実務的な判断チェックリストとしては、次の4点で仕分けるとよい(上3つは「生成」タスク向け、4つ目は複数ステップを自律実行させる「AIエージェント」タスクで特に重要)。

1. 入力データがExcel/CSVなど構造化されているか
2. 成果物の良し悪しを言語化・基準化できるか
3. 反復回数が多いか(例: 毎日同じフォーマットで100回以上発生する)
4. その行動は対外的・不可逆的な影響を持つか(顧客・取引先・公開情報に触れるか、後から取り消せるか)

1〜3が当てはまるならAI化の有力候補、当てはまらない項目が多いほど人による判断・確認を厚くする必要がある。4に該当する場合は「AIに向かない」と即断するのではなく、後述の自律性レベル(事前承認・事後確認・サンプリング確認)を設計した上で段階的に任せる、という発想に切り替える。

## 実務での使い方

### タスク単位で仕分けてから、プロセス全体を見直す

まず個々のタスクを「AIに向くか/向かないか」で仕分け、次に業務プロセス全体をAI前提で作り直す、という2段階で考えると整理しやすい。

- **タスク単位のAI活用**: 既存の業務プロセスは変えず、部分的にAIを当てはめて効率化する(部分最適)
- **BPR(業務プロセス再設計)/AI BPR**: 生成AI・AIエージェントが業務遂行を担うことを前提に、業務プロセスそのものを白紙から再設計する(全体最適)。単にツールを導入して個々の作業を速くするだけでは、全体の生産性は思ったほど上がらないという指摘もあり、「AIに置き換える」のではなく「AI前提でプロセスを再設計する」発想の転換が必要とされる

マッキンゼーは、生成AIの活用が特にインパクトを持つ領域として「顧客対応」「マーケティング&セールス」「ソフトウェアエンジニアリング」「研究開発」の4分野を挙げている。自社の業務がこれらに該当するなら、優先的にAI活用を検討する価値がある。エージェント型のAI活用は2025年から2026年にかけて急速に広がっており、タスク特化型のAIエージェントを組み込んだ業務アプリケーションの割合は、2025年時点のごく一部から2026年末までに大きく増える見通しとされる。日本国内でも、生成AIツールの導入率が6割超に達する一方、AIエージェント(自律実行型)の導入率はその半分に満たない水準にとどまり、生成AIの単純利用とエージェント化の間にはまだ差がある。

### 自律性レベルを段階的に設計する(AIエージェントを任せる場合)

複数ステップの作業をAIエージェントに任せる際は、いきなり全自動化するのではなく、行動のリスクに応じて権限のレベルを分けるのが実務上の定石になっている。

| 自律性レベル | 内容 | 向く業務例 |
|---|---|---|
| 完全監督下 | 1ステップごとに人が確認・承認してから次に進める | 初めて任せる業務、影響範囲が未知の業務 |
| 範囲限定自律 | あらかじめ決めた範囲・操作だけは自律実行させ、逸脱時のみ人に上げる | 反復性が高く失敗の影響が限定的な業務 |
| 完全自律 | 承認なしに一連の作業を最後まで自律実行させる | 低リスクかつ十分な実績データが蓄積された業務のみ |

権限は最初から完全自律を与えず、監視データ(成功率・逸脱事例)が蓄積されてから段階的に引き上げるのが安全な進め方とされる。

### 日本の制度対応(AI事業者ガイドライン第1.2版)

総務省・経済産業省は2026年3月31日、「AI事業者ガイドライン(第1.2版)」を公表し、AIエージェントの業務適用における人間の関与(Human-in-the-Loop)を整理した。リスクの大きさに応じて、高リスクな行動は事前承認、中リスクな行動は事後のログ確認、低リスクな行動はサンプリング確認、という3段階の関与を求める考え方が示されている。実務では、AIエージェントを稼働させる前に「対象業務・操作範囲・承認者・ログ保存方法」を記載した申請書を用意し、情報システム部門の承認を得てから稼働させ、業務フロー図に「どの工程で人が承認するか」を明示しておくとよい。

## 注意点・よくある誤解

- **「AIが得意そうに見えるか」という直感は当てにならない**: ジャギッド・フロンティアの研究が示す通り、AIの得意・不得意は人間の直感的な難易度感覚と一致しない。実際に試してみて検証する姿勢が必要。
- **フロンティア外でのAI利用は「使わないより悪い」結果になりうる**: 不得意な範囲でAIの出力を鵜呑みにすると、AIを全く使わなかった場合よりも成果が悪化することが実証実験で確認されている。
- **境界線は「平準化」しただけで、なくなったわけではない**: 推論モデルやAIエージェントの進化で以前より多くの業務が「向く」側に入ってきたが、大量件数を自律処理させる場面では、境界線外に落ちるわずかな割合が積み重なって高頻度の実害につながる。「以前できなかったから今もできない」「1回試して成功したから任せて大丈夫」のどちらも早計。
- **「AI活用」と「BPR」を混同しない**: 既存業務にAIを当てはめるだけでは部分最適にとどまる。生産性を大きく変えたい場合は、業務プロセスそのものの再設計まで踏み込む必要がある。
- **ガバナンス整備が追いついていない企業が多い**: 自律型AIエージェントに対して成熟したガバナンス体制(権限設計・監査ログ・逸脱時のエスカレーション)を整えている企業はまだ少数派とされる。段階的な権限昇格の設計なしに「エージェントに任せきる」運用は避ける。

## 最初の一歩

自分の業務を1つ選び、「入力が構造化されているか」「成果物の良し悪しを基準化できるか」「反復回数が多いか」「対外的・不可逆的な行動を含むか」の4点でチェックする。前3つが当てはまり、かつ対外的な行動を含まないタスクから生成AI活用を試し、複数ステップの自律実行(AIエージェント化)は低リスクな範囲に限定して小さく始める。
