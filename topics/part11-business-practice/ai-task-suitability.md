# 生成AIに向く業務・向かない業務の切り分け

## これは何か

「AIを使えば何でも効率化できる」という期待だけで導入すると、かえって業務の質が落ちることがある。ハーバード・ビジネス・スクールとボストン・コンサルティング・グループ(BCG)による実証実験では、AIが得意な範囲の業務にAIを使うと品質が40%以上向上した一方、不得意な範囲で使うと平均で約23%パフォーマンスが低下することが確認されている。どの業務にAIを使い、どの業務は人が担うべきかを見極める判断軸を持つことが、生成AI活用の出発点になる。

## 仕組み・背景

BCGとハーバード・ビジネス・スクールの研究者らは、AIの得意・不得意の境界を「ジャギッド・フロンティア(でこぼこした技術の境界線)」と呼んでいる。AIの能力は人間の直感的な「タスクの難易度」とは一致しない、でこぼこした境界を持っており、同じ業務フローの中でもAIが助けになるタスクと悪化させるタスクが混在する。厄介なのは、フロンティアの外側でAIを使った場合の出力は一見もっともらしく見えるため、誤りに気づきにくいという点だ。

生成AIが根本的に苦手とする「ハルシネーション」(事実と異なる情報をもっともらしく生成する現象)も、この境界線を見誤らせる要因になる。存在しない論文を出典として提示したり、架空の人物のプロフィールを作り出したりすることがあり、しかも誤りが自然な文章で提示されるため発見が難しい。

## 使いどころ・使い分け

**向くタスクの特徴**

| 特徴 | 具体例 |
|---|---|
| 大量の非構造化データの要約 | 議事録・レポートの要約 |
| 定型文書のドラフト作成 | メール・提案書・企画書の初稿 |
| アイデア出し・選択肢の生成 | 企画のたたき台、コピー案の複数案作成 |
| パターン化・反復性の高い作業 | 毎日同じフォーマットで大量に発生する定型処理 |
| コードのドラフト生成・レビュー支援 | 既存コードを踏まえた実装案、テストコードの自動生成 |

**向かない・注意が必要なタスクの特徴**

| 特徴 | 具体例 |
|---|---|
| 個人の人生や企業の命運に直結する最終判断 | 与信審査、人事評価、医療診断、契約書の最終リーガルチェック |
| 正確な数値計算・最新の確定情報が必須 | 財務諸表の確定数値、最新の法令解釈 |
| 判断基準が曖昧で属人的、例外処理が多い業務 | ケースバイケースの交渉、個別事情の多いクレーム対応 |
| 誤りが致命的な結果につながる領域 | 安全に関わる設計判断、公表前の重要発表 |

実務的な判断チェックリストとしては、次の3点で仕分けるとよい。

1. 入力データがExcel/CSVなど構造化されているか
2. 成果物の良し悪しを言語化・基準化できるか
3. 反復回数が多いか(例: 毎日同じフォーマットで100回以上発生する)

3つとも当てはまるならAI化の有力候補、当てはまらない項目が多いほど人による判断・確認を厚くする必要がある。

## 実務での使い方

### タスク単位で仕分けてから、プロセス全体を見直す

まず個々のタスクを「AIに向くか/向かないか」で仕分け、次に業務プロセス全体をAI前提で作り直す、という2段階で考えると整理しやすい。

- **タスク単位のAI活用**: 既存の業務プロセスは変えず、部分的にAIを当てはめて効率化する(部分最適)
- **BPR(業務プロセス再設計)/AI BPR**: 生成AI・AIエージェントが業務遂行を担うことを前提に、業務プロセスそのものを白紙から再設計する(全体最適)。単にツールを導入して個々の作業を速くするだけでは、全体の生産性は思ったほど上がらないという指摘もあり、「AIに置き換える」のではなく「AI前提でプロセスを再設計する」発想の転換が必要とされる

マッキンゼーは、生成AIの活用が特にインパクトを持つ領域として「顧客対応」「マーケティング&セールス」「ソフトウェアエンジニアリング」「研究開発」の4分野を挙げている。自社の業務がこれらに該当するなら、優先的にAI活用を検討する価値がある。

### 導入前のチェックポイント

- 機密情報・個人情報を入力する業務ではないか(入力禁止情報の明文化が必要)
- 出力内容を人が検証する工程を組み込めるか
- 属人化の度合い・ナレッジの所在・データの機密度を事前に棚卸しできているか

## 注意点・よくある誤解

- **「AIが得意そうに見えるか」という直感は当てにならない**: ジャギッド・フロンティアの研究が示す通り、AIの得意・不得意は人間の直感的な難易度感覚と一致しない。実際に試してみて検証する姿勢が必要。
- **フロンティア外でのAI利用は「使わないより悪い」結果になりうる**: 不得意な範囲でAIの出力を鵜呑みにすると、AIを全く使わなかった場合よりも成果が悪化することが実証実験で確認されている。
- **「AI活用」と「BPR」を混同しない**: 既存業務にAIを当てはめるだけでは部分最適にとどまる。生産性を大きく変えたい場合は、業務プロセスそのものの再設計まで踏み込む必要がある。

## 最初の一歩

自分の業務を1つ選び、「入力が構造化されているか」「成果物の良し悪しを基準化できるか」「反復回数が多いか」の3点でチェックし、3つとも当てはまるタスクから生成AI活用を試してみる。
