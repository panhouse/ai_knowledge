# 内部監査職における生成AI活用事例

## これは何か

内部監査部門(社内の業務・内部統制が適切に機能しているかを独立した立場でチェックする「第三のディフェンスライン」)の担当者は、リスクアセスメントに基づく監査計画の立案、証憑(しょうひょう、取引の裏付けとなる書類・データ)のサンプリングとレビュー、関係者へのインタビュー記録の整理、監査報告書・発見事項(Finding)のドラフト作成、J-SOX(日本版SOX法、金融商品取引法に基づく内部統制報告制度)対応文書の作成といった「大量の資料を読み込み、正確に文章化する」業務に多くの時間を割いている。生成AIはこうした下読み・下書き作業を大きく速くできるが、内部監査には他の職種にはない固有の論点がある。**監査対象の業務部門が使っているのと同じAIベンダー・同じツールを内部監査自身が使うと、監査の独立性・客観性そのものが疑われかねない**という点である。本ページは、[経理・財務職における生成AI活用事例](finance-accounting-ai-use-cases.md)(日々の経理業務そのもの)や[法務職における生成AI活用事例](legal-ai-use-cases.md)(契約審査・法令調査)とは異なり、社内の業務・統制を独立してチェックする**内部監査という職種**が、監査業務そのもので生成AIをどう使うかに焦点を当てる。

## 仕組み・背景

内部監査でのAI活用には、性質の異なる2つの技術が関わっている。

- **生成AI(LLM)によるテキスト生成・要約**: 監査調書のフォーマットに沿った下書き、インタビュー記録の要約、監査基準や証憑ファイルを読み込ませた一次テスト結果・判断根拠の生成など。デロイト トーマツは、監査基準・証跡ファイルをAIに読み込ませ、テスト結果や判断根拠、証憑からの抜粋を自動生成する仕組みを紹介しており、実務担当者がレビューする前提で効率化・標準化・品質向上に使えるとしている。J-SOX領域では、業務システムの操作ログや既存文書から業務記述書・RCM(リスク・コントロール・マトリクス)・フローチャートのドラフトを自動生成し、監査人は判断・結論部分の編集に集中できるようにするサービス(デロイト トーマツ、PwCなど)が2024年以降相次いで立ち上がっている。
- **継続的監査(Continuous Auditing)・異常検知AI**: 取引ログ・会計データを抽出ベースのサンプリングではなく**全数(100%母集団)**にわたって分析し、パターンから外れる取引を機械学習でフラグ立てする技術。MindBridge AI Auditorのようなツールは、売上・経費・給与などの元帳データを継続的に分析し、不正・誤謬の兆候がある取引を自動的に抽出する。これは従来型の異常検知(機械学習)が中心だが、近年はDataSnipperのように、Excel上の台帳データと大量の証憑ファイルをAIエージェントが自動照合し、監査調書に根拠付きで転記する「生成AI×自動化」の統合も進んでいる。

これらのAIはいずれも「監査対象の業務がどう行われたか」を要約・整理・フラグ立てする一次処理を担うのであり、**その取引が本当に不正・誤謬にあたるか、統制が有効に機能しているかという最終的な監査判断は人間の監査人が行う**という前提は変わらない。

背景として、COSO(トレッドウェイ委員会支援組織、内部統制の代表的フレームワークを策定する団体)は2026年3月に「Achieving Effective Internal Control Over Generative AI」を公表し、生成AIの利用形態を「データ取込(ingestion)」「変換(transformation)」「記帳・計上(posting)」「オーケストレーション(orchestration)」「判断(judgment)」「モニタリング(monitoring)」「規制インテリジェンス(regulatory intelligence)」「人間とAIの相互作用(human-AI interaction)」の8類型に整理し、それぞれに対応する統制の考え方を示した。これは会社全体の生成AI利用を内部監査がどう評価するかの枠組みであると同時に、内部監査部門自身が生成AIを使う際にも参考になる。IIA(内部監査人協会)も「AI Auditing Framework」を提供し、組織のAI戦略・ガバナンス成熟度・AIリスクを評価する枠組みを整備している。

## 使いどころ・使い分け

内部監査の業務は、監査意見の信頼性に直結するため「AIに下読み・下書きを任せてよい範囲」と「監査人が最終判断すべき範囲」の線引きが特に重要になる。

| 活用シーン | AIが担う範囲 | 人が必ず担う範囲 |
|---|---|---|
| リスクベース監査計画の立案 | 過去の監査結果・インシデント・外部の業界リスク情報からのリスク候補の洗い出し | 監査資源の配分、監査範囲・優先順位の最終決定 |
| 証跡サンプリング・文書レビュー | 大量の証憑・契約書・システムログからの該当箇所抽出、チェックリストとの一次突合 | サンプル抽出方針の決定、例外事項の原因究明・重要性の判断 |
| インタビュー録音・議事録の要約 | 発言内容の要約、論点整理、フォローアップ事項のリストアップ | 非言語情報・言い淀みなどニュアンスの解釈、追加質問の要否判断 |
| 監査報告書・発見事項(Finding)のドラフト作成 | 定型フォーマットへの文章化、根拠資料の引用整理 | 発見事項の重要性(高・中・低)判定、是正勧告の妥当性確認、最終承認 |
| J-SOX/内部統制評価文書(業務記述書・RCM・フローチャート)の作成 | 既存文書・システムログからのドラフト生成 | 統制の実在性・整備状況・運用状況の評価、評価結論の確定 |
| 継続的監査・異常検知(取引ログの全数分析) | 100%母集団に対するパターン検出・外れ値のフラグ立て | フラグの原因調査、不正・誤謬の該当性の最終判断 |
| 規程・法令とのクロスリファレンス | 関連条文・社内規程の該当箇所の一次照合 | 解釈の妥当性確認、準拠性の最終判断 |

判断基準は他職種と同様「このAI出力を鵜呑みにして監査意見を出したら、誰にどんな損害が出るか」だが、内部監査ではもう一つ**「そのAIツール・ベンダーは、監査対象の業務部門自身が使っているものと同じか」**という軸を必ず加える。同じベンダー・同じツールを使うと、①AIの処理ロジックに監査対象部門の業務慣行があらかじめ組み込まれている可能性、②ベンダーとの契約・データ関係が監査対象部門側の意思決定に影響される可能性、の2点で独立性・客観性(IIAグローバル内部監査基準1100「独立性と客観性」が要求する要件)が脅かされ得る。この論点は「使いどころ・使い分け」の判断に先立って確認すべき前提条件であり、詳細は下記「注意点」で扱う。

## 実務での使い方

### 1. リスクベース監査計画のドラフト作成

```
あなたは内部監査部門のシニア監査人です。以下の情報から、来期のリスクベース監査計画の
たたき台(監査対象候補とその優先順位)を作成してください。

【会社概要】(業種・規模・主要事業を記載)
【直近の内部監査結果】(過去1〜2年で指摘事項があった領域を箇条書きで貼付)
【直近のインシデント・ヒヤリハット】(内部通報、システム障害、規程違反などの記録を貼付)
【外部環境】(業界特有の規制強化、直近の同業他社の不祥事など把握している情報)

【出力形式】
1. 監査対象候補を「発生可能性」「影響度」の2軸で分類した一覧表
2. 各候補について、優先度を上げるべき根拠を1〜2行で
3. 判断材料が不足している候補には「追加情報が必要」と明記する
```

出てきた優先順位案は監査役会・監査委員会への説明資料の下地として使い、実際の監査資源配分・監査範囲の最終決定は監査部門長が行う。

### 2. 証跡サンプリング・文書レビュー支援

大量の契約書・請求書・稟議書から、社内基準やチェックリストと照らして例外・逸脱がありそうな箇所を一次スクリーニングさせる。

```
あなたは内部監査担当者です。以下は購買稟議データ(申請日・金額・承認者・取引先)の
一覧です。社内規程の「100万円超は部長決裁、500万円超は役員決裁」という基準に
照らして、承認権限に疑義がある申請を抽出してください。

【出力形式】
No | 申請日 | 金額 | 承認者 | 疑義の内容 | 確認が必要な理由
※ 規程上の基準に明確に抵触するものだけを挙げ、判断に迷うものは「要確認」として
別枠にまとめる。記載のない情報から疑義を推測で作り出さないこと

【購買稟議データ】
(ここにデータを貼付)
```

### 3. インタビュー記録・議事録の要約

```
以下は業務部門へのヒアリング(内部統制の運用状況確認)の文字起こしです。
監査調書用に整理してください。

【出力形式】
1. ヒアリング対象者・日時・目的(冒頭に記載があれば転記、なければ「別途記載」と明記)
2. 主な発言の要約(論点ごとに箇条書き)
3. 統制の運用状況について確認できた事実
4. 発言内容だけでは判断できず、証憑突合や追加確認が必要な点
5. フォローアップ事項の候補

【条件】発言していない内容を要約に加えない。断定できない趣旨は「〜という趣旨の
発言があった」と原文に忠実な書き方にする

【文字起こし】
(ここに文字起こしを貼付)
```

### 4. 監査報告書・発見事項(Finding)のドラフト作成

```
以下は監査手続で確認した事実のメモです。監査報告書の発見事項(Finding)として
定型フォーマットに沿って整理してください。

【フォーマット】
1. 発見事項のタイトル(1行)
2. 状況(Condition): 実際に確認した事実
3. 基準(Criteria): 本来あるべき姿(社内規程・法令等)
4. 原因(Cause): 推定される原因(断定できない場合は「要追加調査」と明記)
5. 影響(Effect): 想定されるリスク・影響範囲
6. 是正勧告案(Recommendation)

【確認した事実メモ】
(ここに監査手続で確認した内容を貼付)

【条件】重要性の評価(高・中・低)はあなたが仮の案を出してよいが、
「(監査人による最終判断が必要)」と必ず注記すること
```

### 5. J-SOX・内部統制評価文書の作成支援

既存の業務マニュアルやシステムの操作ログから、業務記述書・RCM(リスク・コントロール・マトリクス)のドラフトを作らせる。デロイト トーマツやPwCは、この工程にRAG(検索拡張生成、社内文書を検索してから回答させる方式)を組み込んだ生成AI導入支援サービスを提供しており、監査人は生成された下書きの判断・結論部分の確認に集中できるとしている。

```
以下は購買プロセスの業務マニュアル(抜粋)です。J-SOX文書化のための
業務記述書・RCMのドラフトを作成してください。

【出力形式】
1. 業務記述書: プロセスの流れを「担当部署・実施内容・使用システム」の
   順で箇条書き
2. RCM: 統制ポイントごとに「リスク」「統制活動の内容」「統制の実施頻度」
   「証跡(何をもって実施を確認できるか)」を表形式で

【条件】マニュアルに記載のない統制活動を新たに作り出さない。
記載が曖昧な箇所は「要現場確認」と明記する

【業務マニュアル抜粋】
(ここに貼付)
```

出力はあくまで一次ドラフトであり、統制の実在性・整備状況・運用状況の評価(デザイン評価・運用評価)は監査人が実際の証跡確認を経て確定させる。

### 6. 継続的監査・異常検知ツールの活用

サンプリング(母集団の一部を抽出して調べる方式)ではなく、取引ログの全数を継続的に分析して外れ値を検出する専用ツールも実務に定着しつつある。MindBridge AI Auditorは売上・経費・給与・仕入先取引などの元帳データを継続的・自動的に分析し、リスクの高い取引や不正の兆候をスコアリングして抽出する。DataSnipperはExcel上の台帳データと証憑ファイル(請求書・契約書等)をAIエージェントが自動照合し、根拠となるエビデンスへのリンク付きで監査調書に転記する機能を持つ。いずれも「フラグが立った取引=不正」ではなく、**フラグは調査の出発点であり、原因調査と最終判断は監査人が行う**という位置づけで運用する。

### ツール横断の対応付けと料金の目安(2026年7月時点)

| 用途 | 主なツール | 特徴・料金の目安 |
|---|---|---|
| 監査報告書・要約・議事録のドラフト作成 | ChatGPT / Claude / Gemini(汎用AI) | 法人向けプラン(学習への非利用が標準)での利用が前提。監査調書に転記する前に必ず人が確認 |
| 監査エビデンスの抽出・台帳との自動照合 | DataSnipper | Excelネイティブのプラットフォーム。AIエージェントによる文書照合・Web証跡取得機能を持ち、Deloitte・EY・KPMG・PwC・BDOなど85カ国60万人超の専門家が利用。料金は個別見積り制 |
| 継続的監査・異常検知(取引データの全数分析) | MindBridge AI Auditor | 元帳データを継続的に分析し、リスクスコアの高い取引を自動抽出。料金は個別見積り制 |
| 監査ワークフロー・GRC(ガバナンス・リスク・コンプライアンス)管理 | AuditBoard / Resolver / Workiva | 監査計画・テスト・是正管理を一元化するプラットフォーム。トレーサビリティ(証跡の追跡可能性)を重視した設計。料金は個別見積り制 |
| J-SOX文書化支援(RAGベースの下書き生成) | デロイト トーマツ・PwC等の生成AI導入支援サービス | 個別コンサルティング契約。業務記述書・RCM・フローチャートのドラフト生成、監査調書フォーマットへの自動流し込みを支援 |

判断基準は「その業務が監査基盤(GRCシステム・監査調書管理)への組み込みを必要とするか」。継続的モニタリングや監査証跡の一元管理を求める場合は専用ツール(DataSnipper・MindBridge・AuditBoard等)、単発の報告書ドラフト・要約には汎用AIチャットで十分なことが多い。

## 注意点・よくある誤解

- **監査対象の業務部門と同じAIベンダー・同じツールを使うと、独立性・客観性が疑われる**: IIAグローバル内部監査基準1100は、内部監査活動が独立して業務を遂行できることと、監査人が客観的であることを求めている。監査対象の業務部門が日常業務で使っているAIツール・ベンダーを内部監査自身がそのまま使うと、①AIの処理結果に監査対象部門の業務慣行があらかじめ反映されている可能性、②ベンダーとの契約・データ提供関係が監査対象部門側の意向に影響される可能性、の2点で独立性の毀損が疑われる。第三者機関の解説でも、第三者AIベンダーの利用そのものを内部監査が評価すべきリスク領域(モデルリスク・データ漏えい・バイアス・シャドーAIなど)として位置づけている。実務上は、監査対象部門と別のツール・別の契約・別の環境を使う、または少なくとも利用実態と利益相反の有無を監査委員会・監査役会に開示することが望ましい。
- **AIのアルゴリズムによる判定を無批判に受け入れることも客観性を損なう**: 「AIが異常なしと判定したから統制は有効」「AIがフラグを立てたから不正」と機械的に結論づけるのは、監査人自身の批判的評価(critical evaluation)を放棄することになり、客観性の観点から問題がある。異常検知のフラグ・生成AIの一次判断は、必ず監査人が独立して裏取り・原因調査を行った上で監査意見に反映する。
- **ハルシネーション(もっともらしい誤情報を生成する現象)のリスクは監査結論の信頼性に直結する**: 存在しない規程条文を引用したり、証憑に記載のない事実を「発見事項」として断定的に書いてしまうことがある。プロンプトで「記載のない情報を推測で断定しない」ことを明記し、AIが生成した発見事項・原因分析は必ず一次証憑(契約書・システムログ・ヒアリング記録)と突き合わせて確認する。詳細は[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md)を参照。
- **監査証跡には機密性の高い情報が集中しやすい**: 内部通報の詳細、未公表の決算情報、人事上の懲戒案件、取引先の機密情報など、他部門以上に機微な情報を扱う。無料プランの汎用AIに入力すると学習データとして利用される規約になっている場合があるため、法人向けプラン(学習への非利用がデフォルト)の利用、社外秘データのマスキングなど、[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md)に沿った運用を徹底する。
- **「継続的監査で全数分析ができる」=「サンプリングの手間がなくなる」ではない**: 全数分析ツールは異常の「候補」を大量に洗い出せるが、フラグの多くは偽陽性(実際には問題のない正常な取引)であり、原因調査・重要性判断という監査人の作業自体は残る。母集団カバレッジの向上と、監査人の実作業負荷の軽減は別の話として捉える。
- **AIによるJ-SOX文書ドラフトは「整備状況の記録」であり「評価結論」ではない**: 業務記述書・RCMのドラフトが自動生成されても、統制が実際に整備され有効に運用されているかの評価(デザイン評価・運用評価)は、証跡確認・現場ウォークスルーを経て監査人が確定させる必要がある。

## 最初の一歩

直近で実施した(または予定している)監査手続のうち、ヒアリング記録の要約、または監査発見事項のドラフト作成のいずれか1件を選び、上記のプロンプトを匿名化・仮の内容に置き換えたサンプルで試し、AIの出力と自分が本来まとめる内容を見比べて、断定的すぎる記述や抜け漏れがないかを確認してみる(社外秘の実データはそのまま入力しないこと)。
