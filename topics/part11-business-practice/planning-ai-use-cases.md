# 企画職における生成AI活用

## これは何か

事業企画・商品企画・新規事業開発といった「企画」職の仕事は、マーケティングや営業のような定型業務が少なく、「まだ形になっていないアイデアを、誰かに承認してもらえる企画書に仕上げる」という0→1の発想と意思決定者への提案が中心になる。この「発散(アイデアを広げる)→収束(絞り込んで裏付ける)→提案(通す)」というサイクルの各段階に生成AIをどう差し込むかが分かれば、1人で考え込む時間を大きく圧縮できる。本ページはリサーチ全般([生成AIによる情報収集・リサーチの実務活用](./ai-research-and-information-gathering.md))や文章作成全般([生成AIによる文章作成・編集の実務活用](./ai-writing-and-editing.md))の一般論はそれぞれの専門ページに委ね、企画職特有の「アイデア発想の壁打ち」「市場規模・ペルソナ仮説」「シナリオ分析」「意思決定者向けの提案」に絞って、コピペで使えるプロンプト例とともに整理する。

## 仕組み・背景

企画業務が生成AIと相性がよい理由は、性質の異なる2つの場面がはっきり分かれていることにある。

1. **発散フェーズ(アイデアを広げる)**: 「できるだけ多くの切り口を出す」ことが目的で、正解が1つではない。人間同士のブレインストーミングは参加人数・時間の制約で1回の会議で出せるアイデアの数に限りがあるが、生成AIは疲れず、遠慮せず、数分で数十〜百件規模の切り口を出せる。SCAMPER法(代用・結合・応用・修正・転用・削除・逆転の7つの視点で既存の製品・サービスに問いを立てる発想フレームワーク)やオズボーンのチェックリスト(転用・応用・変更・拡大・縮小・代用・再配置・逆転・結合の9視点)のような発想フレームワークをAIへの指示に組み込むと、思いつきの雑談に終わらず、視点の網羅性が上がる。
2. **収束フェーズ(絞り込み・裏付け)**: 出てきたアイデアを「本当に成立するか」検証する段階では、市場規模・競合状況・実現可能性といった事実に基づく裏付けが必要になる。ここはAIの発想力よりも[Deep Research系機能](./ai-research-and-information-gathering.md)によるリサーチ代行や、既知の情報を整理させる使い方が向く。

企画職ならではの注意点は、この2つのフェーズでAIに求める役割が正反対だという点である。発散フェーズでは「とにかく数を出させる・突飛な案も歓迎する」指示が有効だが、収束フェーズで同じ調子のまま数値や市場規模を語らせると、AIが「もっともらしいが根拠のない数字」を作ってしまう(ハルシネーションについては[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md)を参照)。フェーズが変わったら、AIへの依頼の仕方(トーン・求める確実性のレベル)も切り替える必要がある。

## 使いどころ・使い分け

### 企画業務フェーズ別のAI活用マップ

| フェーズ | 主なタスク | AIの向き・不向き | 主に使う機能 |
|---|---|---|---|
| 発散(アイデア出し) | ブレインストーミングの壁打ち、SCAMPER等のフレームワーク適用、アイデアの拡張・変形 | 向く(数を出す・視点を広げる) | 通常のチャット(対話形式) |
| 収束(裏付け・検証) | 市場規模推定、競合ポジショニング分析、ペルソナ仮説、実現可能性の一次チェック | 向く(情報の整理・比較)。数値の正確性は要検証 | Deep Research系機能([詳細](./ai-research-and-information-gathering.md)) |
| シナリオ検討 | 楽観・中庸・悲観シナリオの売上・コスト試算、リスク要因の洗い出し | 向く(前提を変えた複数パターンの試算のたたき台)。最終的な数値の妥当性判断は人が担う | 通常のチャット、必要に応じてAdvanced Data Analysis系機能 |
| 企画書化 | 構成案・骨子の作成、本文の肉付け、要約版・詳細版の作り分け | 向く(たたき台・型に沿った文章化) | [文章作成・編集](./ai-writing-and-editing.md) |
| 提案・説得 | 社内プレゼン資料への落とし込み、想定質問への回答案作成 | 向く(想定される反論・質問の洗い出し) | [プレゼン資料・ドキュメント作成](./ai-presentation-and-document-creation.md) |

判断の軸は、「まだ正解が決まっていない・数を出したい」発散寄りの仕事はAIに主導させやすく、「事実・数値の正確性が問われる」収束寄りの仕事は人が検証責任を持つ、という切り分けになる。

### 「壁打ち相手」としての使い方の心構え

企画職がAIを使う場面でとくに効果が出やすいのが、1人で考え込みがちな初期アイデアの「壁打ち」相手としての使い方である。人間の同僚に相談すると気が引ける「まだ粗いアイデア」や「何度も同じ観点で聞き直す」といった使い方も、AIには気兼ねなく持ちかけられる。ただし壁打ちの効果を上げるコツは、AIに一度で結論を出させず、往復の対話を重ねて自分の考えを言語化・構造化していくことにある。1回のプロンプトで「良い企画」を出させようとするのではなく、「この前提はどうか」「この案の弱点は何か」と何度も切り返す使い方が実務的である。

## 実務での使い方

### プロンプト例1: アイデア発想の壁打ち(SCAMPER法での拡張)

まだ漠然とした課題意識・アイデアの種がある段階で、視点を網羅的に広げたいときに使う。

```
あなたは新規事業開発の経験が豊富なブレインストーミングパートナーです。
以下のアイデアの種について、SCAMPER法(代用・結合・応用・修正・転用・削除・逆転の
7つの視点)を使ってアイデアを拡張してください。

## アイデアの種
[例: 社内の会議室予約システムを、そのまま外部の中小企業向けにSaaSとして販売できないか]

## 前提・制約
[例: 開発リソースは最大3人、初期投資は500万円程度まで]

## 出力条件
- SCAMPERの7視点それぞれについて、最低2案(合計14案以上)を出す
- 突飛・非現実的に見える案も歓迎する。この段階では実現可能性で絞り込まない
- 各案は1〜2行で簡潔に。良し悪しの評価はまだしない
- 最後に、上記の中で「議論を深める価値がありそうな案」を3つ選び、
  それぞれ「なぜ有望と考えたか」を一言添える(ただしこれも仮説であり最終判断ではない)
```

出てきた案に対して、「この案について、想定される顧客はどんな人か」「この案の一番のリスクは何か」と続けて聞き返し、対話を重ねて絞り込んでいく使い方が壁打ちの本来の効果を発揮する。

### プロンプト例2: 市場規模・競合ポジショニングの仮説作り(収束フェーズ)

発散フェーズで案を絞ったら、次はその案の市場性を仮説として整理する。ここは通常のチャットよりも[Deep Research系機能](./ai-research-and-information-gathering.md)を使い、TAM(Total Addressable Market、獲得しうる理論上の最大市場規模)・SAM(Serviceable Available Market、実際にアプローチできる市場規模)・SOM(Serviceable Obtainable Market、当面現実的に獲得できる市場規模)の3段階で市場規模を整理させると、企画書にそのまま転用しやすい。

```
あなたは事業開発のリサーチアナリストです。以下の事業アイデアについて、
Deep Researchを実行し、TAM・SAM・SOMの考え方で市場規模の仮説を整理してください。

【事業アイデア】
[例: 従業員300〜1,000人規模の企業向けの会議室・座席予約SaaS]

【調べてほしい項目】
  1. 該当市場のTAM・SAM・SOMの推定値(それぞれの算出根拠・前提条件を明記)
  2. 主要競合5社程度の料金・機能・ターゲット顧客層の比較
  3. 競合と比較した際にこの事業アイデアが取りうるポジショニング(差別化の方向性)の仮説を2〜3個
  4. 想定顧客のペルソナ仮説(役職・課題・意思決定プロセス)を1〜2名分

【出力形式】
  - 数値には必ず出典URLと発表年を明記する
  - 出典が見つからない・推定に留まる数値は「推定」「未確認」と明記する
  - 算出根拠が異なる複数の市場規模データが見つかった場合は、両方を提示し前提の違いを説明する

【除外条件】
  - 個人・フリーランス向けの小規模サービスは競合対象外
  - 3年以上前の古いデータは参考程度にとどめ、本文には反映しない
```

「数値には出典・算出根拠を明記させる」「不確実な部分は推定と明記させる」という2点が、企画書に転用可能な形でハルシネーションのリスクを抑える最低限の指示になる。それでもAIが提示した市場規模はあくまで仮説であり、重要な投資判断の前には人が原典を確認する(検証の考え方は[生成AIによる情報収集・リサーチの実務活用](./ai-research-and-information-gathering.md)の「出てきたレポートの活用フロー」を参照)。

### プロンプト例3: シナリオ分析(楽観・中庸・悲観)のたたき台作成

事業計画の数値見通しを1パターンだけで出すと、意思決定者から「前提が崩れたらどうなるのか」と必ず問われる。AIに複数シナリオのたたき台を出させ、前提条件の違いを整理しておくと議論が速い。

```
あなたは事業計画の策定を支援するアナリストです。以下の事業について、
楽観・中庸・悲観の3シナリオで、初年度〜3年目までの売上見通しのたたき台を作成してください。

## 事業概要
[例: 会議室予約SaaS、月額課金制、想定顧客は中小企業の総務担当者]

## 分かっている前提条件
[例: 想定顧客単価は月額3万円、初年度の営業体制は2名]

## 出力条件
- 楽観・中庸・悲観の3シナリオそれぞれで、契約社数・売上・主要コストの推移を年次で示す
- 各シナリオで「どの前提が変わるとそのシナリオになるか」(契約社数の伸び率、解約率など)を明記する
- 悲観シナリオについては、その状況に陥った場合の対応策(コンティンジェンシープラン)の案を2〜3個提示する
- これはあくまで仮定に基づく試算であることを明記し、実際の数値の妥当性は財務担当者が確認する前提とする
```

このたたき台をそのまま採用するのではなく、実際の受注実績・市場データを持つ営業・財務部門のメンバーと数値をすり合わせる工程を必ず挟む。

### 企画書・事業計画書への落とし込み(構成→肉付けの2段階)

企画書の作成では、AIにいきなり本文を書かせず、まず章立て(骨子)だけを作らせて中身を確認し、OKなら肉付けさせる2段階アプローチが手戻りを減らす(考え方は[生成AIによる文章作成・編集の実務活用](./ai-writing-and-editing.md)の「反復編集の進め方」と同じ)。

```
あなたは事業企画書の作成を支援するコンサルタントです。
以下の情報をもとに、まず企画書の章立て(骨子)だけを作成してください。本文はまだ書かないでください。

## 企画の概要
[プロンプト例1・2で整理した内容を貼り付け]

## 想定読者・提出先
[例: 事業部長・経営企画部、承認可否を判断する立場]

## 出力条件
- 一般的な新規事業企画書の型(背景・課題・市場性・提案内容・実行計画・想定リスク・必要な意思決定事項など)
  をベースに、この企画にとって特に説得力を持たせるべき章を提案してほしい
- 各章に、その章で書くべき要点を箇条書きで3つ程度添える
- 意思決定者が最初に知りたいであろう疑問(なぜ今か、なぜ自社がやるべきか)に
  答える章を冒頭付近に配置する
```

骨子を確認・修正したら、章ごとに「この章を肉付けしてください」と個別に依頼していくと、AIが一度に長文を書いて論点がぼやける事故を防げる。スライド化する段階では[生成AIによるプレゼン資料・ドキュメント作成の実務活用](./ai-presentation-and-document-creation.md)を参照。

### 応用: 想定質問・反論への備え

企画の提案は「通す」ことが目的であり、意思決定者からの想定質問に事前に備えておくと当日の説得力が上がる。

```
あなたは経営会議でこの企画をレビューする立場の経営陣です。
以下の企画内容について、承認する前に必ず確認したいであろう質問・懸念点を
10個リストアップしてください。厳しめの視点で構いません。
その後、それぞれの質問に対する回答の方向性(案)も一言添えてください。

## 企画内容
[企画書の骨子または要約を貼り付け]
```

AIに「レビュアー役」を演じさせて弱点を先に洗い出させておくと、本番での想定外の質問を減らせる。

## 注意点・よくある誤解

- **「もっともらしい市場規模・数値」を無検証で企画書に載せない**: AIは市場規模やシェアの数値を、実在するデータと混同したり、もっともらしい桁数を作文して提示することがある。特にTAM・SAM・SOMのような算出方法によって前提が大きく異なる数値は、出典・算出根拠・発表年を必ず確認し、複数の推計を比較した上で「どの前提に立った数値か」を企画書に明記する(仕組みと対策は[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md)を参照)。
- **発散フェーズと収束フェーズでAIへの依頼の仕方を切り替える**: 発散フェーズの「数を出す」指示のまま数値や市場性を語らせると、AIは「間違っている」より「もっともらしく答える」ことを優先してしまう。数値・事実を扱う段階では、必ず「不確実な場合は推定と明記する」「出典を示す」指示を加える。
- **シナリオ分析の数値をそのまま経営会議に出さない**: 楽観・悲観シナリオのたたき台はあくまで「前提を変えたときの試算パターン」であり、実際の受注実績・市場感覚を持つ営業・財務部門のすり合わせを経ないまま資料化すると、後から前提の甘さを突かれやすい。
- **同質化のリスク**: 同じAIモデルに似たプロンプトで市場調査・企画骨子を作らせると、他社も似たような分析・切り口に行き着きやすい。差別化の核となる部分(独自の顧客インサイト・自社の強みとの接続)は、AIの出力をベースに人間が深掘りして肉付けする。
- **未公表の事業計画・顧客データをそのまま貼り付けない**: 新規事業のアイデアや未公表の数値計画を無料プランのAIに入力すると、学習利用の可否がツールごとに異なるため情報漏洩のリスクがある。会社の利用ルールを確認し、機密性の高い企画は法人向けプラン・社内承認済みツールを使う。
- **AIの「賛成」に安心しない**: 壁打ちでAIに案の良さを聞くと、多くの場合肯定的な評価を返しやすい傾向がある(ユーザーの意見に同調しやすい性質)。本当に弱点を洗い出したい場合は、「この案の欠点だけを厳しく指摘してください」のように役割・視点を明示的に指定する。

## 最初の一歩

今抱えている粗いアイデアや課題意識を1つ選び、プロンプト例1のSCAMPER法テンプレートを使って壁打ちを1回試し、出てきた案の中から気になる1つについて「この案の一番のリスクは何か」とAIに聞き返してみる。
