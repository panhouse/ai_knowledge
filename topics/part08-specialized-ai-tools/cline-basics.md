# Clineの基本(コーディング支援AI)

## これは何か

Cline(クライン)は、VS CodeやJetBrains系IDEに追加する**オープンソース(無償公開・改変自由なソースコード)のAIコーディングエージェント拡張機能**である。GitHub Copilotのような「ベンダーが用意したAIモデルを使う」前提のツールとは異なり、Clineは自分でAnthropic・OpenAI・Google・ローカルLLM(自社PC上で動かすAIモデル)など好きなAIモデルのAPIキーを持ち込んで接続する「BYOK(Bring Your Own Key、自分のAPIキーを持ち込む)」方式が最大の特徴である。

非エンジニアの決裁者にとっての困りごとは、「エンジニアが『Clineを使いたい』と言ってきたとき、Copilotと何が違うのか、会社としてAPIキーやコストの管理をどうすればいいのか判断できない」ことだ。本ページは、Clineが「ツール自体は無料だがAI利用料は自己負担」という特殊な料金構造を持つことと、その構造が向いている企業・向いていない企業の見分け方に絞って解説する。

## 仕組み・背景

### 生まれた経緯

Clineは2024年6月、Anthropicが開催したハッカソンの場で、開発者のSaoud Rizwan氏が個人で作ったツールが元になっている。当時リリースされたばかりのClaude 3.5 Sonnetのモデルカード(性能・特性の説明資料)に「自律的にコーディングできる」という記述を見て試作したのが最初で、拡張機能の名前は当初「Claude Dev」だった。その後Cline(クライン)へ改名されたが、VS Code拡張機能のID(`saoudrizwan.claude-dev`)には今も旧名が残っている。ライセンスはApache 2.0で、GitHub上で誰でもソースコードを閲覧・改変できる。2026年時点でGitHubスター数6万超、VS Code Marketplaceでのインストール数は500万を超える規模に成長した。

### エージェント的な動作の中身

ClineはCopilotのAgent ModeやCursorのComposerと同様に、以下のような「自律的にコードベースを操作する」動作を行う。

- プロジェクト全体のファイル構造を読み込み、関連ファイルを横断して理解する
- 複数ファイルへのコード編集を提案し、diff(差分)として提示する
- ターミナルでコマンド(パッケージインストール・ビルド・テスト実行など)を実行し、出力をリアルタイムで監視する
- ブラウザを実際に操作(Puppeteerというブラウザ自動操作の仕組みを利用)してWebページの表示を確認し、見た目のズレなどを自分でスクリーンショットを見て修正する
- MCP(Model Context Protocol、AIモデルと外部ツール・データを接続する共通規格)に対応し、検索・社内システム連携などのツールを追加できる
- `.clinerules`というファイルにプロジェクト固有のコーディング規約・注意事項を書いておくと、Clineがそれに従って作業する

### Plan/Actモード

Clineの最大の特徴の一つが「Plan(計画)」と「Act(実行)」の2モード切り替えである。

- **Planモード**: コードを変更せず、コードベースを読んで方針を考え、不明点があれば人間に質問する。実際にファイルを書き換えないため消費トークン(≒コスト)が少なく、「的外れな実装をさせて後から直す」手戻りコストを避けられる
- **Actモード**: 実際にファイル編集・コマンド実行を行う。デフォルトでは、ファイル編集1件・コマンド実行1件ごとに人間の承認を求める「Human-in-the-loop(人間による都度承認)」が入り、設定で自動承認(オートアプルーブ)に切り替えることもできる

まず設計をレビューしてから実行に移せる点が、「指示を出したら一気に全部変更される」タイプのツールに比べて、非エンジニアの管理職にも説明しやすい安全弁になっている。

### コスト管理の仕組み

Clineは会話パネル内に、その時点までの**トークン使用量と推定コスト(ドル換算)**をリアルタイム表示する。さらに2026年前半のアップデートでは、あらかじめ設定した上限に達すると処理を止める「Spend Limit(支出上限)」表示や、セッションごとのトークン上限設定機能が追加され、「エージェントが暴走して高額なAPI利用料が発生する」リスクを抑える仕組みが強化されている。また、作業のスナップショットを取る「Checkpoints(チェックポイント)」機能があり、ファイルだけ戻す・会話だけ戻す・両方戻すといった単位で作業を巻き戻せる。

## 使いどころ・使い分け

### そもそも導入すべきか

| 状況 | 判断の目安 |
|---|---|
| 自社で使うAIモデルを厳密に選定・管理したい(特定モデルへのロックインを避けたい) | Clineが最適。Anthropic・OpenAI・Gemini・AWS Bedrock・ローカルLLMなど30以上のプロバイダーから選べる |
| AI利用料をプロジェクト・チーム単位で細かく計測・付け替えたい | 各AIプロバイダー側の管理画面でAPIキー単位の使用量を追跡できるため、コスト配分がしやすい |
| セキュリティ要件で「社内で契約済みのクラウド(Azure OpenAI・AWS Bedrock等)しか使えない」 | ClineはBYOKなので、既存の契約済みインフラにそのまま接続できる |
| ツールの運用・請求・サポートをすべて1社にまとめたい | GitHub Copilotなど、単一ベンダーが課金・サポートを一体で提供するツールの方が管理コストは低い |
| エンジニアがコマンドライン操作に不慣れ、AI利用料の予算感覚がない | 従量課金の請求書に驚くリスクがあるため、まずCopilotのような固定額プランで慣れる方が安全 |

### 料金モデル(2026年7月時点)

Clineの料金構造はCopilot・Cursor・Windsurfとは根本的に異なり、**「ツール自体」と「AIモデルの利用料」が完全に分離**している。

| 項目 | 内容 |
|---|---|
| Individual(個人) | 0ドル。拡張機能は完全無料でオープンソース。サブスクリプションもクレジット制度もない |
| Teams(チーム) | 1ユーザー20ドル/月。ただし最初の10シートは永続的に無料。チーム管理機能・利用状況の一元管理・JetBrains対応などが付く |
| Enterprise(企業) | 個別見積もり。SSO/OIDC/SCIM(ID管理連携)、監査ログ、VPC(閉域網)内デプロイ、専用サポートなどガバナンス機能を提供 |
| AIモデルの利用料 | 上記とは別に、選んだAIプロバイダー(Anthropic・OpenAI等)に対して使った分だけ実費が発生。Clineへの支払いではなく、各プロバイダーへの直接支払いになる |

参考値として、Claude Sonnet系モデルで1日フルにコーディングすると数ドル〜十数ドル、Opus系などの高性能モデルではさらに高くなり、利用量の多い開発者では月200〜500ドル程度のAPI利用料になるという報告もある。**「Clineは無料」という言葉だけを見て、AI利用料までゼロだと誤解しないことが重要である。**価格・無料枠の条件は変更されやすいため、契約前に公式サイト(cline.bot/pricing)で最新値を確認すること。

### 競合ツールとの違い

| ツール | 提供元 | ライセンス/オープンソース | 料金モデル | 位置づけ |
|---|---|---|---|---|
| Cline | Cline Bot Inc.(コミュニティ主体) | OSS(Apache 2.0) | 拡張機能は無料、AI利用料は実費(BYOK) | コスト管理・モデル選択の自由度を最優先したい企業・個人向け |
| GitHub Copilot | GitHub(Microsoft) | 非公開(プロプライエタリ) | 月額固定+AI Credits従量課金 | GitHub本体との統合、組織のガバナンス機能を重視する企業向け |
| Cursor | Anysphere | 非公開(プロプライエタリ) | 月額固定+使用量による上乗せ | AI前提で設計された専用エディタでの一体感を重視する層向け |
| Windsurf | Windsurf(旧Codeium) | 非公開(プロプライエタリ) | 月額固定(クレジット制/使用量クォータ制) | 自社モデルによる大規模コードベース理解を重視する層向け |

Cline・Copilot・Cursor・Windsurfはいずれも「AIがファイルを自律的に編集する」エージェント機能を持つ点は共通している。違いは「モデルを自分で選び、実費だけ払うか(Cline)」「ベンダーが用意したモデル・料金体系に乗るか(Copilot/Cursor/Windsurf)」にある。社内でCopilotを契約しつつ、コスト管理やモデル選定にこだわるエンジニアが個人裁量でClineを併用するケースも多い。

## 実務での使い方

### 導入手順

1. VS Codeの拡張機能タブ(`Ctrl+Shift+X` / `Cmd+Shift+X`)を開き、「Cline」で検索してインストールする(拡張機能ID: `saoudrizwan.claude-dev`。旧名「Claude Dev」の名残でこのIDのままになっている)
2. 左側のアクティビティバーに追加されたClineのアイコンをクリックし、サイドパネルを開く
3. パネル右上の設定(歯車)アイコンをクリックし、「API Provider」欄で使いたいAIモデルの提供元(Anthropic、OpenAI、Google Gemini、AWS Bedrock、Azure、OpenRouter、ローカルLLM用のOllama/LM Studioなど)を選ぶ
4. 選んだプロバイダーのAPIキーを貼り付け、使用するモデル名(例: Claude Sonnet系、GPT系など)を選択して保存する
5. チャット入力欄下部にある「Plan」「Act」の切り替えボタンで、まずPlanモードで方針を確認してから、Actモードに切り替えて実行する

### エンジニアがClineを使う典型的な場面

- 社内で契約済みのAzure OpenAIやAWS Bedrockのアカウントに直接つないで、追加のツール利用料なしでエージェント機能を使う
- 高精度が必要な複雑なタスクはClaude Opus系、日常的な軽いタスクは安価なモデルに切り替えるなど、タスクの重要度に応じてモデルとコストを使い分ける
- 機密性の高いコードを扱うプロジェクトで、外部にコードを送らないローカルLLM(Ollama等)に切り替えて動かす
- MCPで社内のドキュメント検索やIssue管理システムをClineに接続し、社内情報を踏まえたコード生成をさせる

### 導入判断のポイント(非エンジニアの管理職向け)

- **「無料」の意味を正しく伝える**: ツール自体は無料だが、AI利用料は使った分だけ発生する。予算管理担当者には「サブスクリプションではなく従量課金である」ことを明確に伝える
- **APIキーの管理責任は自社側にある**: Copilot Business/Enterprise が提供するIP(知的財産)補償のような保証は、Cline自体には付随しない。使うAIプロバイダーとの契約条件・データの取り扱いを個別に確認する必要がある
- **オートアプルーブ(自動承認)設定の運用ルールを決める**: ファイル編集やコマンド実行を自動承認する設定は効率的だが、任意のシェルコマンドを人間の確認なしに実行するリスクも伴う。本番環境に近いリポジトリでは承認を必須にする運用にする
- **エンジニアの技術力に依存する**: APIキーの発行・プロバイダー選定・コスト監視をエンジニア自身が行う必要があるため、運用の巧拙がエンジニアのスキルに左右されやすい

## 注意点・よくある誤解

- **「Clineが無料」≠「AI利用料もゼロ」**: 拡張機能自体は無料だが、実際にコードを書かせるたびにAPI利用料が発生する。ヘビーユーザーでは月数百ドル規模になった例も報告されており、予算アラートやトークン上限の設定を最初から行っておくべき
- **「Claude Dev」という拡張機能IDはAnthropic公式という意味ではない**: Clineはもともと「Claude Dev」という名前で始まり、拡張機能IDに名残があるが、Anthropicが開発・提供している公式ツールではない(独立したオープンソースコミュニティ/企業が開発している)
- **オートアプルーブは便利だが無防備にもなる**: ターミナルコマンドの自動承認を有効にすると、意図しないコマンド(ファイル削除、外部への送信など)が承認なしに実行される可能性がある。特にAPIキーや機密情報が置かれた環境では慎重に設定する
- **Planモードを軽視しない**: Actモードで一気に実行させると、的外れな実装のやり直しでトークン(コスト)を余計に消費する。まずPlanモードで方針を合意してからActに切り替える運用がコスト面でも有利
- **VS Code拡張機能という性質上、GitHub本体との統合はCopilotほど深くない**: Issueへの直接アサインやPRの自動作成といったGitHub連携の一体感は、GitHub Copilotの方が優位である

## 最初の一歩

VS CodeにCline拡張機能をインストールし、少額のAPIキー(利用上限を設定したもの)を1つ接続して、まずPlanモードで小さなタスク(例: 既存関数へのコメント追加程度)を試し、表示される推定コストを確認することから始めるとよい。
