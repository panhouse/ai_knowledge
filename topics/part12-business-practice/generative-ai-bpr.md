# 生成AIによるBPR(業務プロセス再構築)

## これは何か

BPR(Business Process Re-engineering、業務プロセス再構築)とは、既存の業務の一部を効率化するのではなく、「この業務は本当に必要か」「別のやり方でできないか」を白紙から問い直し、プロセス全体を作り直す取り組みを指す。生成AIを個々の作業に当てはめるだけでは、承認待ちや部門間の引き継ぎといった業務プロセス自体のムダは残ったままで、生産性は思ったほど上がらない。

この構図を裏付けるデータが2025〜2026年にかけて相次いで示されている。MIT(マサチューセッツ工科大学)が2025年に発表した調査(通称「GenAI Divide」)では、生成AIを導入した企業の95%が損益に表れるほどの成果を出せておらず、その主因は汎用ツールを既存の業務フローにそのまま載せただけで、実際の仕事の流れに組み込めていないことだと指摘されている。逆に、Gartnerが2025年に管理職1,973人を対象に実施した調査では、AIツールを配るだけでなく働き方(業務プロセス)自体を作り直した部門は、収益目標を達成できる割合が2倍に達するとしている。IBMが2026年に実施したCEO調査でも同様の傾向が見られ、部門横断でチームの働き方を再設計した企業は事業目標を達成できた割合が2倍以上、技術・財務・人事・オペレーション・部門横断連携の5領域を再設計した企業では4倍という差が出ている。

日本国内でも、帝国データバンクが2026年3月に実施した調査(有効回答10,312社)によれば、生成AIを活用する企業は34.5%(大企業46.5%、中小企業32.4%)まで広がり、活用企業の86.7%が「業務効果あり」と回答している。一方で最多の用途は依然として「文章の作成・要約・校正」(45%)や「情報収集」(22%)など個々の作業支援にとどまり、業務プロセスそのものを作り直すところまで踏み込めている企業は少数派とみられる。つまり「AIをどう使うか」の前に「業務プロセスをどう作り直すか」を考えられるかどうかが、成果の差を分けている。

なお、「AIに向く業務・向かない業務の切り分け」自体は[生成AIに向く業務・向かない業務の切り分け](ai-task-suitability.md)で扱っているため、本ページでは切り分けた後に業務プロセス全体をどう再設計し、定着させるかという「進め方」に絞って解説する。

## 仕組み・背景

従来型のBPR(1990年代に広まった経営改革手法)は、既存の業務フローを図に描き、ムダな工程を削ったりシステム化したりする形で進められてきた。ここでの前提は「業務を実行するのは人間である」ことであり、AIはせいぜい定型作業を代行する補助ツールという位置づけだった。

生成AI時代のBPR(「AI BPR」「Agentic BPR」などと呼ばれる)が従来型と決定的に違うのは、この前提そのものが変わる点にある。生成AI・AIエージェント(自律的に情報収集・判断・実行までを行うAI)が業務の担い手になり得ることを前提に置くと、次のようなプロセスの作り直しが可能になる。

- **承認フローの簡略化**: 一次チェックや情報収集をAIが担うことで、人による確認は「最終判断」だけに絞り込める
- **複数ステップの統合**: 「情報収集→整理→ドラフト作成→初回チェック」のように複数の担当者・部署をまたいでいた工程を、AIエージェント1つが一気通貫で処理できる
- **部門横断でのプロセス共通化**: デロイト トーマツが提唱する「Agentic BPR」では、部門・業務単位ではなく「情報収集」「判断材料の整理」「回答案の作成」といった業務に共通する"動作"に着目してプロセスを組み直すことで、部門最適の壁を越えられるとしている

つまり、従来のBPRが「今ある業務フローをどう効率化するか」を問うのに対し、生成AI時代のBPRは「AIが前提にあるなら、そもそもこのプロセスはどんな形が最適か」を問う。マッキンゼーも、AIによる企業全体の成果を左右する最大の要因は「ワークフローを根本から再設計したかどうか」であり、単にAIツールを既存業務に載せるだけでは限定的な効果しか出ないと指摘している。

現状把握の手法も進化している。ERP・CRMなどの業務システムに残る操作ログを解析し、実際の業務の流れを可視化する「プロセスマイニング」(process mining)を生成AIと組み合わせることで、ヒアリングだけに頼っていた「現状の棚卸し」を、データに基づいて自動化・高速化できるようになってきた。担当者の主観や記憶に頼らず、実際の処理時間・差し戻しの発生箇所・想定外の分岐ルートをログから客観的に洗い出せる点が、生成AI時代のBPRを後押ししている。

## 使いどころ・使い分け

すべての業務改善を大掛かりなBPRとして扱う必要はない。「小さな時短」で十分なケースと、プロセス全体の再設計が必要なケースを見極めることが重要になる。

| | 部分的なAI活用(タスク単位の時短) | プロセス全体のBPR |
|---|---|---|
| 対象 | 個々の作業(メール下書き、議事録要約など) | 複数部署・複数工程にまたがる一連の流れ |
| 目的 | 今のやり方のまま、かかる時間を減らす | やり方自体を作り直し、工程・承認・体制を変える |
| 効果の大きさ | 個人・チーム単位の数十分〜数時間/日 | 部門・全社レベルでのリードタイム短縮、人員配置の見直し |
| 必要な意思決定者 | 現場担当者・チームリーダー | 部門長・経営層(体制や権限の変更を伴うため) |
| 向くサイン | 業務フローそのものは合理的で、作業速度だけが課題 | 承認待ち・手戻り・部門間の引き継ぎが多く、フロー自体がボトルネック |

**見極めの質問**: 「AIで今の作業を速くするだけで十分か、それとも『なぜこの承認が必要か』『なぜこの部署を経由するのか』まで問い直す必要があるか」を自問する。後者に該当する兆候(承認者が形式的にハンコを押すだけ、同じ情報を複数部署で入力し直している、問い合わせの一次対応に人手を割いているなど)が複数見つかったら、部分最適ではなくBPRの対象として扱う。

前述のとおり、MITの調査では生成AI導入企業の95%がパイロット止まりで損益上の効果を出せていないと報告されている。既存の業務フローにツールをそのまま載せるだけの「部分的なAI活用」は、この95%側に留まりやすい。フロー自体の再設計まで踏み込んだ一部の企業だけが、成果につながる「BPR側」の成果を手にしている。

## 実務での使い方

### 進め方チェックリスト(6ステップ)

生成AI前提のBPRは、おおむね以下の順で進める。いずれのステップも「経営層の関与」を欠かすと、現場任せの部分最適で終わりやすい。

1. **現状の業務フローの棚卸し**
   - 対象プロセスの工程を「誰が」「何を」「どのくらいの時間で」行っているか書き出す(ヒアリング・業務日誌・ワークフローシステムのログなどを使う)
   - 承認・確認・差し戻しが発生するポイントに印を付ける
   - システム操作ログが残っている業務であれば、プロセスマイニングツール(Celonis、UiPath Process Miningなど)で実際の処理時間・差し戻し箇所を可視化すると、ヒアリングだけでは見えにくい「実態」を裏取りできる
2. **ボトルネックの特定**
   - 待ち時間が長い工程、手戻りが多い工程、複数部署をまたいで同じ情報を入力し直している工程を洗い出す
   - 「なぜこの工程が必要か」を各ステップに問い、形式的なだけの承認・確認を洗い出す
3. **AI活用ポイントの洗い出し**
   - ボトルネックのうち、AIが得意な「情報収集」「要約」「一次判断」「ドラフト作成」に置き換えられる工程を特定する(向き不向きの判断は[生成AIに向く業務・向かない業務の切り分け](ai-task-suitability.md)を参照)
   - 「工程を速くする」だけでなく「工程そのものを削れないか」「複数工程を1つに統合できないか」まで検討する
4. **試験導入(パイロット)**
   - 影響範囲の狭い1チーム・1業務に絞って新しいプロセスを試す
   - 人による最終確認の工程は必ず残し、AIの出力を鵜呑みにしない運用にする
5. **効果測定**
   - リードタイム(処理にかかる時間)、対応件数、差し戻し率、担当者の工数などをパイロット導入の前後で比較する
   - 数値だけでなく、現場担当者の負担感・顧客満足度などの定性面も確認する
6. **定着化・横展開**
   - 効果が確認できたプロセスを正式な業務手順として明文化し、関連部署に展開する
   - 新しいプロセスに合わせて評価基準・役割分担・権限規定も見直す(プロセスだけ変えて組織や評価制度が旧来のままだと定着しない)

### 業務シーン別のBefore/After

**問い合わせ対応フロー**

- Before: 問い合わせ受付 → 担当者が内容を確認 → 過去事例・マニュアルを検索 → 回答案を作成 → 上長が確認 → 回答送付(1件あたり複数人が関与)
- After: 問い合わせ受付 → AIエージェントが過去事例・マニュアルを検索し回答案を自動作成 → 定型的な内容はそのまま送付、例外的・重要な内容のみ担当者が最終確認 → 送付。人は「例外処理」と「最終判断」に集中する

**資料作成〜承認フロー**

- Before: 担当者がゼロから資料を作成 → 上長が体裁・誤字脱字も含めて細かくレビュー → 修正 → 再レビュー → 決裁(何度も往復)
- After: AIがたたき台・データ集計・グラフ化まで作成 → 上長は内容の妥当性・意思決定に必要な論点のみをレビュー(体裁チェックの往復を削減) → 決裁。レビューの粒度を「形式チェック」から「意思決定支援」に引き上げる

**データ集計〜レポーティングフロー**

- Before: 各部署が個別にExcelで集計 → 担当者が手作業で本社フォーマットに転記・集約 → レポート作成 → 会議で報告
- After: 各部署のデータをAIが自動集計・要約し、異常値や特筆すべき変化点をハイライトしたレポート案を自動生成 → 担当者は解釈・示唆出しに時間を使う。転記・集約という中間工程そのものをなくす

### 国内事例: プロセス再設計を先行させた企業

サッポログループは、3.5年にわたり継続してきたBPRの取り組みで累計約36万時間(人員換算で約200人分)の業務効率化を実現した。その土台の上で、2026年からグループ独自の生成AIツール「SAPPORO AI-Stick(通称:サッポロ相棒)」をグループ全社員(約6,000名)に展開し、2年以内に生成AIを日常業務へ浸透させる方針を掲げている。ポイントは、AIツールの導入を先に進めるのではなく、業務プロセスの棚卸し・再設計を先行させ、そのプロセスの上にAIを載せる順番で進めている点にある。「AIを配ってから使い方を考える」のではなく「プロセスを整理してからAIを充てる」順序が、定着の鍵になる。

## 注意点・よくある誤解

- **「AI導入」が目的化すると現場の反発を招く**: 現場のプロセスを理解せずにAIツールだけを導入すると、「使い方を覚える手間が増えただけ」と受け止められ定着しない。棚卸しとボトルネック特定を飛ばしていきなり導入しないこと
- **経営層の関与なしでは部分最適で終わる**: 承認フローの簡略化や部署の役割変更は、現場の一存では決められない。IBMの調査でも、部門横断で働き方を再設計した企業ほど成果を出しており、経営層が体制変更まで踏み込んで関与することが重要になる。Gartnerの調査でもCEOの8割が「AIによってオペレーション能力の抜本的な見直しが迫られる」と回答しており、経営課題として捉える動きが広がりつつある
- **パイロットで満足しない**: MITの調査では、生成AI導入企業の95%が損益に表れる成果を出せずパイロット止まりになっていると報告されている。汎用ツールを既存の業務フローにそのまま載せただけでは効果が定着しにくい。実際の業務フローに深く組み込み、利用状況を見ながら改善し続ける仕組みまで作って初めて、成果を出す側の少数派に入れる
- **人による確認工程をゼロにしない**: プロセスを効率化しても、AIの出力を検証せずに流す設計にすると誤りが後工程まで伝播する。ハルシネーション(AIが事実と異なる情報をもっともらしく生成する現象)のリスクを踏まえ、最終判断や例外処理には必ず人を残す
- **一気に全社展開しない**: 影響範囲の広いプロセスをいきなり全社で変えると、想定外の不具合や現場の混乱が大きくなる。1チーム・1業務での試験導入→効果測定を経てから横展開する
- **プロセスだけ変えて評価制度・役割分担を変えないと定着しない**: 新しいプロセスに合わせて、担当者の評価基準や引き継ぎ範囲まで見直さないと、旧来のやり方に戻ってしまう

## 最初の一歩

自部署の業務プロセスを1つ選び、その工程を紙やホワイトボードに書き出して「誰が」「何分/何日」かけているかを可視化してみる。承認や確認が形式的になっている工程が見つかったら、そこがBPRの最初の着手候補になる。
