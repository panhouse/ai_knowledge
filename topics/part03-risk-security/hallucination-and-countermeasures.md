# ハルシネーションの仕組みと実務での対策

## これは何か

ハルシネーション(hallucination、幻覚)とは、生成AIが事実に基づかない情報を、あたかも本当であるかのように自信満々な口調で作り出してしまう現象のこと。存在しない判例や統計データ、実在しないURL、間違った日付や数値を、いかにもそれらしい文章で提示してくる。仕組みを知らずに出力を鵜呑みにすると、社外向け資料に誤情報を載せてしまったり、業務判断を誤らせたりするリスクがある。実際に米国では、AIが作り出した架空の判例を訴訟書類に引用してしまい、裁判所から制裁を受けた弁護士の事例が2025年以降だけで100件以上報告されている。

## 仕組み・背景

生成AI(大規模言語モデル、LLM)は「事実データベースを検索して答える」仕組みではなく、「与えられた文脈の続きとして、統計的にもっともらしい単語の並びを予測する」仕組みで動いている。この性質上、事実確認の機能はもともと備わっておらず、ハルシネーションは仕様上避けられない副作用に近い。主な発生要因は次の4つ。

- **知識の空白を「それらしさ」で埋めてしまう**: モデルが正確な答えを持っていない質問に対しても、学習データ中の似た文脈から類推して、文法的に自然で自信ありげな文章を生成してしまう。話し方の自信度と正しさは無関係。
- **学習データの範囲外・古い情報**: モデルの学習データには締め切り(knowledge cutoff)があり、それ以降の出来事や、学習データに含まれていないニッチな情報については、知らないことを「知らない」と言わず、もっともらしい推測で答えてしまうことがある。
- **記憶の混同(confabulation)**: 似た名前の人物・似た内容の判例・似た製品名などを混同し、実在する要素を組み合わせて実在しない事実を作り出してしまう。引用文献のタイトルや著者名、URLの捏造はこのパターンが多い。
- **「わからない」より「答える」ほうが評価されやすい訓練の癖**: 対話AIは人間からのフィードバックで「役に立つ」「はっきり答える」応答を高く評価されるように調整されてきた経緯があり、確信が持てない場面でも断定的に答えてしまう傾向が残っている。

ハルシネーションの発生率を測るベンチマークの一つに Vectara社の「Hallucination Leaderboard」がある。これは要約タスクにおいて、与えられた文書の内容に忠実な要約を作れているかを測定するもので、汎用的な「噓をつく確率」そのものではない点に注意が必要だが、モデル間の相対比較の目安として広く参照されている。2026年2月にベンチマークが刷新され、法務・医療・金融・技術分野を含む7,700件以上・最大24,000語の長文記事を対象にする難易度の高いテストになった結果、旧テストでは多くのモデルが5%未満だったのに対し、新テストでは主要モデルの多くが10%を超える結果になっている(2026年5月時点のリーダーボードでは、GPT-5.4-nanoが3.1%、gemini-2.5-flash-liteが3.3%、gemini-2.5-proが7.0%、GPT-5.5が9.3%、GPT-4oが9.6%、claude-haiku-4.5が9.8%、claude-sonnet-4が10.3%など)。小型・軽量モデルが上位に来ることもあり、「新しく賢いモデルほどハルシネーションが少ない」とは単純に言えない点は覚えておきたい。

## 使いどころ・使い分け

ハルシネーション対策のコストは、扱うタスクの性質に応じて変えるのが実務的。すべての出力を同じ密度でファクトチェックするのは非効率なので、リスクに応じて手間をかける場所を絞り込む。

| タスクの性質 | ハルシネーションのリスク | 必要な対策レベル |
|---|---|---|
| ブレインストーミング・アイデア出し・下書きの叩き台 | 低い(事実性が問われない) | 特別な検証は不要。そのまま使ってよい |
| 一般知識の要約・社内向けメモ | 中程度 | 固有名詞・数値だけ簡易チェック |
| 顧客向け資料・プレスリリース・ブログ記事など外部公開物 | 高い(誤情報がそのまま社外に出る) | 引用・出典の実在確認、複数ソースでのクロスチェック |
| 契約書・判例・医療情報・税務判断・数値を伴う経営判断 | 最も高い(法的・金銭的・人命に関わる) | 一次資料への当たり直し必須。AIの出力だけで判断せず、有資格者によるレビューを経る |

判断基準はシンプルで、「この出力が間違っていた場合、誰がどれだけ困るか」で対策の濃淡を決める。特に数値・日付・固有名詞・URL・法令や判例の番号は、生成AIが最もハルシネーションを起こしやすい要素なので、タスクの重要度に関わらず重点的に見る価値がある。

## 実務での使い方

### コピペで使える防止プロンプト

資料を読み込ませて回答させる場面(要約・分析・Q&A)では、次のような指示をプロンプトの末尾に加えるとハルシネーションを大きく減らせる。

```
以下のルールを厳守してください。

1. 資料に明記されている事実のみを根拠に回答する(一般知識からの推測で補わない)
2. 主張ごとに、根拠となる資料中の一文をそのまま引用として添える
3. 資料の中に根拠となる記述が見つからない場合は、その主張を書かず「資料からは確認できません」と明記する
4. 分からないこと・確信が持てないことは、もっともらしく推測せず「分かりません」「情報が不足しています」と正直に答える

---
資料:
{ここに資料を貼り付け}

---
質問:
{質問内容}
```

長文の資料(2万トークン超が目安)を扱う場合は、いきなり要約・分析させるのではなく「まず該当箇所を一字一句そのまま引用させる→その引用だけを根拠に分析させる」という2段階にすると、資料に書かれていない内容を混ぜにくくなる。

### 主要ツールのハルシネーション低減機能

| ツール | 機能 | 場所・使い方 |
|---|---|---|
| ChatGPT | Web検索(ChatGPT Search)による最新情報の参照、回答内の出典リンク表示 | 入力欄下部の「ツール」または検索アイコンから「Web検索」を選択。最新性が必要な質問では自動的にWeb検索が使われることもある |
| Gemini | 「回答を再確認(ダブルチェック)」機能。Google検索と照合し、一致箇所を緑、古い/未確認の箇所をオレンジで色分け表示。Google検索によるグラウンディング(根拠付け) | 回答下部の二重チェックマークのアイコンをクリック |
| Claude | Web検索機能によるリアルタイム参照。開発者向けにはCitations API(引用元の文書と該当箇所を機械的に返す機能)があり、独自の文書を読み込ませる用途で根拠を明示できる | claude.aiでは入力欄下の「検索」トグルをオン。API利用時は`citations`パラメータで有効化 |
| Perplexity | 標準ですべての回答に脚注形式の出典リンクを付与 | デフォルトで有効、追加設定不要 |
| Microsoft Copilot | Bing検索結果に基づく引用番号付き回答 | 標準搭載 |

API経由で使う場合は「temperature(温度)」というパラメータで、回答の多様性・ランダム性を調整できる。値を下げる(0に近づける)ほど毎回同じような手堅い回答になりやすく、要約や事実確認など「正確さ優先」のタスクに向く。値を上げるほど表現の幅は広がるが、その分ハルシネーションのリスクも増える。ただしChatGPT・Gemini・Claudeいずれも通常の画面(Web/アプリ)ではtemperatureを直接操作できず、API利用時のみ設定可能な点は覚えておきたい。

### 検証タクティクス一覧

| 検証手法 | 概要 | 向いている場面 |
|---|---|---|
| 一次資料への当たり直し | 出力に含まれる固有名詞・数値・日付・URLを検索エンジンや公式資料で直接確認する | 外部公開する文章、数値を含む報告 |
| 出典・引用の実在確認 | AIが提示したURL・論文タイトル・判例番号・法令番号を実際に開いて実在するか確認する | 判例引用、学術参照、リンク集の作成 |
| 複数モデルへのクロスチェック | 同じ質問をChatGPT・Claude・Geminiなど複数のAIに投げ、回答が一致するか比較する | 重要な意思決定の下調べ、社内では答えが分かれやすい専門的な質問 |
| RAG(検索拡張生成、Retrieval-Augmented Generation)化 | 社内マニュアルや規定文書などをAIに読み込ませ、その内容だけを根拠に回答させる | 社内FAQ、規定に基づく問い合わせ対応 |
| Best-of-N比較(同じ質問を複数回投げる) | 同一プロンプトを複数回実行し、回答のブレを確認する。実行のたびに答えが変わる箇所はハルシネーションの疑いが高い | 金銭・人命など影響が大きい判断の根拠固め |
| 専門家による最終レビュー | 法務・医療・会計など専門判断が必要な領域は、AIの出力を下書きとして扱い、必ず有資格者が最終確認する | 契約書チェック、医療情報、税務判断 |

## 注意点・よくある誤解

- **自信満々な口調は正しさの証拠にならない**: 生成AIは「わかりません」を選ばず断定的に話す傾向があるため、話し方の自然さ・堂々とした語り口から正確性を判断することはできない。
- **Web検索やグラウンディング機能も万能ではない**: 検索結果を参照させる機能はハルシネーションを大きく減らすが、ゼロにはできない。検索結果自体に誤りが含まれていたり、AIが検索結果を誤読・誤要約してしまうケースもある。「引用が付いている=内容が正しい」ではなく、引用元を実際に開いて内容が合っているか確認する一手間が要る。
- **新しいモデルや高性能モデルほど安全とは限らない**: ベンチマーク上、軽量モデルが上位に来ることもあり、モデルの新しさ・賢さとハルシネーション率は単純比例しない。特に長文の要約や複数文書をまたぐ統合作業はハルシネーションが増えやすいタスクとして知られる。
- **法律・医療分野での実例**: 米国ユタ州では2025年5月、ChatGPTが作った架空の判例を訴訟書類に引用した弁護士が裁判所から制裁処分を受けた。カリフォルニア州でも、控訴審の準備書面に含まれる23件の引用のうち21件がAIによる捏造だったケースが発覚している。世界全体では、AIが生成した架空の法的引用が裁判に提出された事例が1,000件以上確認されており、業務で生成AIに調査・下書きをさせる際は「出典の実在確認」を省略しない姿勢が欠かせない。
- **実務のコツ**: プロンプトの最後に「分からない場合は推測せず、分からないと明記してください」の一文を必ず添える。これだけで断定的な誤情報の発生をかなり抑えられる。数値・固有名詞・日付・URL・法令番号は特に間違えやすいので、重要な文書では優先的にチェックする。

## 最初の一歩

次に生成AIに調べ物や要約をさせるとき、プロンプトの最後に「分からない場合は推測せず、分からないと答えてください」の一文を付け足してみる。
