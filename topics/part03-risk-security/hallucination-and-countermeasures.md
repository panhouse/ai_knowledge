# ハルシネーションとは何か・対策法

## これは何か

ハルシネーション(Hallucination、幻覚)とは、生成AIが事実と異なる内容を、あたかも正しいかのように自然な文章で作り出してしまう現象のこと。存在しない論文を出典として挙げる、実在しない条文番号を答える、数値を微妙に取り違える、といった形で起きる。厄介なのは「見た目が流暢で自信満々」なため、業務で使う本人が気づかずにそのまま資料や顧客向けの文章に使ってしまう点にある。ハルシネーションを前提知識として持っておくことが、生成AIを業務で安全に使いこなすための出発点になる。

## 仕組み・背景

生成AIの中核にあるLLM(大規模言語モデル、大量のテキストで学習した言語処理モデル)は、「事実かどうかを検索・検証する」仕組みでは動いていない。学習データに含まれるパターンから、直前の文脈に続けて「統計的にもっともらしい次の単語」を予測して積み上げているだけであり、内部に「正解データベース」を持って答えを引き出しているわけではない。文法的・文脈的に自然な文章を作ることは得意でも、その内容が事実として正しいかどうかを検証するプロセスは組み込まれていない。これがハルシネーションが原理的に起きる理由。

OpenAIが2025年9月に発表した研究「Why Language Models Hallucinate」は、この問題をより具体的に説明している。現在の学習・評価の方法では、モデルが「わからない」と正直に答えるよりも、間違っていても自信を持って断定的に答えるほうが、テストのスコアが高くなりやすい構造になっている。人が試験で「わからない」と白紙で出すより、当てはまりそうな答えを書いたほうが得点の可能性が上がるのと同じ構図で、モデルも「推測して答える」ことを学習の過程で評価されてしまう。つまりハルシネーションは、エンジニアリング上の不具合ではなく、現在の学習・評価方法に組み込まれた統計的な必然という位置づけになる。推論(モデルが答えを出す前に段階的に考える処理)を使う最新モデルではハルシネーションの発生率は大きく下がっているが、ゼロにはなっていない。

### ハルシネーションが起きやすい場面

- **存在しない文献・出典の引用**: 架空の論文タイトル・著者名・DOI、実在しない書籍や判例をもっともらしく生成する
- **日付・数値・固有名詞**: 統計値、法律の条文番号、製品の発売日、価格など、1文字違うだけで誤りになる情報
- **マイナーな専門知識**: ニッチな業界の規則、特定企業の内部プロセスなど、学習データに十分な情報が少ない領域
- **学習データのカットオフ以降の最新情報**: Web検索機能を使わない場合、最新の人事異動・株価・ニュースなどは古い情報や推測で埋められがちで、答えを出せない場合でも聞かれた分は答えようとしてしまう
- **長い文章の要約・引用**: 長文の中の細かい数字や条件を、要約時に取り違える

## 使いどころ・使い分け

「ハルシネーションを警戒すべきか」ではなく、タスクの性質によって検証の手間をどこまでかけるかを切り分けるのが実務的。

| タスクの性質 | ハルシネーションのリスク | 対策レベル |
|---|---|---|
| アイデア出し・ブレスト・文章のリライト | 低(事実性が結果を左右しない) | 特別な対策は不要 |
| 一般に広く知られた知識の説明 | 中 | Web検索機能をON、生成後にファクトチェック機能で確認 |
| 統計データ・法令・引用文献を含むレポート・記事 | 高 | 出典URLを自分の目で必ず確認。AIには出典を明示させ、出せない情報は書かせない |
| 契約書レビュー・医療・財務判断など専門性の高い意思決定 | 非常に高 | AIは下書き・一次整理のみに限定し、専門家の確認を必須にする |

## 実務での使い方

### プロンプトでできる対策(コピペ例)

**1. 出典を明示させる**
```
回答には、根拠となる出典(URL・文献名・条文番号など)を必ず付けてください。
出典を明示できない情報は、推測で埋めずに省いてください。
```

**2. 「わからない」と言うことを許可する**
```
確信度が低い部分は、断定せずに「分からない」「確認が必要」と明記してください。
情報が不足している場合は、推測で埋めずにそう伝えてください。
```

**3. Web検索・RAGを併用させる(最新情報・社内資料が絡む場合)**
```
Web検索機能を使って最新の情報を確認し、検索結果に基づいて回答してください。
検索で該当する情報が見つからない場合は、その旨を明記してください。
```

**4. 根拠資料を先に渡し、資料の範囲内でしか答えさせない(RAG的アプローチ)**
```
以下にアップロードした資料の内容だけに基づいて回答してください。
資料に記載がない内容については、一般知識で補わずに「資料に記載なし」と答えてください。
<資料>
(社内文書・PDFなどを添付)
</資料>
```

**5. 引用元の一文を先に抜き出させてから答えさせる(長文の場合に特に有効)**
Anthropicの公式ガイドが推奨する手法。2万トークンを超える長文を扱う際、先に該当箇所を原文のまま逐語で抜き出させ、その引用を根拠に回答させることで、本文にない内容を答えにくくする。
```
1. まず、この文書の中でGDPR・CCPA対応に関連する記述を、原文のまま逐語で抜き出してください。
   該当箇所がなければ「関連する記述は見つかりませんでした」と答えてください。
2. 抜き出した引用のみを根拠に、コンプライアンス上の論点を整理してください。
   引用にない内容は含めないでください。
```

**6. 複数回生成して照合する(Best-of-N検証)**
同じ質問を新しいチャットで2〜3回聞き、数値や固有名詞などの重要部分が毎回一致するかを確認する。回答ごとにブレる箇所があれば、ハルシネーションを疑うべきサインになる。

### ツール横断の対応付け(2026年7月時点)

| 機能 | ChatGPT | Claude | Gemini |
|---|---|---|---|
| Web検索・最新情報の取得 | 「検索」ツール(ChatGPT search)。入力欄の検索アイコン、または「すべてのツールを表示」から選択 | Web検索トグル(2025年5月から全プランで利用可能) | Google検索によるグラウンディング(回答の根拠をGoogle検索結果で裏付ける仕組み) |
| 引用・出典の表示 | 回答内のインライン引用にマウスホバーで詳細表示、クリックで元記事へ。引用が出ない場合は回答下部の「ソース」パネルから確認 | 検索結果を使った回答にはURLがインラインで引用される。学習データのみで答えた場合は引用が付かない点に注意 | 回答生成後、別途「回答を再確認」機能で事後検証 |
| 事後ファクトチェック機能 | ソースパネルから元記事を開いて確認 | 回答内の引用リンクを開いて確認 | 回答下の縦三点メニュー→「回答を再確認」をクリック。緑ハイライト=Google検索で似た内容が見つかった箇所(信頼度が高い)、オレンジハイライト=情報が異なる・見つからなかった箇所(要確認) |
| 精度向上の推奨設定 | 推論モデル(Thinkingモデル)は非推論モデルよりハルシネーションが少ない傾向 | 拡張思考(extended thinking)で効果設定を上げるほど精度が上がる | 思考モードを使うと事実確認の精度が上がる |

Geminiの「回答を再確認」は、回答が広く裏付けられているかを大まかに掴む目安として使い、オレンジ表示の部分は自分でも検索して確認するのが実務的な使い方。

## 注意点・よくある誤解

- **ハルシネーションは完全にはなくせない**: OpenAIの研究が示す通り、現在の学習・評価の仕組みに根ざした統計的な誤りであり、Web検索や引用機能を使っても「ゼロ」にはならない。重要な意思決定に使う数値・引用文献は、必ず一次情報で人が確認する運用を前提にする。
- **自信満々で断定的な口調と、内容の正しさは無関係**: モデルは「わからない」と答えると学習上不利になりやすい構造のため、誤っていても堂々と断定的に話す傾向がある。回答の口調やトーンから信頼度を判断してはいけない。
- **Web検索・グラウンディングも万能ではない**: 検索結果のソース自体が誤っている場合や、AIが検索結果を読み間違える・取り違えるケースもある。検索機能をONにしたからもう安心、とはならない。
- **「ハルシネーションしないでください」という指示だけでは効果は限定的**: 一定の抑制効果はあるが、出典明示・引用の強制・Web検索併用など複数の対策を組み合わせたほうが効果が大きい。
- **社外に出す資料の数値・引用文献は必ず検証する習慣を**: 提案書・記事・顧客向け資料などに使う数値や引用は、AIの回答をそのまま使わず、必ず出典URLや一次情報を自分の目で確認する。

## 最初の一歩

次にAIに数値や引用文献を含む回答を求めるとき、プロンプトの最後に「出典を明示し、確信度が低い場合はその旨を述べてください」の一文を付け加えてみる。
