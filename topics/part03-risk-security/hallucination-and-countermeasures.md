# ハルシネーションとは何か・実務での対策

## これは何か

ハルシネーション(hallucination)とは、生成AIが事実と異なる内容を、誤りだと気づかせないほど自然で断定的な文章で作り出してしまう現象のこと。存在しない判例・論文・URLを実在するかのように提示したり、数値や日付を誤って言い切ったりするのが典型例で、「知らない」と正直に答えず、もっともらしい答えを"でっち上げる"点が単純な誤字脱字と違う。2023年には米国の弁護士がChatGPTに作らせた架空の判例8件をそのまま訴訟資料に引用し制裁金を科されたが、これは特殊な事故ではない。同種の「AIが作った架空の引用を裁判資料に使ってしまった」事例は世界で法廷が把握しているだけで1,000件を超え、2025年後半には週に十数件のペースで新たに発覚するまでに増えている(Damien Charlotin氏によるAIハルシネーション事例データベース)。業務でAIの出力をそのまま報告書・顧客対応・意思決定に使う以上、誰もが遭遇しうるリスクとして仕組みと対策を知っておく必要がある。

## 仕組み・背景

生成AI(大規模言語モデル、LLM)は、事実を保存したデータベースを検索して答えているわけではない。学習データの統計的パターンから「次に来る確率が高い単語」を予測してつなげているだけなので、事実として正しい情報と、文章としてもっともらしいが誤った情報を、モデル自身は区別できない。

- **「わからない」より「それらしい答え」の方が高評価になりやすい**: OpenAIが2025年9月に発表した論文「Why Language Models Hallucinate」は、モデルの学習・評価の仕組み自体が「自信満々に(誤った)答えを出す方が、正直に『わからない』と答えるより高いスコアになる」構造になっていることを指摘した。試験でわからない問題に白紙で出すより、当てずっぽうでも何か書いた方が部分点が入りやすいのと同じ理屈で、モデルは"賭け"に出るよう訓練されてしまっている。
- **学習データにない・古い情報は特に弱い**: 学習時点より後の出来事、社内限定の情報、マイナーな固有名詞(判例番号、論文のDOI、製品の型番など)は、モデルが正解を知らないまま、似たパターンから"それらしい"文字列を生成しやすい。人文系分野の論文DOIのでっち上げ率は自然科学分野より高いなど、分野によって発生しやすさにも差がある。
- **完全にはなくならない**: 2025年時点の研究では、現在のLLMのアーキテクチャを前提とする限りハルシネーションを数式的に完全排除することはできないとされている。「モデルの性能が上がれば自然に消える」ものではなく、使う側が前提として運用でカバーする必要がある。
- **モデル・タスクによって発生率に差がある**: 検索で裏取りしながら回答する「グラウンディング」ありのタスクでは誤り率が数%程度まで下がる一方、法律分野の判例検索のように専門性が高く裏取りが難しいタスクでは誤り率が数十%に達するとの調査結果もある。モデルやタスクの組み合わせで危険度が大きく変わる点を踏まえて対策を選ぶ必要がある。

## 使いどころ・使い分け

ハルシネーションのリスクは「AIに何を答えさせるか」で大きく変わる。用途ごとに必要な対策レベルを変えるのが実務的。

| 用途 | ハルシネーションのリスク | 必要な対策レベル |
|---|---|---|
| アイデア出し・文章の下書き・壁打ち | 低い(事実誤認があっても人間が手直しする前提) | 特別な対策は不要。違和感があれば自分の知識で修正すればよい |
| 社内資料の要約・分析(元資料が手元にある) | 中程度(元資料にない内容を"補完"して混ぜてしまうことがある) | 元資料の範囲に限定させるプロンプト、要約後の照合 |
| 固有名詞・数値・法令・判例・学術情報の引用 | 高い(存在しない情報を実在するかのように断定しやすい) | Web検索・RAGでの裏取り必須。出典URLの実在確認は人間が行う |
| 顧客向け回答・契約審査・医療/法律/財務の判断材料 | 最も高い(誤りがそのまま実害・訴訟リスクに直結) | AIの回答は「たたき台」までとし、専門家によるダブルチェックを必須化する |

判断の目安はシンプルで、「AIの回答が間違っていたときに、誰がどれだけ困るか」で対策の厚みを決める。

## 実務での使い方

### 1. まずプロンプトで"当てずっぽう"を防ぐ

そのままコピーして使えるプロンプトの例。

```
以下の質問に、確認できる事実のみに基づいて回答してください。
確信が持てない情報については、推測で埋めずに「わからない」「確認できない」と明記してください。
断定する場合は、根拠となる情報源(サイト名・URL・発行年)も併記してください。
```

社内資料を要約させるときは、参照範囲を限定する「グラウンディング」の指示を追加すると効果が高い。

```
以下に貼り付けた資料の内容だけに基づいて回答してください。
資料に書かれていない情報は、たとえ一般的に正しそうな内容でも回答に含めないでください。
資料から読み取れない場合は「資料からは判断できません」と答えてください。
```

出力の検証をAI自身にもう一段させたい場合は、続けて次のように聞き返すのも有効。

```
今の回答の中で、あなたが本当に自信を持って正しいと言い切れる部分と、
不確かなまま断定してしまった部分を分けて教えてください。
```

### 2. Web検索・RAGで「一次情報に接続」させる

学習データだけに頼らせず、最新の一次情報を検索・参照させながら回答させる方が誤りは大きく減る。主要ツールでの使い方は次のとおり。

| ツール | Web検索・出典表示機能 | 使い方 |
|---|---|---|
| ChatGPT | チャット入力欄のツールメニューから「ウェブ検索」を選択(質問内容によっては自動で検索が実行される)。回答中に参照元へのリンクが表示される | リンク先を開いて実在すること・内容が一致することを確認する |
| Gemini | 「グラウンディング(Google検索との連携)」により、検索結果を根拠に回答を生成。回答下部の「⋮(その他)」→「回答を再確認」でファクトチェックも可能 | 緑色ハイライト=検索結果と一致、オレンジ色ハイライト=情報が古い・一致しない可能性ありという表示を確認する |
| Claude | チャット入力欄のツールメニューから「ウェブ検索」を有効化。回答に引用(Citations)としてリンクが付く | 引用元のリンクを開いて内容を確認する。API利用時はドキュメントを渡し `citations.enabled` を有効にすることで、回答の各文にどの資料の何行目が根拠かを機械的に紐付けられる |
| Microsoft Copilot | 既定でBing検索と連携し、回答に出典リンクが付く | 出典リンクの実在・内容一致を確認する |

社内の規程集やマニュアルなど「自社データだけを根拠に答えさせたい」場合は、RAG(Retrieval-Augmented Generation、検索拡張生成。質問に関連する社内文書をAIに検索・参照させてから回答させる仕組み)を使う。ChatGPTの「知識ファイル」機能やGemini/CopilotのEnterprise版が持つ社内ドキュメント連携、Difyやカスタム構築のRAGシステムなどが該当する。自由入力のチャットより、社内文書だけを根拠にさせる分ハルシネーションを大きく抑えられるが、参照元の文書自体が古い・誤っている場合はそのまま誤りが引き継がれる点には注意する。

### 3. 人間によるファクトチェックの手順を仕組み化する

- **固有名詞・数値・URLは必ず単体で検索する**: 判例番号、論文タイトル、統計値、製品の型番などは、AIの回答をコピーしてそのまま検索エンジンに貼り、実在するかを確認する。
- **重要な意思決定の資料は「ダブルチェック担当」を決める**: 顧客向け提案書・契約審査・プレスリリースなど、外部に出る前提の文書は、AI出力を鵜呑みにせず人間の担当者が原典に当たって確認する運用をルール化する。
- **複数のAIツールに同じ質問をして答えを突き合わせる**: 1つのツールだけでは気づけない誤りも、別のツールの回答と食い違えば「要確認」のサインになる。
- **「なぜそう言えるのか」を聞き返す**: 回答に納得できない場合は「その根拠は何ですか」「一次情報のリンクを教えてください」と聞き返す。答えに詰まったり、存在しないURLを出してきたりした場合は、その回答自体を疑う。

## 注意点・よくある誤解

- **「有名なAIだから大丈夫」ではない**: モデルの性能が上がってもハルシネーションが完全になくなるわけではなく、2026年時点の最新モデルでも数%程度は誤りを含む回答をする。「自信満々な口調」と「内容の正しさ」は無関係だと肝に銘じる。
- **Web検索機能を使っても100%は防げない**: 検索結果を参照させても、検索結果の解釈を誤ったり、複数の情報源を混ぜて矛盾する内容を作ってしまったりすることがある。出典リンクが付いていても、リンク先を開いて内容が一致するかまで確認するのが確実。
- **「出典を出して」と言えば安心、ではない**: プロンプトで出典を求めると、AIは(検索していない場合)それらしいタイトル・URLを新たに作文してしまうことがある。出典を求めるプロンプトは、Web検索機能をオンにした状態と組み合わせて初めて効果を持つ。
- **専門性が高い分野ほど危険度が上がる**: 法律・医療・財務など、間違いが実害に直結し、かつ非専門家では誤りに気づきにくい分野ほど、AIの回答を最終判断に使わないという原則を徹底する。
- **社内文書を参照させるRAGも万能ではない**: 参照元の社内文書自体が古い・誤っている場合は、AIはその誤りをそのまま正しい情報として回答してしまう。RAGは「ゼロから作文するリスク」を減らすものであり、参照元の品質管理は別途必要。

## 最初の一歩

次にAIに固有名詞や数値を含む質問をするときは、「確信が持てない場合は推測せず『わからない』と答えてください」の一文をプロンプトの最後に付け加え、Web検索機能をオンにした状態で試してみる。
