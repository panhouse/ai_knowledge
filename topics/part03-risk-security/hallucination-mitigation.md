# ハルシネーション対策

## これは何か

生成AIが、事実と異なる内容を誤りだと気づかせないほど自然で自信満々な文章で作り出してしまう現象を「ハルシネーション(幻覚)」と呼ぶ。存在しない判例や論文を引用する、実在しない製品仕様を答える、日付や数値を誤って断言するといった形で現れる。米国の弁護士がChatGPTに作らせた準備書面に存在しない判例を引用し、2023年に5,000ドルの制裁金を科され、同種の事件は2026年にもカンザス州の連邦地裁で起きている(原告側弁護士に5,000ドルの罰金・出廷資格取消しなど)。これを知らずに生成AIの回答をそのまま資料や顧客対応に使うと、誤情報の発信・信用失墜・訴訟リスクに直結する。

## 仕組み・背景

生成AIのハルシネーションは、バグではなく仕組み上の性質として起きる。

- **次単語予測という仕組みの限界**: 大規模言語モデル(LLM)は「これまでの文脈に続く、最もそれらしい単語」を確率的に予測して文章を生成している。事実データベースを検索して答えているわけではないため、事実と「もっともらしい文章」を区別する仕組みを内部に持たない。
- **学習データのカットオフ**: モデルは特定時点までの学習データしか持たない(知識カットオフ)。それ以降の出来事は知らないはずだが、Web検索などの外部情報源につながっていない状態では、知らないことも「それらしく」答えようとしてしまう。
- **「わからない」と言えない評価の仕組み**: OpenAIが2025年に公表した論文「Why Language Models Hallucinate」によれば、モデルの学習・評価は正解率だけで採点されることが多く、「わからないので回答しない」を選んでも加点されない。その結果、モデルは自信なく沈黙するより、間違っていても堂々と「それらしい答え」を出す方が高得点になりやすい構造になっている。OpenAIはこれを試験で山勘を選ぶ受験者に例え、「不正解に-9点、無回答に0点」のような採点方式に変えない限り、この誘因は残ると指摘している。
- **迎合(sycophancy、シコファンシー)という別の落とし穴**: 知識不足による誤生成であるハルシネーションとは別に、ユーザーの意見や前提に過剰に同調してしまう「迎合」という挙動もある。「これで合っていますよね?」と聞くと、間違っていても「はい、その通りです」と答えやすくなるため、質問の仕方自体が誤情報を誘発することがある。
- **完全な解消は原理的に困難**: OpenAIも「ハルシネーションは工学的な改善だけでは完全にゼロにできない、数学的に避けられない性質を持つ」と明言している。実際、GPT-5はOpenAI公表値でGPT-4比で誤答が約45%減、GPT-3比で約80%減とされるが、「減った」のであって「なくなった」わけではない。

## 使いどころ・使い分け

ハルシネーションのリスクは業務内容によって大きく異なるため、「どこまで裏取りするか」を最初に切り分けるのが実務的。

| 業務の性質 | リスク | 対応方針 |
|---|---|---|
| 数値・統計・固有名詞(社名・人名・製品名)・日付を扱う | 高い(誤りがそのまま資料や対外発信に載る) | 一次情報での裏取りを必須にする。AI単体の回答を根拠にしない |
| 法令・契約・判例・医療情報などの専門的事実 | 非常に高い(法的責任・実害につながる) | 専門家によるレビューを必須工程にする。RAGや専門データベースと組み合わせる |
| 社内文書の要約・議事録の整理 | 中程度(原文と突き合わせれば検知できる) | 元の文書を渡した上で生成させ、必ず原文と照合する |
| アイデア出し・ブレインストーミング・文章の言い回し案 | 低い(事実性より発想の幅が価値) | 裏取りは不要。むしろ「幻覚」が発想の多様性として機能することもある |
| 社外向け公式文書・プレスリリース・顧客対応文面 | 高い(誤りが会社の信用問題になる) | ドラフトはAIに作らせてよいが、事実関係は必ず人間が一次情報で確認してから出す |

判断基準はシンプルで、「この回答が間違っていた場合、誰がどれだけ困るか」を基準に裏取りの手間をかけるかどうかを決める。

## 実務での使い方

### 1. 根拠を外部から与える(RAG・Web検索)

AIの記憶(学習データ)だけに頼らず、検索エンジンや社内文書を検索させて、その結果に基づいて回答させる方法が最も効果が大きい。これをRAG(Retrieval-Augmented Generation、検索拡張生成)と呼ぶ。

| ツール | Web検索・グラウンディング機能 | 使い方 |
|---|---|---|
| ChatGPT | ChatGPT Search(全プランで利用可能) | 入力欄の地球儀アイコンをクリックし「ウェブを検索」を選択。回答に引用元リンクが付き、「Sources」ボタンでサイドバーに参考文献一覧が表示される |
| Gemini | Google検索によるグラウンディング/回答の「ダブルチェック」機能 | 回答生成後に表示される検証アイコンをクリックすると、Google検索結果と照合し、合致する記述は緑、根拠が薄い記述はオレンジ・茶色で色分け表示される |
| Claude | Web検索ツール、Citations(引用)機能 | チャット画面でWeb検索を有効化すると出典付きで回答。API/Vertex AI経由では、渡したドキュメントのどの一文から回答を生成したかを`cited_text`として返す「Citations」機能が利用可能 |
| Microsoft Copilot | Bing検索との連携 | 質問すると回答とともに参照したWebサイトが表示される(バージョンによって表示仕様が変わることがある) |

社内文書を根拠にしたい場合は、ChatGPTのGPTs・GeminiのGem・DifyなどでRAGの仕組みを組み、社内規程やFAQをアップロードした上で「渡した文書の範囲でのみ回答する」よう指示すると、学習データ由来のハルシネーションを大きく減らせる。

### 2. コピペで使えるハルシネーション対策プロンプト

**出典明示・不明時は「わからない」と言わせるプロンプト**
```
以下の質問に答えてください。回答の際は次のルールを厳守してください。

1. 断定的に書く事実には、必ず根拠(出典や検索結果)を示すこと。
   出典を示せない場合は、その部分を「未確認情報」と明記すること
2. 確信が持てない場合は、推測で埋めずに「わかりません」「情報が不足しています」と答えること
3. 数値・日付・固有名詞(社名・人名・製品名・法令名)は特に慎重に扱い、
   自信がない場合はその旨を明記すること

質問: (ここに質問を入れる)
```

**ステップバイステップで自己検証させるプロンプト**
```
以下のタスクを行った上で、必ず自己検証のステップを実行してください。

1. まず回答のドラフトを作成する
2. ドラフトに含まれる固有名詞・数値・日付・引用を1つずつ洗い出す
3. それぞれについて「この情報は学習データの記憶に基づく推測か、
   検索結果など確認できる根拠に基づくものか」を自己評価する
4. 根拠が不確かな項目には[要確認]のタグを付けて出力する

タスク: (ここに依頼内容を入れる)
```

**複数AIでのクロスチェック用プロンプト(2つ目以降のAIに投げる)**
```
以下は別の生成AIが出力した回答です。この内容に事実誤認・存在しない
引用・矛盾がないか、批判的にチェックしてください。
問題があれば具体的にどの部分がなぜ疑わしいかを指摘し、
可能であれば正しい情報を提示してください。

---
(チェックしたい回答をここに貼り付け)
---
```

ChatGPT・Gemini・Claude・Copilotは学習データも設計思想も異なるため、同じ質問を2つのツールに投げて答えを突き合わせるだけでも、明らかな捏造(でっちあげ)は検知しやすくなる。特に固有名詞・数値・法令名を扱う場面では、この「クロスチェック」を最終防波堤にするとよい。

### 3. 一次情報での裏取りを仕組み化する

- 数値・統計は、AIの回答をそのまま使わず、必ず統計局・企業IR・公式サイトなど一次情報のURLを自分で開いて確認する。
- 法令・判例は、e-Gov法令検索や裁判所の公式データベースなど、専門データベースで存在を確認してから使う。AIが提示した条文番号・判例番号は特に捏造されやすい。
- 社外向け文書は、公開前に「AIが生成した事実主張のリスト」を作り、担当者がチェック欄にレ点を入れる運用にすると抜け漏れを防ぎやすい。

## 注意点・よくある誤解

- **対策をしてもゼロにはならない**: OpenAI自身が「ハルシネーションは工学的な改善だけでは完全に排除できない」と認めている。Web検索・RAG・複数AIでのクロスチェックはリスクを大きく下げる手段であり、「絶対に間違えない」状態を作る手段ではない。
- **最終確認は必ず人間が行う**: 対外的に発信する文書、法令・契約・医療など実害につながる領域では、AIの回答を鵜呑みにせず、人間が一次情報で最終確認するプロセスを業務フローに組み込むことが前提になる。
- **「自信満々な口調」は正しさの証拠にならない**: ハルシネーションは曖昧な言い方ではなく、断定的で説得力のある文章として出力されることが多い。口調の自然さと内容の正確さは無関係だと理解しておく。
- **「間違っていますよね?」という聞き方は迎合(シコファンシー)を誘発する**: ユーザーの前提に同調してしまう挙動はハルシネーションとは別の問題だが、結果的に誤情報を追認してしまう。検証を頼むときは「この内容に誤りがないか中立的にチェックして」のように、結論を誘導しない聞き方をする。
- **Web検索・RAGを使っても検索結果自体が古い・誤っている場合がある**: グラウンディング(外部情報に基づいて回答させること)は有効だが、検索結果の質に回答の質が引っ張られる点には注意する。

## 最初の一歩

次に生成AIに数値や固有名詞を含む質問をするときは、ChatGPTなら地球儀アイコンでWeb検索をオンにする、GeminiならAndroid版の「ダブルチェック」アイコンをタップするなど、回答に出典を付けさせる機能を今日1回試してみる。
