# 生成AIのハルシネーション対策

## これは何か

ハルシネーション(hallucination、幻覚)とは、生成AIがもっともらしい口調で、実際には存在しない事実・数値・引用・URLなどを作り出してしまう現象のこと。文法も文脈も自然なため、知識がない読み手ほど見抜きにくい。実在しない判例をChatGPTに作らせて裁判所に提出し、制裁金を科された弁護士が2023年以降だけで200件以上報告されているように、「もっともらしい」と「正しい」は生成AIにおいてはまったく別物であり、business上の意思決定や対外文書にそのまま使うと信用・法的リスクに直結する。

## 仕組み・背景

生成AIは「事実データベースを検索して答える」システムではなく、「与えられた文脈の続きとして、統計的にもっともらしい単語列を予測して生成する」システムである。学習データにない、あるいは記憶があいまいな事柄を聞かれても、「分かりません」と答えるより、それらしい単語を並べて文章を完成させる方が学習上「自然」になりやすい。つまりハルシネーションはプログラムの不具合(バグ)ではなく、今のLLM(大規模言語モデル)の仕組み上どうしても一定確率で発生する構造的な副産物だと理解しておくとよい。

さらに近年は、複雑な推論を行う「推論モデル」(o3など)ほど、事実に関する質問で知識の空白を推測で埋めやすく、単純なモデルより高いハルシネーション率を示す場合があるという報告もある(OpenAI自身のPersonQAベンチマークでo3は約33%、後継のGPT-5系では大幅に改善)。「新しい・賢いモデルだから間違えない」という思い込みは禁物で、モデルの世代やタスクによってハルシネーション率は大きく変動する。

## 使いどころ・使い分け(リスクの高い場面・低い場面の見分け方)

すべての出力を同じ密度で疑う必要はない。タスクの性質でリスクの高低を見極め、検証の手間を配分するのが実務的。

| タスクの性質 | リスク | 必要な検証レベル |
|---|---|---|
| アイデア出し・文章の言い回し変更・要約(自分の持つ元データの範囲内) | 低い | 内容の趣旨がずれていないか軽く確認する程度でよい |
| 一般的な知識の説明(仕組みの概要、用語の意味など) | 中程度 | 重要な用途に使う前に、1〜2次資料で裏取りする |
| 固有名詞・具体的な数値・日付・統計・引用文の生成 | 高い | 必ず一次情報源に当たって照合する。AIに聞きっぱなしにしない |
| 判例・論文・URL・書籍名など「存在する/しないを検証できる」情報 | 非常に高い | 実在確認を最優先。存在しない場合の被害が大きい(訴訟、対外公表物など) |
| ニッチな専門領域・マイナー言語・最新の出来事(学習データに乏しい領域) | 非常に高い | 専門家によるレビュー、または検索連動モードの併用が必須 |
| 「分からなくても何か答えて」と穴埋めを強く求めるような聞き方 | 高くなる | 曖昧な質問ほど幻覚が出やすいため、質問自体を具体化する |

ポイントは、「マイナーな固有名詞・具体的な数値・引用・URL」を答えさせる場面が最もハルシネーションが起きやすいということ。AIは「よく知られた大きな話」ほど正確で、「細かい固有情報」ほど怪しくなる傾向がある。

## 実務での使い方

### 1. プロンプトで不確実性を申告させる

何も指示しないと、AIは自信満々な口調で答えを埋めがちになる。以下のようなプロンプトを添えるだけで、不確実な部分を明示させやすくなる(完全にゼロにはならない点は後述)。

```
以下の質問に答えてください。ただし次のルールを守ってください。

1. 確信が持てない情報(固有名詞・数値・日付・URL・出典など)には
   「※未確認」と明記すること。
2. 一次情報源が思い当たらない場合は、無理に埋めず
   「分かりません/確認が必要です」と答えること。
3. 答えの根拠となる情報源(書籍名、公式サイト名など)を
   分かる範囲で併記すること。
4. 断定できる事実と、あなたの推測・一般論を明確に区別して書くこと。

質問: (ここに質問を書く)
```

### 2. 「記憶から答える」より「検索・文書から答える」モードを使う

学習データの記憶だけに頼る回答より、根拠となる情報(グラウンディング、grounding=回答を実在する情報源に紐づけること)を持たせた回答の方がハルシネーションを大きく減らせる。主要ツールの対応は次の通り(2026年7月時点)。

| ツール | 機能名 | 使い方の要点 |
|---|---|---|
| ChatGPT | 検索(Browse/Search) | 画面下のツール選択から「検索」を有効化。回答に本文中の番号付き引用が付き、クリックで出典元に飛べる |
| Gemini | Google検索によるグラウンディング(Grounding with Google Search) | Gemini APIやVertex AIで有効化するとWeb検索結果を根拠に回答し、出典URLが付与される。通常のGeminiアプリでも「Web検索」表示で同様の裏取りが行われる |
| Claude | Citations(引用機能) / Web検索 | APIで参照文書を渡すと、回答の該当箇所がその文書内の具体的な一文にひも付けられる。ある企業ではこの機能導入で「出典の誤り」が10%から0%に減ったという報告もある |
| Perplexity | 常時引用付き回答 | 検索エンジン型のAIで、回答は原則すべて番号付き出典リンク付き。リアルタイムでWebを検索するため学習データの古さに起因する幻覚を抑えやすい |

いずれも「出典が付いている=100%正しい」ではなく、「検証すべき場所が示されている」だけである点に注意(次章参照)。

### 3. RAG(自社文書に基づく回答)を使う

RAG(Retrieval-Augmented Generation、検索拡張生成)とは、AIの「記憶」だけに頼らず、社内マニュアルやFAQなど手元の文書を検索させ、その内容に基づいて回答を生成させる仕組み。社内で使うAIチャットボットやナレッジ検索ツールの多くがこの仕組みを採用している。自社データという「正解の範囲」が明確な分野では、記憶頼みの回答よりハルシネーションを大幅に減らせるため、社内FAQ・マニュアル検索用途では優先的に検討したい。

### 4. 人による検証ワークフローを業務ルール化する

- 固有名詞・数値・日付・引用文・URLは、AIの回答をそのまま使わず必ず一次情報源と突き合わせる
- 法務・医療・財務・対外公表に関わる内容は、AI下書き→専門知識を持つ人によるレビュー→出典の実在確認、の3段階を必須にする
- 「出典を教えて」と聞いて出てきた書名・URL・判例番号は、実際に検索して実在するかを確認する(存在しない出典を作文されるケースが最も見落とされやすい)
- 社外に出す文書(契約書、プレスリリース、法廷提出書類など)は、AI利用の有無にかかわらず人間の最終承認を経るプロセスを明文化する

## 注意点・よくある誤解

- **「自信満々に断定的に話しているから正しいはず」は誤り**: AIの語調の自信度と、内容の正確さの間には相関がない。ハルシネーションした内容ほど、むしろ流暢で説得力のある文章になりやすい。
- **「新しい・大きいモデルなら幻覚は起きない」も誤り**: モデルの世代が進んでも、タスクの種類(特に固有情報の想起)によっては逆にハルシネーション率が上がる場合がある。モデル名の新しさを過信しない。
- **「Web検索・グラウンディング機能を使えば安心」も過信は禁物**: 検索結果を誤読・誤要約する、複数の情報源を混同する、検索でヒットしなかった部分を記憶で埋める、といった形で検索連動でもハルシネーションは残る。あくまで「軽減」であり「根絶」ではない。
- **実際の事故例**: 2023年、ニューヨークの弁護士がChatGPTに生成させた実在しない判例6件を法廷に提出し、5,000ドルの制裁金と裁判所への謝罪状送付を命じられた(Mata v. Avianca事件)。2026年5月にはオレゴン州の弁護士2名が23件の架空引用を含む書面を提出し、米国の同種事案で過去最高額となる合計11万ドルの制裁を受けている。こうした事案の急増を受け、米国では2026年時点で少なくとも25の連邦地裁がAI利用の申告と人間によるレビューを義務付ける標準命令を導入している。
- **出典の実在確認は最も軽視されがちな検証項目**: 内容の妥当性は確認しても、「そのURL・書名・判例番号が実在するか」まで確認しない人が多い。存在しない出典の生成は、内容の誤りより見抜きにくく被害も大きい。

## 最初の一歩

直近でAIに書かせた文章の中から、固有名詞・数値・URL・引用を1つ選び、実際に検索して実在するかを今すぐ確認してみる。
