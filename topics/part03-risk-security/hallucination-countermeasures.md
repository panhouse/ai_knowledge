# 生成AIのハルシネーション対策

## これは何か

ハルシネーション(hallucination、幻覚)とは、生成AIが事実と異なる情報を、断定口調で自信満々に作り出してしまう現象のこと。存在しない論文を実在するかのように引用したり、ありもしない条文番号や統計値を答えたりする。厄介なのは「知らないので調べます」と言う代わりに、もっともらしい嘘を流暢に語ってしまう点で、議事録要約・市場調査・契約書チェックのように結果をそのまま業務で使う場面ほど被害が大きくなる。ハルシネーションを完全にゼロにする方法は現時点では存在しないため、「どう防ぐか」ではなく「どう発生を減らし、どう見抜くか」という運用の技術として身につける必要がある。

## 仕組み・背景

なぜAIは平然と嘘をつくのか。仕組みを厳密に理解する必要はないが、次の2点を押さえておくと対策の勘所がつかめる。

1. **「わからない」を出す仕組みが標準では備わっていない**: 生成AIの基本動作は、それまでの文脈から「次に来る単語として最もそれらしいもの」を予測し続けることである。この仕組み自体には「自分がこの事実を知っているかどうか」を検証する機能が組み込まれていない。学習データに一度しか出てこない固有名詞(誕生日、論文タイトル、判例番号など)を聞かれると、AIは統計的にそれらしい単語を並べてしまい、結果として存在しない事実を作文してしまう。
2. **「自信満々に間違える」方が高評価になりやすい**: OpenAIが2025年9月に公表した研究では、AIの学習・評価の仕組み自体が「わからないので回答を控える」よりも「外れるかもしれないが断定的に答える」方を高く評価しがちだと指摘されている。テストで自信を持って答えた方が正答率のスコアが上がりやすいため、不確実な質問にも当てずっぽうで答える傾向が強化されてしまう。裏を返せば、AIに「不確実なら『わからない』と答えてよい」と明示的に伝えることが、対策として一定の効果を持つ理由でもある。

加えて、学習データそのものに存在しない・古い・偏った情報しかないテーマ(最新のニュース、社内固有の情報、マイナーな数値データなど)では、そもそも正しい答えを知りようがないため、ハルシネーションが起きやすい。

## 使いどころ・使い分け

対策のコストは「どこまで念入りに確認するか」に比例するので、タスクのハルシネーションリスクに応じて力の入れどころを変えるのが実務的。

| リスクの高さ | 典型的なタスク | 対応の目安 |
|---|---|---|
| 高(必ず検証が要る) | 固有の統計値・法令条文・判例、医療情報、日付・数値・URL、人名や役職の引用、社内規程の解釈 | ウェブ検索連動モードや自社データ参照(RAG)を使う。出典を明示させ、最終的に人間が原典に当たって裏取りする |
| 中 | 業界動向のまとめ、競合分析、専門的だが検証可能なテーマの解説 | ウェブ検索連動モードを使う。重要な数値・固有名詞だけピンポイントで裏取りする |
| 低(誤りがあっても実害が小さい) | ブレインストーミング、文章の言い換え・校正、構成案づくり、壁打ち相手としての利用 | 通常のチャットで問題ない。事実確認の手間をかけずに生産性を優先してよい |

判断基準はシンプルで、「この回答の中の固有名詞・数値・引用を、もし間違っていたら困るか」で線を引く。困るなら高リスク運用に切り替える。

## 実務での使い方

対策は「何か一つやれば安心」というものではなく、優先度の高い順に重ねがけするのが基本。

### 1. ウェブ検索連動モードを使う(最も効果が大きい)

チャットのみのモード(学習データの記憶だけで回答する)と、ウェブ検索を連動させたモードとでは、ハルシネーション率に大きな差が出る。GPT-5系では通常モードで約47%あったハルシネーション率が、ウェブ検索を有効にすると約9.6%まで下がったという計測結果が報告されている。統計値・最新情報・固有名詞を聞くときは、必ず検索連動モードを使う。

| ツール | 検索連動モードの呼び方・場所 |
|---|---|
| ChatGPT | 入力欄下部の「検索」アイコンをオン、または「Web検索」機能付きモデルを選択 |
| Gemini | 標準で Google 検索と連携(該当箇所に「Google 検索で確認」のリンクが表示される) |
| Claude | 入力欄下部の「ウェブ検索」トグルをオン |
| Perplexity | 標準でウェブ検索・引用付き回答が既定動作 |

ただし検索連動でも万能ではない。米コロンビア大学ジャーナリズム大学院(Columbia Journalism Review)の引用監査では、検索を使ってもChatGPT Searchの引用の67%、Perplexityで37%、Grok 3で94%に何らかの誤りが見つかったと報告されている。「実在するURLを引用しているのに、内容は捏造されている」という一見信頼できそうな誤りも起きるため、検索連動=無条件に信用してよい、ではない点に注意する。

### 2. プロンプトで「わからない」を許可する

AIは「答えを出すこと」を優先しがちなので、指示文の中で明示的に「不確実なら分からないと言ってよい」と伝えると、当てずっぽうの回答が減る。

```
以下の質問に答えてください。
- 断定できる根拠がない場合は、推測で答えず「わからない」「確認が必要」と明記してください
- 数値・日付・固有名詞・引用を含める場合は、その情報の出典(URLや文献名)を併記してください
- 出典を提示できない事実は、本文に含めないでください
- 自信の度合いを「確度: 高/中/低」で回答の末尾に付けてください

質問: 〇〇について教えてください
```

### 3. Chain-of-Verification(検証の連鎖)で回答を自己点検させる

一度出た回答をそのまま信じず、AI自身に検証させる2段階の使い方。

```
【1回目のプロンプト】
〇〇についてレポートを作成してください。

【2回目のプロンプト(1回目の回答を踏まえて)】
上記の回答に含まれる事実(数値・日付・固有名詞・引用)を1つずつ箇条書きにし、
それぞれについて「この情報は学習データの記憶に基づく推測か、検索で確認できた事実か」を
自己申告してください。断定できないものには「未検証」と明記してください。
```

研究(Chain-of-Verification, Meta AI, 2023)では、下書きを作成→検証用の質問を立てる→その質問に(下書きを見ずに)個別に答える→検証結果を踏まえて最終回答を作り直す、という手順によって幻覚の混入率を大きく下げられることが確認されている。実務では簡易版として、上記のように「一度出た回答を後から自己点検させる」だけでも一定の効果がある。

### 4. RAG(検索拡張生成)で社内データに根拠づける

RAG(Retrieval-Augmented Generation、検索拡張生成)は、AIが回答する前に社内文書やデータベースから関連情報を検索し、その内容を根拠にして回答させる仕組み。社内規程・製品マニュアル・過去の商談履歴のように「学習データにない、または古い」情報を扱う業務では、RAGを使うことでAIが自分の記憶だけで作文するリスクを大きく減らせる。データの形式やまとめ方によって検索精度が変わる点は[AIが扱いやすいデータ形式](../part06-data-analysis/ai-friendly-data-formats.md)を参照。

### 5. 生成の"ブレ幅"を絞る(temperatureの調整)

temperature(生成のランダム性を決めるパラメータ)を下げると、AIは毎回似た・より一貫性のある回答をしやすくなり、突飛な作文が減る効果が期待できる。ただしこれは主にAPI経由の開発者向け設定であり、ChatGPT・Gemini・Claudeなどの通常のチャット画面には温度を直接調整するUIは用意されていない(GPT-5系のAPIでは温度パラメータ自体が廃止されている)。業務で温度調整をしたい場合は、APIやそれを組み込んだ社内ツールを使う必要がある。

### 6. 高リスクな出力は必ず人間が原典に当たる

どれだけプロンプトを工夫しても、AIが提示した出典やURL自体が実在するとは限らない。特に統計値・法令・医療情報・引用文は、AIの回答をそのまま使わず、提示された出典に人間が実際にアクセスして確認する運用を業務フローに組み込む。契約書・対外発表資料・顧客向け提案書など、誤りが信用問題に直結する成果物では、この「人間による最終検証」を省略しない。

## 注意点・よくある誤解

- **「ハルシネーションしないでください」と頼むだけでは効果が薄い**: 抽象的な注意書きよりも、「出典を示す」「わからなければそう言う」「確度を明記する」など、AIが従いやすい具体的な行動指示に落とし込む方が効果が高い。
- **検索連動モード=100%正確、ではない**: 前述の通り、検索を使っても引用元と内容が一致しない誤りは一定割合で発生する。検索連動は「リスクを下げる」ものであって「ゼロにする」ものではない。
- **モデルが新しくなってもハルシネーションはなくならない**: 高性能なモデルほど幻覚が減る傾向はあるが、構造的な原因(わからないと言う動機づけが弱い)が解消されない限り、根本的にはなくならない。「新しいモデルだから大丈夫」と過信しない。
- **もっともらしい形式(丁寧な学術文体、整った引用形式)ほど信じやすい**: 体裁が整っているほど人間は疑わなくなる傾向があるため、フォーマットの綺麗さと内容の正しさは別問題だと意識する。
- **ハルシネーションと「情報漏洩」は別のリスク**: 誤情報を作り出すハルシネーションと、入力した機密情報が外部に漏れるリスクは別物。後者については[生成AI利用における情報漏洩対策](./information-leakage-prevention.md)を参照。

## 最初の一歩

直近でAIに数値や固有名詞を含む回答を作らせたやり取りを1つ選び、検索連動モードをオンにして同じ質問を投げ直し、回答内容や出典がどう変わるかを比較してみる。
