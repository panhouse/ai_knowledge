# ハルシネーションの仕組みと対策

## これは何か

ハルシネーション(hallucination、幻覚)とは、生成AIが事実に基づかない情報を、もっともらしい自信満々の口調で生成してしまう現象のこと。存在しない統計データを引用したり、実在しない論文・URLをでっち上げたり、法令の条文番号を間違えたりする形で現れる。業務資料にそのまま載せてしまうと、社外への誤情報発信や取引先からの信用失墜につながる、実務上かなり厄介なリスクである。

## 仕組み・背景

生成AI(大規模言語モデル、LLM)は「次にくる単語として最も確率が高いものを予測する」仕組みで文章を生成しており、事実データベースを検索して裏取りをしているわけではない。文法的にも文脈的にも自然な文章を作ることは得意だが、それが「事実として正しいか」は別問題であり、もっともらしさと正しさは仕組みの上では別の軸にある。

特にハルシネーションが起きやすいのは次のようなケースである。

- 学習データのカットオフ以降に起きた最新の出来事(モデルは知らないのに、知っているかのように答えてしまう)
- 学習データに登場頻度が低いマイナーな固有名詞・社内独自の用語・ニッチな製品名
- 具体的な数値・日付・条文番号・URL・引用文献など、「厳密に一致していないと意味がない」情報
- 「〇〇について教えて」のように答えが1つに定まらない曖昧な質問(モデルが「それらしい答え」を作りにいく)

2026年時点のフロンティアモデルはハルシネーション対策が大きく進み、オープンドメインの事実質問ベンチマークではClaudeやGPTの最新モデルで数%台まで抑えられているとの報告もあるが、これは「かなり減った」であって「なくなった」ではない点に注意が必要である。Web検索機能を有効にすると、していない場合に比べてハルシネーション発生率を大きく下げられるとの報告もあり、対策の柱の1つになっている。

## 使いどころ・使い分け

すべての回答を同じ警戒レベルで疑う必要はない。「ハルシネーションが起きやすいタスクか」を見極めて、対策の手間をかけるべきところに絞るのが実務的。

| タスクの性質 | ハルシネーションの起きやすさ | 実務での扱い方 |
|---|---|---|
| 固有の数値・統計・日付・法令条文番号 | 高い(でっち上げやすい) | 必ず一次情報で裏取りする。AIの回答だけを根拠にしない |
| 論文・書籍・URLなどの引用文献 | 非常に高い(存在しない文献を自然な体裁で作る) | リンクを実際にクリックして実在確認する。存在しない引用は「あるある」だと心得る |
| マイナーな固有名詞・社内独自ルール・専門的すぎる質問 | 高い | RAGや資料添付で手元の一次資料を根拠にさせる |
| 最新のニュース・価格・法改正などカットオフ以降の情報 | 高い | Web検索機能を必ず併用する |
| 手元の文章の要約・言い換え・校正 | 低い(参照元が明示されている) | 通常利用で問題ないが、要約に元文書にない情報が混入していないかは軽く確認する |
| アイデア出し・ブレインストーミング・構成案作成 | 低い(そもそも「正解」がない) | そのまま活用してよい |
| コードのロジック相談・レビュー観点の洗い出し | 低〜中 | 実行結果で検証できるため実害は出にくいが、存在しないライブラリ名・API名の提示には注意 |

判断基準はシンプルで、「答えが1つに定まる事実」を聞くほどハルシネーションのリスクは上がり、「正解のない発想」を求めるほどリスクは下がる。

## 実務での使い方

### 対策1: Web検索機能を使わせる

学習データにない最新情報や裏取りが必要な質問には、必ずAIのWeb検索機能を使う。生成AIが自分の記憶だけで答えるのではなく、実際にWebページを検索・参照してから回答するため、特に最新情報がらみのハルシネーションを大きく減らせる。

| ツール | 機能名 | 有効化の場所 |
|---|---|---|
| ChatGPT | ChatGPT search | 入力欄の地球儀アイコン、または「/search」で切り替え。2026年時点で無料プランを含む全プランで利用可能 |
| Gemini | グラウンディング(Google 検索との連携) | 標準で有効。回答下部の「その他」メニュー→「回答を再確認」で事後検証も可能 |
| Claude | Web検索(web_search) | claude.aiの入力欄でWeb検索をオンにするか、APIでは`web_search`ツールを指定。回答に出典への引用(Citations)が自動で付く |
| Microsoft Copilot | Bing連携の検索 | 標準で有効。回答とあわせて参照したWebサイトの一覧が表示される |

### 対策2: 「わからなければ分からないと答えて」と明示的に指示する

何も指定しないと、AIは「答えられない」より「それらしい答えを作る」方に寄りやすい。プロンプトに一言加えるだけで、無理に答えを作る挙動をある程度抑制できる。

```
以下の質問に答えてください。
ただし、確信が持てない情報や、あなたの学習データに含まれていない可能性がある
情報(最新の統計・固有名詞・URL・条文番号など)については、
断定せずに「不明」「要確認」と明記してください。
推測で数値や固有名詞を作り出すことは絶対にしないでください。

質問: (ここに質問を書く)
```

### 対策3: RAGや「渡した資料だけを根拠にする」ツールを使う

RAG(Retrieval-Augmented Generation、検索拡張生成)とは、質問に答える前に手元の文書から関連箇所を検索し、その内容を根拠にして回答を生成させる仕組み(原理の詳細は別ページに譲る)。社内マニュアルやFAQをAIチャットボットの土台にする場合など、モデル自身の記憶ではなく手元の一次資料に基づいて答えさせたい場面で有効。

個人・小規模チームで手軽に使うなら、Googleの「NotebookLM」のように、アップロードした資料の内容だけを根拠に回答する専用ツールが向いている。NotebookLMは「ソースグラウンディング」と呼ばれる仕組みで、インターネット全体の知識ではなくアップロードした資料のみを参照するため、資料にない内容を答えにくい設計になっている。使うときは次のようなプロンプトを添えると精度が上がる。

```
アップロードした資料に書かれている内容のみを根拠に回答してください。
資料に記載がない場合は、推測で補わずに
「アップロードされた資料には記載がありません」と答えてください。
回答の該当箇所を資料から引用してください。
```

### 対策4: 出典・引用を明示させ、人間が最終確認する

AIに「出典を示して」と指示するだけでもハルシネーションを100%防げるわけではないが、後で裏取りしやすくなる効果は大きい。

```
回答には必ず根拠となる出典(URL・文献名・発行元)を明記してください。
出典が不明な情報は含めないでください。
```

出典が付いた回答でも、リンクを実際に開いて実在を確認する、数値は一次情報(公式サイト・統計機関の発表など)と突き合わせる、というダブルチェックを業務フローに組み込む。特に対外的に出す資料(プレスリリース・提案書・レポート)は、AIが作った文章を人間が確認せずにそのまま出さない、という運用ルールを決めておくとよい。

### 対策5: 生成後にファクトチェックを別プロンプト・別AIにやらせる(セルフチェック)

1回の生成で終わらせず、続けて「今の回答を検証して」と指示する、あるいは別のAIサービスに同じ内容を検証させると、誤りに気づける確率が上がる。

```
先ほどの回答について、以下の観点でファクトチェックしてください。
- 固有名詞・数値・日付に誤りがないか
- 引用したURLや文献が実在するか(不確かなら「未確認」と明記)
- 断定しているが根拠が薄い記述がないか
問題があれば具体的に指摘し、修正案を示してください。
```

Geminiの場合は、この検証作業を「回答を再確認」機能がワンクリックで代行してくれる。回答の各部分がGoogle検索のソースと一致していれば緑色、古い・確認できない場合はオレンジ色で表示されるため、業務資料に使う前のセルフチェックとして活用できる。

## 注意点・よくある誤解

- **ハルシネーションはゼロにはできない**: 最新モデルでも精度は大きく上がっているが、対策を組み合わせてもリスクをゼロにはできない。「重要な情報は必ず人間が裏取りする」という前提を崩さないこと。
- **自信満々な口調に騙されない**: AIは「わかりません」より断定的な文章を出しやすい傾向がある。口調の自信度と情報の正しさは無関係だと心得ておく。
- **出典が付いていても安心しきらない**: 存在しない論文名やURLを、実在するかのような体裁で作ってしまうケースは典型的なハルシネーションのパターン。出典が示されていても、実際にリンクを開いて実在を確認する一手間を省かない。
- **社内マニュアルなどをRAGに使う場合の機密管理**: RAGやNotebookLMのようなツールに社内文書をアップロードする際は、その文書に機密情報が含まれていないか、アップロード先のサービスがデータをどう扱うか(学習利用の有無、保存期間)を事前に確認する。機密度が高い文書を扱う場合は、法人契約かどうか、アクセス権限が適切に絞られているかも合わせて確認したい(詳細は情報漏洩対策のページを参照)。
- **「ハルシネーションしないで」だけでは効果が薄い**: 精神論的な指示より、「わからない場合は分からないと言う」「出典を明示する」など、具体的な行動を指定するプロンプトの方が効果が出やすい。

## 最初の一歩

次にAIに数値や固有名詞、引用文献を聞くときは、プロンプトの最後に「確信が持てない場合は分からないと答えてください」の一文を足してみる。
