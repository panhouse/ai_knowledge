# 認識系AIの応用(画像認識・音声認識・従来型自然言語処理)

## これは何か

「AI」と聞くとChatGPTやGeminiのような生成AI(文章や画像を新しく作るAI)を思い浮かべがちだが、企業の現場で実際に長年利益を生んでいるのは、画像・音声・テキストといった既存のデータを「読み取り、分類し、判定する」**認識系AI**であることが多い。工場の外観検査、コールセンターの通話ログ化、来店客数からの発注量の予測などは、生成AIが登場するはるか前から機械学習・ディープラーニング(第3・4章)を使って実用化されてきた技術で、地味だが投資対効果が測りやすいのが特徴だ。2026年現在はGPT-5.5/5.6やGemini 3.1 Proのようなマルチモーダル(画像・音声・テキストを統合的に扱えるモデル)の精度が上がり両者の境界は狭まりつつあるが、「AI導入」の相談が生成AIの話なのか認識系AIの話なのかを最初に仕分けないと、的外れなツール選定につながる点は変わらない。

## 仕組み・背景

認識系AIは大きく「画像認識」「音声認識」「従来型の自然言語処理(NLP)」「数値データの異常検知・予測」の4系統に分けて理解すると整理しやすい。

### 画像認識:4段階のタスクがある

画像認識は一枚岩ではなく、目的に応じて次の4段階のタスクに分かれる。いずれもディープラーニングのCNN(畳み込みニューラルネットワーク、[ディープラーニングの基礎](deep-learning-basics.md)参照)を土台にしており、リアルタイム物体検出の代表格「YOLO」系列は2026年1月に最新版「YOLO26」が公開された。NMS(重複検出の間引き処理)を廃止したend-to-end方式により、従来版(YOLO11)比で最大43%高速なCPU推論を実現し、分類・検出・セグメンテーション・姿勢推定などを1系統のモデルで統一的に扱えるようになっている([Ultralytics公式ブログ](https://www.ultralytics.com/blog/ultralytics-yolo26-the-new-standard-for-edge-first-vision-ai))。

| タスク | 何がわかるか | 代表的な業務用途 |
|---|---|---|
| 画像分類(Classification) | 画像全体が「何」であるか | 製品の良品/不良品の一次判定、書類の種類の自動仕分け |
| 物体検出(Object Detection) | 画像の「どこに」「何が」あるか(矩形の位置=バウンディングボックス) | 監視カメラでの人物検知、自動運転の信号・標識・障害物の認識 |
| セグメンテーション(Segmentation) | 物体の輪郭をピクセル単位で切り出す | 医療画像での病変領域の特定、工場での傷・欠陥の面積計測 |
| OCR(文字認識) | 画像内の文字をテキストデータに変換 | 請求書・帳票のデータ化、名刺・免許証の読み取り |

OCRは「文字」というくくりの中で物体検出的な手法(どこに文字ブロックがあるか特定)と文字認識を組み合わせている。近年の「AI-OCR」は罫線や手書き文字への対応に加え、読み取った内容の意味を生成AI(LLM)が解釈して勘定科目を自動割当したり複雑な表組みを構造化したりする連携が定着した。国内シェア最大手の「DX Suite」は自社開発の言語モデル「PolySphere」を組み込み、非定型帳票でも平均99.6%の読み取り精度を公称している([renue「AI-OCR主要15製品徹底比較2026」](https://renue.co.jp/posts/ai-ocr-product-comparison-15-tools-2026))。

### 音声認識:音声波形をテキストに変換する

音声認識(ASR: Automatic Speech Recognition)は、マイクで捉えた音声波形をディープラーニングでテキストに変換する技術。クリアな音声環境では誤り率(WER: Word Error Rate、書き起こしの誤り割合)が5〜6%台まで下がっており、人間の書き起こしに迫る水準に達しているという計測結果もある一方、雑音・方言・専門用語の多用があると精度が落ちるため、業界特化の辞書登録などの運用が精度を左右する点は変わらない([note「AI音声認識の精度比較2026年版」](https://note.com/ai_labo26/n/nf56c0385a1dd))。日本語特化エンジンとして「AmiVoice Cloud Platform」(アドバンスト・メディア)が国内で高い認識精度と実績を持ち、多言語対応では15.5億パラメータの「Whisper large-v3」(OpenAI、オープンソースで99以上の言語に対応)や、Gemini系モデルとの統合で文脈理解を活かす「Google Speech-to-Text(Chirp 2)」が広く使われている。

### 従来型の自然言語処理(NLP):生成AI以前の「読む・分類する」技術

生成AI以前のNLPは、文章を「作る」のではなく「分解・分類・抽出する」ことが主目的だった。代表的な要素技術は次の通り。

- **形態素解析**: 文章を意味を持つ最小単位(形態素)に分割し、品詞や活用形を判定する。日本語には単語の区切りに空白がないため、この工程が日本語NLPの土台になる
- **係り受け解析**: 文中の単語同士の主語・修飾関係を特定する
- **感情分析(センチメント分析)**: テキストが肯定・否定・中立のどれに近いかを自動判定する。SNSやレビュー、通話ログのテキストマイニングに使われる
- **固有表現抽出**: 人名・地名・製品名などの固有名詞を文章から抜き出す

これらはルールベース・辞書ベース、または統計的な機械学習モデルが中心で、「品質が良い」も「品質が悪い」も同じ「品質」という語で一括りに数えてしまうなど、文脈依存の言い回しには弱いという限界があった。現在のLLM(大規模言語モデル)は文脈や意図まで踏み込んで解析でき、部署横断の定性データを統合して改善提案まで自動生成するような使い方が広がっている([aicentralapp「テキストマイニングツール比較」](https://aicentralapp.com/media/text-mining-tool-comparison))。2025年から2026年にかけてLLM APIの平均コストは60〜80%下落しており、以前は「コストが見合わず従来型NLPを選ばざるを得なかった」用途でもLLM活用が現実的になってきた([genai-ai.co.jp「LLM APIの料金比較」](https://genai-ai.co.jp/ai-kanri/blog/cc-llm-api-pricing-guide/))。それでも、超大量データを一定の基準だけで機械的に分類する処理や、判定根拠の説明可能性(ルールが明示できること)が求められる用途では、軽量で安価な従来型NLPが今も現役で使われている。

### 異常検知・需要予測:数値データからのパターン検知

工場のセンサー値やPOS(販売時点情報)データのような表形式データについては、[機械学習の基礎](machine-learning-basics.md)で扱う教師あり学習・教師なし学習が使われる。異常検知は「正常時のパターン」を学習し、そこから外れた挙動を検知する仕組みで、設備の予知保全に使われる。需要予測は過去の販売実績・天候・イベント情報などから将来の需要を回帰的に予測する仕組みで、発注最適化に使われる。どちらも画像や音声のような非構造化データではなく表形式データが対象になるため、必ずしもディープラーニングを必要とせず、比較的少ないデータ・計算コストで導入できることが多い。2025年以降はAmazon「Chronos-2」やGoogle「TimesFM 2.5」のような**時系列基盤モデル**(大量の時系列データで事前学習し、追加学習なしで様々な予測タスクに適用できるモデル)が登場し、プロモーション予定や天候といった外部要因(共変量)を加味した予測をゼロショット(自社データでの再学習なし)で行えるようになりつつある([AWS公式ブログ「Chronos-2の紹介」](https://aws.amazon.com/jp/blogs/news/introducing-chronos-2/))。ただし実務では、予測の前提条件や外部要因の設計が結果を大きく左右するため、「モデルを差し込めば終わり」ではなく検証・チューニングの工程は引き続き必要になる。

## 使いどころ・使い分け

まず押さえるべきは、**認識系AI(識別・判定)と生成AI(新規作成)は目的が違う**という軸だ([AIの分類と生成AIの位置づけ](ai-classification-and-generative-ai.md)も参照)。業務シーンごとにどちらが向いているかを整理する。

| 業務シーン | 向いている技術 | 理由 |
|---|---|---|
| 製品の傷・欠陥を検出したい | 画像認識(物体検出・セグメンテーション) | 位置・面積まで特定できる専用モデルが速く安価 |
| 紙の請求書・帳票をデータ化したい | AI-OCR(+生成AIで意味解釈) | 文字認識は専用OCRが最速最安。意味の解釈だけLLMを補助的に使う |
| コールセンターの会話を記録・要約したい | 音声認識+従来型NLP/生成AI | 文字化は音声認識、感情の傾向集計は従来型NLP、個別の要約文生成はLLMが得意 |
| 設備の故障を事前に察知したい | 異常検知(教師なし学習) | 「壊れる前の予兆」は正常パターンからのズレとして捉えるのが最適 |
| 発注量・在庫量を最適化したい | 需要予測(回帰・時系列モデル、時系列基盤モデル) | 表形式データの数値予測は従来型の機械学習・時系列モデルで十分な精度が出やすい |
| 例外的な指示や柔軟な判断が必要 | 生成AI(マルチモーダルLLM) | 画像を「見て」自由記述で説明するなど、定型を超えた対応に強い |

判断基準をもう一段シンプルにすると、**「定型的・大量・リアルタイム性が必要」なら専用の認識系AI、「非定型・少量・柔軟な指示が必要」なら生成AI**という切り分けになる。GPT-5.5/5.6(OpenAI)、Gemini 3.1 Pro(Google)、Claude Sonnet 5(Anthropic)のようなマルチモーダルLLMは画像を見て説明したり音声を理解したりする精度が着実に上がっているが、ミリ単位の欠陥検出や大量画像のリアルタイム処理では、専用に学習・最適化された認識系AI(YOLO26など)の方が精度・速度・コストの面で優位なことが多い。

## 実務での使い方

### 画像認識:外観検査の具体例

製造業のAI外観検査では、経済産業省の事例集で目視検査をAIに置き換えた工程で不良見逃し率を1/10以下に圧縮した報告が複数あるほか、直径3mmの円筒状部品をAIが自動でOK/NG判定する仕組みを構築した墨田加工の事例、H形鋼の圧延ラインにAI画像判定サービスを導入した東京製鐵九州工場の事例が報告されている([日本AI導入支援協会「製造業のAI活用事例と導入状況」](https://j-aix.or.jp/journal/702/))。PoC(概念実証)から始める場合、費用は50万〜300万円、期間は2〜3ヶ月程度が目安とされる(同上)。

### 音声認識・従来型NLP:コールセンターの具体例

コールセンターでは、通話をリアルタイムでテキスト化することで後処理業務(ACW: After Call Work)の時間を短縮できるほか、通話録音データをテキストマイニング(感情分析)で分析し、特定製品への問い合わせが多いことを突き止めてFAQ・解説動画を拡充し、返品率を下げた事例もある([NTTデータ数理システム](https://www.msiism.jp/article/nttdata-smart-voc.html))。

### 異常検知・需要予測:効果の目安と具体例

予知保全AIの導入効果は業界差が大きいが、自動車業界では金型コストを15%削減し故障率を半減、突発故障を80%削減したという報告や、化学業界では多変量センサーAIによるバッチ異常予測が報告されている([OptiMax「予知保全のメリット完全解説」](https://www.optimax.co.jp/ai-information/predictive-maintenance-benefits/))。需要予測では、サッポロビールが人とAIの協働による需要予測システムを導入し予測精度を20%向上させた事例や、熊本のスーパー「ロッキー」が精肉部門でAI需要予測とダイナミックプライシング(需要予測に応じた価格変更)を組み合わせた実証実験で食品ロス率を1.3ポイント改善、値引き作業の工数を83.3%削減した事例がある(全28店舗展開時の年間コスト削減効果は約9,900万円と試算)([renue「需要予測AIとは?」](https://renue.co.jp/posts/demand-forecasting-ai-guide)、[シノプス](https://www.sinops.jp/news/260204/))。

### ツール横断の対応表

| 用途 | 代表的なサービス・製品 |
|---|---|
| 画像認識API(汎用) | Google Cloud Vision AI、AWS Rekognition、Azure AI Vision |
| 画像認識(自前学習・エッジ向けOSS) | YOLO26(Ultralytics) |
| 音声認識(日本語特化) | AmiVoice Cloud Platform(アドバンスト・メディア) |
| 音声認識(多言語・API) | Whisper API(large-v3、OpenAI)、Google Speech-to-Text(Chirp 2)、AWS Transcribe |
| AI-OCR | AI inside「DX Suite」、Cogent Labs「SmartRead」(旧Tegakiの手書きエンジンを内蔵)、各クラウドベンダーのOCR API |
| 需要予測・在庫最適化 | sinops、Deep Predictor(AI Cross)、Amazon Chronos-2・Google TimesFM 2.5などの時系列基盤モデル |
| 柔軟な認識補助(汎用マルチモーダルLLM) | GPT-5.5/5.6(OpenAI)、Gemini 3.1 Pro(Google)、Claude Sonnet 5(Anthropic) |

自社でこれらを検討する際は、ベンダーに「学習済みモデルをそのまま使うのか、自社データで追加学習が必要か」「誤検知率・見逃し率の許容水準はどこか」を確認すると、過剰スペック・過小スペックを避けやすい。

## 注意点・よくある誤解

- **「AI導入」の話が生成AIと認識系AIで噛み合わないことがある**: 社内で「AIを使いたい」という要望が出たとき、それが画像・音声・数値データの「判定・予測」なのか、文章・画像の「新規作成」なのかを最初に仕分けると議論が早い
- **精度は環境依存**: 音声認識はクリアな音声で誤り率5〜6%台まで下がっていても、雑音・方言・専門用語が多い現場では精度が落ちる。カスタム辞書の登録や録音環境の改善など運用面の工数を織り込む必要がある
- **教師データに写っていないパターンには弱い**: 画像認識も異常検知も、学習時に想定していなかった不良パターン・故障モードには対応できない。運用開始後も定期的な再学習・チューニングが前提になる
- **時系列基盤モデルも「差し込めば終わり」ではない**: ゼロショットで動く時系列基盤モデルが登場しているが、プロモーション予定や季節性などの外部要因(共変量)の設計次第で精度が大きく変わるため、検証工程は依然として必要
- **誤検知(過検知・見逃し)のバランス調整が必要**: 外観検査で検出を厳しくしすぎると良品まで不良品と判定してしまい、緩めると不良品を見逃す。最終判断に人によるダブルチェック工程を残す設計が安全
- **生成AIで何でも代替できるわけではない**: GPT-5.5/5.6やGemini 3.1 Proのようなマルチモーダルモデルは画像や音声を扱えるようになったが、ミリ単位の欠陥検出や大量データのリアルタイム処理では専用の認識系AIの方が精度・速度・コストで優位なことが多い

## 最初の一歩

自社で「AIを使いたい」と思っている業務を1つ思い浮かべ、それが「既にあるものを読み取る・分類する」(認識系AI向き)か「新しく何かを作る」(生成AI向き)かを仕分けてみる。前者であれば、まずは無料トライアルのあるAI-OCRサービスや音声認識サービスで、実際の帳票・通話データを1件試してみるのが手軽な第一歩になる。
