# 認識系AIの応用(画像認識・音声認識・従来型自然言語処理)

## これは何か

「AI」と聞くとChatGPTのような生成AI(文章や画像を新しく作るAI)を思い浮かべがちだが、企業の現場で実際に長年利益を生んでいるのは、画像・音声・テキストといった既存のデータを「読み取り、分類し、判定する」**認識系AI**であることが多い。工場の外観検査、コールセンターの通話ログ化、来店客数からの発注量の予測などは、生成AIが登場するはるか前から機械学習・ディープラーニング(第3・4章)を使って実用化されてきた技術で、地味だが投資対効果が測りやすいのが特徴だ。この区別を知らないと、「AI導入」の相談が生成AIの話なのか認識系AIの話なのか噛み合わず、的外れなツール選定につながる。

## 仕組み・背景

認識系AIは大きく「画像認識」「音声認識」「従来型の自然言語処理(NLP)」「数値データの異常検知・予測」の4系統に分けて理解すると整理しやすい。

### 画像認識:4段階のタスクがある

画像認識は一枚岩ではなく、目的に応じて次の4段階のタスクに分かれる。いずれもディープラーニングのCNN(畳み込みニューラルネットワーク、[ディープラーニングの基礎](deep-learning-basics.md)参照)を土台にしており、近年は「YOLO」のような高速なリアルタイム検出モデルが物体検出の主流になっている([AI Market](https://ai-market.jp/purpose/image-recognition-object_detection/))。

| タスク | 何がわかるか | 代表的な業務用途 |
|---|---|---|
| 画像分類(Classification) | 画像全体が「何」であるか | 製品の良品/不良品の一次判定、書類の種類の自動仕分け |
| 物体検出(Object Detection) | 画像の「どこに」「何が」あるか(矩形の位置=バウンディングボックス) | 監視カメラでの人物検知、自動運転の信号・標識・障害物の認識 |
| セグメンテーション(Segmentation) | 物体の輪郭をピクセル単位で切り出す | 医療画像での病変領域の特定、工場での傷・欠陥の面積計測 |
| OCR(文字認識) | 画像内の文字をテキストデータに変換 | 請求書・帳票のデータ化、名刺・免許証の読み取り |

OCRは「文字」というくくりの中で物体検出的な手法(どこに文字ブロックがあるか特定)と文字認識を組み合わせている。近年の「AI-OCR」は、罫線や手書き文字への対応に加え、読み取った内容の意味を生成AI(LLM)が解釈して勘定科目を自動割当したり複雑な表組みを構造化したりする連携が進んでいる。

### 音声認識:音声波形をテキストに変換する

音声認識(ASR: Automatic Speech Recognition)は、マイクで捉えた音声波形をディープラーニングでテキストに変換する技術。クリアな音声環境であれば認識精度95%以上を達成するサービスが2026年時点では一般的だが、雑音・方言・専門用語の多用があると精度が落ちるため、業界特化の辞書登録などの運用が精度を左右する([CBA Japan](https://blog.cba-japan.com/ai-speech-recognition-service/))。日本語特化エンジンとして「AmiVoice」(アドバンスト・メディア)が国内で高い認識精度と実績を持ち、多言語対応では「Whisper」(OpenAI、オープンソース)や「Google Speech-to-Text」が広く使われている([IT trip](https://ittrip.xyz/system/web-service/asr-engines-compare-japanese))。

### 従来型の自然言語処理(NLP):生成AI以前の「読む・分類する」技術

生成AI以前のNLPは、文章を「作る」のではなく「分解・分類・抽出する」ことが主目的だった。代表的な要素技術は次の通り。

- **形態素解析**: 文章を意味を持つ最小単位(形態素)に分割し、品詞や活用形を判定する。日本語には単語の区切りに空白がないため、この工程が日本語NLPの土台になる
- **係り受け解析**: 文中の単語同士の主語・修飾関係を特定する
- **感情分析(センチメント分析)**: テキストが肯定・否定・中立のどれに近いかを自動判定する。SNSやレビュー、通話ログのテキストマイニングに使われる
- **固有表現抽出**: 人名・地名・製品名などの固有名詞を文章から抜き出す

これらはルールベース・辞書ベース、または統計的な機械学習モデルが中心で、未知語や文脈依存の言い回しには弱いという限界があった。現在のLLM(大規模言語モデル)は深層学習で文脈や意味そのものを学習しており、分類・抽出だけでなく新しい文章の生成までを高い精度でこなせる点が決定的な違いになる([Qiita](https://qiita.com/atkyoshizumi/items/6c65ad4d948ef132dbeb))。ただし、感情分析やテキストマイニングのように「大量データを一定の基準で機械的に分類する」用途では、軽量で安価な従来型NLPが今でも現役で使われている。

### 異常検知・需要予測:数値データからのパターン検知

工場のセンサー値やPOS(販売時点情報)データのような表形式データについては、[機械学習の基礎](machine-learning-basics.md)で扱う教師あり学習・教師なし学習が使われる。異常検知は「正常時のパターン」を学習し、そこから外れた挙動を検知する仕組みで、設備の予知保全に使われる。需要予測は過去の販売実績・天候・イベント情報などから将来の需要を回帰的に予測する仕組みで、発注最適化に使われる。どちらも画像や音声のような非構造化データではなく表形式データが対象になるため、必ずしもディープラーニングを必要とせず、比較的少ないデータ・計算コストで導入できることが多い。

## 使いどころ・使い分け

まず押さえるべきは、**認識系AI(識別・判定)と生成AI(新規作成)は目的が違う**という軸だ([AIの分類と生成AIの位置づけ](ai-classification-and-generative-ai.md)も参照)。業務シーンごとにどちらが向いているかを整理する。

| 業務シーン | 向いている技術 | 理由 |
|---|---|---|
| 製品の傷・欠陥を検出したい | 画像認識(物体検出・セグメンテーション) | 位置・面積まで特定できる専用モデルが速く安価 |
| 紙の請求書・帳票をデータ化したい | AI-OCR(+生成AIで意味解釈) | 文字認識は専用OCRが最速最安。意味の解釈だけLLMを補助的に使う |
| コールセンターの会話を記録・要約したい | 音声認識+従来型NLP/生成AI | 文字化は音声認識、感情の傾向集計は従来型NLP、個別の要約文生成はLLMが得意 |
| 設備の故障を事前に察知したい | 異常検知(教師なし学習) | 「壊れる前の予兆」は正常パターンからのズレとして捉えるのが最適 |
| 発注量・在庫量を最適化したい | 需要予測(回帰・時系列モデル) | 表形式データの数値予測は従来型の機械学習で十分な精度が出やすい |
| 例外的な指示や柔軟な判断が必要 | 生成AI(マルチモーダルLLM) | 画像を「見て」自由記述で説明するなど、定型を超えた対応に強い |

判断基準をもう一段シンプルにすると、**「定型的・大量・リアルタイム性が必要」なら専用の認識系AI、「非定型・少量・柔軟な指示が必要」なら生成AI**という切り分けになる。近年はGPT-4oやGeminiのようなマルチモーダルLLM(画像・音声・テキストを統合的に扱えるモデル)が画像を見て説明したり音声を理解したりできるようになっているが、ミリ単位の欠陥検出や大量画像のリアルタイム処理では、専用に学習・最適化された認識系AIの方が精度・速度・コストの面で優位なことが多い。

## 実務での使い方

### 画像認識:外観検査の具体例

製造業のAI外観検査では、微細な傷やバリを人の目視以上の精度で検出し、不良品の市場流出率を90%以上削減した自動車部品メーカーの例や、AIカメラで検査員3名分の目視作業を代替して24時間無人検査を実現した電子部品メーカーの例、生産条件を自動調整して労働生産性を2倍に高めた大手電機メーカーの例が報告されている([AI Market](https://ai-market.jp/case_study/examples-visual-inspection/))。

### 音声認識・従来型NLP:コールセンターの具体例

コールセンターでは、通話をリアルタイムでテキスト化することで後処理業務(ACW: After Call Work)の時間を短縮できるほか、通話録音データをテキストマイニング(感情分析)で分析し、特定製品への問い合わせが多いことを突き止めてFAQ・解説動画を拡充し、返品率を下げた事例もある([NTTデータ数理システム](https://www.msiism.jp/article/nttdata-smart-voc.html))。

### 異常検知・需要予測:効果の目安と具体例

予知保全AIの導入効果として、保全コストを20〜30%削減、突発的な設備停止を70〜80%防止できたという報告がある([renue](https://renue.co.jp/posts/ai-anomaly-detection-predictive-maintenance-manufacturing-it-guide))。需要予測では、熊本のスーパー「ロッキー」が精肉部門でAI需要予測とダイナミックプライシング(需要予測に応じた価格変更)を組み合わせた実証実験を実施し、食品ロス率を1.3ポイント改善、値引き作業の工数を83.3%削減した。全28店舗に展開した場合、年間約9,900万円のコスト削減効果を試算している([シノプス](https://www.sinops.jp/news/260204/))。

### ツール横断の対応表

| 用途 | 代表的なサービス・製品 |
|---|---|
| 画像認識API(汎用) | Google Cloud Vision AI、AWS Rekognition、Azure AI Vision |
| 音声認識(日本語特化) | AmiVoice Cloud Platform(アドバンスト・メディア) |
| 音声認識(多言語・API) | Whisper API(OpenAI)、Google Speech-to-Text、AWS Transcribe |
| AI-OCR | AI inside DX Suite、Tegaki、各クラウドベンダーのOCR API |
| 需要予測・在庫最適化 | sinops、その他業界特化のSaaS型需要予測ツール |

自社でこれらを検討する際は、ベンダーに「学習済みモデルをそのまま使うのか、自社データで追加学習が必要か」「誤検知率・見逃し率の許容水準はどこか」を確認すると、過剰スペック・過小スペックを避けやすい。

## 注意点・よくある誤解

- **「AI導入」の話が生成AIと認識系AIで噛み合わないことがある**: 社内で「AIを使いたい」という要望が出たとき、それが画像・音声・数値データの「判定・予測」なのか、文章・画像の「新規作成」なのかを最初に仕分けると議論が早い
- **精度は環境依存**: 音声認識はクリアな音声で95%以上の精度が出ても、雑音・方言・専門用語が多い現場では精度が落ちる。カスタム辞書の登録や録音環境の改善など運用面の工数を織り込む必要がある
- **教師データに写っていないパターンには弱い**: 画像認識も異常検知も、学習時に想定していなかった不良パターン・故障モードには対応できない。運用開始後も定期的な再学習・チューニングが前提になる
- **誤検知(過検知・見逃し)のバランス調整が必要**: 外観検査で検出を厳しくしすぎると良品まで不良品と判定してしまい、緩めると不良品を見逃す。最終判断に人によるダブルチェック工程を残す設計が安全
- **生成AIで何でも代替できるわけではない**: マルチモーダルLLMは画像や音声を扱えるようになったが、ミリ単位の欠陥検出や大量データのリアルタイム処理では専用の認識系AIの方が精度・速度・コストで優位なことが多い

## 最初の一歩

自社で「AIを使いたい」と思っている業務を1つ思い浮かべ、それが「既にあるものを読み取る・分類する」(認識系AI向き)か「新しく何かを作る」(生成AI向き)かを仕分けてみる。前者であれば、まずは無料トライアルのあるAI-OCRサービスや音声認識サービスで、実際の帳票・通話データを1件試してみるのが手軽な第一歩になる。
