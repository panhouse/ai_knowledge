# 外食・フードサービス業における生成AI活用事例

## これは何か

外食・フードサービス業(飲食チェーン・個人店・給食事業者など、料理を提供する事業そのものを営む業種)は、需要変動が激しいわりに利益率が薄く、「発注量の見誤り=食品ロスか欠品」「人員配置の見誤り=人件費過多か接客品質低下」という二択の綱渡りを日々続けている業種である。加えて電話予約・口コミ対応・インバウンド接客など「定型だが手間のかかる」窓口業務も多い。
本ページは、宿泊・観光業(ホテル・旅館・旅行会社)を扱う[宿泊・観光業における生成AI活用事例](./hospitality-tourism-ai-use-cases.md)とは異なり、外食チェーン・飲食店の運営そのもの(発注・シフト・メニュー・電話予約・口コミ対応)に絞って、実在する導入事例とすぐ使えるプロンプト例を整理する。

## 仕組み・背景

外食業でAI活用が広がっている背景は主に3つ。

1. **人手不足の深刻化**: 電話予約対応・発注業務・シフト作成など、店長やスタッフの時間を奪う定型業務が多く、限られた人員をピーク時の接客に振り向けたいニーズが強い
2. **食品ロス・欠品のトレードオフ**: 外食産業全体の食品ロスは年間で数百万トン規模とされ、個店レベルでも廃棄ロスが売上の数%に達するとされる。天候・曜日・イベントによる需要変動を人の勘だけで読み切るのは難しく、データに基づく需要予測へのニーズが強い([折兼ラボ「AIとDXが飲食店・外食産業を変える」](https://www.orikane.co.jp/orikanelab/35101/))
3. **インバウンド需要の急増**: 2025年の訪日外国人数は4,268万人と過去最高を更新しており、多言語メニュー・多言語接客への対応が売上機会に直結するようになっている

技術的には、(1)POSデータ・気象データなどを学習させた需要予測AI(食品ロス削減・発注最適化・人員配置)、(2)音声対話型の生成AIによる電話予約自動応答、(3)ChatGPT・Claude・Geminiなど汎用チャットAIによるメニュー説明文・SNS投稿文・口コミ返信のドラフト作成、という3つの型で普及が進んでいる。前者2つは専用SaaS・ベンダー主導、後者は店舗・チェーンの現場担当者が汎用チャットAIを直接使うケースが多い。

## 使いどころ・使い分け

| 業務 | 主な用途 | 向いているツールの型 |
|---|---|---|
| 需要予測に基づく発注量算出 | 気象・POSデータから発注量・仕込み量を予測しレポート化 | 需要予測特化AI(富士通AI需要予測サービスなど)+ POSデータ連携 |
| シフト作成・人員配置 | 希望シフト・需要予測を踏まえたシフト表のたたき台作成 | AIシフト管理SaaS(需要予測連携型) |
| 電話予約・問い合わせ対応 | 予約受付・変更・キャンセル、順番待ち管理の自動応答 | 音声対話型生成AI(AI Shift、IVRy、トレタ予約番など) |
| メニュー開発・説明文作成 | 季節メニューのアイデア出し、原価計算、メニュー説明文生成 | 汎用チャットAI(ChatGPT・Claude・Geminiなど) |
| 多言語メニュー・接客マニュアル | 訪日外国人向けメニュー翻訳、外国語接客FAQのたたき台 | 汎用チャットAI + 翻訳特化アプリ(Payke等)の併用 |
| 口コミ・レビュー返信 | Googleマップ・食べログの口コミへの返信文ドラフト | 汎用チャットAI、または口コミ管理SaaS(Gyro-n等) |
| SNS販促文・投稿文 | Instagram・Xの投稿文、ハッシュタグ、キャンペーン文面 | 汎用チャットAI + SNS運用ツール(Canva、Ocoyaなど) |

判断基準:
- **食品衛生・安全管理に関わる情報**(アレルギー表示、賞味期限、衛生管理手順)→ AIは下書き・整理までとし、最終確認は必ず有資格者・現場責任者が行う
- **数値に基づく意思決定**(発注量・人員配置・価格)→ AIはレポート・示唆出しまで、最終判断は店長・本部担当者が行う
- **定型的でリスクの小さいやり取り**(予約受付、館内・店内案内、口コミへの一般的な返信)→ AI自動応答をフロントに出してよい

## 実務での使い方

### 事例1: 電話予約対応のAI音声エージェント

- 「焼肉きんぐ」を展開する物語コーポレーションは、2026年2月にAI Shift社の生成AIエージェント「AI Worker VoiceAgent」を全国約230店舗に導入し、月間約15万件にのぼる電話予約対応を無人化した。「順番待ち」「翌日以降の予約」といった同ブランド特有の複雑な予約体系にも対話形式で対応し、予約管理システム「EPARK」と連携して自動処理する([PR TIMES/AI Shift](https://prtimes.jp/main/html/rd/p/000000203.000055962.html)、[IoT NEWS](https://iotnews.jp/digital-transformation/271578/))
- リクルートの予約管理アプリ「レストランボード」は、対話型音声AI SaaS「IVRy」と連携し、2024年10月から電話予約・変更・キャンセルに24時間対応する機能の提供を開始している([リクルート プレスリリース](https://www.recruit.co.jp/newsroom/pressrelease/2024/1008_14787.html))
- 「トレタ予約番」導入店舗では、1時間あたりの予約対応件数が10件から13件に増加し、予約数が3割アップ。導入初月には全予約(約800件)のうち約23%(約180件)をAIが受け付けた事例が報告されている([トレタ予約番](https://toreta.in/toreta-yoyakuban/))

いずれも「予約の受付・変更・キャンセル」という定型かつ失敗時の被害が小さい業務にAIを任せ、アレルギー対応や特別な要望が出た場合のみ店舗スタッフに転送する設計が共通している。

### 事例2: 需要予測に基づく発注量算出・食品ロス削減

- トリドールホールディングスは、2023年2月に富士通の「AI需要予測サービス」を「丸亀製麺」の国内全823店舗に採用した。気象データとPOSデータをもとに店舗ごとの日別・時間帯別の客数や販売数を高精度に予測し、スタッフの適正配置、発注業務・うどんの仕込み量の最適化、空調などの適正稼働を実現。食品ロス削減や店舗運営の効率化、エネルギーマネジメントにつなげている([富士通 プレスリリース](https://info.archives.global.fujitsu/jp/news/2023/02/2.html)、[日本経済新聞](https://www.nikkei.com/article/DGXZRSP648618_S3A200C2000000/)、[EnterpriseZine](https://enterprisezine.jp/news/detail/17301))
- 回転寿司チェーンのスシロー(あきんどスシロー)は、2002年からすべての寿司皿にICタグを付け、「どのネタが、どのテーブルで、いつ取られたか」という喫食データをリアルタイムに収集。混雑状況や着席からの経過時間も加味し、1分後・15分後の需要をAIで予測してレーンに流すネタと量を制御することで、メニューの廃棄率を75%削減しながら原価率50%を維持している([アシスト 導入事例](https://www.ashisuto.co.jp/case/industry/service/1195255_1563.html)、[AIsmiley](https://aismiley.co.jp/ai_news/case-study-of-demand-forecasting-ai-to-reduce-food-waste/))
- すき家・吉野家など大手牛丼チェーンでも、売上データと気象情報を組み合わせたAI需要予測による仕入れ量の調整や、在庫管理AIによる廃棄ロス削減・発注業務の効率化が報告されている([折兼ラボ](https://www.orikane.co.jp/orikanelab/35101/))

**コピペで使える発注量レポート作成プロンプト例**(需要予測AIやPOSデータの数値を人がまとめ、経営会議・本部向けレポートの文章化を汎用チャットAIに任せる想定):

```
あなたは飲食チェーンの店舗運営担当者です。以下のデータをもとに、
来週の発注量提案レポートを作成してください。最終的な発注判断は
店長が行うため、あなたの役割は「根拠を整理して提案すること」です。

# 入力データ
- 過去4週間の曜日別・時間帯別の客数実績: (ここに数値を貼り付け)
- 来週の天気予報: (例: 月・火は雨、週末は晴れで気温上昇)
- 近隣イベント情報: (例: 土曜日に近隣で花火大会、来客増が見込まれる)
- 主要食材の現在庫と賞味期限: (ここに数値を貼り付け)

# 出力形式
- 曜日ごとに「予測客数」「推奨発注量(通常比+/-%)」「根拠」を表形式で
- 特に発注量を平常より増減させる日は、その理由を1〜2行で明記
- レポートの末尾に「本提案は目安であり、最終発注量は店舗の在庫・
  廃棄実績を踏まえて店長が決定してください」という一文を必ず入れる
```

### 事例3: シフト作成・人員配置のたたき台作成

AIシフト管理ツールは、従業員の希望勤務日・スキル・労働基準法上の制約と、POSデータに基づく時間帯別の来客予測を組み合わせてシフト表のたたき台を自動作成する。シフト作成の工数を90%以上削減できたとする事例や、需要予測と連動させることで月間人件費を5〜10%削減できた事例が報告されている([はたLuck](https://hataluck.jp/column/shift/shift-restaurant-ai/)、[renue](https://renue.co.jp/posts/ai-shift-management-auto-scheduling-optimization-guide-2026))。
重要なのは、これらのツールが出すのはあくまで「たたき台」であり、急な欠勤対応や従業員間の相性・不満といった機微な調整は店長が最終判断するという運用が前提になっている点。

### 事例4: メニュー開発・メニュー説明文の生成

生成AIにコンセプト(季節・ターゲット層・調理負荷)を伝えると、レシピ案・調理方法・原価計算・メニュー説明文までを一度に生成でき、対話しながら店舗の実情に合わせて調整できる。都内のカジュアルイタリアンでは、「春の旬野菜」「調理負荷低め」「女性受けするビジュアル」という条件を入力して限定メニューを開発し、売上が2割上昇した事例が報告されている([飲食AIナビ](https://inshokuai.jp/ai-recipe-creation-tools/)、[STOREPADマガジン](https://storepad.jp/magazine/LVTCBLlG))。

**コピペで使える季節メニュー開発プロンプト例**:

```
あなたは(業態: 例 居酒屋)のメニュー開発担当です。以下の条件で、
季節限定メニューを3案考えてください。

# 条件
- 季節・時期: (例: 8月、真夏の暑気払いシーズン)
- ターゲット客層: (例: 20〜30代の女性グループ)
- 原価率の上限: 30%
- 主要な仕入れ食材(在庫を優先消化したいもの): (例: なす、みょうが)
- 調理負荷: 既存メンバーで調理可能な範囲(新規調理器具の追加なし)

# 各案について出力してほしい内容
1. メニュー名(キャッチーで写真映えする名前)
2. 簡単な調理手順(3〜5行)
3. 想定原価と、原価率30%を満たす販売価格の目安
4. メニュー説明文(お品書き・SNS投稿にそのまま使える、80文字程度)

# 注意
- 実際の仕入れ価格は店舗によって異なるため、原価はあくまで目安と
  明記してください
- アレルギー表示が必要な食材(卵・小麦・そば・落花生・えび・かになど)を
  使う場合は、その旨を必ず明記してください
```

### 事例5: 多言語メニュー・口コミ返信・SNS販促文

- **多言語メニュー**: 生成AIは単なる直訳ではなく、「お通し」を「席についた人全員に提供される、少額の料金が含まれる前菜」のように文脈を補って説明できる点が強み。QRコードで多言語表示するPaykeのような専用アプリと、独自メニューの説明を膨らませる生成AIを併用する店が増えている([Uravation](https://uravation.com/media/ai-multilingual-inbound-service-2026/))
- **口コミ返信**: 感情的になりやすい低評価レビューへの返信も、生成AIに下書きさせることで冷静で丁寧なトーンを保ちやすい。ただしGoogleは定型文的な返信をパターン認識で検出する傾向があるため、「客が書いた内容に触れる一言」を必ず人が手直しで加えることが実務のコツとされる([Qiita](https://qiita.com/menumenu/items/ab9850506c4ca5b7985b))
- **SNS販促文**: 都内のラーメン店では、ChatGPTとMeta Business Suiteを組み合わせ、週1回30分で1週間分のInstagram投稿文をまとめて作成する運用に切り替え、1投稿あたりの準備時間を10分以下に短縮した事例が報告されている([@DIME](https://dime.jp/genre/2017986/)、文章生成・推敲の考え方は[文章作成・編集の実務活用](../part11-business-practice/ai-writing-and-editing.md)も参照)

**コピペで使える多言語メニュー説明文プロンプト例**:

```
あなたは日本の飲食店のメニュー翻訳・説明担当です。以下の料理名を、
英語・繁体字中国語・韓国語の3言語に翻訳し、外国人観光客にも
伝わるよう一言説明を添えてください。

# 料理名と簡単な説明(日本語)
(例: お通し/席料込みで最初に出る小鉢。内容は日替わり)
(例: だし巻き玉子/出汁をたっぷり含ませた甘めの卵焼き)

# 出力形式
言語ごとに「料理名の翻訳」「1〜2文の説明(食材・味の特徴・
アレルギー物質があれば明記)」を出力してください。
価格・提供時間などの数値情報は翻訳せず、元の表記のまま残してください。
```

**コピペで使える口コミ返信プロンプト例**:

```
あなたは飲食店「(店名)」のスタッフとして、口コミサイトに投稿された
レビューへの返信文を作成します。

# 対応方針
- ポジティブな口コミ: 具体的に触れられた点(料理名・接客・雰囲気など)に
  お礼を述べ、再訪を促す一言を添える
- ネガティブな口コミ: まず謝罪、次に事実確認できる範囲での状況説明、
  改善への取り組みを一言添える(言い訳・反論・返金の即答はしない)
- 返信は120〜200文字程度、日本語、丁寧だが定型文っぽくならないよう
  口コミ本文の具体的な内容に必ず触れる

# 入力する口コミ
「(ここに実際の口コミ本文を貼り付け)」

# 出力形式
返信文のみを出力してください。前置きや解説は不要です。
```

## 注意点・よくある誤解

- **食品衛生・安全管理はAIに最終判断させない**: アレルギー表示、消費期限・賞味期限の管理、食中毒リスクに関わる判断は、生成AIの提案を鵜呑みにせず、必ず有資格者・現場責任者が最終確認する。メニュー説明文にアレルギー物質の記載漏れがあると重大事故につながる
- **需要予測AIは「導入して終わり」では効果が出ない**: 丸亀製麺・スシローの事例はいずれもPOSデータや喫食データを長年蓄積した上でAIを活用しており、データ基盤が薄い状態でAIだけ導入しても精度は出にくい
- **発注・シフト・価格の最終決定はAI任せにしない**: AIはレポート作成・たたき台作成までに留め、在庫状況や従業員の事情など現場でしか分からない情報を踏まえた最終判断は店長・本部担当者が行う
- **口コミ返信はテンプレ化しすぎない**: 定型文をそのまま貼り付けると、口コミサイト側にパターンとして検出され評価が下がる場合がある。AIが作った下書きに「その口コミ特有の内容」への言及を必ず人が加える
- **多言語対応は「翻訳の正確さ」だけでなく文化的な自然さも確認する**: 機械的に正しくても不自然・失礼な表現になることがあるため、可能であればネイティブスタッフのチェックや逆翻訳で確認する

## 最初の一歩

直近で来た口コミ(または想定の口コミ文)を1件用意し、上記の「口コミ返信プロンプト例」にそのまま貼り付けてAIにドラフトを作らせてみる。出てきた文面を店長が3分以内でチェック・修正できるかを確認するところから始めるとよい。
