# GPTsのナレッジファイル活用法

## これは何か

ナレッジ(Knowledge)は、GPTs(カスタムGPT)にPDFや社内マニュアルなどの独自ファイルをアップロードし、そこに書かれた内容を根拠にして回答させる機能である。指示(Instructions)欄に全文を貼り付けるには長すぎる社内規程・製品マニュアル・FAQ集などを、質問のたびに必要な部分だけ引っ張り出して参照させたいときに使う。この機能がないと、GPTは一般知識だけで回答するしかなく、社内独自のルールや最新の製品情報には対応できない。

## 仕組み・背景

ナレッジファイルをアップロードすると、GPTsはファイル内容をそのまま一度に読み込むわけではなく、質問内容に関連しそうな箇所だけを検索して回答に利用する。これはRAG(Retrieval Augmented Generation、検索拡張生成。質問に関連する文書の断片を検索し、それを踏まえて回答を生成する仕組み)と同様の仕組みで動いている。そのため「ファイルのどこに何が書いてあるか」をAIが的確に検索できるかどうかが、回答精度を大きく左右する(検索・抽出の技術的な詳細は「RAGの仕組み」のページを参照)。

なお、CSV・Excelなどの表形式ファイルについては、GPTs側の「Code Interpreter & Data Analysis」(Pythonコードを実行してデータ集計やグラフ作成を行う機能)がオンになっている場合、検索ではなくPythonコードを使った集計・計算処理が行われることがある。オフの場合は他のファイルと同様にテキストとして検索対象になる。

## 使いどころ・使い分け

| やりたいこと | 向いている方法 |
|---|---|
| 短い前提・キャラクター設定を常に伝えたい | 指示(Instructions)欄に直接書く |
| 数十ページの規程・マニュアル・FAQを参照させたい | ナレッジファイルとしてアップロード |
| 数値データを集計・グラフ化させたい | ナレッジ+Code Interpreter & Data Analysisをオンにする |
| 最新のWeb情報を都度取得させたい | ナレッジではなくWeb検索(ブラウジング)機能を使う |
| 社外システムのデータをリアルタイムに参照させたい | ナレッジではなくActions(外部API連携)を使う |

ナレッジは「静的な文書」を参照させるのに向いており、更新頻度が高い情報や外部システムとの連携が必要な場合は、Actionsなど他の手段と使い分ける。

## 実務での使い方

### アップロード手順(2026年7月時点の目安)

1. ChatGPT(Web版)にログインし、左サイドバーの「GPTを探す」から対象のGPTを開くか、右上の「＋作成する」で新規GPTのGPT Builderを開く(既存GPTの場合は「マイGPT」から編集したいGPTの鉛筆アイコンを選択)
2. 画面上部の「Configure」タブを選択する
3. 「Knowledge」欄の「ファイルをアップロード」ボタンをクリックし、端末内のファイルを選択する(ドラッグ&ドロップも可)
4. 数値データの集計・グラフ化もさせたい場合は、下部の「Capabilities」で「Code Interpreter & Data Analysis」をオンにする
5. 画面右上の「保存」をクリックして公開範囲を選ぶ(自分のみ/リンクを知っている人のみ/誰でも)
6. 保存後、プレビュー画面で実際に質問を投げ、ナレッジの内容を根拠に回答できているか確認する
7. ファイルを削除・差し替えたい場合は、「Knowledge」欄に表示されたファイル名にカーソルを合わせ、×アイコンから削除してから再アップロードする

### 対応ファイル形式と上限(2026年7月時点)

| 項目 | 内容 |
|---|---|
| 添付できるファイル数 | 1つのGPTにつき最大20ファイル |
| 1ファイルあたりの最大サイズ | 512MB |
| テキスト・文書ファイルのトークン上限 | 1ファイルあたり最大200万トークン |
| CSV・表計算ファイルの実務上の上限 | 行数・列数によるが、目安として数十MB程度を超えると処理が不安定になりやすい |
| 対応形式の例 | PDF、TXT、DOCX、PPTX、CSV、TSV、XLSX/XLS など主要な文書・表計算・コードファイル |
| 画像や一部形式の扱い | Code Interpreter & Data Analysisをオンにしないと使えない形式がある |

※ OpenAIのヘルプ記事間でファイル数上限の記載(10件/20件)に食い違いが見られるため、実運用では「20ファイルまで」を上限の目安としつつ、実際にアップロードして反映されるか都度確認するのが安全である。

### 精度を上げるコツ

- **1トピック1ファイルに分割する**: 巨大な1ファイルに全情報を詰め込むより、規程・FAQ・製品情報などテーマごとにファイルを分けたほうが、関連箇所の検索精度が上がる
- **Q&A形式・見出し+要点セットで書く**: 「見出し(質問・項目名)→本文(回答・要点)」の構造にすると、検索でヒットしたときに文脈が伝わりやすく、回答の一貫性が上がる
- **複雑なレイアウトのPDFは避ける**: 多段組みや図表中心のPDF、スキャン画像PDFはテキスト抽出に失敗しやすい。可能であればテキスト中心のPDF・Word・Markdown・テキストファイルに変換してから渡す
- **目次・免責事項・装飾的な前書きは削る**: 検索でヒットしても回答の根拠にならない「ノイズ」になりやすいため、本文に関係ない定型文は事前に取り除く
- **ファイルサイズは必要最小限にする**: 使わない情報まで含めると検索対象が広がりすぎて、関係の薄い箇所がヒットしやすくなる。関連するデータだけに絞り込む
- **アップロード後は必ずプレビューでテストする**: 実際に想定質問を投げてみて、期待したファイルの内容を根拠に回答しているかを確認し、外れている場合はファイルの構成を見直す

### 他ツールでの類似機能

| 概念 | ChatGPT(GPTs) | Gemini(Gem) | Microsoft 365 Copilot |
|---|---|---|---|
| 独自ファイル参照機能 | ナレッジ(Knowledge) | Gemの「知識」ファイル添付 | エージェントビルダーの「ナレッジ」ソース(SharePoint等) |

## 注意点・よくある誤解

- **アップロードした全文をAIが常に読んでいるわけではない**: 質問と関連しそうな断片だけを検索して使うため、ファイル全体を要約させるような使い方には向かない(全文要約はファイルをその場の会話に添付する方が適している)
- **ナレッジファイルは完全な機密性を保証しない**: Code Interpreter & Data Analysisがオンになっていると、ユーザーがコード実行機能経由で元ファイルをダウンロードできてしまう可能性がある。機密情報を含むファイルを扱う場合は、Code Interpreterをオフにするか、公開範囲を「自分のみ」「リンクを知っている人のみ」に限定する
- **CSV・Excelは挙動が変わりやすい**: Code Interpreterのオン/オフで「テキスト検索」か「Pythonでの集計」かが切り替わるため、意図した挙動と異なる場合はまずこのトグルを確認する
- **ファイル数・サイズの上限は変更されやすい**: OpenAIのヘルプ記事間でも数値の食い違いが見られるため、大量のファイルを扱う予定がある場合は事前に少数でテストしてから本運用に入る

## 最初の一歩

自分がよく参照する社内マニュアルやFAQを1つ選び、目次や前書きを削った本文だけのテキストファイルにしてGPTのナレッジにアップロードし、実際の質問を投げて回答の根拠が正しいか確認してみる。
