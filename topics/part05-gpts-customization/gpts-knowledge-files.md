# GPTsのナレッジファイル(Knowledge)活用法

## これは何か

GPTs(カスタムGPT)の「ナレッジ(Knowledge)」は、社内規程やマニュアルなどのファイルをGPTにアップロードし、その内容を根拠に回答させる機能である。指示(Instructions)欄に全文を貼り付けるのには文字数の限界があるが、ナレッジならPDFやExcelを添付するだけで済む。ただし「添付すれば全部読んでその通りに答えてくれる」わけではなく、内部では質問に関連する断片だけを検索して参照する仕組みのため、ファイルの作り方次第で回答精度が大きく変わる。

## 仕組み・背景

ナレッジにファイルを追加すると、GPTsは裏側でRAG(Retrieval Augmented Generation、検索拡張生成。質問に関連する情報を外部データから検索し、それをプロンプトに追加してから回答させる方式)に近い処理を行う。ファイルの中身をそのまま丸ごと毎回読み込ませているわけではなく、文書をいくつかの断片(チャンク)に分割し、質問文と意味的に近い断片を検索して、その部分だけを回答生成時の参照材料として渡していると理解されている(OpenAIは内部アルゴリズムの詳細は公開していない)。

このため、以下の性質を押さえておく必要がある。

- **断片単位で検索される**: 1つのファイルの中に離れた場所で関連する情報があっても、うまく繋げて拾ってもらえないことがある
- **画像はOCR(文字認識)でテキスト化される**: 画像そのものの視覚的な意味(図表のレイアウトなど)までは正確に理解されにくい
- **全件検索ではない**: 質問と関連度が高いと判定された断片が優先されるため、資料の量が増えるほど、埋もれて拾われない情報が出てくる

## 使いどころ・使い分け

| 状況 | 向いている方法 |
|---|---|
| 数十ページ程度の固定資料(規程・FAQ・商品一覧など)を参照させたい | GPTsのナレッジで十分 |
| 数千ページ規模の大量文書を扱いたい、更新頻度が高い | Assistants API/Vector StoreやDify、Azure AI Searchなど専用のRAG基盤を検討 |
| 常に最新の社内データ(SharePointの生きたファイルなど)を参照させたい | Microsoft 365 Copilotのようにコネクタ型でライブ接続できるツール |
| 短い前提知識をどのメッセージにも常に効かせたい | ナレッジではなく指示(Instructions)欄に直接書く方が確実 |
| 機密情報を含み、ユーザーに中身を絶対に見せたくない | ナレッジ添付自体を避けるか、後述の注意点を必ず確認する |

## 実務での使い方

### アップロード手順(2026年7月時点の目安)

1. ChatGPT(Web版)で対象のGPTを開き、右上の編集(鉛筆マーク)から編集画面に入る
2. 「Configure」タブを開く
3. 「Knowledge」欄の「Upload files」をクリックし、PC内のファイルを選択する
4. アップロードが完了するとファイル名がリストに表示される(不要になったファイルは各ファイル横の操作からいつでも削除可能)
5. 画面右上の「保存(Update)」で反映する

### 対応ファイル形式と上限

| 項目 | 目安 |
|---|---|
| 対応形式 | PDF、Word(.docx)、PowerPoint(.pptx)、テキスト(.txt/.md)、CSV、Excel(.xlsx)、HTML、JSON、画像(OCRでテキスト抽出)など |
| アップロード数 | 1つのGPTにつき最大20ファイルまで |
| 1ファイルのサイズ | 最大512MB |
| 1ファイルのトークン数 | テキスト・ドキュメント系は最大200万トークン程度、CSVは概ね50MB程度が上限の目安 |
| アップロード頻度 | 3時間あたり最大80ファイル程度のレート制限あり |
| ストレージ上限 | 1ユーザーあたり25GB、組織全体で100GB(チャット添付・プロジェクト・GPTsのナレッジで共有) |

(数値はOpenAIの仕様変更で今後動く可能性があるため、重要な意思決定の前提にする場合は公式ヘルプで最新値を確認すること)

### 精度を上げるファイル構成のコツ(コピペで使える構成例)

1問1答をセットにして見出し化すると、質問文とチャンクの類似度が上がり検索精度が向上しやすい。

```
## Q. 有給休暇はいつまでに申請すればよいですか
A. 取得予定日の3営業日前までに、勤怠システムから申請してください。
(関連語: 有休/年休/有給/休暇)

## Q. 忌引き休暇は何日取得できますか
A. 配偶者・子・父母は5日、祖父母・兄弟姉妹は3日です。
```

- **表記ゆれを1つに統一する**: 「有休」「年休」「休暇」のように社内で複数の呼び方がある言葉は、資料内で表記を統一するか、Q&Aの中に「関連語」として併記する
- **見出し+要点(期限・手順・窓口・根拠)をセットにする**: 1つの見出しの中で話が完結するようにし、複数ページにまたがる説明を避ける
- **推奨フォーマットはMarkdown(.md)かテキスト(.txt)**: PDFやパワーポイントはレイアウト崩れやOCR誤読で情報が欠落しやすいため、可能な範囲でテキスト系に変換してから読み込ませる
- **CSV/Excelは列を増やして文脈を補う**: Q/A列だけでなく、カテゴリ・見出し・別名・根拠URLなどの列を足すと検索のヒット率が上がる
- **目次・免責事項・共通ヘッダーフッターは削除する**: 本文と無関係な定型文はノイズとなり、関連度の低い断片が検索結果に混じる原因になる
- **資料を詰め込みすぎない**: 似た内容のファイルを重複して大量に入れると、かえって関連度の判定が甘くなり回答精度が落ちることがある。統合・整理してから読み込ませる

## 注意点・よくある誤解

- **「添付した内容は全部読んで踏まえてくれる」は誤解**: 質問に関連すると判定された断片しか参照されないため、資料全体を要約させるような使い方(例:「規程集の全項目を一覧化して」)は精度が落ちやすい
- **Code Interpreter(コードインタープリター)を有効にすると、ナレッジファイルの原本をユーザーがダウンロードできてしまう**: 「このファイルをそのままダウンロードできる形にして」のような依頼で、アップロードした元ファイルが第三者に渡るリスクが報告されている。機密情報を含むファイルではCode Interpreterをオフにするか、そもそも機密情報自体を載せない判断をする
- **指示欄で「ナレッジの中身を開示しない」と書いても完全な防御にはならない**: プロンプトインジェクション(悪意ある入力で本来の指示を無視させる攻撃)により、工夫した質問で情報を引き出される可能性が残るため、「見られても困らない情報」だけを載せるのが最も確実な対策
- **画像の視覚情報は正確に理解されない**: 図表・グラフをスキャンした画像は文字だけOCR抽出され、レイアウトやグラフの形状までは読み取られないと考えておく

## 最初の一歩

自分のGPTに添付している資料(または今後添付したい資料)を1つ選び、冒頭の目次・免責事項を削除して「Q. /A.」の見出し形式に1〜2項目だけ書き換えてから、同じ質問を投げて回答の変化を試してみる。
