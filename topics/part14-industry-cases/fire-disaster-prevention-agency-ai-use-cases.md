# 消防・防災機関における生成AI活用事例

## これは何か

消防本部・消防庁・自治体の防災部局は、人手不足が進む一方で119番通報件数や救急出動件数は高止まりし、「現場に出ている職員が事務作業に追われる」「ベテランの経験知(通報内容からの緊急度判断、火災原因の見極め)が若手に継承されにくい」という慢性課題を抱えている。しかも判断ミスが即座に人命に関わるという、他の公共分野以上に「誤りの許容度が低い」領域である。本ページは、[公共・自治体における生成AI活用事例](public-sector-ai-use-cases.md)(住民対応・行政文書作成など自治体業務全般を扱う総論)を土台に、消防・防災機関に固有の領域――119番通報の受理支援、火災調査・救急報告書の作成支援、避難所運営・被災者支援業務、気象データと連携した災害予測――に絞って実例を整理する事例カタログである。

## 仕組み・背景

消防・防災分野のAI活用は、性質の異なる3つの層に分けて理解すると全体像をつかみやすい。

1. **通信指令(119番receiving)を支援するAI**: 音声認識で通報内容をリアルタイムにテキスト化し、生成AIが会話から傷病者の状態・症状を抽出して緊急度判定画面の該当項目を自動選択する、あるいは通報内容を要約して指令員・統括者に提案する。あくまで「入力支援・判断材料の提示」であり、最終的な緊急度判定・出動指令の決定権は人間の指令員に残る設計が基本になっている。
2. **記録・調査業務(火災調査報告書・救急報告書)を支援する生成AI**: 火災現場写真から状況説明文(写真書見)の下書きを生成する画像認識AI、医師の引き渡し書からOCR(光学文字認識)で患者情報を抽出するAI、過去の火災データベースを学習させた類似事例検索など、事後の文書作成を効率化する用途。
3. **避難所運営・被災者支援業務のAI活用**: 罹災証明の発行、避難所の入退所管理、被災者からの問い合わせ対応(チャットボット)など、災害発生後の自治体・防災部局側の事務負担を軽減する用途。個人情報(要配慮者情報を含む)を扱うため、平時以上に慎重な運用ルールが求められる。

これらとは別に、気象データ×AIによる災害予測(河川水位予測・土砂災害危険度判定・SNS解析によるリアルタイム被害把握など)を手がける専業ベンダーが存在するが、その企業一覧・製品比較は[気象・防災AI企業一覧](../part16-japan-ai-companies/weather-disaster-prevention-ai-companies-japan.md)(Part16)に集約してあるため、本ページでは重複説明を避け、消防・防災機関側が「どう連携して使うか」という業務目線でのみ触れる。

**行政側の体制整備**: 総務省消防庁は2026年4月、消防防災分野のDX・新技術活用を推進する「技術戦略室」を大臣官房に新設した。2026年1月20日公表の「令和7年版 消防白書」でも「消防防災分野におけるDX・新技術活用の推進」が特集の1つとして取り上げられ、AIによる救急需要予測・救急隊の最適配置に関する研究について、令和7年度(2025年度)時点で12消防本部が導入に向けた検討を、うち4消防本部が実証研究を行っていると報告されている([総務省消防庁「令和7年版消防白書」](https://www.fdma.go.jp/publication/hakusho/r7/69377.html))。

## 使いどころ・使い分け

| 業務 | 向いているAIの使い方 | 人の判断が最終決定権を持つ理由 |
|---|---|---|
| 119番通報の緊急度判定 | 生成AI・音声認識による「入力支援・提案」まで | 誤判定(過小評価)が救急隊の出動遅れ・現場到着遅延に直結する。2026年時点の実証でも人手入力との一致率は約85%にとどまり、残り約15%は人による確認が前提 |
| 火災現場写真の状況説明文(写真書見)下書き | 生成AI・画像認識AIによる下書き生成 | 火災原因の特定は消防法第31条に基づく法的な調査であり、事実誤認は原因究明・保険や責任追及に影響する。調査員が現地の記憶と照合して修正する運用が前提 |
| 救急搬送記録・引き渡し書の転記 | OCR+生成AIによる情報抽出 | 患者名・診断名などの医療情報を誤変換すると重大な事故につながるため、最終確認は必須 |
| 避難所の入退所管理・罹災証明の事務処理 | 生成AI・自動化ツールによる事務効率化 | 支援対象者の特定・給付額の算定など、公平性・説明責任が求められる行政処分に関わる |
| 被災者からの問い合わせ対応(支援制度検索・チャットボット) | 生成AIチャットボット(FAQ・制度検索) | 制度の適用要件を誤案内すると被災者の不利益に直結するため、正式な申請可否の最終回答は職員が行う |
| 避難勧告・避難指示などの安全情報の確定・発信 | 人が判断・発信し、AIは下書き作成のみに留める | 生成AIだけで避難情報を確定・自動発信することは前提として避けるべきとされている(後述) |
| 気象データに基づく河川水位・土砂災害の予測 | 専業ベンダーの予測AIを情報源として活用 | 予測はあくまで「早期の警戒・準備」のための参考情報であり、避難判断は自治体・住民が行う |

## 実務での使い方

### 代表事例

**1. 119番通報の緊急度判定入力支援(NEC×横浜市消防局)**
NECは2026年3月、生成AIを使って119番通報の会話音声から傷病者の状態・症状を抽出し、横浜市が2008年から運用する「横浜方式救急事後検証システム」の緊急度判定プロトコルに沿って該当項目を自動選択するプロトタイプを発表した。横浜市消防局の協力で検証した結果、人が入力した結果との一致率は約85%だった。NECは2026年度中に横浜市消防局での実装、および同プロトコルを採用する全国の消防本部向けにAI入力支援システムを開発・提供する計画を示している([NEC プレスリリース](https://jpn.nec.com/press/202603/20260312_03.html))。

**2. 119番通報AI活用の共同実証実験(株式会社Quick×東京消防庁)**
東京消防庁は「INNOVATION PROJECT」の枠組みで、株式会社Quickなど複数の企業と119番通報の共同実証実験を実施している。2025年12月から2026年3月にかけて、AIによる通報内容の自動分析・重要情報抽出・緊急度判定、受理担当者と統括者へのリアルタイム支援を検証するもので、夏季・冬季など通報が集中する時期に「つながりにくい」状況が生じている課題を背景としている([株式会社Quick プレスリリース](https://prtimes.jp/main/html/rd/p/000000002.000156902.html))。

**3. 政府の中期方針: 119番通報へのAI自動応答(2030年目標)**
政府は消防の119番通報について、2030年までにAIへの切り替えを目指す計画案をまとめた。AIが自動で応答して通報内容を分析し、対応にあたる指令員に提案する仕組みで、深刻な人手不足を背景に救急業務の効率化を狙う。消防はこの計画で対象とされる「バーティカルAI(領域特化型AI)」20分野の1つに位置付けられている([日本経済新聞](https://www.nikkei.com/article/DGXZQOUA096YE0Z00C26A7000000/))。

**4. 火災調査・救急報告書作成のAI活用検討(都留市消防本部)**
山梨県都留市消防本部では、年間1,600件超・1日4〜5件の救急出動に対応する中で、医師の引き渡し書からバイタルデータ・患者名・診断名などをOCRで自動抽出する仕組みや、火災現場写真から状況説明文(写真書見)の下書きを生成する画像認識AIの活用可能性が生成AI体験ワークショップで検討されている。実況見分調書・調査書の作成に約1か月かかるケースもあるとされ、総務省消防庁が過去に蓄積した火災データを学習させて類似事例を検索する構想も含まれる([生成AI体験ワークショップ](https://workshop.c-table.co.jp/columns/ai20251212-1))。

**5. 火災調査業務の効率化に向けたICT活用(総務省消防庁「火災調査の業務効率化に向けた検討部会」)**
消防庁は「火災調査の業務効率化に向けた検討部会」で、スマートグラス(装着型カメラでハンズフリー記録)、360度カメラ、寸法計測ソフト、図面作成ソフト、写真整理ソフト、音声認識ソフトなど各種ICT機材の実証・検証を行い、火災原因調査(消防法第31条に基づく)・損害調査の効率化策を報告書にまとめている([総務省消防庁「火災調査の業務効率化に向けた検討部会報告書」](https://www.soumu.go.jp/main_content/000751559.pdf))。

**6. 救急隊の最適配置に向けたAI活用研究**
「令和7年版 消防白書」によれば、AIで救急需要を予測し救急隊を最適に配置する研究について、令和7年度時点で12消防本部が導入検討を、うち4消防本部が実証研究を行っている。あわせてドローンが撮影した映像を即座に地図上へ反映するシステムの開発も進められている([総務省消防庁「令和7年版消防白書」](https://www.fdma.go.jp/publication/hakusho/r7/69377.html))。

**7. 海外比較: 米国FEMA(連邦緊急事態管理庁)の生成AI活用**
米国土安全保障省(DHS)が公開する「AI活用事例一覧(AI Use Case Inventory)」によれば、FEMAは会計業務向けの生成AIチャット「OCFO Response Augmentation Suite」やコード生成支援「OCFO Code Assist GPT」、要約作成支援「Executive Summary GPT」を既に運用段階(deployed)としている。一方、被災地域向けのハザード緩和計画作成支援チャットボット「Hazard Mitigation Assistance Chatbot」はパイロット段階、個人向け支援文書の多言語翻訳支援はまだ開発前段階にある。なお、資源の乏しいコミュニティ向けのハザード緩和計画作成支援ツール「PARC(Planning Assistant for Resilient Communities)」は開発・利用が中止されている。日本の消防・防災機関がAI導入を検討する際、「どの業務は既に実運用段階まで進んでいるか」「どの業務はまだパイロットに留まっているか」という国際的な進捗の目安として参考になる([DHS AI Use Case Inventory: FEMA](https://www.dhs.gov/ai/use-case-inventory/fema))。

### プロンプト例1: 119番通報の要約・引き継ぎメモ作成(内部研修・事後検証用)

実際の通報対応では専用の指令システムが使われるが、事後検証・研修目的で「通報内容の要約メモ」を生成AIに作らせる場合のプロンプト例。個人が特定される情報は入力前に匿名化・仮名化しておく。

```
あなたは消防指令センターの事後検証を支援するアシスタントです。
以下は匿名化済みの119番通報の文字起こしです。
研修・事後検証用に、次のフォーマットで要約メモを作成してください。

# 出力フォーマット
- 通報種別: (火災/救急/その他)
- 傷病者の状態・症状(通報内容から読み取れる範囲):
- 現場の状況(場所・周辺状況):
- 緊急度に関わりそうなキーワード:
- 通報内容から読み取れない・不明な点:

# 制約
- 通報内容に書かれていないことは推測で補わず「記載なし」としてください
- 医学的な診断や緊急度の判定そのものは行わず、あくまで情報整理に留めてください

# 通報内容(匿名化済み文字起こし)
[ここに貼り付け]
```

出力はあくまで研修・振り返り用の下書きであり、実際の緊急度判定・出動指令の代替には使わない。

### プロンプト例2: 避難所の物資・人員ニーズ調査メモの下書き作成

避難所運営担当者が現場から報告を受けた内容を、本部への報告・物資要請の下書きに整形する用途。

```
あなたは自治体の防災担当者を支援するアシスタントです。
以下は避難所の運営担当者からの報告メモ(箇条書き)です。
本部への状況報告・物資要請の下書きを、次のフォーマットで作成してください。

# 出力フォーマット
- 避難所名・報告日時:
- 避難者数(概数):
- 要配慮者(高齢者・障害者・乳幼児等)の状況: ※個人が特定される情報は含めない
- 不足している物資・人員:
- 至急対応が必要な事項:
- その他共有事項:

# 制約
- 個人名・住所など特定の個人を識別できる情報は要約に含めないでください
- メモにない数値は推測せず「未確認」としてください

# 避難所からの報告メモ
[ここに貼り付け]
```

出力後は必ず防災担当の責任者が内容を確認し、要配慮者情報の取り扱いが庁内ルールに沿っているかを点検してから正式な報告・要請として使う。

## 注意点・よくある誤解

- **「入力支援」と「判断の代替」を混同しない**: NECの119番緊急度判定支援プロトタイプでも一致率は約85%であり、残り約15%は人による確認・修正が前提になっている。生成AIの提案をそのまま採用して出動判断を省略する運用は、現時点の技術水準では想定されていない。
- **誤分類(過小評価)のリスクは人命に直結する**: 緊急度を実際より低く判定してしまうと、救急隊の到着が遅れる、あるいは適切な資源(高度救命処置ができる隊)が手配されないといった事態につながりうる。AIの提案精度が高くても、指令員による最終確認のプロセスを省略しない設計・運用が必須である。
- **避難情報の確定・発信は生成AIだけに任せない**: 避難勧告・避難指示など住民の安全に直接関わる情報は、生成AIの提案をそのまま自動発信するのではなく、人が最終確認したうえで発信する運用が基本とされる。生成AIは「公開済み資料の要約」「マニュアルの検索補助」「訓練資料・報告書の下書き」といった領域に用途を絞るべきとの指摘がある([ArcHack「消防・防災における生成AIの業務活用法」](https://www.arc-hack.com/blog/fire-disaster-generative-ai/))。
- **被災者・傷病者の情報は特に機微な個人情報である**: 避難所運営・罹災証明・救急搬送記録には、身体状況や病歴、要配慮者(高齢者・障害者等)に関する情報が含まれる。内閣府は「災害時には個人情報を積極的に活用すべき」という基本姿勢を示しているが、これは「無制限に外部AIサービスへ入力してよい」という意味ではない。無料の一般消費者向け生成AIサービスにそのまま入力するのではなく、庁内の閉域環境や、入力データが学習に使われないことが確認された環境を使うべきである(詳細は[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md))。
- **火災調査の結果は法的な調査記録である**: 消防法第31条に基づく火災原因調査の記録は、保険金請求や責任追及の場面で参照されうる公的な文書である。画像認識AIが生成した状況説明文の下書きは、必ず調査員自身が現場の記憶・実測データと照合してから正式な調書に反映する。
- **ハルシネーション(もっともらしい誤り)は事務作業でも起こりうる**: 救急引き渡し書のOCR+生成AIによる情報抽出でも、読み取り誤りや存在しない情報の補完が起こりうる。患者名・診断名・時刻などの重要事実は必ず人が原本と照合する。

## 最初の一歩

まずは人命に直結しない領域から始めるとよい。過去の(個人情報を匿名化した)火災調査報告書や救急事後検証記録を1件用意し、汎用生成AI(ChatGPT・Gemini・Claude等)に「状況説明文の下書き」「要約メモ」を作らせてみて、実際の記録とどこが違うか・どこを必ず人が直す必要があるかを確認することから始めるとよい。
