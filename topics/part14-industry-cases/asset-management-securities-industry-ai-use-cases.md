# 証券・資産運用業界における生成AI活用事例

## これは何か

証券会社(野村證券・SBI証券・楽天証券・大和証券など)と資産運用会社(アセットマネジメント会社)は、「アナリストが大量の決算資料・ニュースを読み込んで調査する」「営業担当者が顧客ごとに運用提案書を作る」「コンプライアンス部門が全通話・全メールをチェックする」といった、文章の読解・要約・下書き作成が業務の中心を占める業種であり、生成AIの効果が特に出やすい。本ページは、銀行・保険を含む金融業界全般を扱う[金融・保険における生成AI活用事例](finance-insurance-ai-use-cases.md)とは切り分け、**証券会社・資産運用会社に固有の業務**――株式リサーチ・運用提案・ロボアドバイザー・営業コンプライアンス・顧客対応事務――に絞って、2026年8月時点の実例を整理する。

## 仕組み・背景

証券・資産運用業界のAI活用は、大きく3つのレイヤーで進んでいる。

1. **顧客接点レイヤー**: 投資情報チャット、ロボアドバイザー(独自アルゴリズムで自動運用するサービス)、AIオペレーターによる問い合わせ・事務手続き対応
2. **調査・運用レイヤー**: アナリストの決算分析・レポート作成を支援するAIエージェント、ファンドマネージャーの銘柄調査支援
3. **管理・コンプライアンスレイヤー**: 営業担当者の通話・面談記録のモニタリング、金融商品取引法(金商法)や自主規制ガイドラインへの適合チェック

このうちロボアドバイザーやコンプライアンス監視は、もともと機械学習(統計的にパターンを学習するAI)ベースで2010年代から存在していたが、2024年以降はここに生成AI(LLM)による要約・文章生成が組み合わさり、「数値を出す・異常を検知する」だけでなく「その根拠や提案理由を自然な文章で説明する」層が追加された。さらに2026年に入り、野村證券が「生成AIからエージェントAIへ」とトレンドが移行していると発信するなど、人が都度指示しなくても複数の作業工程(情報収集→分析→ドラフト作成)を自律的にこなす**AIエージェント**の実装が本格化している段階にある。

## 使いどころ・使い分け

| 業務 | AI活用の向き不向き | 理由 |
|---|---|---|
| 決算資料・アナリストレポートの要約 | 向く | 大量文書からの情報抽出・要約は生成AIの得意領域。ただし数値は原資料と必ず突合する |
| 運用提案書・ライフプラン説明資料のドラフト作成 | 向く(下書きのみ) | 顧客属性に応じた文章生成は速いが、最終的な推奨内容の妥当性は担当者・審査部門が確認する |
| ロボアドバイザーのポートフォリオ配分計算 | 向く(説明文の生成に限り生成AIを併用) | 配分計算自体は既存の最適化アルゴリズムが担い、生成AIは配分理由・レポートの文章化を担当する組み合わせが主流 |
| 営業通話・面談記録のコンプライアンスチェック | 向く | 全量チェックは人手では不可能な規模。異常検知の一次スクリーニングに有効 |
| 断定的な投資判断・個別銘柄の売買推奨をAIが顧客に直接答える | 向かない(要ガードレール) | 金商法第38条が禁じる「断定的判断の提供」に抵触しかねない。AIの出力はあくまで一般的情報提供に限定し、フィルタリングが必須 |
| インサイダー情報を含む未公表情報の要約・分析 | 向かない(外部AIへの入力は原則不可) | 外部の生成AIサービスに入力すると情報漏洩・インサイダー取引規制違反のリスクがある。社内クローズド環境での利用に限定する |

判断に迷う場合は、[生成AIに向く業務・向かない業務の切り分け](../part12-business-practice/ai-task-suitability.md)の基本チェックに加えて、「顧客への説明義務・適合性原則(金商法第40条、顧客の知識・経験・財産状況・投資目的に照らして不適当な勧誘をしてはならないという原則)に抵触しないか」を必ず4つ目の判断軸として加えること。

## 実務での使い方

### 1. リサーチ・アナリスト支援

決算資料や有価証券報告書の読み込み・要約はアナリスト業務で最も時間を取られる工程であり、各社が生成AI・AIエージェントの導入を進めている。

| 提供元 | サービス・機能 | 内容 |
|---|---|---|
| 野村ホールディングス | 株式ファンダメンタルズ分析AIエージェント | 東京大学との連携知見をもとに、決算説明資料等のテキストを分析し、運用プロフェッショナルのノウハウを組み込んで運用パフォーマンス向上を狙うAIエージェントを2026年3月に発表 |
| Bloomberg | AI-Powered Document Insights / BloombergGPT | 決算資料・開示文書に対して自然言語で質問し、要点を対話形式で引き出せる機能。BloombergGPTは金融データ363億トークンで学習した500億パラメータのモデルで、2億件超の文書を参照するRAG(検索拡張生成)を組み合わせている |
| FactSet | Transcript Assistant | 決算説明会の書き起こし(トランスクリプト)に対してチャット形式で質問できる機能 |

**コピペで使えるプロンプト例(決算説明資料の要約)**:

```
あなたは証券会社の株式アナリストです。以下の決算説明会資料のテキストを読み、
次の形式で要約してください。
1. 今期の売上・営業利益の実績と前年同期比(数値は原文の表記のまま引用)
2. 会社側が説明した増減要因(コスト・為替・需要動向など)
3. 通期予想の修正有無とその理由
4. 質疑応答で経営陣が慎重な言い回しをした箇所(トーンの変化に注目)
※数値の要約は必ず原文の該当箇所を引用元として明記し、憶測で数値を補完しないこと

[決算説明会資料のテキストを貼り付け]
```

出力後は必ず原資料の該当ページと数値を突き合わせる。生成AIは文章の要約は得意だが、表内の数値を読み違える・注記を見落とすことがあるため、レポートとして対外発信する前の一次ドラフトに留める。

### 2. 運用提案書・ポートフォリオ提案のドラフト作成

- **大和証券グループ × Sakana AI**: 2025年に日本マイクロソフトとAIエージェント活用に関する戦略的枠組みを締結し、パーソナライズされた資産運用ポートフォリオ提案を2026年度末から順次サービス開始する計画を公表
- **大和証券「生成AIチャット」**: 顧客向けの一般的な情報提供チャットで、2026年4月時点の平均解決率は87%
- **大和証券グループ「DAIWA LIFEPLAN生成AIチャット」**: 職域サービス利用者向けにライフプラン・資産運用の一般的な情報提供を行うチャット

営業担当者・IFA(独立系ファイナンシャルアドバイザー)が顧客ごとの提案書ドラフトを作る際は、次のように「顧客属性→ドラフト生成→人による最終確認」の順に使うのが実務的な型になる。

```
以下の顧客情報をもとに、資産運用提案書の説明文ドラフトを作成してください。
- 年齢・家族構成・投資経験・リスク許容度: [ここに入力]
- 現在の資産配分: [ここに入力]
- 提案する商品・配分案: [ここに入力(担当者が決定した内容)]

出力条件:
- 「必ず値上がりする」「元本が保証される」など断定的な表現は一切使わない
- リスク(価格変動・為替変動など)の説明を必ず配分案とセットで記載する
- 専門用語(シャープレシオ、標準偏差など)は初出で一言説明を付ける
```

**重要**: 商品の組入れ判断・最終的な推奨配分そのものをAIに決めさせるのではなく、担当者が決めた配分案を「顧客にわかりやすく説明する文章」に変換させる使い方に留める。断定的判断の提供禁止(後述)に触れないための最重要ポイント。

### 3. ロボアドバイザーの生成AI化

| サービス | 提供元 | 特徴・手数料(2026年8月時点) |
|---|---|---|
| WealthNavi | ウェルスナビ | 預かり資産1兆円超。世界約50カ国・12,000銘柄以上に分散投資し、AIが最適なリバランスタイミングを常時監視。年率1.1%(税込)の手数料 |
| THEO / THEO+ docomo | お金のデザイン | 最大11資産クラス・100本超のETFで運用。「カラーパレット機能」で「資産成長」「安定成長」「インフレヘッジ」の3目的の配分比率を調整可能 |
| SBIラップ AI投資コース | FOLIO(SBIグループ)、SBI新生銀行経由で提供 | 投資判断アルゴリズムはROBOPROと同等。投資一任手数料は運用資産額(現金部分を除く)に対し年率0.66%(税込) |

ロボアドバイザーの「AI」は元来、現代ポートフォリオ理論に基づく資産配分アルゴリズムであり、生成AI(LLM)とは別物である点に注意。2026年時点での生成AIの役割は、①運用状況・リバランス理由を顧客に説明するレポート文の自動生成、②チャット形式での問い合わせ対応、の2つが中心で、「資産配分の意思決定そのもの」はまだ既存のアルゴリズムが担う分業構造になっている。

### 4. 営業コンプライアンス・通話モニタリング

| 導入企業 | 仕組み | 概要 |
|---|---|---|
| 三菱UFJモルガン・スタンレー証券 | 日立Lumada「音声デジタルソリューション」× FRONTEO「KIBIT」 | 2021年10月から、通話音声の文字起こし→コンプライアンス・リスク箇所の抽出→モニタリング担当者への提供までを自動化。全量モニタリングにより担当者の負担を軽減 |
| 各社共通(NRI等が提供) | 音声データのコンプライアンスチェックサービス | 通話・面談記録から不適切な勧誘表現や適合性の原則に反する発言を検出し、一次スクリーニングを自動化 |

2021年頃の導入はルールベース・機械学習中心だったが、2025年以降はここに生成AIによる「該当箇所の要約」「注意すべき発言の言い換え案の提示」が重なり、モニタリング担当者が確認すべき情報量を圧縮する方向に進化している。

### 5. バックオフィス・顧客対応事務

- **大和証券のAIオペレーター**: 2024年10月に音声会話型のAIオペレーターサービスを導入し、2025年6月に24時間365日対応へ拡大、同年10月には住所変更・NISA口座開設・マイナンバー届出といった事務手続きの受付にも対応範囲を拡大した

こうした定型の顧客対応・事務手続きは、金商法上の説明義務・適合性の原則が絡む「勧誘・助言」とは切り離しやすく、生成AI・音声AIの導入が比較的進めやすい領域になっている。

### 主要ツール横断の対応(証券・資産運用業界)

| 目的 | 主なツール・サービス |
|---|---|
| 決算資料・開示文書の要約(海外株・機関投資家向け) | Bloomberg Terminal(AI-Powered Document Insights)、FactSet(Transcript Assistant) |

## 注意点・よくある誤解

- **断定的判断の提供は金商法違反になりうる**: 金融商品取引法第38条は、不確実な事項について断定的判断を提供して勧誘する行為を禁止している。生成AIが「必ず値上がりします」「元本は減りません」といった表現を出力してしまうと、担当者がそのまま顧客に伝えた場合に法令違反となるリスクがある。顧客向けに生成AIの出力を使う場合は、断定表現をフィルタリングする仕組みを必ず設ける
- **適合性の原則にも配慮が必要**: 金商法第40条は、顧客の知識・経験・財産状況・投資目的に照らして不適当な勧誘をしてはならないと定める。生成AIが顧客属性を踏まえずに一律の提案文を生成すると、この原則に抵触しかねない。プロンプトに必ず顧客属性を入力させ、それを踏まえた出力になっているかを人が確認する
- **金融庁「AIディスカッションペーパー」を踏まえた社内ルール整備が前提**: 金融庁は2025年3月に第1.0版、2026年3月に第1.1版を公表し、モデルリスク管理・説明可能性・公平性・ハルシネーション対策・個人情報保護などをAI活用の論点として整理している。今後、生成AIを「顧客への資産運用相談・コンサルティングなど本業に近い領域」で直接活用する動きが想定されるとしており、証券・資産運用会社は導入前にガバナンス体制の整備が求められる
- **未公表のインサイダー情報を外部の生成AIサービスに入力しない**: 決算前の未公表財務情報や合併・買収情報などを一般公開の生成AIチャットに入力すると、情報漏洩やインサイダー取引規制違反につながる。社内で完結するセキュアな環境(法人向け生成AI基盤)を用いる
- **ロボアドバイザーの「AI」と生成AIを混同しない**: ロボアドバイザーの資産配分計算は伝統的な最適化アルゴリズムによるものが中心で、生成AIはあくまで説明文・チャット対応を担う付随機能であることが多い。「AIが自動で儲かる配分を選んでくれる」という誤解を顧客に与えない説明を心がける
- **数値の最終確認は必ず人が行う**: 決算要約・レポートドラフトの数値は生成AIの誤読・ハルシネーションが起こりうる。対外発信前に原資料との突合を徹底する

## 最初の一歩

自社(または取引先)が使っている決算資料・アナリストレポートを1本選び、上記の要約プロンプト例を社内の法人向け生成AI環境で試し、出力された数値を原資料と突き合わせて精度を確認するところから始めるとよい。
