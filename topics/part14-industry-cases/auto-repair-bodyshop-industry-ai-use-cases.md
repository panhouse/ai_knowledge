# 自動車整備・鈑金業界における生成AI活用事例

## これは何か

街の整備工場・鈑金塗装工場・カー用品量販店の整備部門・ディーラー系サービス工場は、
**整備士の高齢化・人手不足**と**紙のマニュアル・属人的な経験に依存した診断作業**という
2つの課題を同時に抱えている。本ページは、この「整備・鈑金の現場」で生成AIがどう
使われ始めているかを、故障診断支援・損傷画像からの見積もり自動生成・
整備マニュアル検索・顧客説明文作成・部品在庫最適化・技術伝承という6つの切り口で
整理する事例カタログである。

なお、[自動車業界における生成AI活用事例](automotive-industry-ai-use-cases.md)は
**自動車メーカー・ディーラー側の視点**(車載AIアシスタント、ディーラーの商談支援、
OEM純正データを使った整備士向けTSB検索など)を扱っており、本ページとは層が異なる。
本ページは**整備・鈑金という「サービス業」としての現場業務**(工場の受付・診断・
見積もり・作業・引き渡しという一連のフロー)に焦点を当て、特定のメーカー系列に
属さない独立系整備工場・鈑金工場・量販チェーンでも導入できる汎用的な事例を中心に扱う。

## 仕組み・背景

整備・鈑金業界での生成AI活用は、大きく3つの技術要素の組み合わせでできている。

1. **画像認識AI(コンピュータビジョン)による損傷判定**: スマートフォンで撮影した
   車両の傷・凹みの写真をAIが解析し、損傷箇所・修理方法・想定工賃を自動算出する。
   これ自体は分類・検出系のAI(いわゆる「識別系AI」)であり、文章を生成する
   生成AI(LLM)そのものではないが、算出した損傷情報をもとに見積書や顧客説明文を
   自動生成する後段の工程では生成AIが使われることが多く、両者はセットで
   語られることが多い
2. **RAG(検索拡張生成、社内外の資料をAIに検索させてから回答を作らせる仕組み)による
   故障診断・マニュアル検索支援**: OBD-II診断機(車両の故障コードを読み取る機器)が
   吐き出すエラーコードや、整備士が入力した症状の説明文をもとに、サービスマニュアル・
   技術サービスブレティン(TSB)・過去の修理記録を検索し、「この症状にはこの原因の
   可能性が高い」という当たりをAIが提示する
3. **汎用生成AI(ChatGPT・Gemini等)による文章生成**: 見積もり内容や整備内容を、
   専門知識のない顧客にもわかりやすい説明文・提案文に変換する用途。汎用チャットAIで
   十分にまかなえる

背景には、国土交通省の統計等でも指摘される整備士不足・高齢化の進行と、
損害保険会社側が事故車両の損害査定を迅速化したいという思惑(査定待ちで代車費用が
かさむ、修理までのリードタイムが長いといった課題)がある。保険会社が画像認識AIによる
損害査定を先行導入したことが、結果として整備・鈑金工場側のAI活用を後押ししている
という構図も見られる。

## 使いどころ・使い分け

| 用途 | 課題 | AIの役割 | 成熟度(2026年8月時点) |
|---|---|---|---|
| 故障診断支援 | 症状の原因特定に経験と時間がかかる | 症状・エラーコードから可能性の高い原因・修理手順をAIが提示 | 欧州の大手工具・診断機メーカーが機能として組み込み始めた段階 |
| 損傷画像からの見積もり自動生成(AI鈑金見積もり) | 板金・塗装の見積もり作成は損傷部位の目視確認と工数積算に時間がかかる | 写真から損傷範囲・修理方法・概算金額を自動算出 | 保険金査定領域では実用段階、板金工場の一次見積もりとしても普及が進む |
| 整備マニュアル検索・作業手順アシスタント | 車種・年式ごとに異なる整備手順書やTSBを探すのに時間がかかる | 自然言語の質問でマニュアル・TSBを横断検索 | OEM・整備チェーン向けの専用プラットフォームが先行(詳細は自動車業界ページ参照) |
| 顧客への説明・提案文面の自動生成 | 専門用語だらけの見積もりは顧客に伝わりにくく、追加整備の提案も響きにくい | 見積もり内容をもとに平易な説明文・提案文をAIが下書き | 汎用チャットAIで即座に実践可能 |
| 部品在庫・発注の最適化 | 部品の欠品・過剰在庫が工場回転率を下げる | 過去の入出庫データから需要を予測し発注点・発注量を自動算出 | 一般的な在庫管理SaaSの一機能として提供 |
| 人手不足下での技術伝承 | ベテラン整備士の勘・コツが言語化されず退職とともに失われる | ベテランへのヒアリング音声の文字起こし・要約、ノウハウのマニュアル化・検索可能化 | 製造業全般の技術伝承ソリューションを整備業向けに転用する段階 |

**判断の軸**: 「損傷の見立て」「診断の当たりをつける」といった**専門判断の補助**は
まだ発展途上で、必ず整備士・査定士による最終確認を前提にする必要がある。一方
「顧客向けの説明文を書く」「在庫の発注点を計算する」といった**定型的な情報加工**は
汎用ツールでも十分な精度が出るため、まず着手しやすい。

## 実務での使い方

### 1. 損傷画像からの見積もり自動生成(AI鈑金見積もり)

海外の大手見積もりプラットフォームでは、スマートフォンで撮った損傷写真から
AIが一次見積もりを自動生成する機能が実用段階にある。

- **CCC ONE Mobile Jumpstart**(米CCC Intelligent Solutions): 損傷写真をアップロードすると
  約80秒で予備見積もりを作成し、最終見積もり金額の約84%相当をカバーする
- **Mitchell Intelligent Estimating**(米Mitchell International、AI画像診断のTractableと提携):
  見積もり項目の約7割をAIが自動入力し、スマホ撮影からの見積もり作成を数秒〜数分に短縮
- **損保ジャパン × Tractable**: 英国の画像認識AI企業Tractableと提携し、事故車両の
  全損判定(修理か買い替えかの判断)をスマホ写真から数分で行う仕組みを2021年10月に
  国内損保として初めて導入。判定確度は95〜97%とされる
- **トヨタモビリティパーツ × ギックス「AI整備見積りシステム」**: 車両情報を入力すると
  約80項目の整備内容をAIが診断し、整備の必要性の推奨度を示す「AI診断書」を自動作成する
  仕組みを共同開発し、2024年3月からトヨタモビリティ新大阪の23店舗へ試験導入、
  2025年以降は全国のトヨタ系販売店への展開を進めている(こちらは板金・鈑金というより
  日常整備・車検の提案見積もりだが、「車両情報→AIが診断書を自動生成」という
  仕組みは板金見積もりAIと同じ発想である)
- トヨタは別途、板金・塗装修理の損傷部位特定と修理方法選定をAI・ビッグデータで
  自動化し、見積もり作成時間を平均8割短縮するシステムをディーラー向けに開発している
- **AutoX3**(シンガポール発、日本市場進出): 整備士がスマホで撮影した車両の外装・
  内装・下回りの画像をAIが解析し、不具合の予測や新車デジタル納車点検に活用する
  SaaS「AI-Empowered Vehicle Health Check」を提供。保険業界での活用も見込まれている

これらはいずれも**一次見積もり(予備見積もり)を高速に作る**ためのツールであり、
最終的な金額確定・作業指示は人が行うことが前提になっている(米国の業界メディアでも
「AIの見積もりはあくまで写真と人の目の両方が必要」と繰り返し指摘されている)。

### 2. 故障診断支援(症状からの原因推定)

- **Bosch ESI[tronic] AIアシスタント**: 独Boschの整備士向け診断ソフト
  「ESI[tronic]」に、故障コードやキーワードを入力すると関連する診断・修理情報を
  提示するAIアシスタント機能を追加。修理作業中も対話形式で診断ステップの確認や
  代替手順の検討ができる。2026年後半のソフトウェア更新(2026/4版)で提供開始予定で、
  Advanced・Masterパッケージの利用者は追加費用なしで使える

### 3. 顧客への説明・提案文面の自動生成(今日から使えるプロンプト例)

見積もりが専門用語だらけで顧客に伝わらない、追加整備の提案が「営業っぽく」
響いてしまうという悩みには、汎用チャットAI(ChatGPT・Gemini・Copilot等)の
プロンプトで十分対応できる。

```
あなたは自動車整備工場の受付スタッフです。以下の点検結果をもとに、
車に詳しくない顧客にもわかりやすい説明文を作成してください。

## 点検結果
- 車種・年式: (例: 5年落ちのミニバン)
- 指摘箇所: (例: フロントブレーキパッド残量2mm、タイミングベルトのひび割れ)
- 緊急度: (例: ブレーキパッドは今回交換必須、ベルトは次回車検までに要交換)
- 概算費用: (例: ブレーキパッド交換 18,000円、ベルト交換 45,000円)

## 条件
- 「なぜ交換が必要か」を専門用語を避けて1〜2文で説明する
- 緊急度が高い箇所とそうでない箇所を分けて伝える
- 不安を煽る表現・断定的な危険表現は避け、事実にもとづいて書く
- 最後に「ご不明点はお気軽にお尋ねください」等の一言を添える
```

同様に、板金修理の場合は「損傷箇所」「修理方法(交換 or 板金修正)」「なぜその
方法を選んだか」を入力すれば、保険会社提出用ではなく顧客向けのわかりやすい
説明文を下書きできる。

### ツール横断の対応付け

| 用途 | 主に使われるツール・基盤 | 導入のハードル |
|---|---|---|
| 損傷画像の一次見積もり | CCC ONE Mobile Jumpstart、Mitchell Intelligent Estimating(Tractable連携)、AutoX3、トヨタ系販売店向け独自システム | 見積もりソフト・保険会社システムとの連携が前提で、個人での導入は難しい |
| 全損判定(保険査定) | Tractable(損保ジャパン等の損害保険会社経由) | 一般の整備工場が直接契約する対象ではなく、保険会社の査定フローに組み込まれている |
| 故障診断支援 | Bosch ESI[tronic] AIアシスタント、その他診断機メーカーのソフトウェア更新 | 既存の診断機・ソフトウェアのサブスク契約に含まれる形が主流 |
| 顧客説明文・提案文の下書き | ChatGPT、Gemini、Copilot等の汎用チャットAI | 無料〜月数千円のプランで今日から利用可能 |
| 部品在庫の需要予測・自動発注 | AI需要予測機能付きの在庫管理SaaS | 基幹システムの入れ替えではなく在庫管理だけに絞って小さく始めるのが定石 |
| 技術伝承(ベテランのノウハウの言語化) | 汎用チャットAIの文字起こし・要約機能 + 社内RAGシステム | ヒアリング音源の確保とマニュアル化の運用体制づくりが先に必要 |

## 注意点・よくある誤解

- **AI見積もりは「予備見積もり」であって最終見積もりではない**: CCC ONE Mobile
  Jumpstartの一次見積もりが最終金額の約84%相当、Mitchell Intelligent Estimatingが
  項目の約7割の自動入力にとどまるように、AIが出す数字はあくまで下書きである。
  隠れた損傷(内部フレームのゆがみ等)は写真だけでは判定できないため、最終的な
  金額確定は必ず人の目視・分解確認を経る必要がある
- **故障診断AIの提示は「当たり」であって確定診断ではない**: 症状から可能性の高い
  原因を提示するAIアシスタントも、あくまで診断の出発点を示すものであり、
  実際の修理判断・作業はメーカーの正規手順に沿って整備士が行う必要がある。
  AIの提示をそのまま作業指示にすると、誤診断による事故・クレームの責任の所在が
  曖昧になりかねない
- **全損判定AIの確度(95〜97%)にも例外はある**: 高確度とはいえ100%ではないため、
  境界事例(修理か買い替えか迷うケース)は必ず人による最終確認を挟む運用にする
- **顧客向け説明文は「不安を煽らない・断定しすぎない」よう必ず人が確認する**:
  生成AIは「緊急性を強調してほしい」という指示に忠実に従いすぎて、過度に不安を
  煽る文面を作ってしまうことがある。送信前に整備士自身が事実と齟齬がないか
  必ず確認する
- **技術伝承AIは「聞けば答えが出る魔法の箱」ではない**: ベテランの暗黙知を
  言語化するには、ヒアリングの実施・録音の同意取得・要約結果のチェックという
  地道な工程が必要で、AIはその作業を「効率化」するものであり「代替」するものではない
- **画像・音声データを扱う以上、個人情報・車両情報の取り扱いに注意する**:
  顧客の車両写真や会話音声を外部AIサービスに送る場合は、利用規約・データ保存先を
  事前に確認し、必要に応じて顧客への告知・同意取得を行う

## 最初の一歩

まずはコストゼロで始められる「顧客への説明・提案文面の自動生成」から着手し、
上記のプロンプト例を自社の点検項目に合わせて書き換えて試してみるとよい。
