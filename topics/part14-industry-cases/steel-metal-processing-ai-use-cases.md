# 鉄鋼・金属加工業における生成AI活用事例

## これは何か

鉄鋼・金属加工業は、高炉・転炉などの巨大レガシー設備を長期間運用しながら、
熟練オペレーターの暗黙知に支えられてきた業界である。生成AIはここでは
主に「①社内マニュアル・熟練者の知見を検索・要約できる形にする技能伝承」
「②開発・コーディングなど間接業務の効率化」「③新素材開発・特許調査の高速化」
の3領域で導入が進んでいる。予知保全や外観検査そのものは従来型の異常検知AI
(機械学習)が担うことが多く、生成AIはその結果を人間に分かりやすく伝える
後段のレイヤーとして重なりつつある。

## 仕組み・背景

高炉・転炉のような設備は、汎用LLMが学習していない設備固有のセンサー配置・
過去トラブル・操業ノウハウを大量に持っている。そのため汎用LLMをそのまま
使っても現場の役には立たず、社内データで根拠づけるRAG(検索拡張生成、
社内文書などを検索してから回答を生成する仕組み)や、専用のチャット環境の
構築が前提になる。日本製鉄や神戸製鋼所は、まず情報システム部門が
安全に使える社内専用チャット環境を用意し、そこにRAGや自社データを
段階的に組み込んでいくアプローチを取っている。

## 使いどころ・使い分け

| 課題 | 向いている打ち手 | 効果の例 |
|---|---|---|
| 熟練者しか知らない操業ノウハウの継承 | 現場データ・マニュアルをRAG化した社内チャットボット | 類似FAQへの問い合わせ件数を70件から2件に削減(神戸製鋼) |
| 社内問い合わせ・情報検索・議事録作成 | Microsoft 365 CopilotなどのオフィスAI導入 | 全社数千人規模への展開(日本製鉄) |
| システム開発・保守の工数増大 | コーディング支援AI(生成AI) | 実装・単体テスト工程で約68%の工数削減(JFEスチール) |
| 新素材の探索・特許調査 | マテリアルズインフォマティクス+生成AI、AIによる先行技術調査 | 調査時間を数日〜数週間から数分〜数時間に短縮 |
| 設備の異常検知・予知保全 | 従来型の異常検知AI(生成AIではない) | センサーデータからの早期異常検知 |

**使い分けの目安**: 「言葉を扱う業務」(検索・要約・レポート作成・コード生成)は
生成AIが得意な領域。「センサーデータから異常を検知する業務」は生成AI単体ではなく
従来型の機械学習・異常検知モデルの領域であり、両者を組み合わせて使う
(マルチモーダルAI化)のがこれからの方向性とされる。

## 実務での使い方

- **社内専用チャット環境の構築**: 日本製鉄はChatGPT・Bing Chatの試験利用を経て、
  社内情報を扱える独自環境「NS Chat」を構築し、その後Microsoft 365 Copilotを
  パイロット300人規模から全社4,400人規模へ展開。情報抽出・要約・検索・校正・
  議事録自動作成・メール下書きなどに活用している。生成AI活用の習熟度を
  「①公開情報のみ→②社内情報を安全な環境で利用→③社内データ+ナレッジベースの活用→
  ④自社データで学習した独自AIモデル」の4段階で定義し、段階的に進めている
- **熟練者ノウハウの形式知化**: 神戸製鋼所は2023年に自然言語処理AIチャットボットを
  導入し約1万人の従業員の社内問い合わせに対応、類似FAQの登録件数を70件から2件に
  削減した。2025年には全社横断の「生成AI CoE(センター・オブ・エクセレンス)」を
  設立し、RAGを活用しながら2週間サイクルで開発・レビューを回す体制を構築している
- **重機操業技術の可視化**: エクサウィザーズと日本製鉄は、マルチモーダルAIを使い
  熟練オペレーター(勤続10年以上)の重機操業技術を可視化し、新人に要点を提示して
  技能伝承を支援する基盤を構築した
- **コーディング支援AIの導入**: JFEスチールは自社システム開発にコーディング支援の
  生成AIを導入し、実装・単体テスト工程で約68%(開発工程全体では約20%)の
  工数削減を実証。2027年度末までに開発工程全体で約3割の生産性向上を目指す
- **新素材開発・特許調査の高速化**: プロテリアル(旧日立金属)はマテリアルズ
  インフォマティクス基盤に生成AIを組み込み新素材探索を効率化。日本ガイシは
  生成AIで自社技術の新規用途探索を高速化する実証実験を行い、開発者自身が
  数分で一次調査を完結できるようになったとしている

## 注意点・よくある誤解

- **ハルシネーションが品質・安全事故に直結しうる**: 製造業全般に言えることだが、
  高炉・転炉のような安全性が求められる設備の操業判断に生成AIの誤った出力を
  そのまま使うと重大事故につながりかねない。先行企業は「安全性が求められない
  領域限定でまず導入する」「人間が安全性を保証する体制を作る」という2段構えで
  導入範囲を広げている
- **RAGなしの汎用LLMは現場では役に立たない**: 高炉・転炉は設備ごとにセンサー配置や
  過去トラブルが異なり、汎用LLMはこれらを学習していない。社内データを検索してから
  回答させるRAGや、専用チャット環境の整備が前提になる([RAG(検索拡張生成)の基本](../part07-data-analysis/rag-basics.md)も参照)
- **UACJ・日本軽金属など非鉄・アルミ大手は一次情報が薄い**: 2026年8月時点で
  生成AI活用の公開情報が限られる企業もあり、業界全体を語る際は鉄鋼大手
  (日本製鉄・JFEスチール・神戸製鋼所)の事例に偏りがちな点に注意する

## 最初の一歩

自社内で「ベテランにしか答えられない質問」が繰り返し発生している業務を1つ選び、
その質問と回答をテキストで書き出してみることから始めるとよい。それがそのまま
RAG化・チャットボット化の最初の教材になる。
