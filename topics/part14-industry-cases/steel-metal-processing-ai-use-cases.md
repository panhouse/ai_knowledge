# 鉄鋼・金属加工業における生成AI活用事例

## これは何か

鉄鋼・金属加工業は、高炉・転炉などの巨大レガシー設備を長期間運用しながら、
熟練オペレーターの暗黙知に支えられてきた業界である。生成AIはここでは
主に「①社内マニュアル・熟練者の知見を検索・要約できる形にする技能伝承」
「②開発・コーディングなど間接業務の効率化」「③新素材開発・特許調査の高速化」
の3領域で導入が進んでいる。予知保全や外観検査そのものは従来型の異常検知AI
(機械学習)が担うことが多く、生成AIはその結果を人間に分かりやすく伝える
後段のレイヤーとして重なりつつある。

## 仕組み・背景

高炉・転炉のような設備は、汎用LLMが学習していない設備固有のセンサー配置・
過去トラブル・操業ノウハウを大量に持っている。そのため汎用LLMをそのまま
使っても現場の役には立たず、社内データで根拠づけるRAG(検索拡張生成、
社内文書などを検索してから回答を生成する仕組み)や、専用のチャット環境の
構築が前提になる。日本製鉄や神戸製鋼所は、まず情報システム部門が
安全に使える社内専用チャット環境を用意し、そこにRAGや自社データを
段階的に組み込んでいくアプローチを取っている。

## 使いどころ・使い分け

| 課題 | 向いている打ち手 | 効果の例 |
|---|---|---|
| 熟練者しか知らない操業ノウハウの継承 | 現場データ・マニュアルをRAG化した社内チャットボット | 類似FAQへの問い合わせ件数を70件から2件に削減(神戸製鋼) |
| 社内問い合わせ・情報検索・議事録作成 | Microsoft 365 CopilotなどのオフィスAI導入 | 全社数千人規模への展開(日本製鉄) |
| システム開発・保守の工数増大 | コーディング支援AI(生成AI) | 実装・単体テスト工程で約68%の工数削減(JFEスチール、標準的なJava開発案件での検証結果) |
| 新素材の探索・特許調査 | マテリアルズインフォマティクス+生成AI、AIによる先行技術調査 | 調査時間を数日〜数週間から数分〜数時間に短縮 |
| 設備の異常検知・予知保全 | 従来型の異常検知AI(生成AIではない) | センサーデータからの早期異常検知 |

**使い分けの目安**: 「言葉を扱う業務」(検索・要約・レポート作成・コード生成)は
生成AIが得意な領域。「センサーデータから異常を検知する業務」は生成AI単体ではなく
従来型の機械学習・異常検知モデルの領域であり、両者を組み合わせて使う
(マルチモーダルAI化)のがこれからの方向性とされる。

## 実務での使い方

- **社内専用チャット環境の構築**: 日本製鉄はChatGPT・Bing Chatの試験利用を経て、
  社内情報を扱える独自環境「NS Chat」を構築し、その後Microsoft 365 Copilotを
  パイロット300人規模から全社4,400人規模へ展開。情報抽出・要約・検索・校正・
  議事録自動作成・メール下書きなどに活用している。生成AI活用の習熟度を
  「①公開情報のみ→②社内情報を安全な環境で利用→③社内データ+ナレッジベースの活用→
  ④自社データで学習した独自AIモデル」の4段階で定義し、段階的に進めている
- **熟練者ノウハウの形式知化**: 神戸製鋼所は2023年に自然言語処理AIチャットボットを
  導入し約1万人の従業員の社内問い合わせに対応、類似FAQの登録件数を70件から2件に
  削減した。2025年には全社横断の「生成AI CoE(センター・オブ・エクセレンス)」を
  設立し、RAGを活用しながら2週間サイクルで開発・レビューを回す体制を構築している
- **重機操業技術の可視化**: エクサウィザーズと日本製鉄は、マルチモーダルAIを使い
  熟練オペレーター(勤続10年以上)の重機操業技術を可視化し、新人に要点を提示して
  技能伝承を支援する基盤を構築した
- **コーディング支援AIの導入**: JFEスチールはグループIT企業のJFEシステムズと協力し、
  設計書・仕様書からソースコードを書く自社システム構築作業に生成AIの活用を開始した。
  標準的なJava開発案件での検証では実装・単体テストの工数が約68%減り、
  開発工程全体では約20%の工数削減を**見込む**(実績値ではなく見込み。
  2026年5月時点、日刊産業新聞の報道=第三者取材)
- **新素材開発・特許調査の高速化**: プロテリアル(旧日立金属)はマテリアルズ
  インフォマティクス基盤に生成AIを組み込み新素材探索を効率化。日本ガイシは
  生成AIで自社技術の新規用途探索を高速化する実証実験を行い、開発者自身が
  数分で一次調査を完結できるようになったとしている

## 導入事例カタログ

鉄鋼・金属加工業で生成AI(LLM・チャットAI・AIエージェント)を業務に組み込んだ実名事例を、共通カード書式で集める(2026年11月時点)。外観検査や予知保全などの従来型の機械学習AIだけの事例は除き、生成AIの利用が出典で確認できたものだけを載せた。効果の数値は、利用回数・PoC段階の所感・ベンダーとの共同発表など性質がそれぞれ違うので、各カードの注記もあわせて読むこと。

### 日本製鉄(国内粗鋼生産1位の高炉メーカー・Copilot 4,400ライセンス) — 対象業務: 全社の事務・間接業務(会議の議事録、メール要約、社内ファイル検索)
- **導入形態**: 汎用チャットAI活用(Microsoft 365 Copilot)
- **段階**: 全社展開(2024年4月から約300ライセンスで4か月間パイロット。2025年1月に4,400ライセンスへ拡大し、100以上の部署に配布。グループ全体では11,000ライセンス)
- **やったこと**: パイロットの利用アンケートを踏まえてライセンスを拡大し、約7割を部署に割り当て、残りは申請制にした。30日使われないライセンスは回収して再配分する。最も使われたのはTeams会議のAIメモ(要約・議事録)。データ共有がSharePoint Online上にあったため、既存のアクセス権のままCopilotに社内ファイルを検索させられた。生成AIの活用を4段階で定義し、Copilotは「社内データ+ナレッジベース」の段階3に位置づけている
- **効果**: 4,400ライセンスに拡大した翌月(2025年2月)の利用実績は、Teams会議AIメモ約2万回、メールスレッド要約約4,500回、社内ファイル検索のプロンプト5万回超(2025年5月・ベンダー公表)。時間削減は、パイロットのアンケート平均から4,400ライセンスで年間数万時間と試算した値で、本番展開後に実測した数値ではない
- **学べること**: 「30日使われなければ回収」のルールと、部署割り当て+申請制の組み合わせで、限られたライセンスを使う人に集められる
- **出典**: [Microsoft Customer Stories「日本製鉄株式会社 Microsoft 365 Copilot」(2025年5月22日)](https://www.microsoft.com/ja-jp/customers/story/23624-nippon-steel-corporation-microsoft-365-copilot) / 最終確認日: 2026-11-16

### 神戸製鋼所(鉄鋼・アルミ・機械の複合素材メーカー) — 対象業務: 技術文書・過去トラブル情報の調査と初動対応
- **導入形態**: 内製(グループ会社コベルコシステムの支援を受けたRAGアプリの開発。基盤のAIモデル名は非公表)
- **段階**: PoC(本番開発に向けた要件整理の段階)
- **やったこと**: 2023年8月に生成AIの活用を始め、全社横断の「生成AI CoE(活用推進の専任チーム)」を立ち上げた。特定業務を重点施策に据え、技術文書や過去のトラブル情報を対象にしたRAG(社内文書を検索してから回答させる仕組み)のアプリを実際の業務課題で作り、データクレンジングとプロンプト調整で回答精度を高めた。短いサイクルで検証を繰り返し、実務に使えるかを早めに判断している
- **効果**: 数値公表なし(2026年4月・ベンダー公表)。調査業務や初動対応への適用の方向性が見えた、という定性的な成果のみ。神戸製鋼所の担当者は「最短数日でプロトタイプを形にできるようになった」とコメントしている
- **学べること**: 過去のトラブル記録のような現場の文書をRAGに載せるなら、まずデータクレンジングに手間をかけ、数日単位の試作サイクルで「使えるか」を早めに見極める
- **出典**: [PR TIMES(コベルコシステム)「コベルコシステム、神戸製鋼所の生成AI CoE活動を支援」(2026年4月15日)](https://prtimes.jp/main/html/rd/p/000000022.000168691.html) / 最終確認日: 2026-11-16

### ポスコ(韓国最大の鉄鋼メーカー。海外事例) — 対象業務: 人事・労務・総務・法務の社内問い合わせと申請手続き
- **導入形態**: 内製(社内GPTサービス「経営支援GPT」)
- **段階**: 全社展開(2025年9月に従業員向けに本格提供)
- **やったこと**: 先行して提供していた「人事・労務GPT」を、人事・労務・総務・法務まで広げた。光陽(クァンヤン)・浦項(ポハン)製鉄所の経営支援の対応事例を学習材料にし、年休・休暇申請の手順、給与計算、出張・派遣、福利厚生、保養所予約、社内保育所、健康診断などの質問に答える。回答が専門部署の担当者と同じ水準になるようペルソナを設定した。業務システムと連携し、年休申請や研修の受講申請もチャットから実行できる
- **効果**: 数値公表なし(2025年9月・第三者取材)
- **学べること**: 問い合わせの回答だけで終わらせず、使われる頻度の高い申請手続きから順に業務システムとつなぎ、「答える」から「手続きまで済ませる」へ広げていく
- **出典**: [The Asia Business Daily「POSCO Launches Management Support GPT... Making AI-Based Work Smarter」(2025年9月19日)](https://www.asiae.co.kr/en/article/2025091910424561566) / 最終確認日: 2026-11-16

### タタ・スチール(インドの大手鉄鋼メーカー。海外事例) — 対象業務: 人事ヘルプデスク・顧客の苦情対応・請求書処理などのバックオフィス
- **導入形態**: 内製(Google Cloud上の社内基盤。Gemini・Agent Development Kit・BigQueryなどを利用)
- **段階**: 全社展開(9か月で300以上のAIエージェントを製造・バックオフィス・顧客サービス・社内サポートに展開)
- **やったこと**: データサイエンティストでなくても開発者や現場の管理者がエージェントを作れるローコード基盤「Zen AI」と、公開情報・社内システム・通話録音やPDFなどのファイルを横断して質問できる社内ポータル「Tata Steel Digital Assistant(TDA)」を整えた。請求書処理、インドの物品・サービス税(GST)の控除可否の分類、契約書の分析、顧客の苦情の分析と振り分けなどをエージェントに任せている
- **効果**: TDAが人事ヘルプデスクの定型的な問い合わせの70%超を人手を介さずに解決、専用エージェントで顧客の苦情対応の平均所要時間が50%短縮(2026年4月・Google Cloudとの共同発表のためベンダー公表)。比較の基準時点や計測期間は公表されていない
- **学べること**: 現場の担当者が自分でエージェントを作れるローコード基盤を先に用意すると、部門ごとの小さな自動化を短期間に大量展開しやすい
- **出典**: [Google Cloud Press Corner「Tata Steel Partners with Google Cloud To Deploy a Unified Agentic AI Across its Global Value Chain」(2026年4月22日)](https://www.googlecloudpresscorner.com/2026-04-22-Tata-Steel-Partners-with-Google-Cloud-To-Deploy-a-Unified-Agentic-AI-Across-its-Global-Value-Chain) / 最終確認日: 2026-11-16

## 注意点・よくある誤解

- **ハルシネーションが品質・安全事故に直結しうる**: 製造業全般に言えることだが、
  高炉・転炉のような安全性が求められる設備の操業判断に生成AIの誤った出力を
  そのまま使うと重大事故につながりかねない。先行企業は「安全性が求められない
  領域限定でまず導入する」「人間が安全性を保証する体制を作る」という2段構えで
  導入範囲を広げている
- **RAGなしの汎用LLMは現場では役に立たない**: 高炉・転炉は設備ごとにセンサー配置や
  過去トラブルが異なり、汎用LLMはこれらを学習していない。社内データを検索してから
  回答させるRAGや、専用チャット環境の整備が前提になる([RAG(検索拡張生成)の基本](../part07-data-analysis/rag-basics.md)も参照)
- **UACJ・日本軽金属など非鉄・アルミ大手は一次情報が薄い**: 2026年8月時点で
  生成AI活用の公開情報が限られる企業もあり、業界全体を語る際は鉄鋼大手
  (日本製鉄・JFEスチール・神戸製鋼所)の事例に偏りがちな点に注意する

## 最初の一歩

自社内で「ベテランにしか答えられない質問」が繰り返し発生している業務を1つ選び、
その質問と回答をテキストで書き出してみることから始めるとよい。それがそのまま
RAG化・チャットボット化の最初の教材になる。
