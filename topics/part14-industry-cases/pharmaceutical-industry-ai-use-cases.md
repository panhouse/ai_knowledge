# 製薬業界における生成AI活用事例

## これは何か

製薬業界は、新薬開発に平均10年以上・数百億円規模のコストを要する一方、治験関連文書・規制当局への提出資料・医療従事者向け資材・副作用報告といった膨大な文書業務を抱える業種であり、生成AIによる効率化の余地が大きい。本ページは、[医療・ヘルスケアにおける生成AI活用事例](healthcare-ai-use-cases.md)が病院・クリニックでの問診・診療記録作成支援を1領域として扱うのに対し、創薬(候補化合物の探索・設計)・治験文書作成・ファーマコビジランス(PV、医薬品安全性情報管理)・MR(医薬情報担当者)/MSL(メディカルサイエンスリエゾン、KOLとの科学的対話を担う専門職)の実務という、医薬品を開発・提供する企業側の業務に焦点を当てて掘り下げる事例カタログである。

## 仕組み・背景

製薬業界における生成AI・AIの活用は、バリューチェーンに沿って大きく4つの段階に分かれる。

1. **創薬(候補化合物の探索・設計)**: AIが分子構造を生成し、標的探索から治験成功率の予測までを高速化する。第一三共はAmazon Web Servicesと協業し、AlphaFoldによるタンパク質立体構造予測や化合物の薬効・安全性・薬物動態を同時に予測するマルチパラメータ最適化を組み込んだ「AIエージェント統合型創薬基盤」を構築しており、2026年中の運用開始を目指している。中外製薬は独自の抗体配列最適化AI「MALEXA」を開発し、既存抗体と比較して結合強度が1,800倍以上に向上した配列を提案した実績がある([AI革命株式会社メディア](https://ai-revolution.co.jp/media/ai-in-pharmaceutical/))。武田薬品は2026年7月、生成AIで創薬候補分子を設計する米Insilico Medicineと戦略的提携を締結した。Insilicoが生成AIで有望な化合物構造を特定し、武田がその有効性・安全性を検証する役割分担で、契約一時金6,000万ドル(約97億円)に加え、開発進捗に応じたマイルストーン支払いを含め契約総額は最大6億ドルに達する([日経バイオテク](https://bio.nikkeibp.co.jp/atcl/news/p1/26/07/02/14758/)、[日刊薬業](https://nk.jiho.jp/article/303460))。海外では2026年8月、Novo NordiskがAWSと戦略的提携を結び、創薬標的候補の生成・評価に使う「Amazon Bio Discovery」や、複数のAIエージェントを連携させる「Amazon Bedrock AgentCore」を導入してロンドンに共同イノベーション拠点を設置すると発表しており、25,000人超の従業員を対象に治験関連文書の作成時間短縮などの効果が出始めているという([GlobeNewswire](https://www.globenewswire.com/news-release/2026/08/10/3341794/0/en/novo-nordisk-and-aws-enter-strategic-partnership-to-accelerate-drug-discovery-through-ai.html))。2026年時点でAI由来の医薬品候補は173件以上が臨床開発段階にあり、第I相試験の成功率は80〜90%と、従来の平均(約52%)を大きく上回るという報告もある([axis-intelligence](https://axis-intelligence.com/ai-drug-discovery-2026-complete-analysis/))。
2. **治験・規制文書の作成支援**: 治験総括報告書・治験実施計画書など、規制当局(PMDA・FDA等)への提出が前提の文書は、フォーマットが厳格に決まっている一方で分量が膨大という特性を持つ。塩野義製薬と日立製作所は生成AIを活用した規制関連文書作成支援ソリューションを共同開発し、治験総括報告書の作成時間を約50%、治験実施計画書の作成時間を約20%削減する効果を確認した。2026年2月には日立がこのソリューションのライセンス提供を受け、国内の医薬品・ヘルスケア企業向けに外販を開始している([塩野義製薬公式](https://www.shionogi.com/jp/ja/news/2026/02/20260224.html))。規制側の動きとして、FDAとEMA(欧州医薬品庁)は2026年1月14日、医薬品開発におけるAI活用の考え方を示す共同文書「Guiding Principles of Good AI Practice in Drug Development」を公表し、非臨床・臨床・市販後・製造の各段階でAIを使う際のリスクベースアプローチ・データガバナンス・ライフサイクル管理など10の原則を示した。両当局は今後これを土台に正式なガイダンスを整備していく方針を示している([EMA公式PDF](https://www.ema.europa.eu/en/documents/other/guiding-principles-good-ai-practice-drug-development_en.pdf))。国内でもPMDA(医薬品医療機器総合機構)自身が2026年4月15日、職員全員を対象にMicrosoft Copilotなど生成AIの業務利用を開始したと公表しており、審査当局側でも生成AI活用の実務化が進んでいる([PMDA公式](https://www.pmda.go.jp/about-pmda/news-release/0093.html))。
3. **ファーマコビジランス(PV、医薬品安全性情報管理)**: 市販後に収集される副作用報告(ICSR)は件数が膨大で、重篤性・因果関係の一次分類やMedDRA(副作用用語の標準コード)への紐付けに時間がかかる。中外製薬はNTTデータの伴走のもと、RAG(検索拡張生成、社内文書を検索して回答精度を高める仕組み)と生成AIを組み合わせて安全性資材(添付文書の安全性関連記載など)の作成を自動化する取り組みを進めている([NTTデータ DATA INSIGHT](https://www.nttdata.com/jp/ja/trends/data-insight/2026/0402/))。業界全体でも、副作用報告のOCR+LLMによる情報抽出や、重篤度に応じた一次トリアージにAIを使い、PV担当者(薬剤師・医師等の有資格者)が重要度の高い症例に集中できるようにする「AI下書き・人間最終判断」の二層運用が標準化しつつある。
4. **MR・MSLの営業・学術活動支援**: MR(医薬情報担当者)は医療従事者への情報提供・資材作成、MSLはKOL(キーオピニオンリーダー、その領域で影響力の大きい専門家)との科学的対話を担う。生成AIは、面談相手の医師の経歴・注力領域・直近の筆頭著者論文・学会登壇履歴といった背景情報の収集、文献の翻訳・要約、医師との対話を模擬したロールプレイングなどに活用されている([Medinew](https://www.medinew.jp/articles/marketing/trend/genai-pharma-usecases))。

McKinseyは、生成AIが製薬バリューチェーン全体で年間600〜1,100億ドルのコスト削減効果を生む可能性があると試算している([PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC13118854/))。

## 使いどころ・使い分け

| 業務 | 生成AI・AIが向く | 向かない/慎重にすべき理由 |
|---|---|---|
| 候補化合物の分子構造生成・標的探索 | 向く(専用の創薬AI基盤による高速スクリーニング) | 最終的な有効性・安全性の証明は臨床試験でしか得られない |
| 治験総括報告書・実施計画書のドラフト作成 | 向く(定型フォーマットの下書き高速化) | 提出前の数値・記載内容は必ず専門部署が原本と照合する |
| 安全性資材の下書き・副作用報告の一次トリアージ(PV) | 向く(RAGによる下書き自動化・重篤度の一次分類補助) | 重篤性判定・当局報告の要否・シグナル検出の最終判断はPV有資格者(薬剤師・医師)が行う |
| MR向け医師背景リサーチ・資材の壁打ち | 向く(下調べ・想定問答の準備) | 医療従事者への最終的な情報提供内容は薬機法上の広告規制を踏まえ人が確認する |
| 文献の翻訳・要約 | 向く | 臨床判断に関わる要約は必ず原文と照合する |
| MR・MSLと医師との実際の面談内容 | 向かない | AIによる代替は薬機法・倫理上想定されていない |

## 実務での使い方

### プロンプト例1: MR向け医師面談前の背景リサーチ

```
以下の医師について、次回面談前の準備資料を作成してください。
- 専門領域・直近の学会発表テーマ
- 筆頭著者として発表した論文の要旨(直近2年分)
- 過去の面談記録で言及された関心事項(あれば要約)

[医師名・専門領域・入手済みの経歴情報を記載]

出力は箇条書きで、事実確認が必要な項目には「要確認」と明記してください。
```

生成された背景情報は必ず一次情報(論文・学会プログラム等)で裏取りを行う。医師の個人情報の取り扱いは社内規程に従う。

### プロンプト例2: 治験実施計画書のセクション下書き

```
以下の治験概要をもとに、治験実施計画書の「対象患者の選択基準・除外基準」セクションの
下書きを作成してください。規制当局への提出を前提とした、簡潔で明確な記載にしてください。

[治験の目的・対象疾患・投与方法などの概要を記載]

出力後、既存の類似治験の記載と表現の統一が必要な箇所があれば指摘してください。
```

下書きは必ず臨床開発部門・regulatory affairs(薬事)担当が内容を精査し、最終稿は原本のデータ・過去の承認事例と突合する。

### プロンプト例3: 医学論文の要約・翻訳

```
以下の英語論文のアブストラクトを、MR向けの社内資料として日本語に要約してください。
- 対象疾患、試験デザイン、主要評価項目、結果の要点を4行程度で
- 専門用語には初出で一言説明を付ける
- 数値(有効率・p値など)は原文の表記のまま正確に転記する

[論文アブストラクトを貼り付け]
```

医療従事者向けに配布する資料として使う場合は、必ず学術情報部門の確認を経る。

### プロンプト例4: 副作用報告(ICSR)の一次トリアージ下書き

```
以下の副作用報告の内容から、一次トリアージのための下書きを作成してください。
- 重篤性の分類案(重篤/非重篤)とその判断根拠
- MedDRA(副作用用語の標準コード)に対応しそうな用語の候補
- 当局報告の要否について、PV担当者が確認すべき論点

[副作用報告の内容(症状・時系列・被疑薬・患者背景など)を記載]

最終判断はPV有資格者が行う前提で、判断が分かれそうな箇所は明示してください。
```

出力はあくまで一次分類の下書きであり、重篤性判定・当局報告の要否・シグナル検出の最終判断は必ずPV有資格者(薬剤師・医師等)が行う。患者の個人情報・機微情報の入力は社内規程とGVP(Good Vigilance Practice、医薬品安全性監視の基準)の要件に従う。

### ツール横断の対応表

| 用途 | ツール例 |
|---|---|
| 創薬(分子設計・標的探索) | 中外製薬「MALEXA」、Insilico Medicine(武田薬品と戦略提携)、第一三共×AWSの創薬基盤、Novo Nordisk×AWS「Amazon Bio Discovery」/「Amazon Bedrock AgentCore」(海外事例) |
| 治験・規制文書の作成支援 | 塩野義製薬×日立の規制関連文書作成支援ソリューション(2026年2月〜日立が外販) |
| 安全性情報管理(PV)の資材作成・一次トリアージ | 中外製薬×NTTデータのRAG活用安全性資材自動化 |
| MR・MSLの背景リサーチ・文献要約・資材壁打ち | ChatGPT/Gemini/Claude/Copilot(汎用チャットAI、法人契約前提) |

## 注意点・よくある誤解

- **「AIが創薬した」と「承認された医薬品」は別物**: 武田薬品×Insilico Medicineの契約のように、AIが担うのは候補化合物の生成までで、有効性・安全性の検証は製薬企業側が臨床試験で行うという役割分担が一般的である。2026年時点でAI由来の医薬品候補は臨床開発段階にある品目が多数を占め、「AIが創薬した薬」という表現を過度に一般化して社内外に発信しない。
- **提出文書は必ず原本データと突合する**: 治験総括報告書等の作成時間短縮は「下書き作成」の効率化であり、記載された数値・結論の正しさを担保する仕組みではない。規制当局への提出前に専門部署による精査を必ず挟む。FDA・EMAの共同原則も、AIの活用範囲を明示し人によるレビュー体制を組み込むことを求めている。
- **PV(ファーマコビジランス)はAI下書き+人間最終判断が原則**: 副作用報告の重篤性判定・当局報告の要否・シグナル検出は、誤ると患者の健康被害に直結する。AIは資材の下書きや一次トリアージまでにとどめ、最終判断・記録保存はPV有資格者が行う体制を崩さない。
- **医療従事者への情報提供は薬機法の広告規制を踏まえる**: AIが生成した文章表現が、未承認効能の示唆や誇大表現に該当しないか、資材化する前に確認する。
- **患者・治験参加者の個人情報を安易に入力しない**: 治験データや副作用報告には機微な個人情報が含まれるため、法人契約でデータ学習利用がオプトアウトされているツールを使う([生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md))。

## 最初の一歩

MR・MSL業務であれば次回の医師面談前の背景リサーチを、開発部門であれば治験文書の1セクションの下書き作成を、PV部門であれば副作用報告1件の一次トリアージ下書きを、チャットAIに試させて、事実確認込みでどれだけ準備時間が短縮できるかを確認してみる。
