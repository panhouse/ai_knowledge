# プロンプトテンプレート化(変数管理・再利用のコツ)

## これは何か

毎回「議事録を要約して」「このメールに返信して」とゼロからプロンプトを書き直していると、書く人によって出来栄えがバラつき(属人化)、同じ指示を打ち込む時間も積み重なる。プロンプトテンプレート化とは、よく使うプロンプトの「変わらない骨格」と「毎回変わる部分(変数・プレースホルダー)」を分離し、骨格を固定のひな形として保存しておく手法である。使うときは変数部分だけ差し替えればよく、指示の質を毎回一定に保ちながら、入力の手間を最小化できる。[プロンプトの基本構成要素](./prompt-basic-structure.md)で組み立てた「型」を、そのまま複製・配布可能な部品にする工程と考えるとよい。

## 仕組み・背景

テンプレート化の考え方自体は単純で、次の2つを分けるだけである。

1. **固定部分(骨格)**: 役割・タスクの指示・出力形式・トーンなど、案件が変わっても共通して使う指示文
2. **変数部分(プレースホルダー)**: 案件ごとに変わる情報(顧客名、対象テキスト、日付、条件など)

変数の書き方に厳密な業界標準はないが、実務では二重波かっこ `{{変数名}}` や角かっこ `[変数名]` で「ここは埋める場所」だと視覚的にひと目でわかるようにするのが定石になっている。前者はDifyやHandlebars系のテンプレートエンジンで実際に変数展開の構文として使われる書き方でもあり、後者はChatGPT・Claude・Geminiのチャット画面にそのまま貼り付けて手動で書き換える運用に向く。どちらを使うかは「AIツール側が変数を自動展開してくれるか(Dify等)」「人間が目で見て手打ちで埋めるか(チャットにコピペ)」で選べばよい。

テンプレート化が業務で重要な理由は3つある。

- **属人化の防止**: 優秀な担当者が書いた「効くプロンプト」を型として固定すれば、経験の浅いメンバーでも同水準の指示を再現できる
- **品質の均一化**: 出力フォーマット・トーン・チェック項目を毎回明示するため、成果物のばらつきが減る
- **時短**: 変数部分だけ入力すればよいので、プロンプト作成にかかる時間を数分から数十秒に短縮できる

## 使いどころ・使い分け

すべてのプロンプトをテンプレート化する必要はない。次の基準で判断するとよい。

| 状況 | テンプレート化すべきか |
|---|---|
| 週に何度も同じ種類の作業(議事録要約、メール返信、レビュー等)を頼む | すべき。骨格を固定し変数だけ差し替える |
| 一度きりの調べ物・雑談的なやり取り | 不要。都度書く方が早い |
| チーム内で複数人が同種の作業をしている | すべき。品質のばらつきを抑える効果が特に大きい |
| 案件ごとに前提が大きく変わり、共通化できる指示がほとんどない | 不要(または骨格を最小限にとどめる) |
| 顧客対応など「言い回しの一貫性」が信頼に直結する業務 | すべき。トーン・NGワードまでテンプレートに組み込む |

保存場所は「使う場面の広さ」で選ぶのが実務的な目安になる。

| 使う範囲 | 向いている保存先 |
|---|---|
| 自分だけが繰り返し使う | ChatGPT/Claude/Geminiの各チャット画面に都度貼り付け、または後述の「保存済み情報」「カスタム指示」欄に組み込む |
| 自分専用だが呼び出しを自動化したい | ChatGPTの[プロジェクト](../part03-ai-chat-tools/chatgpt-projects-feature.md)の指示欄、[Claude Projectsのカスタム指示](../part03-ai-chat-tools/claude-basics.md) |
| 社内の複数人で使い回す | Notion・Googleスプレッドシート・社内Wikiに「プロンプト集」としてまとめる |
| 変数入力フォームを用意してノーコードで運用したい | [Dify](../part10-nocode-lowcode/dify-basics.md)や[GPTs](../part06-custom-ai/gpts-creation-basics.md)などのプラットフォーム側に組み込む |

## 実務での使い方

### コピペで使えるテンプレート例1: 議事録要約テンプレート

```
あなたは経験豊富な社内秘書です。以下の会議の文字起こしを要約してください。

【出力形式】
- 冒頭に「会議名・日時・参加者」を1行で記載
- 「決定事項」「懸案事項(未決)」「宿題(担当者・期限つき)」の3見出しで箇条書き
- 宿題は「誰が・何を・いつまでに」の形式で明記する
- 全体で400字以内

【文字起こし】
{{会議名}}: [例: 定例MTG]
{{日時}}: [例: 2026年7月6日 10:00-11:00]
{{参加者}}: [例: 田中、佐藤、鈴木]

{{文字起こし本文}}
```

### コピペで使えるテンプレート例2: メール返信テンプレート

```
あなたは{{自分の役職}}として、以下の受信メールに返信します。

【前提】
- 相手: {{相手の名前・関係性}}(例: 取引先A社の担当者、初回のやり取り)
- 返信の方針: {{伝えたい結論}}(例: 納期を1週間延ばしてほしいと依頼する)
- トーン: {{トーン指定}}(例: 丁寧だが率直に、謝罪は1回だけ)

【制約】
- 件名は「Re:」から始める
- 本文は300字以内
- 結論を最初の2文で述べてから理由を説明する

【受信メール本文】
{{受信メール本文を貼り付け}}
```

### コピペで使えるテンプレート例3: 文章レビュー・添削テンプレート

```
あなたは{{レビュー対象の分野}}(例: 広報資料、技術ブログ、営業提案書)の
編集者です。以下の文章を、次の観点でレビューしてください。

【チェック観点】
1. 誤字脱字・文法ミス
2. 主張が読み手({{想定読者}})にとってわかりやすいか
3. 冗長な表現・二重表現の有無
4. {{追加のチェック観点}}(例: 専門用語に説明が付いているか)

【出力形式】
- 指摘は「箇所: 元の表現 → 修正案(理由)」の一覧形式
- 全体講評を最後に3行以内でまとめる

【レビュー対象の文章】
{{レビュー対象テキストを貼り付け}}
```

### ツール横断の対応付け(2026年7月時点)

| ツール | テンプレート的に使える機能 | 設定場所・使い方 |
|---|---|---|
| ChatGPT | ネイティブの「プロンプト保存」機能は現時点でも存在しない。実務では[カスタム指示](../part03-ai-chat-tools/chatgpt-custom-instructions.md)や[プロジェクト](../part03-ai-chat-tools/chatgpt-projects-feature.md)の指示欄に骨格を固定し、変数部分だけ都度メッセージ欄に書き足す運用が現実的 | アカウントメニュー→設定→パーソナライズ→カスタム指示/各プロジェクトの「Instructions」欄 |
| ChatGPT(GPTs) | [GPTs](../part06-custom-ai/gpts-creation-basics.md)のInstructions欄に骨格を固定し、「会話のきっかけ」に変数の入力例を提示する形でテンプレートを配布できる | GPT Builder→Configureタブ→「指示」「会話のきっかけ」 |
| Claude | Projectsの「プロジェクトの指示(Project instructions)」欄にテンプレートの骨格を登録。参照ファイルもナレッジとして追加可能 | claude.ai/projects→対象プロジェクト→設定→「手順」欄 |
| Gemini | 「保存された情報(Saved info)」に「自分について」「回答してほしい形式」など全チャット共通の前提を登録。用途特化の骨格は「Gem」として個別に作成 | プロフィールアイコン→設定→「保存済み情報」、またはgemini.google.com→「Gem」メニュー→「新しいGemを作成」 |
| Dify | プロンプトエディター内で `{{変数名}}` の形式でユーザー入力・システム変数・前段ノードの出力を挿入できる。エディターで `/` または `{` を入力すると変数の挿入メニューが開く | Difyアプリ編集画面→LLMノード→プロンプト欄→`/`または`{`で変数挿入、「コンテキスト」欄に他ノードの出力を割り当て |
| 社内プロンプト集(汎用) | Notionのデータベース、Googleスプレッドシートに「用途/骨格/変数の説明/最終更新日」の列を作り、部署内で共有 | 各ツールの共有権限で編集者・閲覧者を分ける |

Difyの`{{変数名}}`はエディターが実際に値を自動展開してくれる「本物の変数」だが、ChatGPT・Claude・Geminiのチャット画面に貼るテンプレートの`{{}}`や`[]`はあくまで「人間への目印」であり、AIが自動で埋めてくれるわけではない点に注意する(コピペ後、自分で書き換える必要がある)。

## 注意点・よくある誤解

- **変数の説明不足による誤用**: `{{対象}}`とだけ書くと、何を入れればよいか作成者以外には伝わらない。`{{対象: 例 "先月の売上データ"}}`のように、変数名の直後に一言説明と入力例を添えるだけで誤用は大きく減る
- **機密情報を含むテンプレートの共有範囲に注意**: テンプレート自体に実在の顧客名・社内数値・契約条件をそのまま埋め込んで保存すると、共有範囲を誤ったときに機密情報が漏れる。テンプレートは変数のまま保存し、値は使用時にその都度入力する運用にする。社外秘のテンプレート集をNotion等で共有する場合は、権限設定(閲覧者・編集者)を必ず確認する
- **テンプレートの陳腐化**: モデルが賢くなると、古いモデル向けに書いた「出力形式を細かく縛る指示」や「ハルシネーション対策の注意書き」が不要になったり、逆に新機能(画像・ファイル添付等)に対応していなかったりする。テンプレート集には「最終更新日」「最終確認したモデル」を明記し、定期的に棚卸しする
- **骨格に詰め込みすぎない**: 「念のため」で条件や注意書きを増やし続けると、テンプレートが長大化して逆に使われなくなる。まずは最小限の骨格で運用し、実際に精度不足が起きた箇所だけ足していく方が定着しやすい
- **バージョン管理をしないと「どれが最新か」わからなくなる**: 同じ用途のテンプレートが複数人によって少しずつ改変され、社内に似たようなコピーが乱立しがち。1つの用途につき「正本」を1つ決め、改訂履歴を残す

## 最初の一歩

直近1週間で2回以上使ったプロンプトを1つ選び、変わらない部分と毎回書き換えている部分を洗い出して、変わる部分を`{{}}`で置き換えたテンプレートを1本作ってみる。
