# 知財・特許担当者における生成AI活用事例

## これは何か

企業の知財部門・特許事務所の弁理士は、「発明を掘り起こす→先行技術を調べる→出願書類を書く→審査対応する→権利を守る」という一連の業務を担う。1件の特許出願の背景には数百件規模の先行文献調査があり、明細書(発明の内容を文章化した出願書類)は技術的正確性と法律要件を両立させる専門文書で、いずれも読む・調べる・書く負荷が大きい。生成AIは特許検索の高速化やドラフト作成の下書きとして急速に浸透しているが、**出願前の発明内容を外部AIに入力すると新規性(特許を取るための「まだ世に知られていない」という要件)を失いかねない**という、他の職種にはない固有のリスクを抱える分野でもある。

本ページは、企業の知財部門・弁理士という**職種**が生成AIをどう使うかに焦点を当てる。隣接ページとの境界は次のとおり。

- [法務職における生成AI活用事例](legal-ai-use-cases.md): 契約書レビュー・法令調査・コンプライアンスなど、知財以外の一般法務を扱う。知財部門が契約審査を兼ねる場合はそちらも参照
- [研究開発(R&D)職における生成AI活用事例](rd-ai-use-cases.md): 研究者・技術者が発明の過程で行う一次的な特許調査・明細書ドラフトの入口を扱う。本ページは、その後工程を専門に担う**知財部門・弁理士**の業務(先行技術調査の本調査、特許性判断、クレーム設計、中間処理、商標調査、IPランドスケープなど)を扱う

## 仕組み・背景

知財領域のAI活用には、性質の異なる2つの流れがある。

- **特許検索特化のAI**: Patentfield、AI Samurai、海外ではPatSnap Eureka・IPRallyなどは、数億件規模の特許・論文データベースを機械学習で構造化し、キーワードだけでなく技術的な意味の近さで類似文献を探せるようにしたサービス。IPRallyは自然文の質問文をクレーム(特許請求の範囲)に最適化された検索式に変換する「Graph AI」を採用し、PatSnap Eurekaは新規性調査・FTO調査(Freedom to Operate、他社特許を侵害せず事業化できるかの調査)・設計変更時のFTO調査などをタスクごとの専用AIエージェントとして提供する。日本語では、Patentfieldが2025年7月に生成AI調査・分析オプション「Patentfield AIR」をリリースし、独自要約・外国語文献の翻訳・実施例からのデータ抽出・新アイデア/クレームとの対比分析などを月額数万円台から提供している。
- **汎用LLMのエージェント化**: ChatGPT・Claude・Geminiのようなチャット型AIを、発明提案書のたたき台作成・先行文献の要約比較・クレーム草案の作成・拒絶理由通知への応答文ドラフトなど、幅広い知財タスクの下書き役として使う流れ。2026年7月にはAI Samuraiが、生成AIと日米中の特許実データをMCP(Model Context Protocol、AIが外部データ・ツールと直接やり取りする標準規格)で接続する「IP Samurai MCPサーバー」と「知財AIエージェント活用支援プログラム」を発表し、特許調査・競合分析・SDI(定期的な監視調査)・発明発掘・クレーム/明細書作成・OA(Office Action、拒絶理由通知)対応・知財戦略立案など10業務を対象に、AIが特許・文献情報を直接取得しながら書類作成まで支援する構成を打ち出した。同社はIPランドスケープ(自社・競合の特許ポートフォリオを俯瞰する競合分析)業務で通常8時間かかる作業を30分程度に短縮できる例を示している(ベンダー公表値)。

いずれの方式でも、AIは既存の文献パターンや学習データ上の頻出表現から出力を組み立てているにすぎず、「その発明が本当に新規性・進歩性を持つか」「クレームの権利範囲が広すぎず狭すぎないか」といった特許要件の最終判断はできない。日本弁理士会(JPAA)は2025年4月に「弁理士業務AI利活用ガイドライン」を公表し、生成AIの出力は正確性が保証されておらず、AIを使う場合でも専門家としてその内容を検証し、最終的な責任は弁理士自身が負うという原則を明記している。あわせて機密保持義務との関係、および後述する新規性喪失リスクについても注意喚起している。

## 使いどころ・使い分け

知財部門・弁理士の業務は工程ごとに「AIに任せてよい範囲」と「専門家が必ず判断すべき範囲」が明確に分かれる。

| 業務工程 | AIが担える範囲 | 人(弁理士・知財担当者)が必ず担う範囲 |
|---|---|---|
| 発明発掘・発明提案書の整理 | 技術者のメモ・議事録から発明のポイントをたたき台として要約 | 発明として権利化する価値があるかの一次判断、発明者の特定 |
| 先行技術調査・侵害予防調査(FTO) | 特許DBからの類似文献の抽出・自然文検索・複数文献の要約比較 | 抽出結果の技術的な当てはめ、新規性・進歩性・侵害リスクの最終判断 |
| クレーム・明細書のドラフト作成 | 発明の構成要素を特許文書らしい構文でたたき台化 | 権利範囲の設計、実施可能要件・サポート要件を満たす記載の確定 |
| 拒絶理由通知(OA)対応 | 通知内容の要約、応答方針の選択肢出し、意見書・補正書の下書き | 引用文献との相違点の主張構成、補正内容の最終決定 |
| 商標調査 | 類似商標・ロゴの一次スクリーニング | 識別力・類似性の法的な最終判断、出願可否の意思決定 |
| IPランドスケープ・競合特許分析 | 大量特許の技術分類・可視化・トレンド抽出のたたき台 | 経営判断に落とし込む解釈、事業戦略への反映 |

使い分けの判断基準は法務と同様に「この出力を鵜呑みにして進めた場合、誤りがあったら何を失うか」。特許は一度出願・登録されると差し替えが利かない性質が強く、**AIの出力は常に「一次ドラフト」、権利化に関わる最終判断は弁理士・知財部門が行う**という運用を徹底する。

## 実務での使い方

### 1. 発明発掘・発明提案書のたたき台作成

技術者から口頭・箇条書きで受け取った発明の種を、社内様式の発明提案書の形に整理する。**この段階では、未公開の技術情報を扱うため入力先の選定が重要**(詳細は後述の注意点を参照)。

```
あなたは知財部門の担当者です。以下は技術者からのメモです。
これを社内の発明提案書フォーマットに沿って整理してください。

【出力項目】
1. 発明の名称(仮)
2. 解決しようとする課題(従来技術の何が問題か)
3. 課題を解決するための構成(発明のポイントを箇条書きで)
4. 期待される効果
5. 実施例として考えられる具体例
6. 追加で技術者に確認すべき質問事項(不明点があれば列挙)

技術者メモ:
(ここに発明メモを貼付)
```

### 2. 先行技術調査・侵害予防調査(FTO)の一次整理

対象特許・公報の特定は特許検索特化AI(Patentfield、AI Samurai、PatSnap Eureka、IPRallyなど)やJ-PlatPat(特許情報プラットフォーム、特許庁が提供する無料の公的検索システム)で行い、抽出された文献の内容比較・要約は汎用AIに読み込ませると効率が上がる。

```
アップロードした特許公報3件(A・B・C)について、以下を整理してください。

1. 各公報のクレーム1(独立請求項)の技術的構成を箇条書きで要約
2. 自社が検討している構成(下記)と各公報の共通点・相違点
3. 相違点のうち、自社構成の新規性・進歩性の主張に使えそうなポイント
4. 各公報が自社の事業実施に対して抵触するリスクの有無(一次評価)

自社が検討している構成:
(ここに自社構成の概要を貼付。既に外部に開示済みの内容のみ)

※本評価はあくまで一次スクリーニングであり、最終判断ではないことを
前提に、断定的な表現を避けて出力してください。
```

### 3. クレーム・明細書ドラフトのたたき台作成

発明提案書をもとに、特許文書らしい構文でのたたき台を作らせる。実際の出願には弁理士のレビュー・書き直しを必ず挟む。

```
以下の発明提案書の内容をもとに、特許請求の範囲(クレーム)の
独立請求項(請求項1)のたたき台を作成してください。

【出力条件】
- 「〜を備えることを特徴とする、〜」の形式に沿った特許文書らしい文体にする
- 構成要素を過不足なく含め、不要な限定は加えない
- 発明の効果や作用効果に関する記載はクレームに含めず、
  明細書の「発明の効果」欄に回す形で別出力する
- 実施可能要件(第三者がこの記載だけで発明を再現できること)を意識し、
  抽象的すぎる表現があれば注記で指摘する

発明提案書:
(ここに発明提案書の内容を貼付)
```

### 4. 拒絶理由通知(オフィスアクション)対応の下書き

```
特許庁から届いた以下の拒絶理由通知の内容を要約し、
対応方針の選択肢を整理してください。

1. 拒絶理由の要約(進歩性・新規性・記載不備のどれに該当するか)
2. 引用文献と本願発明との相違点として主張できそうなポイント(たたき台)
3. 補正で対応する場合と意見書のみで反論する場合、それぞれのメリット・デメリット

拒絶理由通知の本文:
(ここに通知内容を貼付)

※最終的な補正内容・反論方針は弁理士が確定するため、
断定的な結論ではなく選択肢として整理してください。
```

### 5. 商標調査

Toreru商標検索のように、AI(ディープラーニング)による画像類似検索でロゴの類似商標を一次スクリーニングできる無料ツールもある。同社は誰でも使える無料の「AI調査®」(簡易な自己診断)と、弁理士が行う本格的な「Toreru調査®」を区別しており、AI調査はあくまで一次チェック、出願前の最終判断は本格調査に委ねる運用になっている。

```
以下の候補商標について、一般的な観点から出願前チェックすべき
論点を整理してください(法的な最終判断ではなく、確認observationの
たたき台として)。

- 候補商標: (商標名)
- 指定商品・役務: (例: 第9類 コンピュータソフトウェア)

1. 一般名称・記述的表現に近くないか(識別力の観点)
2. 想起される既存の有名商標がないか
3. 出願前に商標検索AI・専門家によるチェックを推奨する理由
```

### 6. IPランドスケープ・競合特許分析

競合他社の特許ポートフォリオを俯瞰する分析は、従来はアナリストが手作業で行っていたが、AI Samuraiの「知財AIエージェント」のように特許DBとAIを直接連携させ、通常8時間かかる分析作業を30分程度に短縮した例が報告されている(ベンダー公表値)。汎用AIを使う場合も、大量の特許リストをアップロードし、技術分類・出願人別の傾向・時系列トレンドを可視化するたたき台作成に活用できる。

### 特許・商標特化AIツールと汎用AIの使い分け(2026年8月時点)

| ツール | 位置づけ | 特徴 |
|---|---|---|
| Patentfield AIR | 国内の特許検索プラットフォーム「Patentfield」の生成AI調査・分析オプション(2025年7月リリース) | 独自要約・外国語文献の自動翻訳・実施例からのデータ抽出・自社アイデア/クレームとの対比分析・ポートフォリオ分析。Mini/Corpプランに追加契約する形で、月額数万円台〜(処理件数に応じて変動)。自身のChatGPT/Gemini/ClaudeのAPIキーを使う選択肢もある |
| AI Samurai / IP Samurai MCPサーバー | 大阪大学・北陸先端科学技術大学院大学(JAIST)発のAI特許調査ツール。2026年7月に生成AIと特許DBをMCPで接続する新サービスを発表 | 特許調査・競合分析・発明発掘・クレーム/明細書作成・OA対応・知財戦略立案など10業務に対応するエージェント型。「みんなの特許」は類似先行文献のAI4段階評価を5万円・最短3日で提供する簡易調査サービス |
| PatSnap Eureka | 海外発のAI-nativeな特許・研究開発インテリジェンスプラットフォーム | 208百万件超の特許・174法域・216百万件超の文献データを基盤に、新規性調査・FTO調査・設計変更時のFTO調査などタスク別のAIエージェントを提供 |
| IPRally | 海外発のAI特許検索プラットフォーム | 独自の「Graph AI」で自然文の質問をクレーム最適化検索式に変換。基本プランは1ユーザー月額50ドル程度から |
| J-PlatPat | 特許庁が提供する無料の公的特許情報検索システム | AI特化ではないが、対象特許・公報の一次特定や正式な出典確認の基盤として引き続き必須。AI検索ツールの結果は最終的にJ-PlatPatなど公的情報源で裏取りする |
| Toreru商標検索 / AI調査® | 商標検索・出願支援サービスToreruのAI機能 | ロゴの画像類似検索を含む無料の商標検索エンジンと、簡易自己診断の「AI調査®」を提供。出願前の最終判断は弁理士による「Toreru調査®」などの本格調査に委ねる設計 |
| ChatGPT / Claude / Gemini(汎用AI) | 発明提案書の整理・クレーム草案・OA対応下書き・IPランドスケープの可視化たたき台など幅広い用途 | 特許DBの網羅性は特化ツールに劣るため、対象文献の特定は専用ツール・J-PlatPatで行い、要約・比較・文章化の部分を汎用AIに任せる組み合わせが実務的 |

## 注意点・よくある誤解

- **出願前の発明を外部AIに入力すると新規性を失うリスクがある**: 特許法上、新規性は「不特定多数の第三者が知りうる状態になったか」で判断される。弁理士による解説では、AIサービスのサーバーに一時的に情報が記録されるだけで直ちに新規性喪失にはならず、第三者が実際にアクセスできる状態でなければ問題にはならないとされる一方、個人向け・無料プランの規約では入力内容がモデルの学習に再利用される場合があり、その結果として意図せず技術情報が外部に開示される恐れが指摘されている。日本弁理士会の「弁理士業務AI利活用ガイドライン」(2025年4月)も、機密保持義務との関係でこの新規性喪失リスクを注意喚起している。未公開の発明内容を扱う際は、学習への非利用が既定の法人向け・API契約を使う、または社内専用環境を使うなど、[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md)に従った運用を徹底する。
- **AIが生成したクレーム・明細書はそのまま出願できる完成品ではない**: AIの出力は技術的正確性・実施可能要件(第三者が記載内容だけで発明を再現できること)・サポート要件(クレームの範囲が明細書の記載で裏付けられていること)を満たすとは限らず、存在しない先行技術・規格名への言及(ハルシネーション)が混ざることもある。AI下書き+弁理士による技術的正確性・要件充足性のチェックという「ハイブリッド作成」が実務での標準的な位置づけであり、AI下書きをそのまま出願書類として提出しないこと。
- **AIを発明者として出願することはできない**: 「DABUS事件」と呼ばれる訴訟で、AIが自律的に発明した内容についてAI自身を発明者として出願した事案があったが、知的財産高等裁判所は2025年1月30日、現行の特許法上「発明者」は創作行為に実質的に関与した自然人に限られ、AIを発明者とすることはできないと判断し、最高裁もこれを不受理として判決が確定している。AIが発明のアイデア出しに関与した場合でも、出願書類上の発明者欄には必ず自然人を記載する必要がある。
- **AIの検索結果は網羅性を保証しない**: 特許検索特化AIも汎用AIも、学習データ・インデックスの範囲外の文献は検索できない。侵害予防調査(FTO)や特許性判断のような「見落としが致命的になる調査」では、AI検索の結果をJ-PlatPatなど公的データベースや専門家による本調査で必ず裏取りする。
- **「弁理士が最終責任を負う」という前提を崩さない**: 日本弁理士会のガイドラインが示すとおり、AIの出力は正確性が保証されておらず、専門家としての検証と最終責任は変わらず弁理士側にある。「AIが調べたから大丈夫」という思い込みは、依頼者への説明責任の観点でも避けるべき誤解になる。

## 最初の一歩

社外秘の未公開発明ではなく、**既に公開済みの自社特許や競合の公開特許公報**を1件選び、上記の「先行技術調査・侵害予防調査の一次整理」プロンプトに貼って要約させてみる。AIの要約と自分の理解にズレがないかを確認したうえで、未公開情報を扱う際の入力先(学習非利用の法人契約かどうか)を必ず事前にルール化してから業務利用に進む。
