# 労務・給与担当者における生成AI活用事例

## これは何か

労務・給与担当者は、毎月の給与計算の実行とチェック、入社・退社に伴う社会保険・雇用保険の手続き、年末調整、勤怠データの集計と残業時間の管理、就業規則や社内規程に関する社員からの問い合わせ対応まで、「決められた通りに、間違いなく、期限内に回す」ことが仕事の中心になる職種である。人事(採用・評価・タレントマネジメント)と同じ部門にいることが多いが、業務の性質はかなり異なる。生成AIは「文章のドラフト作成」や「定型的な問い合わせへの一次対応」には強い援軍になる一方、給与額そのものの計算やマイナンバーなど特定個人情報の取り扱いには重い制約がかかる。本ページは、労務・給与担当者の業務フローに沿って、どこにAIを入れてよく、どこには入れてはいけないかを整理する。

**隣接する2つのページとの境界線**は次の通り。

- **[人事(HR)職における生成AI活用事例](./hr-ai-use-cases.md)**: 求人票作成・応募者スクリーニング・面接・評価・タレントマネジメントなど、採用と人材配置・育成が中心。本ページは採用後の「雇用契約の履行・労務管理・給与計算」の実務に絞る。両者は同じ人事部内で隣接する業務のため、境界を明確にする(例: 「評価コメントのドラフト」はHR職ページ、「年末調整の扶養控除申告書チェック」は本ページ)
- **社会保険労務士(社労士)**: 社労士は、社会保険・労働保険の手続き代行や就業規則の作成・改定を業として行う**社外の国家資格者**(顧問契約や単発依頼で関わる外部専門家)である。本ページが扱うのは、それとは別に**自社に雇用されている労務・給与担当の社員(インハウス)**が日々行う実務であり、独占業務(社労士法で定められた1号・2号業務)の外部委託・代行そのものは扱わない。社労士が自らの業務にAIをどう使うかは別テーマとして切り出す

## 仕組み・背景

労務・給与担当の業務でのAI活用は、大きく3系統に分かれる。

1. **給与計算・労務管理SaaSに組み込まれたAI機能**: SmartHR、freee人事労務、マネーフォワード クラウド給与などが標準搭載しつつある機能。年末調整のAI-OCR(書類画像から文字を読み取る技術)による証明書読み取り、従業員からの問い合わせに答えるAIアシスタント、独自の給与ルールを日本語で伝えるとシステム上の計算式に変換する機能などがこれにあたる
2. **汎用チャットAI(ChatGPT/Gemini/Claude/Copilot)によるドラフト生成・チェック補助**: 雇用契約書・扶養控除等申告書の記入案内文、社会保険手続きの案内メールなど、その場でテキストを作らせる使い方。給与計算ソフトの検算式(IF関数など)を作らせたり、集計結果の妥当性を確認させたりする使い方も含む
3. **社内規程に基づくRAG(Retrieval Augmented Generation、検索拡張生成。社内文書を検索してから回答を生成する仕組み)チャットボット**: 就業規則・給与規程・休暇制度などについて社員から寄せられる定型的な質問に、一次情報を参照させて自動応答する仕組み

SmartHRは2025年8月28日、証明書のAI-OCR読み取りとAIアシスタントを組み合わせた「2025年版 年末調整」機能の提供を開始し、担当者の差し戻し・確認作業と従業員からの問い合わせ対応の負荷軽減を打ち出している。2025年8月の社内実証では、約1,500人が1日平均1回AIアシスタントを利用し、問い合わせ対応工数が全体で約1割、総務・情シスなど一部部門では約2割削減されたと公表されている。2026年8月17日には、従業員が自分の給与明細・賞与明細・源泉徴収票をAIアシスタント経由で検索できる機能も追加された。マネーフォワード クラウド給与も、企業ごとに異なる手当・控除の独自ルールを日本語で指示するとシステム上で動く計算式にAIが変換する機能を提供しており、年末調整でも従業員がスマホから扶養控除等申告書を入力できる仕組みで担当者側の集計・入力作業を減らす方向性を取っている。freee人事労務は社会保険・雇用保険の資格取得届・喪失届などの書類作成とe-Gov・マイナポータル経由の電子申請に対応しており、法改正(2026年4月開始の子ども・子育て支援金制度など)への自動アップデートも組み込まれている。

一方で、この職種が扱うデータは、通常の個人情報よりもさらに機微度が高い。給与額・賞与額・扶養家族の情報に加え、マイナンバー(個人番号)は番号法(行政手続における特定の個人を識別するための番号の利用等に関する法律)上「特定個人情報」として、通常の個人情報よりも厳格な利用目的の制限・提供制限を受ける。個人情報保護委員会は2023年6月、事業者が本人の同意なく個人データを含むプロンプトを生成AIサービスに入力し、それが応答生成以外の目的(AIの学習など)に使われる場合は個人情報保護法違反となり得ると注意喚起しており、この考え方は給与計算・労務管理の実務にもそのまま当てはまる。

## 使いどころ・使い分け

### 業務フェーズ別のAI活用マップ

| 業務フェーズ | 主な業務 | AIの向き・不向き | 使うAI・機能 |
|---|---|---|---|
| 入社時 | 雇用契約書・労働条件通知書のドラフト作成、社会保険・雇用保険の資格取得手続き案内 | 向く(定型文書のたたき台まで) | 汎用チャットAI、労務SaaSの書類作成機能 |
| 月次給与計算 | 勤怠データの取り込み、給与計算の実行、計算結果の検算・異常値チェック | **計算そのものは不向き**(誤りをそれらしく出力するリスク)。検算式の作成・異常値の洗い出し補助は向く | 給与計算ソフト本体(計算実行)+ ChatGPT等(検算ロジック・チェック式の作成補助) |
| 年末調整 | 扶養控除等申告書・保険料控除申告書の内容確認、証明書の読み取り、従業員からの質問対応 | 向く(AI-OCRでの読み取り、定型質問への一次回答) | SmartHR「AIアシスタント」+AI-OCR、マネーフォワード クラウド給与、freee年末調整 |
| 勤怠管理 | 打刻データの集計、残業時間の異常検知、36協定上限のアラート | 向く(パターン検知・アラート生成の補助) | 勤怠管理SaaSの分析機能、ChatGPT/Gemini等での集計データ分析(個人が特定できる生データは避ける) |
| 退職時 | 退職手続き案内、離職票・源泉徴収票の案内文書、社会保険資格喪失手続きの案内 | 向く(案内文書のたたき台まで) | 汎用チャットAI、労務SaaSの書類作成機能 |
| 日常の問い合わせ対応 | 就業規則・休暇制度・給与規程に関する社員からの質問 | 向く(一次対応。個別事情の判断は人へエスカレーション) | RAG型の社内FAQボット(SmartHR AIアシスタント、Dify等での自社構築) |
| 手続き・提出書類の最終確認 | 提出前の書類内容の最終チェック、行政への申請 | **不向き(必ず人が確認)** | 労務担当者本人が最終確認 |

判断基準は明快で、「金額を計算させる/確定させる」用途にはAIを主役にしない。給与計算ソフトが計算を行い、生成AIは「検算のロジックを一緒に組み立てる」「入力ミスや不整合(生年月日と年齢の不一致など)を見つけるための整理役」に徹させるのが実務での定石になっている。

## 実務での使い方

### 使えるツール・構成

- **汎用チャットAI(ChatGPT/Gemini/Claude/Microsoft 365 Copilot)で足りる部分**: 雇用契約書・案内文・問い合わせ回答文のドラフト作成、検算用の関数・チェックロジックの相談、社内マニュアルの文章化。ただし実在の従業員の氏名・給与額・マイナンバーなど機微情報は入力しない(匿名化・ダミー化して使う)
- **専用ツールが必要な部分**: 給与計算の実行そのもの(SmartHR、freee人事労務、マネーフォワード クラウド給与など)、社会保険・労働保険の電子申請(e-Gov・マイナポータル連携)、年末調整の証明書OCR、従業員データを参照したAI回答(社内SaaSのAIアシスタント機能を使えば、入力データを学習に使わない前提で運用しやすい)

### 1. 給与計算結果の検算ロジック作成

給与計算ソフトの出力そのものをAIに計算させるのではなく、「検算のためのチェック式・チェック観点」を作らせる使い方。実際の給与額や氏名は入力せず、ダミーの数値・列名で依頼する。

```
あなたは給与計算のチェック業務を支援するアシスタントです。
以下はExcelでの給与計算チェック表の列構成です(実データではなくダミーです)。

【列構成】
A列:社員番号 / B列:基本給 / C列:残業時間 / D列:残業単価
E列:残業代(=C×D) / F列:社会保険料(標準報酬月額×料率) / G列:所得税(源泉徴収税額表に基づく)
H列:差引支給額(=基本給+残業代-社会保険料-所得税)

依頼:
1. E列・H列の計算が正しいかを検証するIF関数のチェック式を提案してください
   (一致していれば「正」、不一致なら「要確認」と表示する形)
2. 前月比で急激に増減した社員を検知するための条件式(閾値付き)を提案してください
3. 生年月日と入社日など、矛盾があり得る組み合わせのチェック観点を3つ挙げてください

実在の氏名・金額は入力していません。関数・ロジックの提案のみを行ってください。
```

### 2. 雇用契約書・労働条件通知書のドラフト作成

```
あなたは労務担当者です。以下の条件で雇用契約書(労働条件通知書を兼ねる)の
ドラフトを作成してください。最終的な法的確認は別途行う前提です。

【雇用形態】正社員(無期雇用)
【職種】経理事務
【就業場所】本社(東京都〇〇区)
【就業時間】9:00〜18:00(休憩1時間、フレックスタイム制なし)
【賃金】月給28万円(固定残業代5万円/30時間分を含む。超過分は別途支給)
【契約期間】期間の定めなし
【試用期間】入社日から3か月

労働基準法第15条・労働基準法施行規則第5条で明示が義務付けられている事項
(就業場所・従事すべき業務、始業・終業時刻、賃金の決定・計算・支払方法、
退職に関する事項など)に抜け漏れがないか、最後にセルフチェックしてください。
```

### 3. 年末調整の記入内容チェック・社員向け案内文

扶養控除等申告書や保険料控除申告書そのもの(氏名・マイナンバー・家族情報を含む)はAIに読み込ませない。記入ルールの説明文や、よくある記入ミスのチェックリスト作成にとどめる。

```
年末調整の「給与所得者の扶養控除等(異動)申告書」について、
経理・労務の知識がない社員向けに、記入時に間違えやすいポイントを
Q&A形式で5つ作成してください。

条件:
・実際の申告書の画像やPDFは渡していません(渡す予定もありません)
・「扶養親族の年齢区分による控除額の違い」「配偶者の年収の見込み方」など、
  一般的な記入ルールの説明にとどめてください
・社内FAQ・イントラネット掲載を想定した、丁寧だが簡潔な文体にしてください
```

### 4. 勤怠データの異常検知・残業時間分析(個人特定情報を含めない集計データで)

個人が特定できる生データ(氏名付きの日次打刻)をそのまま外部のチャットAIへ投げるのは避け、部署・職位単位に集計してから分析させるのが安全な運用。

```
以下は部署別・月別の残業時間の集計データです(個人名は含みません)。

【データ】
部署,月,平均残業時間(h),36協定上限に対する超過者数
営業部,2026年8月,32,3
開発部,2026年8月,45,7
管理部,2026年8月,18,0
(以下略)

依頼:
1. 36協定の上限に近い・超過している部署を優先順位付けしてください
2. 前月比で急増している部署があれば指摘してください
3. 経営会議向けに3行でサマリーを作成してください
4. 個人を特定するような表現は使わないでください
```

### 5. 社会保険の手続き案内文書の下書き

入社・退社・扶養異動に伴う社会保険・雇用保険の手続きについて、社員向けの案内文をたたき台として作らせ、実際の制度・自社ルールと突き合わせて労務担当者が確定する。

```
中途入社した社員向けに、入社後2週間以内に提出してほしい書類と、
それぞれの提出理由をやさしく説明する案内メールの文面を作成してください。

【提出書類】
・扶養控除等(異動)申告書
・雇用保険被保険者証(前職で交付されている場合)
・年金手帳またはマイナンバー確認書類(提出方法は別途案内するため、
  このメールには持参・提出のお願いのみを記載し、マイナンバーの実際の番号は
  絶対に記載しない・尋ねない形にしてください)

トーン: 事務的になりすぎず、初めての手続きでも安心できる文体
```

### 6. 社内規程Q&Aチャットボット(RAG)

就業規則・給与規程・休暇制度に関する問い合わせは、汎用チャットAIに丸投げするとハルシネーション(事実と異なる内容をもっともらしく生成する現象)のリスクが高いため、社内文書を参照させるRAG型の仕組みが向く。

- **SmartHR「AIアシスタント」**: 労務担当がアップロードした就業規則・給与規程・マニュアル等を参照し、社員からの問い合わせにチャット形式で自動回答する。年末調整の質問対応にも同機能が使われており、2026年8月時点では社員が自分の給与明細・賞与明細・源泉徴収票を検索する機能も追加されている
- **Microsoft 365 Copilotの従業員セルフサービスエージェント**: Copilot Studioでカスタマイズし、給与・休暇・社会保険手続きに関する問い合わせに対応させる
- **自社構築のRAGチャットボット**: Difyなどのノーコードツールで給与規程・休暇規程のPDFを読み込ませ、自社専用のQ&Aボットを構築するケースもある(構築方法はPart 10「ノーコード・ローコード開発」、RAGの精度改善はPart 7「RAGの精度改善と基盤」を参照)

### ツール横断の対応表

| やりたいこと | 主に使うツール |
|---|---|
| 給与計算の実行 | SmartHR、freee人事労務、マネーフォワード クラウド給与など専用ソフト(AIには任せない) |
| 給与計算の検算ロジック・チェック式の作成補助 | ChatGPT / Gemini / Claude(ダミーデータで依頼) |
| 年末調整の証明書読み取り・質問対応 | SmartHR「AIアシスタント」+AI-OCR、マネーフォワード クラウド給与(スマホ入力) |
| 社会保険・雇用保険の書類作成・電子申請 | freee人事労務(e-Gov・マイナポータル連携)、SmartHR |
| 雇用契約書・労働条件通知書・案内文のドラフト | ChatGPT / Gemini / Claude / Microsoft 365 Copilot(Word) |
| 社内規程・給与規程のQ&A自動応答 | SmartHR AIアシスタント、Microsoft 365 Copilot 従業員セルフサービスエージェント、Dify等での自社RAG構築 |
| 勤怠データの異常検知・残業分析(集計データ) | 勤怠管理SaaSの分析機能、ChatGPT/Gemini等での集計値分析 |

## 注意点・よくある誤解

- **マイナンバー(特定個人情報)は生成AIに入力しない**: マイナンバーは番号法上、通常の個人情報よりも利用目的・提供先が厳格に制限された「特定個人情報」であり、外部のAIサービスへの入力は目的外の第三者提供とみなされるリスクが高い。案内文やチェックリストの作成では「マイナンバーの実際の番号を記載・入力しない」条件を毎回プロンプトに明記する運用にする
- **給与額・口座情報など機微な数値情報は実データのまま入力しない**: ダミーの数値・列名に置き換えてから、計算式やチェックロジックの相談に使う。個人情報保護委員会は2023年6月、本人の同意なく個人データを含むプロンプトを生成AIに入力し、応答生成以外の目的(学習等)に利用されると個人情報保護法違反になり得ると注意喚起している。法人契約でオプトアウト設定(入力データを学習に使わない設定)が確認できているツール以外には、実在の従業員の機微情報を入力しない(詳細はPart 4「生成AI利用における情報漏洩対策」を参照)
- **給与計算そのものをAIに計算させない**: 生成AIは確率的に「それらしい」文章・数値を生成する仕組みであり、四捨五入や端数処理、社会保険料率の適用範囲などを間違って計算しても、もっともらしい体裁で出力してしまう。計算の実行は必ず給与計算ソフト(専用の計算エンジン)に任せ、AIは検算ロジックの相談・チェック観点の洗い出しに限定する
- **ハルシネーションによる誤案内のリスク**: 「弊社の育児休業の取得可能期間は?」のような社内規程の問い合わせを汎用チャットAIだけで運用すると、法定制度と自社制度を混同したり、存在しない手当をもっともらしく回答したりすることがある。社内規程Q&Aは必ず一次情報(自社の規程文書)を参照させるRAG構成にし、回答に出典(規程の該当箇所)を表示させる
- **法改正への追従が遅れやすい**: 社会保険料率・所得税の源泉徴収税額表・年末調整の控除額などは毎年見直される。汎用チャットAIの知識には学習時点のカットオフがあり、最新の制度改正が反映されていない場合があるため、税率・控除額などの数値は必ず給与計算ソフトの自動アップデート機能や国税庁・日本年金機構等の一次情報で確認する
- **「最終確認は必ず人が行う」を業務ルールとして明文化する**: 提出前の書類内容確認や行政への申請そのものは、AIの提案を参考情報として扱い、必ず労務担当者本人が最終確認する。ミスがあった場合の責任の所在を明確にしておくことが、後のトラブルを防ぐ

## 最初の一歩

まずは個人情報を含まない業務から着手する。実データを含まないダミーの給与計算チェック表を用意し、上記の検算ロジック作成のプロンプト例をそのまま試してみる。あるいは、就業規則の中から社員によく聞かれる質問を1つ選び、Q&A形式の案内文をチャットAIに下書きさせてみるのもよい。
