# 金融アドバイザー・FP(ファイナンシャルプランナー)における生成AI活用事例

## これは何か

証券会社・銀行の営業担当、IFA(Independent Financial Advisor=独立系ファイナンシャルアドバイザー)、独立系FP(ファイナンシャルプランナー)など、**個人の顧客に対面で資産運用・保険・ライフプランを提案する仕事**は、提案書やシミュレーションの「たたき台作成」を生成AIで大きく速くできる一方、成果物がそのまま顧客の意思決定(=お金を動かす判断)に直結し、かつ金融商品取引法・金融サービス提供法といった顧客保護のための規制が直接かかるという特殊性を持つ。他の営業職であれば「言い過ぎた」程度で済む表現の誤りが、この職種では法令違反(断定的判断の提供、無登録での投資助言)に直結しかねない。本ページでは、提案書・シミュレーション説明文のドラフト作成から商談記録の自動化、コンプライアンスチェックまでの実務活用と、金融庁が2026年3月に示した最新の考え方、この職種特有の規制リスクを整理する。

**[経理・財務職における生成AI活用事例](finance-accounting-ai-use-cases.md)(第7章)との違い**: あちらは自社の証憑処理・決算・予実分析など**社内向け**の数値業務を扱う。本ページは、対価をもらって**顧客個人**に資産運用・保険・ライフプランを提案する対顧客業務を扱う。業種の全体像(銀行・証券・保険業界でのAI活用)は[金融・保険における生成AI活用事例](../part14-industry-cases/finance-insurance-ai-use-cases.md)(Part 14第3章)を参照。本ページはその中の「顧客対応する担当者個人の仕事」に絞って書く。

## 仕組み・背景

この職種の生成AI活用は、大きく2つの層で進んでいる。

1. **担当者個人が汎用チャットAIを使う層**: 資産配分の提案書ドラフト、ライフプランシミュレーション結果の説明文、商品比較資料、商談メモの整理など、「情報を整理し文章化する」作業にChatGPT・Gemini・Claude・Copilotなどを使う。金融庁も、AIに「この銘柄を買うべきか顧客に提案して」と判断させるのではなく、「決算書のポイントを整理して」「顧客向けの説明文のドラフトを作って」と依頼する使い方に限定するのが実務上の適切な線引きだとしている。
2. **金融機関が業務システムに組み込む層**: 2026年に入り、証券・銀行各社が生成AIを営業支援システムに組み込む動きが本格化している。
   - **SBI証券**は2024年12月、生成AIを活用した投資情報サービス(個別銘柄の好材料・悪材料のニュース分析、マーケットの見通し・振り返りの要約)の提供を開始した(口座の有無を問わず無料で利用可能、AlpacaTechが技術サポート)。
   - **静岡銀行**は2024年10月からSnowflake・ブレインパッドと連携し、過去の営業活動データを学習して最適な商品・サービス提案につなげる「生成AIチャットボット」の開発に着手。顧客データを扱うため閉域環境で構築できる「Snowflake Cortex」を採用している。
   - **七十七銀行**はNTT東日本と連携し、稟議書・提案書のドラフトを行内データ(財務情報・面談記録・企業情報等)から自動生成する仕組みを含め、本部55業務以上に生成AI活用を拡大している。
   - **野村ホールディングス**はOpenAIとの戦略連携や東京大学との共同研究で株式AIエージェントの開発を進めており、野村総合研究所(NRI)は業界特化型LLMを証券・保険の「営業会話チェック機能」などの検証に組み込んでいる。
   - **IFA向け**では、フィナテキスト系のナウキャストが、オンライン商談の会話書き起こしと担当者メモから生成AIが商談結果資料を自動作成するサービスを提供している。

これらはいずれも「AIが最終判断をする」のではなく「AIが下書き・整理を行い、資格を持つ人間が確認・説明・最終判断を行う」設計になっている点が共通する。金融庁は2025年3月に公表した「AIディスカッションペーパー」を2026年3月に第1.1版へ改訂し、対顧客向け生成AIサービスのリスクを整理する「4つの視点」の提示、関連法令の適用関係の明確化、AIエージェントを含むユースケースの拡充を行った。同ペーパーでは、バックオフィスでの生成AI活用は広がっている一方、顧客の目に触れる対顧客領域での実導入事例はまだ「限定的」だと指摘している。

## 使いどころ・使い分け

### 業務フェーズ別の活用マップ

| フェーズ | 主なタスク | AIの向き・不向き | 理由 |
|---|---|---|---|
| 顧客準備 | 保有資産・家族構成・要望のメモ整理、過去の商談履歴の要約 | 向く | 定型情報の整理・要約は得意。ただし個人情報の入力管理が前提 |
| 商品・市場情報の収集 | 投資信託・保険商品の特徴比較、決算・市況ニュースの要約 | 向く(裏取り必須) | 情報の整理・比較表化は速いが、最新の料率・費用は必ず商品パンフレット・目論見書の原本で確認する |
| 資産配分提案書のドラフト作成 | アセットアロケーション案の説明文、リスク・リターンの解説文 | 向く(下書きのみ・最終判断は資格者) | 文章化は速いが、「この配分を勧める」という投資判断そのものをAIに行わせて顧客に提示すると、無登録での投資助言に該当するリスクがある |
| ライフプランシミュレーションの説明文生成 | シミュレーションソフトが出した数値を分かりやすい文章に変換 | 向く | 数値は既存のシミュレーション結果を使い、AIは「説明文への変換」に限定するのが安全 |
| 商談記録・議事録の自動作成 | 会話の書き起こし、要点整理、フォローアップメールの下書き | 向く | 定型化しやすく、実際にIFA向けサービスとして提供されている |
| コンプライアンスチェック(一次) | 断定的表現・NGワードの検出、説明義務項目の抜け漏れチェック | 向く(一次チェックのみ) | 見落としやすい表現の洗い出しに有効。最終判断はコンプライアンス部門・管理者が行う |
| 個別商品の売買判断・最終提案 | 「この株を買うべきか」「この保険に入るべきか」の最終決定 | **不向き** | 投資助言業の登録・資格者による適合性判断が必要な領域。AIの出力をそのまま顧客提示に使わない |

判断に迷う場合は、Part 12「[生成AIに向く業務・向かない業務の切り分け](../part12-business-practice/ai-task-suitability.md)」の基準に、この職種特有の4つ目の軸「**顧客の資産に関わる最終判断そのものをAIにさせていないか**」を加えて仕分けるとよい。

## 実務での使い方

### プロンプト例1: 資産配分提案書の説明文ドラフト(断定的表現の禁止・免責文言を必須化)

すでに社内で承認されたモデルポートフォリオ・提案方針がある前提で、顧客向けの説明文だけをAIに書かせる使い方。個別の投資判断そのものをAIに決めさせない設計にしている点がポイント。

```
あなたは金融機関の顧客説明資料の作成アシスタントです。以下の情報をもとに、
顧客向けの資産配分提案の説明文ドラフトを作成してください。

# 前提(すでに社内で承認済みの提案内容)
- 提案する資産配分: [例: 国内株式30%、先進国株式30%、国内債券20%、先進国債券20%]
- 顧客の投資目的・リスク許容度: [例: 65歳での退職金活用、安定重視]
- 想定運用期間: [例: 10年]

# 出力条件
- 「必ず上がる」「絶対に損しない」など将来の市場動向を断定する表現は一切使わない
- 過去のパフォーマンスに触れる場合は「過去の実績は将来の成果を保証しない」旨を明記する
- リスク(価格変動リスク・為替リスク等、該当するもの)を必ず記載する
- 手数料・費用がかかる旨を明記する(具体的な金額・料率は空欄にして人が後で記入する)
- 文末に「本資料は情報提供を目的としたものであり、投資の勧誘を目的としたものではありません。
  最終的な投資判断はお客様ご自身の判断でお願いいたします。」を必ず入れる
- 出力後、断定的な表現や誇大な期待を招く言い回しが残っていないか自己チェックし、
  該当箇所があれば別途リストで示す
```

出てきたドラフトは、必ずコンプライアンス部門のチェック手順(社内規程に基づく資料審査)を経てから顧客に提示する。AIが作った文章であっても、最終的な説明責任は資格者(登録外務員・IFA・FP本人)が負う。

### プロンプト例2: ライフプランシミュレーション結果の説明文生成

シミュレーションソフト(FP名人、FP-UNIV等)が出力した数値をそのまま渡し、顧客に分かりやすい説明文へ変換させる。数値そのものをAIに作らせない設計にする。

```
以下はライフプランシミュレーションソフトが出力した数値結果です。この数値をそのまま使い、
お客様向けの説明文を作成してください。

# シミュレーション結果(そのまま使用する数値)
[ここにシミュレーション結果の表・数値を貼り付け]

# 前提条件(お客様に伝えるべき前提)
[年間の収支想定、インフレ率、投資リターンの仮定値などシミュレーションで使った前提]

# 出力条件
- 数値は入力データの値をそのまま使い、新しい数値を作らない・推測で数値を補わない
- シミュレーションが「一定の前提に基づく仮の予測」であり、実際の結果とは異なる可能性がある旨を
  冒頭または末尾に明記する
- 前提条件(インフレ率・想定利回りなど)を必ず本文中に明示する
- 中学生でも理解できる言葉で、専門用語(NISA、iDeCoなど)は初出で一言説明を付ける
```

### プロンプト例3: 商談記録からのフォローアップ資料下書き作成

```
以下は顧客との商談の会話書き起こしと、担当者が取ったメモです。この内容から、
社内記録用の商談メモと、お客様へのフォローアップメールの下書きをそれぞれ作成してください。

# 出力1: 社内商談記録(項目立てで)
- 顧客の要望・懸念点
- 提示した情報・資料
- 次回までのアクション(担当者側・顧客側それぞれ)

# 出力2: フォローアップメール下書き
- 本日の商談への謝辞
- 次回までにお送りする資料の予告
- 断定的な将来予測や投資助言に該当する表現は含めない

【書き起こし・メモ】
(貼り付け)
```

### ツール横断の対応表

| やりたいこと | 主に使うツール |
|---|---|
| 提案書・説明文の下書き作成 | ChatGPT/Gemini/Claude/Copilot(法人向けプランでの利用が原則) |
| 商談の書き起こし・記録の自動作成 | フィナテキスト系(ナウキャスト)のIFA向け非対面商談支援サービスなど業界専用ツール |
| 個別銘柄ニュースの分析・要約 | SBI証券の生成AI投資情報サービス(無料、口座不問) |
| 社内データと連携した提案書・稟議書のたたき台生成 | 静岡銀行×Snowflake Cortexの生成AIチャットボット、七十七銀行×NTT東日本の全行導入事例など、各金融機関が独自に構築する社内システム(社外では利用不可) |
| 営業トーク・提案文言のコンプライアンス一次チェック | NRIの業界特化型LLMによる営業会話チェック機能など各社の内製ツール |
| ライフプランシミュレーションの数値計算そのもの | FP名人・FP-UNIVなど専用シミュレーションソフト(生成AIは説明文化のみを担う) |

## 注意点・よくある誤解

- **AIに個別の投資判断をさせて顧客に出すと「無登録での投資助言」に該当しかねない**: 金融商品取引法上、対価を得て個別具体的な投資判断について助言を行う業務は投資助言業の登録が必要になる。「この株を買うべきか」をAIに答えさせ、その回答をそのまま顧客に提示する行為はこの規制に抵触するリスクがあると法律専門家が指摘している。AIの役割は「情報の整理・文章化」に限定し、投資判断そのものは資格者が行う。
- **AIが書く文章は「断定的判断の提供」の禁止規定に触れやすい**: 金融商品取引法第38条は、不確実な事項について断定的な判断を示し、または確実であると誤解させるような説明を行う勧誘行為を禁止している。生成AIは説得力のある自然な文章を作るのが得意な一方、「必ず上がります」「絶対に安全です」といった断定表現を(悪意なく)混ぜてしまうことがある。プロンプトで明示的に禁止し、出力後も人が目視で確認する。
- **適合性の原則・説明義務は「顧客ごとの事情」を反映できているかが問われる**: 金融商品取引法第40条の適合性の原則、および金融サービスの提供に関する法律第4条の説明義務は、顧客の知識・経験・財産の状況・取引目的に照らして適切な勧誘・説明を行うことを求めている。AIは目の前の顧客の資産状況やリテラシーを本当には理解していないため、テンプレート的な説明文をそのまま使うと、この顧客には情報量が多すぎる・少なすぎるといったミスマッチが生じやすい。AIの出力は「その顧客向けに調整する前の素材」として扱う。
- **顧客の資産・家族構成などの個人情報をAIに入力するリスク**: 金融庁のAIディスカッションペーパー(第1.1版、2026年3月)は、顧客情報をプロンプトに含める場合、生成AIサービスの提供事業者を個人データの委託先として管理し、金融機関の指示なく追加学習に使われないことをサービス選定・契約時に確認する必要があると指摘している。個人向け無料プランでの利用は避け、学習非利用が契約で保証された法人向けプランを使う。
- **AIが作成した資料であることの開示をどう扱うかは発展中の論点**: 同ペーパーは、対顧客向け生成AIサービスの実導入例は現時点でまだ限定的であり、生成AIが関与したことの顧客への開示や説明の仕方を含め、リスクを「4つの視点」から整理する段階にあるとしている。自社のコンプライアンス部門の最新方針を必ず確認し、独自判断で運用を決めない。
- **商品情報・料率のハルシネーションは金銭トラブルに直結する**: 投資信託の信託報酬、保険の保険料率などをAIが誤って生成すると、顧客への誤説明につながる。数値・料率は必ず最新の目論見書・パンフレットの原本で確認してから使う。

## 最初の一歩

直近で作成した提案書・説明資料を1つ選び、プロンプト例1の「断定的表現の禁止・免責文言の必須化」の条件を付けてAIにドラフトを作らせてみる。出てきた文章に断定的な表現が残っていないかを自分の目でチェックし、社内のコンプライアンス確認手順に沿って提示可否を判断する。
