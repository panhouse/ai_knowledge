# 銀行員(窓口・融資担当)における生成AI活用事例

## これは何か

銀行・信用金庫の窓口担当者(テラー)と融資担当者(ローンオフィサー)は、来店した顧客への対応・本人確認(KYC: Know Your Customer、顧客の身元や取引目的を確認する手続き)・住宅ローンや事業性融資の審査資料づくりという、紙の書類と行内規定に縛られた業務を数多く抱えている。ミスが顧客の資産や融資判断に直結するため、これまで自動化が進みにくかった領域だが、2025〜2026年にかけて融資稟議書(融資の可否を判断するための社内提案書)のドラフト作成、行内規定・マニュアルの検索、本人確認書類の読み取りといった場面で生成AIの実導入が急速に広がっている。本ページは、この2つの職種に特有の業務フェーズに沿って、どこに生成AIが入り込んでいるか、どこまでは汎用チャットAIで足り、どこから専用システムが必要かを整理する。

**隣接ページとの境界**: 本ページは銀行・信用金庫という**金融機関側の窓口・融資担当者**の業務に焦点を当てる。事業会社の経理・財務部門の業務は「[経理・財務職における生成AI活用事例](finance-accounting-ai-use-cases.md)」で扱い、顧客に投資助言を行うファイナンシャルアドバイザー(FP・IFA)の業務は別ページの対象とする。業界全体の動向(不正検知・コールセンター・保険査定なども含む俯瞰)は「[金融・保険における生成AI活用事例](../part14-industry-cases/finance-insurance-ai-use-cases.md)」を参照し、本ページはその中でも**窓口・融資という個人の業務フローに絞った実務ガイド**という位置づけである。

## 業務フェーズ別の活用マップ

窓口担当と融資担当では業務の流れが異なるため、それぞれのフェーズ別にAIの入り込み方を整理する。

### 窓口担当(テラー)の業務フロー

| フェーズ | 具体的な業務 | AIの役割 | 2026年時点の実装度 |
|---|---|---|---|
| 受付・ヒアリング | 来店目的の確認、必要書類の案内 | 汎用チャットAIで「この用件にはどの書類が必要か」を下調べ可能 | 一部行で先行導入 |
| 本人確認(KYC) | 運転免許証・マイナンバーカード等の読み取り、記載事項の突合 | AI-OCR(画像から文字情報を読み取る技術)+生成AIで書類の転記・整合性チェックを自動化 | 百五銀行×日立などで実証済み、2026年度から順次実業務展開 |
| 規定・マニュアルの確認 | 「この手続きに必要な特例は何か」を行内規定から調べる | RAG(検索拡張生成。社内文書を検索してAIに回答させる仕組み)型チャットボットが規定・マニュアルを検索し即答 | 京都銀行・呉信用金庫など複数行で本導入済み |
| 事務処理・記録 | 手続き内容のシステム入力、応対記録の作成 | 音声認識+生成AIで会話内容を要約し、記録作成の下書きを自動生成 | コールセンター向けは先行、窓口向けは拡大中 |
| 資産運用・商品相談 | 投資信託・保険等の提案 | 生成AIが商品説明の下書きを提示するが、最終提案は行員が判断(高度な相談は専用ツール領域) | 限定的(実証・一部拠点) |

### 融資担当(ローンオフィサー)の業務フロー

| フェーズ | 具体的な業務 | AIの役割 | 2026年時点の実装度 |
|---|---|---|---|
| 融資相談受付 | 事業性融資・住宅ローンの新規相談、借換相談 | 汎用チャットAIでヒアリング項目の整理や説明文のドラフト作成 | 一般的 |
| 事前審査・診断 | 住宅ローンの通過可能性診断、融資可能額の提示 | AIスコアリング(統計・機械学習モデルによる自動採点)による事前診断サービス | みずほ銀行「住宅ローンAI事前診断」、住信SBIネット銀行など複数行で提供中 |
| 資料収集・データ入力 | 決算書・事業計画書・物件資料・本人確認書類の読み取りとシステム入力 | 生成AI+AIエージェント(自律的に複数の作業工程を実行するAI)がフォーマットの異なる書類から転記し、申込内容との整合性を確認 | 百五銀行×日立で1件あたりの作業時間を約20分→7分以下に短縮(2025年8月〜2026年2月の効果検証、2026年度から本展開) |
| 財務分析・稟議書ドラフト作成 | 決算書の分析、過去の類似稟議書を参照した稟議案の作成 | 生成AIが過去の稟議書・社内規定を参照(グラウンディング)して稟議書の初稿を自動生成 | 宮崎銀行(作成時間95%短縮)、ふくおかフィナンシャルグループ(35%短縮)、あいち銀行(審査役の指摘数25%削減、最大年間13,400時間削減)、京都銀行、三菱UFJ銀行×Sakana AIなど本導入・実証が急拡大中 |
| 審査部への提出・質疑対応 | 審査部からの質問への回答、追加資料の準備 | 過去の質疑応答パターンを参照した回答案の下書き | 一部行で検討段階 |
| 契約後モニタリング | 融資後の業況確認、期日管理 | 定型的な業況レポートの下書き作成 | 限定的 |

## 使えるツール・構成:汎用チャットAIで足りる部分と専用ツールが必要な部分

| 業務 | 汎用チャットAI(ChatGPT Enterprise・Copilot・Gemini等)で足りるか | 専用ツールが必要になる理由 |
|---|---|---|
| 一般的な文章のドラフト作成(顧客への案内文、社内メール) | 足りる | — |
| 行内規定・マニュアルの検索・即答 | 足りない(社内文書との連携が必要) | 行内の規定・マニュアル数千件をRAGで検索できる専用チャットボット(京都銀行のPKSHA Chatbot、呉信用金庫のOfficeBotなど)が必要。汎用AIに規定文書を毎回貼り付けるのは非効率で情報漏洩リスクも高い |
| 融資稟議書のドラフト作成 | 足りない | 決算書データ・CRM(顧客関係管理システム)・過去の類似稟議書を自動で参照させる「グラウンディング」の仕組みが必要。単体のチャットAIに手元の資料を貼り付けるだけでは、過去の類似案件との整合性や社内フォーマットへの準拠が担保できない |
| 本人確認書類・物件資料の読み取り・転記 | 足りない | AI-OCRと基幹システムへの入力を連携させる専用のワークフロー(日立のBranch in Mobileサービス等)が必要。汎用チャットAIの画像認識機能で代用すると、精度検証や個人情報の取り扱いルールが不十分になりやすい |
| 住宅ローンの事前審査・通過可能性診断 | 足りない | 信用スコアリングは個社の与信モデル(統計・機械学習)に基づくため、各行が提供する専用の診断サービスを使う必要がある |
| 顧客との対話の要約・記録作成 | 一部足りる(議事録要約は汎用AIでも可能) | リアルタイムの音声認識と連携させる場合は専用のコンタクトセンター向けAIスイート(PKSHA AI Suite等)が必要 |

**判断の目安**: 「行内の機密情報・顧客の個人情報・過去案件データを参照する必要があるか」で線引きするとよい。参照が不要な一般的な文章作成・アイデア出しは汎用チャットAI(法人向け・学習利用オプトアウト設定のプランに限る)で十分だが、行内データとの照合が必要な業務は専用システムの導入が前提になる。

## 実務での使い方

### 1. 行内規定・マニュアルの検索(RAG型チャットボット)

京都銀行は2025年2月、行内向けAIチャットボットに生成AIによる文書検索・回答機能を追加し、全従業員約4,300人を対象に運用を開始した。導入前はチャットボットへの1日平均約400件の照会のうち自動回答できたのは30〜40%程度だったが、生成AI導入後の検証では検索精度86%を達成し、行員の9割が導入を希望した。参照元の規定・マニュアルは導入時点の約1,000種類から2025年内に約4,000種類まで拡大する計画で、年間8,000時間の業務削減効果が見込まれている。呉信用金庫もRAG型生成AIサービス「OfficeBot」を導入し、規程・マニュアルに関する問い合わせ対応を自動化している。

**この業務は汎用チャットAIでは代替しにくい**理由は、行内規定が数千種類に及び、かつ改訂が頻繁なため、都度資料を貼り付ける運用では実務に追いつかないことにある。行内規定検索の専用チャットボットを導入する際は、まず問い合わせ件数の多い分野(融資手続き、口座開設、相続関連など)から規定・マニュアルを整備し、段階的に対象を広げるのが実務上の定石になっている。

### 2. 融資稟議書ドラフト作成(コピペ用プロンプト例)

融資稟議書は、多くの銀行で「過去の類似稟議書・行内規定を参照させる」形の専用システムを使うが、社内で汎用チャットAIを使って初稿の骨子を作る場合は、以下のような形でヒアリングメモから稟議案の骨子を作らせると、行員の作成時間を短縮できる(実例では平均60分から15〜20分に短縮された事例がある)。実際の稟議書提出には、必ず行内規定に沿ったフォーマットへの反映と、上席・審査部による確認を挟む。

```
あなたは銀行の融資担当者の稟議書作成を支援するアシスタントです。
以下の顧客ヒアリングメモと決算データを基に、融資稟議書の「概要」セクションの
初稿を作成してください。

# 条件
- 記載する情報は入力データにあるものだけを使い、記載のない数値・事実を推測で補わない
- 構成は「借入目的」「借入希望額・期間」「業況の概要」「懸念点(あれば)」の4項目とする
- 業況の評価は決算データの数値のみから読み取れる内容にとどめ、
  定性的な評価(経営者の資質等)は「ヒアリングで確認が必要」と明記する
- 文体は行内の稟議書フォーマットに合わせた簡潔な報告文とする

# ヒアリングメモ
[顧客との面談内容をここに貼り付け]

# 決算データ(直近3期)
[売上高・利益・借入残高等の数値をここに貼り付け]
```

出力された初稿は「たたき台」であり、財務分析の妥当性・懸念点の網羅性は必ず融資担当者・上席が確認し、行内規定に定められた必須記載事項が漏れていないかをチェックしてから審査部に提出する。

### 3. 融資稟議書作成AIの主要な導入事例(2026年時点)

| 銀行・信用金庫 | 導入形態 | 効果・特徴 |
|---|---|---|
| あいち銀行 | NTTデータの「LITRON Generative Assistant on finposs」(RAG活用)を2026年7月27日から導入 | 試行利用で審査役による指摘数を約25%削減、最大で年間13,400時間の業務削減効果を見込む |
| 京都銀行 | NTTデータと共同開発した稟議書作成AIサービスを2026年7月から本番導入 | 品質向上と効率化を同時に実現する仕組みとして構築 |
| 宮崎銀行 | 日本IBMと共同で内製開発し2024年4月から一部店舗で利用開始 | 稟議書作成時間を約95%短縮。要件定義から利用開始まで約2カ月というスピード導入 |
| ふくおかフィナンシャルグループ | 日本IBMと協業。2024年5月から一部拠点で利用開始 | 過去の類似稟議書を検索・参照する「グラウンディング」技術を採用。顧客名を入力するとCRM・Excelから財務データを自動取得しAIへのプロンプトを自動生成。作成時間を35%短縮 |
| 三菱UFJ銀行 | Sakana AI(2025年に包括的パートナーシップを締結)と共同開発した「AI融資エキスパート」を2026年4月から実案件の検証フェーズで運用 | 約100名が参加したPoC(概念実証)を経て実案件検証へ移行。今後全国の営業店へ段階展開の方針 |

### 4. 本人確認書類・住宅ローン申込書類の読み取り・転記

百五銀行と日立製作所は、本人確認書類や物件資料・図面などフォーマットの異なる書類を生成AIとAIエージェントで読み取り、システムへの転記と申込内容との整合性確認までを自動化する取り組みを進めている。2025年8月〜2026年2月に住宅ローン業務を対象に効果検証を行った結果、1件あたりの作業時間を約20分から7分以下(約3分の1)に短縮できることを確認し、2026年度から実業務での運用を順次開始する。行員はAIの処理結果に対する最終確認・判断に専念する設計になっており、日立は2026年度中にこの機能を「Branch in Mobileサービス」に追加し他の金融機関にも展開する計画を示している。

住宅ローンの事前診断では、みずほ銀行の「住宅ローンAI事前診断」のように、入力内容から正式審査が通る確率を最短1分程度で診断できるサービスが定着している。住信SBIネット銀行も、物件を選ぶ前の段階で融資可能額を提示するサービスを提供している。これらは生成AIというよりも統計・機械学習によるスコアリングが中心だが、申込内容のヒアリング・説明文の作成部分に生成AIが組み合わされている点が実務上のポイントになる。

### 5. ツール横断の対応付け

| やりたいこと | 主に使われるツール・仕組み |
|---|---|
| 行内規定・マニュアルの検索 | 行内導入のRAG型チャットボット(PKSHA Chatbot、OfficeBot等)。ChatGPT・Copilot等の汎用チャットAIに社内文書を都度貼り付ける運用は非効率でリスクも高いため推奨されない |
| 融資稟議書のドラフト作成 | 各行が導入する専用の稟議書作成AI(LITRON Generative Assistant、IBM watsonxベースのグラウンディング機構等)。個人が汎用チャットAIで骨子を作る場合は必ず行内ルールで許可された範囲・環境で行う |
| 本人確認書類・申込書類の読み取り | AI-OCR+AIエージェント(日立Branch in Mobile等)。個人情報を含む書類を個人が汎用チャットAIにアップロードすることは原則禁止される運用が多い |
| 住宅ローンの事前診断 | 各行の専用診断サービス(みずほ銀行「住宅ローンAI事前診断」等) |
| 顧客対応の記録・要約 | コンタクトセンター向けAIスイート(音声認識+生成AI)。窓口では議事録要約に汎用チャットAIを使う行内許可済みの環境が使われることもある |

## 注意点・よくある誤解

- **個人情報・機密情報を汎用の生成AIサービスに入力しない**: 顧客の氏名・口座情報・本人確認書類の画像・決算情報などを、行内で許可されていない外部の生成AIサービスにそのまま入力することは、多くの銀行で内規上禁止されている。愛媛銀行がMicrosoft Azure OpenAIで専用環境を構築し、AI利用に関する行内ポリシー・規定の制定と生成AIポータルの整備を行っているように、まず「行内で使ってよいAI環境はどれか」を確認することが大前提になる。
- **稟議書・審査結果は「最終判断」ではなく「たたき台」**: 融資の可否は顧客の事業継続や資金繰りに直結するため、AIが生成した稟議書の初稿・診断結果をそのまま最終判断として使うことは想定されていない。各行の事例でも、AIの処理結果を行員・審査部が最終確認・判断する前提で設計されている。
- **数値の裏取りは省略できない**: 決算書の数値や物件情報など、AIが読み取り・要約した内容は必ず原本(決算書・申込書・本人確認書類)と突き合わせて検証する。特にAI-OCRの誤読(桁の誤認識、氏名の一部欠落など)は本人確認・融資額の誤りに直結するため、確認フローを事前に業務ルールとして定めておく。
- **説明責任・公平性への配慮**: 金融庁は2025年6月に「AI官民フォーラム」を立ち上げ、2026年3月には「AIディスカッションペーパー(第1.1版)」を公表しており、生成AIのハルシネーション(もっともらしい誤情報の生成)やバイアスによる不公正な判断のリスク、それに対する責任の所在の明確化を論点として挙げている。融資審査でAIの判断結果に頼りすぎると、顧客や当局への説明が難しくなるリスクがあるため、判断の根拠(どのデータを参照したか)を残せる設計・運用にする。
- **法規制の順守**: 融資業務は貸金業法・銀行法、本人確認業務は犯罪収益移転防止法(いわゆる本人確認法)の適用を受ける。AIによる自動化はあくまで事務作業の効率化であり、法定の確認事項・記録保存義務が省略されるわけではない点を運用ルールに明記する必要がある。
- **PoC(概念実証)止まりで終わるリスク**: 融資稟議書作成AIは、複数行がPoCで良好な結果を得ているが、実案件への本格展開には行内規定の整備やリスク管理体制の構築に時間がかかる。三菱UFJ銀行×Sakana AIの事例のように、PoC後にどの拠点・業務から段階的に展開するかの計画まで確認しておくと、導入の現実的なスケジュール感がつかめる。

## 最初の一歩

自分が繰り返し行内規定やマニュアルを調べている業務を1つ挙げ、行内で導入済み(または導入予定)のAIチャットボット・検索機能があるかをまず情報システム部門に確認してみる。まだ導入されていない場合は、その業務が「規定・マニュアルの検索に時間がかかっている」典型例として、導入検討の材料に使える。
