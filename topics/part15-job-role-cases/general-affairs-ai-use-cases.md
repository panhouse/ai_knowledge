# 総務職における生成AI活用事例

## これは何か

総務(General Affairs)は、オフィス・設備の管理、契約書類のファイリングと期限管理、社内イベントの企画・運営、什器備品や固定資産の管理、来客・郵便物対応、社内アナウンスや社内報の作成、取引先(ベンダー)窓口、名刺・社印(電子印鑑)の管理、防災マニュアル(BCP)の整備、慶弔規定・福利厚生の運用案内など、「会社という組織を日々動かすための実務」を一手に引き受ける仕事である。[バックオフィス職における生成AI活用](./backoffice-ai-use-cases.md)は人事・総務・経理・法務を横断した総論であり、総務については規程ドラフトと社内FAQボットに軽く触れるのみにとどまる。本ページは総務特有の業務――設備・備品の問い合わせ対応、契約書のファイリングと更新期限管理、社内イベント・株主総会関連文書の下書き、来客・郵便物対応の自動化、社内報・社内アナウンスの作成、防災マニュアルの改訂、慶弔規定・福利厚生の案内、名刺・電子印鑑の管理――に絞って深掘りする。契約書の法的リスク判断や締結可否の助言は[法務職における生成AI活用事例](./legal-ai-use-cases.md)に委ね、本ページは総務が担う「台帳管理・ファイリング・一次対応」の範囲にとどめる。

## 仕組み・背景

総務業務での生成AI活用は、性質の異なる2つの使い方に分かれる。

1. **汎用チャットAI(ChatGPT/Gemini/Claude/Copilot)によるドラフト生成**: 社内規程・防災マニュアルの改訂案、社内報・社内アナウンスの原稿、株主総会の招集通知・議事録のたたき台、契約書からの要点抽出など、その場でテキストを渡して文章を作らせる使い方。
2. **業務システムに組み込まれたAI機能**: 契約書管理・電子契約サービス(クラウドサイン、GMOサイン、マネーフォワード クラウド契約など)のAIによる契約情報自動抽出、名刺管理サービス(Sansan)のAI+オペレーターによるデータ化、郵便物仕分けサービス(トドケール)のAI画像判定、来客対応を代行するAI受付システム、社内規程を参照して問い合わせに自動応答するRAG(検索拡張生成、社内文書を検索してから回答を生成する仕組み)型の社内FAQボットなど、総務向けSaaSに標準搭載されつつある機能。

帝国データバンクの調査(2026年3月)では、業務で生成AIを活用している企業は34.5%(大企業では46.5%)まで増加し、活用企業のうち86.7%が「業務への効果が出ている」と回答している([帝国データバンク](https://www.tdb.co.jp/report/economic/20260514-genai/))。LINEヤフーは人事総務領域で2026年春までに新たに10件のAI活用ツールを順次運用開始すると発表しており、人事総務部門全体で月間1,600時間以上の工数削減を見込んでいる([LINEヤフー](https://www.lycorp.co.jp/ja/news/release/020104/))。総務は「大量の定型的な問い合わせ・文書作成」を抱える一方、契約締結の可否や災害時の安否確認・初動対応など「人が最終判断すべき場面」も多く、どちらの性質の業務かを見極めて使い分けることが実務上のポイントになる。2026年に入ってからは、契約書管理システムがAIエージェントとの連携用API(MCP=Model Context Protocol、AIが外部サービスと安全にデータをやり取りするための標準規格)を提供し始めるなど、「AIに情報を抽出させる」段階から「AIエージェントに業務プロセスの一部を任せる」段階への移行が総務向けSaaSでも進みつつある。

## 使いどころ・使い分け

### 総務業務のシーン別・AI活用マップ

| 業務 | AIの向き・不向き | 主に使うAI機能・ツール |
|---|---|---|
| 会議室・社用車の予約ルール、備品の貸出・購入ルールの問い合わせ対応 | 向く(定型FAQ) | 社内FAQボット(RAG) |
| 備品・固定資産の棚卸し・台帳管理 | 向く(画像認識+台帳突合) | 画像認識AI搭載の備品管理システム |
| 契約書のファイリング・更新期限の管理 | 向く(定型情報の抽出・台帳化) | クラウド契約書管理システムのAI抽出機能 |
| 契約内容の法的リスク判断・締結可否の最終判断 | 不向き(総務の業務範囲を超える) | 法務・弁護士に委ねる(→[法務職における生成AI活用事例](./legal-ai-use-cases.md)) |
| 社内イベント案内文の下書き | 向く(たたき台まで) | 汎用チャットAI |
| 株主総会 招集通知・議事録・想定問答集の下書き・自動生成 | 向く(たたき台まで、確定は法務・IR) | 汎用チャットAI、AvaTwin Chatbot、exaBase IRアシスタント |
| 来客対応・取次 | 向く(一次対応) | AI受付システム |
| 郵便物・宅配便の仕分け・データ化 | 向く | AI-OCR搭載の郵便物仕分けシステム |
| 社内報・社内アナウンス文の作成 | 向く | 汎用チャットAI |
| 名刺情報のデータ化・全社共有 | 向く | Sansan等の名刺管理AI |
| 防災マニュアル・BCP(事業継続計画)の改訂ドラフト | 向く(たたき台まで、内容確定は人) | 汎用チャットAI |
| 慶弔規定・福利厚生の問い合わせ対応 | 向く(一次回答) | 社内FAQボット(RAG) |
| 災害発生時の安否確認・初動対応の最終判断 | 不向き | 人(総務責任者・BCP責任者) |

判断の軸はバックオフィス他部門と同様に、「大量の定型的な問い合わせ・下書きを人に代わってAIがさばく」仕事は任せやすく、「一つの結論を確定させる、または人命・法的責任に関わる」判断は人が主導する、という切り分けになる。

## 実務での使い方

### 1. 会議室・備品・オフィス問い合わせ対応(社内FAQボット/RAG)

「会議室の予約方法は?」「備品の購入申請はどこから?」といった総務宛ての定型的な問い合わせは、チャットで都度回答するのではなく、社内規程・マニュアルをAIに検索させて自動応答する仕組み([RAG(検索拡張生成)の基本](../part07-data-analysis/rag-basics.md))を作ると効果が大きい。Microsoft 365 Copilotの従業員セルフサービスエージェント、SmartHRのAIアシスタント、DifyやNotebookLMを使った自社構築のRAGボットなどが選択肢になる。備品・固定資産の棚卸しには、JANコードや製品ラベルをスマートフォンのカメラで撮影するだけで登録・貸出・返却を処理できる画像認識AI付きの備品管理システムを組み合わせると、台帳と実物のズレを継続的に減らせる([ds-b.jp](https://ds-b.jp/dsmagazine/general-affairs-ai-chatbot/))。

想定Q&Aを整備してRAGボットに投入する下地作りは、汎用チャットAIでもたたき台を作れる。

```
あなたは総務担当者です。以下の社内規程・運用ルールのメモから、
社内FAQボット(RAGチャットボット)に登録する想定Q&Aを作成してください。

## 規程・ルールのメモ
[例: 会議室は社内ポータルの予約システムで先着順予約。1回の利用は最大3時間。
社用車は前日17時までに総務宛てメールで申請。備品購入は1万円未満は部門長承認のみで可、
1万円以上は総務経由で稟議]

## 出力条件
- 質問文は社員が実際に打ち込みそうな話し言葉(例: 「会議室って何時間まで借りられる?」)で作る
- 1つの質問につき回答は3行以内で簡潔にまとめる
- 規程に明記されていない曖昧なケースは「総務担当者へ直接確認してください」という回答にする
- 想定される類似質問(言い回し違い)も2〜3パターン追加する
```

RAGボットは参照させる社内文書が古いと誤った回答を返すため、規程改訂のたびに参照元を更新する運用体制を決めておく必要がある点は[人事(HR)職における生成AI活用事例](./hr-ai-use-cases.md)や[バックオフィス職における生成AI活用](./backoffice-ai-use-cases.md)と共通する。実際の規模感としては、朝日生命保険が「PKSHA AI ヘルプデスク」を導入し、業務手続要領書など3,500件超の社内文書をRAGで検索対象にしたうえでMicrosoft Teams上に自動応答窓口を設置し、AIが自己解決できなかった問い合わせは有人窓口へ取り次ぐ運用に切り替えた例がある([IT Leaders](https://it.impress.co.jp/articles/-/27197))。総務が扱う規程・マニュアルの数が数百〜数千件規模になっている企業では、こうした「AI一次回答+有人エスカレーション」の二段構成が定着しつつある。

### 2. 契約書のファイリング・更新期限管理

総務が担うのは契約の法的な当否判断ではなく、締結済み契約書を正しく台帳化し、更新・解約期限を漏れなく管理することである。契約書管理・電子契約サービスにはAIによる自動抽出機能が搭載されているものが多い。マネーフォワード クラウド契約は契約名・取引先・契約日など10項目をAIが自動抽出して台帳作成の負担を軽減し、クラウドサイン(累計送信件数3,000万件超、導入企業150万社超)は契約締結日・有効期限・自動更新条項・解約通知期限などをAIが読み取ってデータベースに自動入力する高精度AI機能を備える([マネーフォワード クラウド](https://biz.moneyforward.com/ai/basic/5862/)、[AI業務ハック](https://ai-gyomu.jp/cloudsign-review/))。料金の目安(2026年8月時点)は、クラウドサインがCorporateプラン月額28,000円(税込30,800円)+送信1件ごとに220円(税込242円)の従量課金([AI業務ハック](https://ai-gyomu.jp/cloudsign-pricing-howto/))、GMOサインがスタンダードプラン月額24,000円(税抜、年契約)/立会人型送信料100円・当事者型300円(いずれも1件あたり)、契約印&実印プランが月額9,680円〜と、送信件数・機能に応じた従量課金が別途かかる構成が一般的である([AI業務ハック](https://ai-gyomu.jp/gmo-agree-vs-cloudsign/))。

契約管理の次の段階として、GMOグローバルサイン・HDは2026年6月にGMOサインのMCPサーバー(AIエージェントが業務システムのデータを安全に読み書きするための連携規格)を発表し、2026年秋の一般提供開始を予定している。グループウェアや文書管理・ワークフローなどの社内SaaSとAIエージェントを連携させ、契約書の作成依頼から承認・署名依頼までの一連の業務を自動化できるようにする狙いで、セキュリティはGMO AIコネクトが管理する([GMOインターネットグループ](https://group.gmo/news/article/10056/))。現時点では「AIが情報を抽出して人に提示する」段階だが、契約業務の一部をAIエージェントに直接実行させる仕組みが電子契約サービス側から整い始めている点は、今後の運用設計を考える際に押さえておきたい。

紙で保管している既存契約をAIで台帳化する場合、汎用チャットAIに契約書テキストを読み込ませて要点だけ抽出させる使い方も実務的である。

```
あなたは総務担当者です。以下の契約書本文から、契約管理台帳に登録する
項目のみを抽出してください。法的な有効性の判断や条文の解釈はしないでください。

## 契約書本文
[契約書のテキストを貼り付け]

## 出力条件
- 「契約当事者」「契約締結日」「契約期間・満了日」「自動更新の有無と条件」
  「解約通知の必要期限」「支払条件・金額」の6項目を表形式で出力
- 本文に記載がない項目は「記載なし・要確認」とし、推測で埋めない
- 契約の有利・不利、リスクの評価はしない(この作業は法務の担当範囲)
```

### 3. 社内イベント・株主総会関連文書の下書き

忘年会・歓送迎会・周年イベントなどの企画書、案内メール、進行表の下書きは汎用チャットAIが得意とする領域である。株主総会関連では、招集通知の文面案や当日想定問答集の下書き、議事録のたたき台作成にAIを使う動きが広がっているが、招集通知は会社法上の記載事項を満たす必要があり、議事録も最終的な内容の正確性を法務・総務責任者が担保する必要がある。生成AIはあくまで作成支援ツールであり、AIが生成したたたき台を人が確認・修正したうえで正式な文書として確定する運用が推奨される([しょうぶ法律事務所](https://www.shobu-law.com/topics/2026/%E7%94%9F%E6%88%90ai%E3%82%92%E6%A0%AA%E4%B8%BB%E7%B7%8F%E4%BC%9A%E3%81%AB%E5%88%A9%E7%94%A8%E3%81%99%E3%82%8B/))。

想定問答集(株主から出る質問と回答例をまとめた資料。総会当日はIR・総務担当者が引きながら回答する)の作成・当日運用は、企業規模が大きくなるほど工数が膨らむ業務で、AI活用が最も進んでいる領域の一つである。東急は約2,300問の想定問答をAIに読み込ませ、株主からの質問を入力すると約7秒で回答案が生成される仕組みを導入し、従来のように紙のファイルから該当箇所を探す作業をなくした([日経ビジネス](https://business.nikkei.com/atcl/gen/19/00879/042700005/))。GMOインターネットグループは約200問の想定問答をAIに作成させ、総会前に経営陣と行っていた確認の打ち合わせを4回から2回に減らした([日経ビジネス](https://business.nikkei.com/atcl/gen/19/00766/071500008/))。グラッドキューブは2026年7月28日、自社のAIチャットボット「AvaTwin Chatbot」の株主総会プランに、IR資料や過去の想定問答集をもとに50問から最大1,000問の想定問答を自動生成するオプションを追加し、100問の生成に要する時間は約10分としている([PR TIMES](https://prtimes.jp/main/html/rd/p/000000058.000019309.html))。宝印刷とエクサウィザーズが共同提供する「exaBase IRアシスタント」のように、上場企業の開示支援を手がける印刷会社とAI企業が連携して想定問答作成を支援するサービスも定着している([IT Leaders](https://it.impress.co.jp/articles/-/26990))。想定問答の下書き作成はAIに任せられる部分が大きいが、開示済み情報との整合性・法的な言い回しの適切性は最終的に法務・IR部門が確認する。

```
あなたは総務担当者です。以下の情報をもとに、社内イベントの案内メール文面を
作成してください。

## イベント情報
[例: 忘年会、12月中旬、全社員対象、会費制(1人4,000円)、
会場は未定で候補を2〜3案募りたい、出欠は社内ポータルのフォームで回収]

## 出力条件
- 「開催概要」「参加方法・出欠回答の締切」「会場候補への意見募集」の
  3段落構成
- 業務都合で参加できない社員にも配慮した一文を入れる
- 件名案を3パターン提案する
```

### 4. 来客・郵便物対応の自動化

来客対応では、来訪者が受付端末に情報を入力すると担当者のスマートフォンやPCにリアルタイム通知が届くAI受付システムを導入すると、総務担当者が取り次ぎのために離席する必要がなくなる。郵便物対応では、株式会社トドケールが2026年3月16日に発表した仕分け機能のように、郵便物・配達物の写真から宛先情報をAIが読み取り、事前に登録した仕分けルールと照合して仕分け先を約99%の精度で自動判定するサービスが登場している([PR TIMES](https://prtimes.jp/main/html/rd/p/000000085.000045280.html))。スキャン・撮影からPDF化、タグ付けまでをAIが一貫処理する運用に切り替えると、郵便物の手渡し・仕分け作業そのものを減らせる。

### 5. 社内報・社内アナウンスの作成

社内報の記事や全社アナウンスは、取材メモや決定事項の箇条書きをAIに渡し、読みやすい構成・トーンに整えさせる使い方が定着しつつある。文章作成全般のコツは[生成AIによる文章作成・編集の実務活用](../part12-business-practice/ai-writing-and-editing.md)に譲り、ここでは総務特有の「定型通知の量産」に絞ったプロンプト例を示す。

```
あなたは総務担当者です。以下の決定事項を、全社員向けの社内アナウンス文に
してください。

## 決定事項
[例: オフィスの一部座席をフリーアドレス化。対象は3階フロアのみ。
開始は来月1日から。荷物はロッカーに集約]

## 出力条件
- 「何が変わるか」「いつからか」「社員が今すぐ準備すべきこと」の
  3項目を冒頭にまとめてから詳細を書く
- 問い合わせ窓口(総務部)を明記する
- 一方的な通達に見えないよう、変更の背景・目的を1〜2行添える
```

ある2〜3名体制の中小企業の総務部門では、Geminiを使って通知文の作成時間を約80%短縮し、NotebookLMを使って社内問い合わせ件数を半減させたという報告もある([boostx](https://boostx-inc.com/blog/soumu-ai-case-study/))。個社の効果は業務量・運用体制によって変わるため、自社での検証が前提になる。

### 6. 防災マニュアル・BCP(事業継続計画)の改訂ドラフト

防災マニュアル・BCPの改訂は、ゼロから書かせるのではなく既存のマニュアルを土台に、変更点だけをAIに反映させる方が抜け漏れが少ない([バックオフィス職における生成AI活用](./backoffice-ai-use-cases.md)の社内規程改訂の考え方と共通)。

```
あなたは総務・防災担当者です。以下の既存の防災マニュアルを土台に、
新しい体制に対応した改訂案を作成してください。

## 既存マニュアル(現行の地震発生時対応フロー)
[既存マニュアルの本文を貼り付け]

## 変更したい点
[例: 新しい避難場所を追加、安否確認システムの連絡先を変更、
在宅勤務者向けの初動対応セクションを新設]

## 出力条件
- 変更箇所には[変更]の印を付け、変更前と変更後を対比できるようにする
- 「人の安全確保」を最優先とする章立ての順序は変更しない
- 既存の他の章(BCPの復旧優先順位、取引先への連絡フロー等)と矛盾が
  生じないか、懸念点があれば末尾に指摘する
```

改訂案は必ず総務責任者・防災担当役員が内容を確認し、必要に応じて訓練で実際に運用できるかを検証してから発効させる。災害発生時の安否確認・避難誘導・事業継続の可否判断そのものをAIに委ねることはできない。

### 7. 慶弔規定・福利厚生の問い合わせ対応(FAQボット)

結婚・出産・弔事の際に必要な社内手続きや取得できる休暇、慶弔見舞金の申請方法といった問い合わせは、就業規則や慶弔見舞金規程をRAGの参照データとして登録しておけば、複数の規程を横断して回答を組み立てられる([Qiita: モデル就業規則×生成AIで社内問い合わせを自動化](https://qiita.com/pomeshiba29/items/bf0bf881c422cb047ced))。福利厚生に関する問い合わせは個人差(扶養家族の有無、勤続年数など)が絡むケースもあるため、FAQボットの回答には「詳細は総務担当者に確認してください」という導線を必ず残す。

### 8. 名刺・電子印鑑(社印)の管理

名刺管理では、Sansanのように名刺データをAIが自動でスキャン・分類し、AIが処理しきれない細部をオペレーターが補正して精度を担保するサービスが法人向けシェアの高いツールとして定着している(2026年1月時点で契約件数1万1,000件超・法人向け名刺管理サービスの業界シェア85.8%、13年連続シェアNo.1、[Sansan](https://jp.corp-sansan.com/news/2026/0113.html))。名刺を個人の持ち物からデータとして全社共有できる状態にすることは、営業部門だけでなく総務が管理する取引先窓口台帳の整備にも役立つ。Sansanは2026年に入り、メール署名からの名刺情報自動抽出を11か国語に対応させ、商談相手企業内の意思決定関係者・部署を可視化する「AI組織図分析」機能(2026年3月提供開始)も追加しており、名刺データの活用範囲は取引先の「連絡先台帳」から「関係性の把握」まで広がりつつある([クラウド Watch](https://cloud.watch.impress.co.jp/docs/news/2095689.html))。社印についても、電子契約サービス(クラウドサイン、GMOサイン等)への移行が進むにつれて、押印そのものの手続きを電子化し、稟議・捺印申請のフローをAIチャットボットで案内する運用に置き換える企業が増えている。

## 注意点・よくある誤解

- **契約書・来客・名刺情報は機密性が高い**: 取引先の契約条件、来訪者の氏名・所属、名刺の個人情報などを無料プランの汎用チャットAIにそのまま貼り付けず、法人契約プラン(学習利用が既定オフになっているもの)や業務システム側のAI機能を使う(詳細は[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md))。
- **総務のAI活用と法務のAI活用を混同しない**: 契約書の条文リスクの洗い出しや締結可否の判断は法務の担当範囲であり、総務が行うのは台帳化・期限管理までにとどめる。両者を混同すると、法的な確認が抜けたまま契約が進んでしまうリスクがある。
- **災害時・人命に関わる最終判断はAIに委ねない**: 防災マニュアル・BCPの改訂ドラフトはAIに任せてよいが、実際の災害発生時の避難誘導・安否確認・事業継続の可否判断は、訓練で検証済みの人による意思決定フローに従う。
- **規程・契約内容のハルシネーションに注意**: 慶弔見舞金の金額や契約の更新期限をAIが文脈から誤って補完・要約してしまうことがある。規程・契約書のような「一言一句が意味を持つ」文書は必ず原本と照合し、AIの出力を鵜呑みにしない(詳細は[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md))。
- **社内FAQボットは「作って終わり」ではない**: RAGボットは参照させる社内文書が古いと誤った回答を返す。規程・マニュアルの改訂のたびに参照元を更新する運用担当を決めておかないと、導入初期の効果が長続きしない。

## 最初の一歩

会議室・備品の利用ルール、または慶弔見舞金の申請方法のどちらか1つを選び、社内に届く典型的な質問と回答を3〜5組書き出して、本ページのプロンプト例(想定Q&A作成)をコピーしてAIに整理させてみる。実際の問い合わせ対応と比べて、抜け漏れや誤りがないかを確認する。
