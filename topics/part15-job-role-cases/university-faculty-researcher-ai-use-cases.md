# 大学教員・研究者における生成AI活用事例

## これは何か

大学教員・研究者の仕事は「研究(論文執筆・文献レビュー・研究費申請)」「教育(講義・シラバス作成・成績評価)」「大学運営・査読などの学術コミュニティ活動」の3本柱からなる。生成AIはこの全てで下書き・たたき台づくりを速められるが、大学教員には企業の研究開発職(詳細は[研究開発(R&D)職における生成AI活用事例](rd-ai-use-cases.md)を参照)にはない特有の制約がある。研究費申請書は「自分自身のオリジナリティ」が審査対象になり、論文は学術誌ごとに生成AI利用の開示ルールが異なり、査読は多くの出版社で生成AIの使用そのものが禁止されている。本ページは、企業のR&D職とは異なる「大学という制度の中で生成AIをどこまで・どう使ってよいか」を軸に、研究・教育・学術コミュニティ活動の場面別に整理する。

## 仕組み・背景

大学教員が直面する制約は、技術的な限界というより**制度・ルールの限界**である点が企業のR&D職と異なる。3つの背景を理解しておくと使い分けの判断がしやすくなる。

1. **研究費審査は「申請者本人の考える力」を評価する制度**であること。科研費(科学研究費助成事業、日本学術振興会が配分する国内最大級の競争的研究資金)の公募要領では、生成AI利用を明示的に禁止してはいないが、研究計画の独自性・申請者の考察は本人のものであることが前提とされ、利用する場合は著作権侵害・個人情報漏洩などのリスクを申請者自身の責任で管理するよう求められている。AIに研究計画そのものを「考えさせる」と、内容の希薄化(独自性が薄まる)や、原文にない要素の混入・逆に独自の強みが一般化されて消えるといった問題が起きやすい。
2. **学術誌の生成AI利用ポリシーは出版社・分野ごとに異なり、しかも変化し続けている**こと。Elsevier・Springer Nature・ICMJE(医学雑誌編集者国際委員会)など主要な学術出版社・団体はいずれも「生成AIを著者として記載することは認めない(責任を負えないため)」「文章生成に使った場合は開示を義務付ける」という大枠では一致しているが、開示の粒度(謝辞欄か独立セクションか)、画像生成AIの扱い(Elsevierは原則禁止)、コピーエディット目的の軽微な支援(Springer Natureは開示不要とするなど)の線引きは出版社ごとに異なる。
3. **査読(ピアレビュー、専門家が論文の妥当性を評価するプロセス)には「機密保持」という固有の制約がある**こと。査読対象の論文は未公開情報であり、これを外部の生成AIサービスに入力すると、著者の未発表データ・アイデアを外部に開示することになりかねない。この機密保持上の懸念に加え、AIによる評価の不正確さ・偏りへの懸念もあり、NIH(米国立衛生研究所)やElsevierなど資金配分機関・出版社の多くが査読プロセスでの生成AI利用を明確に禁止している。

## 使いどころ・使い分け

### 業務フェーズ別の活用マップ

| フェーズ | 生成AIが向く作業 | 生成AIを避けるべき・要注意な作業 |
|---|---|---|
| 研究費申請(科研費など) | 申請書の構成案・文章の推敲、想定質問への回答準備、審査員視点でのレビュー壁打ち | 研究計画のコア・独自性そのものをAIに考案させること |
| 文献レビュー・先行研究サーベイ | 大量の論文の要約・比較・研究ギャップの洗い出し(NotebookLM、Elicit等) | 出典を確認せず引用文献リストをそのまま使うこと |
| 論文執筆 | 構成案作成、英文校正・言い回しの改善、平易化 | 実験結果・データの創作、投稿先ジャーナルの開示ルール未確認での使用 |
| 査読(ピアレビュー) | (出版社が許可する範囲での)査読コメントの文章推敲のみ | 未公開の論文原稿・データそのものを外部AIに入力すること |
| 講義・シラバス作成 | 講義資料のたたき台、小テスト・演習問題の作成、シラバスの文章化 | 成績評価・単位認定の最終判断をAIに委ねること |
| 学生指導 | 生成AI利用ガイドラインの説明・学生からの質問対応 | 学生の生成AI利用の有無をAI検出ツールのみで断定すること |

### 研究費申請AIツールと汎用チャットAIの使い分け

科研費申請書に特化した支援サービス(SciGrant、G-DPAなど、研究者コミュニティ発の申請書執筆支援AI)も登場しているが、審査基準に沿った構成の型を提供するものであり、研究内容の独自性を生み出すものではない。汎用チャットAI(ChatGPT・Claude・Gemini)でも同様の壁打ちは可能なため、「型を効率よく整えたいか」「使い慣れたツールで壁打ちしたいか」で選べばよい。いずれの場合も、研究計画の核となるアイデア・仮説は自分の頭で作り、AIには「伝わりやすく整える」役割に限定するのが安全である。

### 文献調査ツールの比較

| ツール | 得意なこと | 大学教員が使う場面 |
|---|---|---|
| NotebookLM(Google) | アップロードした論文・PDF・ノートだけを情報源にして要約・Q&A・音声解説を生成。出典箇所(どの文書のどの部分か)が明示される | 手元に集めた論文セットの中だけで文献レビューを進めたいとき。学習データからの創作が入らないため誤引用のリスクが低い |
| Elicit・Consensus・SciSpace | Semantic Scholarなど外部の学術データベースを検索し、未収集の論文まで広く探す | まだ読んでいない先行研究を新たに発掘したいとき(詳細・料金は[研究開発(R&D)職における生成AI活用事例](rd-ai-use-cases.md)を参照) |
| 汎用チャットAI(ChatGPT/Claude/Gemini) | 文章の推敲、構成の壁打ち、既存の理解の整理 | 論文構成案の作成、英文校正、審査員向けの想定問答の準備 |

判断基準は「情報源を自分の手元にある文献に限定したいか、外部データベースまで広げたいか」。前者はNotebookLM、後者はElicit等の専門ツールが向く。

## 実務での使い方

### シーン1: 科研費・学振申請書の下書き・推敲支援

```
あなたは科研費審査員の視点でこの申請書を評価してください。
【研究課題】(研究課題名を記載)
【研究目的・内容】(下書きをここに貼り付け)

以下の観点でレビューしてください。
1. 「学術的独自性・新規性」が具体的に伝わる書き方になっているか
2. 審査員が読んで疑問に思いそうな点(想定質問)を3つ挙げる
3. 専門外の審査員にも伝わるよう、平易にすべき箇所を指摘する

【条件】
- 研究内容そのものを書き換えたり、新しい実験・手法を提案したりしないこと
- あくまで「伝わりやすさ」の観点での指摘に限定すること
```

### シーン2: 文献レビュー・先行研究サーベイ(NotebookLM活用)

1. NotebookLM(notebooklm.google.com)にアクセスし、新しいノートブックを作成
2. 手元の先行研究論文(PDF)を「ソースを追加」からまとめてアップロード(数十本まで一括登録可能)
3. チャット欄に質問を入力して要約・比較を依頼する

```
アップロードした論文について、以下を整理してください。
1. 各論文の研究手法・主要な結論を1〜2行で要約(出典箇所も明記)
2. 論文間で一致している知見と、結論が対立している論文の組み合わせ
3. まだどの論文でも扱われていない研究ギャップ

【条件】アップロードした論文の内容のみを根拠にし、それ以外の知識で補完しないこと
```

NotebookLMは登録した文書だけを情報源にして回答するため、汎用チャットAIより出典の追跡がしやすい。ただし要約・解釈自体の誤りは起こり得るため、レビュー章に引用する重要な結論は原典を人が読んで確認する。

### シーン3: 論文執筆(英文校正・構成案作成)

```
以下は英語論文のDiscussion(考察)セクションの下書きです。
学術英語として自然になるよう校正してください。

【条件】
- 事実関係・数値・結論は変更しないこと
- 変更箇所には理由を簡潔に添えること
- 専門用語は分野の慣用表現を優先すること

【下書き】
(考察セクションの下書きをここに貼り付け)
```

投稿前に必ず投稿先ジャーナルの生成AI利用ポリシーを確認する。多くの主要出版社は「文章の言い回し改善程度の軽微な支援は開示不要、内容生成に関わる利用は開示必須、AIを著者として記載することは不可」という考え方で概ね一致しているが、線引きの詳細(独立の開示セクションを設けるか謝辞に書くか等)は出版社ごとに異なるため、投稿規定(Author Guidelines)の該当項目を確認する。

### シーン4: 査読(ピアレビュー)対応

査読を引き受けた際、査読対象の論文原稿やデータそのものを外部の生成AIサービスに入力することは、多くの学術出版社・資金配分機関で明確に禁止されている(未公開情報の機密保持のため)。生成AIの利用が許容されるのは、自分がすでに書き終えた査読コメントの文章表現を整えるといった、原稿の内容そのものを外部に渡さない範囲に限られる。査読を依頼された学術誌の査読者向けポリシーを必ず確認し、迷う場合は編集部に問い合わせる。

### シーン5: 講義資料・シラバス作成支援

```
以下の講義テーマについて、90分の講義スライド構成案を作成してください。

【科目】(科目名)
【対象】(学年・専攻)
【今回のテーマ】(テーマ)
【到達目標】(この回が終わった時点で学生ができるようになってほしいこと)

【出力してほしいもの】
1. 導入(5分)・本論(70分、3パートに分割)・まとめ(15分)の時間配分
2. 各パートで使える具体例・ケーススタディの案
3. 理解度確認のための小テスト問題(3問、記述式)
```

シラバスの文章化(到達目標・評価方法・授業計画の言語化)も同様の要領で下書きを作らせ、実際のカリキュラムポリシーと整合するかを教員自身が確認して仕上げる。

### シーン6: 学生への生成AI利用指導という別の役割

大学教員は生成AIの「利用者」であると同時に、学生の適切な利用を指導する立場でもある。文部科学省は初等中等教育向けに「生成AIの利活用に関するガイドライン」を整備しているが、大学・高専は各大学が個別にガイドラインを策定するのが実情であり(多くの大学が全学的な利用指針や授業別の可否表示ルールを公表)、担当科目のシラバス・課題説明に「この課題での生成AI利用の可否・条件」を明記することが実務上の最初の一歩になる。

```
以下の課題(レポート課題)について、生成AI利用に関する注記文を作成してください。

【課題内容】(課題の概要)
【許可したい利用】(例: 構成の壁打ち、文献検索の補助)
【禁止したい利用】(例: 本文の全文生成、参考文献リストの丸ごと生成)

【出力】学生向けのシラバス・課題説明に貼り付けられる、1段落程度の注記文
```

## 注意点・よくある誤解

- **研究費申請書は「自分の考える力」が審査対象**: 科研費の公募要領は生成AI利用を明示的に禁止していないが、申請内容の独自性・オリジナリティは申請者本人に帰属することが前提になっている。AIに研究計画そのものを考案させると、内容が一般化されて独自性が薄まったり、逆に事実にない要素が紛れ込んだりするリスクが指摘されている。AIの役割は「伝え方の推敲」に限定し、研究の核となる着想・仮説は自分で作る
- **学術誌ごとに開示ルールが異なる**: Elsevierは独立した開示セクションでの明記とAI画像生成の原則禁止を求め、Springer Natureはコピーエディット程度の軽微な支援は開示不要とするなど、出版社によって線引きが異なる。ICMJE(医学系学術誌編集者の国際団体)は2026年改訂版でAI利用に関する章を新設し、AIを著者として記載することを明確に禁じている。投稿前に必ず投稿先の最新の投稿規定を確認する
- **査読での生成AI利用は「機密保持」の観点でほぼ禁止**: 査読対象の論文は未公開情報であり、外部の生成AIサービスに入力すると著者の未発表データを外部に開示することになる。NIHやElsevierなど多くの機関・出版社が査読プロセスでのAI利用を明確に禁止しており、「隠れたAI利用」は研究倫理上の問題として指摘されている。査読を依頼されたら、まずその学術誌の査読者向けポリシーを確認する
- **文献調査でのハルシネーション(AIが事実と異なる内容を自信満々に生成する現象)リスクは研究開発職と共通**: 実在しない論文タイトル・著者名を生成AIが作り出す「捏造引用」のリスクは学術分野全般で増加が報告されている。対策の詳細は[研究開発(R&D)職における生成AI活用事例](rd-ai-use-cases.md)および[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md)を参照
- **学生の生成AI利用を検出ツールだけで断定しない**: AI生成テキスト検出ツールは誤判定(生成AIを使っていない文章を「AI生成」と誤って判定するなど)が起こり得る。学生への指導・成績評価は検出ツールの結果を唯一の証拠とせず、対話や複数の根拠を組み合わせて判断する
- **無料の個人向けチャットAIに未発表データ・査読中の論文内容を入力しない**: 学習への利用がデフォルトの個人向け無料プランでは、入力内容が外部に開示されるリスクがある。所属大学が契約する法人向けプラン(学習への非利用が既定の契約)や、大学が提供する生成AI環境を優先して使う

## 最初の一歩

直近で読み込もうとしている先行研究のPDFを3〜5本、NotebookLMの新しいノートブックにアップロードし、「これらの論文の一致点・対立点・研究ギャップ」を質問してみる。あわせて、担当する次回授業のシラバス・課題説明に、その課題での生成AI利用の可否を1文で明記してみる。
