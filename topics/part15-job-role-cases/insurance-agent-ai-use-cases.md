# 保険営業(生命保険・損害保険)における生成AI活用事例

## これは何か

保険営業パーソン(生命保険会社の営業職員=いわゆる「生保レディ」、乗合代理店・専属代理店の代理店営業、損害保険代理店の担当者)の仕事は、一般的な法人営業と違って「保険業法に基づく募集規制」という強い制約の中で行われる。見込み客のニーズを聞き出し、複数商品を比較して提案し、契約後もフォローし続けるという業務フローは営業職に共通するが、保険営業では「意向確認書面の作成」「告知書の内容確認」「募集文書は保険会社の承認を受けたものしか使えない」といった手続きが各所に挟み込まれる。この規制を理解しないまま汎用チャットAIを使うと、AIが書いた文章をそのまま印刷して顧客に渡してしまい、保険会社の承認を得ていない「私製文書」を配布したことになるなど、業種特有の落とし穴にはまりやすい。本ページは、この保険営業という**職種**の業務フローに沿って、どこにAIを差し込めて、どこは人が最終確認すべきかを整理する。

**Part 14(業種別事例)との境界**: 保険会社・保険業界全体の生成AI活用(引受査定AI、コールセンターAI、不正検知など、会社側のシステム・組織としての取り組み)は[金融・保険における生成AI活用事例](../part14-industry-cases/finance-insurance-ai-use-cases.md)で扱っている。本ページはその逆側、**現場の募集人・代理店営業パーソン個人が日々の営業活動でAIをどう使うか**に絞る。会社側の審査AI(あいおいニッセイ同和損保×NRIの事例など)は、代理店側の視点から関連する範囲でのみ触れる。

## 仕組み・背景

保険営業でAIを使う際は、まず「誰が何を確認する義務を負っているか」を押さえておく必要がある。保険業法上、募集人には大きく2つの行為義務が課されている。

1. **意向把握・確認義務**: 顧客のニーズ(意向)を把握したうえで提案し、提案内容が顧客の意向に合致しているかを最終的に確認すること
2. **情報提供義務**: 契約を検討するために必要な情報を、必要書面の交付とともに適切に提供すること

さらに乗合代理店(複数の保険会社の商品を扱う代理店)には、複数商品を比較して提案する「比較推奨販売」のルールが課されている。2026年6月1日施行の改正保険業法により、比較推奨方式は「イ方式(顧客の求めに応じて商品を絞り込まず情報提供する方式)」と「ロ方式(顧客の意向に沿って特定の推奨理由を示し絞り込んで提案する方式)」に整理され、従来認められていた「ハ方式」は廃止・ロ方式に一本化される([hokan: 【保険業法改正の羅針盤⑥】比較推奨販売の現在地①](https://hkn.jp/column/25-09/))。ロ方式では推奨理由の合理性・具体性を示す説明と、その記録の作成・保存が求められるため、代理店の実務としては「意向確認・比較推奨の記録作成」の負荷が増える方向にある。

もう1つ押さえておくべきなのが「私製文書の禁止」というルールである。損害保険協会の「募集文書等の表示に係るガイドライン」などにより、代理店・募集人が独自に作成した募集文書(商品説明資料、比較表、案内チラシ等)は、保険会社の審査・承認を受けていないものを顧客に交付してはならないとされている。生成AIに指示して作った文章をそのまま印刷・配布すると、この私製文書の禁止と、保険業法第300条第1項第1号が禁じる「虚偽のことを告げる行為」の双方に抵触するリスクがある(生成AIのハルシネーションで補償内容や免責事項を不正確に説明してしまうケースが典型)。この2つの規制がある以上、**保険営業におけるAIの使いどころは、原則として「募集人自身が読む下書き・たたき台」までであり、保険会社の承認を経ていない生成物をそのまま顧客に渡す用途には使わない**、という線引きが実務の基本になる。

## 使いどころ・使い分け

### 業務フェーズ別のAI活用マップ

| フェーズ | やること | AIが向く範囲 | 最終判断・確認は誰が行うか |
|---|---|---|---|
| ① 見込み客リストアップ・アプローチ準備 | 既契約者・紹介者リストの整理、初回接触時のトークメモ準備 | 汎用チャットAIで想定される会話の流れ・切り出し方の下書き作成 | 募集人本人が内容を選別 |
| ② ヒアリング・ニーズ喚起トークの準備 | 家族構成・年収・資産・既契約状況をどう聞き出すか、保障の必要性をどう伝えるかの想定問答づくり | 汎用チャットAIでロールプレイ相手・想定質問リストの作成 | 実際のヒアリング内容は募集人が記録・意向把握 |
| ③ 保険提案書・比較資料のドラフト作成 | ヒアリング結果をもとに、複数商品の比較や提案の骨子を作る | 汎用チャットAIで**社内向けの下書き**を作成(保険会社所定の提案書フォーマットへの転記は募集人が行う) | 保険会社が承認した提案書フォーマット・比較推奨ロジックへの落とし込みは募集人・代理店システムが担当。**AIの出力を未承認のまま顧客に渡さない** |
| ④ 告知書内容の確認補助 | 顧客が記入した告知内容に記入漏れ・矛盾がないかの一次チェック | 汎用チャットAI・保険会社側の引受査定AIで記入漏れ・表記ゆれの検出補助 | **告知内容の医学的な評価・引受可否の最終判断は募集人ではなく保険会社の査定担当・査定医が行う**([renue: 生命保険の引受査定をAIで効率化する方法](https://renue.co.jp/posts/insurance-underwriting-ai))。募集人はあくまで記入漏れの確認までにとどめる |
| ⑤ 既契約者フォロー・乗り換え提案メール | 更新時期・ライフイベント(結婚・出産・住宅購入等)に合わせたフォロー文面の下書き | 汎用チャットAIでメール文面のたたき台作成 | 保障内容の変更提案は意向確認・比較推奨のプロセスに乗せ、募集人が正式な意向確認書面を作成 |
| ⑥ 保険金請求サポート文書の下書き | 請求手続きの案内文、必要書類チェックリストの作成 | 汎用チャットAIで案内文の下書き、保険会社のAIチャットボットで一次案内 | 請求の可否・支払額の判断は保険会社の査定部門が行う。募集人はあくまで手続き案内役 |
| ⑦ コンプライアンス研修・募集文書チェック | 自己点検・研修内容の理解確認、募集文書の事前チェック | hokan×三井住友海上の対話支援ツールのような**社内向けAI**、LibelliS・TRUSQUETTA INSURANCEのような文書チェックAI | 最終的な文書の使用可否は保険会社の審査部門が判断 |

判断の目安はシンプルで、「顧客に渡る/顧客に見える成果物になるか」「募集人個人の理解・下書き止まりか」の2点。前者は保険会社が承認したフォーマット・システム経由に限定し、後者は汎用チャットAIを自由に使ってよい。

### 使うべきでない場面

- **AIが生成した比較表・説明文をそのまま顧客に印刷して渡す**: 前述の私製文書の禁止に抵触するリスクがある。比較推奨の説明は、保険会社が定めた比較推奨ロジック・システム(代理店システムの意向把握・比較推奨機能等)を経由する
- **告知書の医学的な内容や、引受可否の見込みをAIに聞いて顧客に伝える**: 告知義務違反や不正確な引受可否案内は、将来の保険金不払い・契約解除に直結する重大なリスクであり、募集人が独自にAIの回答を根拠に案内してはならない
- **顧客の氏名・病歴・資産状況など機微な個人情報を、法人契約でない個人向けの生成AIサービスにそのまま入力する**: 保険情報は健康状態や資産といった機微な個人情報を多く含むため、入力データが学習に使われない法人向けプラン以外での取り扱いは避ける
- **AIによる比較表の作成を、特定商品の販売実績や自社の手数料が高い商品に偏らせる目的で使う**: 比較推奨は「顧客の意向に沿った合理的な推奨理由」が求められる規制であり、販売側の都合を優先した比較はロ方式の趣旨に反する

## 実務での使い方

### コピペで使えるプロンプト1: 見込み客ヒアリングの想定問答づくり

初回面談前に、聞くべき項目に抜け漏れがないかを確認するためのプロンプト。あくまで社内での準備用であり、実際のヒアリング内容(意向把握の記録)は募集人自身が作成する。

```
あなたは保険営業のロールプレイ相手です。以下の設定で、初回ヒアリングの想定問答を作成してください。

【顧客の設定】
- 年齢・家族構成: (例: 38歳、配偶者・子ども2人)
- 職業: (例: 会社員、年収概算)
- 相談のきっかけ: (例: 住宅購入を検討中で保障の見直しを考えている)

【聞き出したい項目】
1. 家族構成・扶養状況
2. 収入・資産の概況(答えにくい場合の聞き方の工夫も含める)
3. 既加入の保険(生保・損保問わず)の内容
4. 保障に対する不安・関心事(死亡保障、医療、就業不能、老後resource等)
5. 保険を検討するに至った具体的なきっかけ

【出力形式】
- 上記5項目それぞれについて、聞き方の例を2パターンずつ(ストレートな聞き方／雑談から自然に聞く方法)
- 顧客が答えを渋りそうな質問(特に年収・資産)には、聞きにくさを和らげる一言を添える
- 最後に、ヒアリングで分かった内容から「保障の必要性を感じてもらうための説明の切り口」を3つ提案する

【注意】
- 断定的な保障提案(「この保険が必要です」等)はまだ書かない。あくまでヒアリングの進め方の提案にとどめる
```

出てきた「保障の必要性を感じてもらうための説明の切り口」は、あくまで会話の糸口の候補であり、実際の提案内容は必ずヒアリングで把握した顧客本人の意向に基づいて組み立てる。

### コピペで使えるプロンプト2: 保険提案資料のたたき台生成

ヒアリング結果をもとに、社内検討用の提案骨子を作らせるプロンプト。**この出力をそのまま顧客向け資料として使わず**、保険会社所定の提案書フォーマット・比較推奨ロジックに転記してから使う。

```
以下のヒアリング結果をもとに、保険提案の骨子(社内検討用のたたき台)を作成してください。
まだ完成した提案書ではなく、私(募集人)が内容を組み立てるための下書きです。

【顧客情報】
- 家族構成: (例: 本人38歳・会社員、配偶者36歳・パート、子ども2人(8歳・5歳))
- 既加入の保険: (例: 会社の団体保険のみ、死亡保障500万円)
- ヒアリングで分かった不安・関心事:
  - (例: 自分に何かあったときの子どもの教育費が心配)
  - (例: 就業不能になった場合の収入減少が不安)
- 相談の温度感: (例: 情報収集段階。まだ具体的な商品名は決めていない)

【出力してほしい内容】
1. ヒアリング内容から読み取れるリスク・保障ニーズを3つに整理(それぞれ根拠となるヒアリング内容を添える)
2. 上記ニーズに対応する保障の「考え方」の説明案(特定の商品名は出さず、死亡保障/医療保障/就業不能保障といった保障タイプの説明にとどめる)
3. 次回面談で確認すべき追加ヒアリング項目
4. 意向確認書面を作成する際に記載すべき「顧客の意向」の要点メモ

【注意】
- 特定の保険会社・商品名を挙げた推奨はしない(比較推奨は社内の比較推奨ロジックに基づいて別途行うため)
- 保険料や返戻率など数値の記載はせず、考え方の整理にとどめる
- 断定的な「加入すべき」という表現は避け、「検討材料」として提示する
```

### コピペで使えるプロンプト3: 既契約者フォロー・見直し提案メール

```
以下の情報をもとに、既契約のお客様へのフォローメールの下書きを作成してください。

【お客様の状況】
- 契約内容: (例: 10年前に加入した定期死亡保険、更新時期が近い)
- 分かっているライフイベント: (例: 昨年第二子が誕生)
【フォローの目的】(例: 更新のご案内と、必要であれば保障内容の見直し相談の提案)
【トーン】売り込み感を出さず、お客様の状況を気にかけている姿勢を伝える
【含めてほしい要素】
- 更新時期が近いことのお知らせ
- ライフイベントの変化に触れ、保障の見直し相談を「押し付けではなく選択肢として」提案する一文
- 相談は任意であり、今のままでよい場合はその判断も尊重する旨

【出力形式】
件名と本文を分けて出力してください。
```

このメールも、保障の見直し提案を実際に進める場合は、正式な意向確認・比較推奨のプロセス(意向確認書面の作成等)に乗せる前提の「きっかけ作り」の文面として使う。

### ツール横断の対応付け(2026年8月時点)

| 用途 | ツール例 | できること | 備考 |
|---|---|---|---|
| 提案書・メール文面の下書き、ヒアリング準備 | ChatGPT / Gemini / Claude等の汎用チャットAI | 文章生成、想定問答づくり、要約 | 法人向けプラン(学習利用オフ)を使い、機微な個人情報は入力しない |
| 代理店の顧客管理・意向把握・比較推奨 | hokan(保険代理店システム) | 顧客管理・契約管理に加え、意向把握・比較推奨機能をAIでアップデート。2026年5月にAIエージェントと業務システムを繋ぐMCP(Model Context Protocol)サーバーを試験公開し、自然言語での顧客データ照会・更新を目指す([hokan: MCPサーバー試験公開](https://hkn.jp/news/20260520/)) | 全国420超の代理店で導入、更新率99.9%(hokan公式) |
| 代理店の自己点検・コンプライアンス研修 | hokan×三井住友海上「AIを活用した代理店自己点検の対話支援ツール」 | 自己点検の回答と代理店監査データ・顧客アンケートをAIが分析し、改善点・対話のアドバイスを提示。2026年6月に一部拠点で先行導入、同年10月に全国展開予定 | 損害保険代理店業務品質評価運営第三者機関の評価基準を踏まえた仕組み |
| 募集文書のコンプライアンスチェック(保険会社側) | LibelliS(キャピタル・アセット・プランニング)、TRUSQUETTA INSURANCE(トラスクエタ) | 募集文書PDFをAI-OCR化し、法令・ガイドライン・社内規定との整合性を複数観点でチェック。LibelliSはAmazon BedrockとAnthropic Claudeを採用 | 主に保険会社の審査部門向け。あいおいニッセイ同和損保はNRIと共同開発した同種ツールで年間約8,000件の募集文書初期点検にかかる時間を半減(約4,000時間分の効率化) |
| 保険金請求の一次案内 | 三井住友海上あいおい生命のAIチャットボット、損保ジャパンの「LINEによる保険金請求サービス」 | 請求方法など定型的な問い合わせに24時間対応 | 支払可否・金額の判断は査定部門が行う |
| 生保営業職員向けの社内ナレッジ検索 | 日本生命「N-Chat」 | 社内規程・マニュアル・Q&Aを取り込んだ生成AIチャットで、約2万人の職員が利用 | 社内向けナレッジ検索が中心で、顧客向け提案文書の自動作成用途ではない |

料金感の目安(要問い合わせのものが多いため、必ず最新の公式情報を確認すること):

- 汎用チャットAIの法人向けプランは月額2,000〜3,000円/ユーザー程度が目安(詳細は[AIチャットツールのプラン・モデル比較](../part03-ai-chat-tools/ai-chat-tools-plan-model-comparison.md)を参照)
- hokanは公式サイトに料金を明示しておらず、代理店規模に応じた個別見積もり
- LibelliS・TRUSQUETTA INSURANCEは主に保険会社向けの審査部門ツールであり、個々の代理店・募集人が直接契約する製品ではない

## 注意点・よくある誤解

- **AIが作った文章を「私製文書」として顧客に渡さない**: 損害保険協会の「募集文書等の表示に係るガイドライン」により、募集人・代理店が独自に作成した募集関連文書は保険会社の審査・承認を経る必要がある。AIに書かせた比較表や商品説明をそのまま印刷・配布すると、私製文書の禁止と保険業法第300条第1項第1号(虚偽告知の禁止)の双方に抵触するリスクがある
- **告知書の確認はあくまで「記入漏れの一次チェック」にとどめる**: 告知内容の医学的評価や引受可否の判断は保険会社の査定担当・査定医の役割であり、募集人がAIの回答を根拠に「この内容なら加入できる」といった案内をすると、告知義務違反やトラブルの原因になる
- **比較推奨のAI活用は「特定商品への誘導」になっていないか常に点検する**: 2026年6月施行の改正保険業法でロ方式に一本化されたことで、推奨理由の合理性・具体性の説明責任が増している。AIに比較資料を作らせる場合も、顧客の意向に基づいた推奨理由になっているかを人が確認する
- **顧客の機微な健康・資産情報を個人向け生成AIにそのまま貼り付けない**: 保険営業が扱う情報は病歴・資産状況など機微性の高い個人情報を含む。学習利用がオフになっている法人向けプランを使い、氏名等の特定につながる情報は伏せ字にするなどの工夫をする([生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md)も参照)
- **ハルシネーションによる補償内容の誤案内に注意**: 生成AIは免責事項や特約の適用条件についてもっともらしい誤情報を生成することがある。募集人自身が最終的な補償内容を保険会社の約款・重要事項説明書で確認してから顧客に説明する運用を徹底する([ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md)も参照)

## 最初の一歩

次回の見込み客面談を1つ選び、プロンプト1(ヒアリングの想定問答づくり)を試してみて、出てきた質問例のうち1つを実際の面談で使ってみる。その際、AIが提案した「保障の必要性の切り口」は仮説として扱い、実際の提案は必ずヒアリングで把握した顧客本人の意向に基づいて組み立てる。
