# 法務職における生成AI活用事例

## これは何か

事業会社の法務部門(社内弁護士・法務担当者)は、契約書レビュー・法令調査・社内問い合わせ対応など「読む・調べる・書く」量が非常に多い職種であり、生成AIによる時間短縮効果が大きい一方、誤りが契約トラブルや訴訟リスクに直結しやすい分野でもある。日経の調査では主要企業の76%が法務業務で生成AIを活用していると回答しており、もはや「使うかどうか」ではなく「どこまで・どう使うか」を設計する段階に入っている。本ページは、法律事務所という**業種**としての事例([Part 14 士業・専門サービス](../part14-industry-cases/_index.md)で扱う範囲)ではなく、事業会社に所属する**職種としての法務**が生成AIをどう使うかに焦点を当てる。

## 仕組み・背景

法務でのAI活用が広がった背景には2つの技術的な流れがある。

- **契約書特化のLegalTech AI**: LegalOn Cloud(旧LegalForce)やOLGA(旧GVA assist)のような日本発の契約書レビューSaaSは、大量の契約書・判例・自社の過去レビュー履歴を学習させたAIに、あらかじめ弁護士監修の「レビュー基準(プレイブック)」を組み込んでいる。アップロードした契約書を基準と照合し、抜け漏れ・不利な条項をハイライトする仕組みで、汎用AIより「見落としを減らす」ことに特化している。
- **汎用LLMのエージェント化**: ChatGPT・Claude・GeminiなどはWeb検索・ファイル読み込み・複数ステップの推論を組み合わせられるようになり、契約書ドラフトの初稿作成や社内FAQ対応など、契約審査以外の幅広い法務タスクをカバーできるようになった。米国のHarveyのように、汎用LLM(Anthropic Claude・OpenAI GPTなど)を基盤に法務特化のエージェント機能を載せるプレイヤーも急成長しており、2026年3月時点で1,300以上の組織・2万5,000超のカスタムエージェント・1日あたり40万件のクエリを処理する規模まで拡大している。日本でも大手法律事務所がアジア初のHarvey独占パートナーとして全社導入するなど、大手事務所主導で導入が先行している。

いずれの方式でも、AIは「条文パターンの類似性」や「学習データ上の頻出表現」から出力を組み立てているのであり、個別契約の商慣習上の妥当性やその会社固有の交渉方針までは判断できない。最終的な法的判断は依然として人間の弁護士・法務担当者が担う、という前提を理解しておく必要がある。この前提は法務省の整理とも一致する。法務省は「AI等を用いた契約書等関連業務支援サービスと弁護士法72条との関係」について、AIが補助し最終判断を人が行う運用であれば同条に違反しないとの考え方を示しており、2026年1月の資料でも「現状・時代ニーズに即した再整理」の必要性を明記し、ガイドライン改訂(ソフトロー)と法改正(ハードロー)を組み合わせた段階的な見直しを検討中としている。裏を返せば、AIに個別条項の法的解釈やリスク判断そのものを最終決定させる使い方は同条上のグレーゾーンに踏み込むリスクがあり、「AIは一次判断、最終判断は人」という運用線を社内ルールとして明文化しておくことが重要になる。

## 使いどころ・使い分け

法務の業務は「AIに任せてよい範囲」と「必ず人が最終確認すべき範囲」の差が大きい。主な活用シーンごとに整理する。

| 活用シーン | AIが担う範囲 | 人が必ず担う範囲 |
|---|---|---|
| 契約書レビュー・リスク条項の抽出 | 抜け漏れ・不利条項の一次スクリーニング、社内基準との照合 | 商慣習上の妥当性判断、修正条文の最終確定、締結の意思決定 |
| 契約書ドラフト作成 | 定型契約のたたき台生成、条項の言い回し候補出し | 取引固有のリスク条件の設定、相手方との交渉方針 |
| 法令調査・社内問い合わせ対応 | 一般的な法令・社内規程の要約、FAQへの一次回答 | 個別事案への当てはめ、最新の法改正・判例の裏取り |
| コンプライアンス研修資料作成 | 研修スライドのたたき台、Q&A形式の設問生成 | 事例の正確性チェック、自社の実際の違反事例の扱い方 |
| 契約書の平易な日本語要約 | 現場の事業部門向けにリスクをかみ砕いて説明する下書き | 要約に法的に重要な留保・例外が漏れていないかの確認 |

使い分けの判断基準はシンプルに「この出力を鵜呑みにして進めた場合、誤りがあったら誰にどんな損害が出るか」。契約締結の可否・金額・違約条件に関わる最終判断は必ず人が行い、AIは「一次ドラフト・見落とし防止のダブルチェック役」と位置づけるのが実務的な線引きになる。

## 実務での使い方

### 1. 契約書レビュー・リスク条項の抽出

汎用AIに直接契約書全文を貼ってレビューさせる方法と、LegalTech AIのように事前にプレイブックが組み込まれた専用ツールを使う方法がある。汎用AIを使う場合はプレイブック(自社の許容範囲)をプロンプトで明示すると精度が上がる。

```
あなたは企業法務担当者です。以下の業務委託契約書(甲=当社、乙=委託先)を、
次の自社基準に沿ってレビューしてください。

【自社基準】
- 損害賠償の上限が契約金額の範囲内に収まっているか
- 秘密保持義務の期間が契約終了後も存続する条項になっているか
- 再委託の可否と当社への事前承諾義務の有無
- 契約解除条項に当社が一方的に不利な条件がないか

【出力形式】
1. リスクが高い条項を条番号付きで列挙し、なぜ問題かを1〜2行で説明
2. 各条項について修正案の文言を提示
3. 上記基準に抵触しない一般的な条項は「問題なし」として省略

契約書本文:
(ここに契約書のテキストを貼付)
```

### 2. 契約書ドラフト作成

```
以下の条件で秘密保持契約(NDA)のドラフトを作成してください。

- 契約形態: 相互型(甲乙双方が秘密情報を開示する)
- 目的: 新規事業の業務提携検討のための情報交換
- 秘密保持期間: 契約終了後3年間
- 準拠法・管轄: 日本法、東京地方裁判所を第一審の専属的合意管轄
- 当社は「甲」、相手方は「乙」とする

一般的なNDAの条項(定義、目的外利用禁止、除外情報、返還・破棄、損害賠償、
存続条項)を漏れなく含め、口語ではなく契約書らしい文体で出力してください。
出力後に、法令上または実務上とくに確認が必要な条項があれば、その理由とあわせて
別途注記してください。
```

### 3. 法令調査・社内問い合わせ対応(FAQボット)

社内向けには、汎用AIの記憶だけに頼らせず、自社の規程集や過去のFAQをRAG(検索拡張生成、外部・社内の文書を検索してから回答させる方式)で読み込ませたチャットボットが有効。日本ペイントホールディングスは社内専用の生成AI「NP ASSISTANT」を導入し、稟議規程や契約書ひな形に関する定型的な問い合わせに自動回答させることで、法務担当者の一次対応の負荷を減らしている。

```
あなたは当社の法務部が管理する社内問い合わせ対応AIです。
添付した社内規程集・契約書ひな形集の内容のみを根拠に回答してください。
資料に記載がない、または資料からは判断できない質問については、
推測で答えず「規程集に記載がないため法務部への確認が必要です」と回答してください。

質問: 取引先との覚書に押印ではなく電子署名を使ってよいか。
```

### 4. コンプライアンス研修資料作成

```
新入社員向けの下請法(下請代金支払遅延等防止法)に関する社内研修スライドの
構成案を作成してください。

- 対象: 営業部門の新入社員(法律の専門知識なし)
- 時間: 30分の研修を想定した10スライド程度
- 各スライドには「タイトル」「本文の要点(3行程度)」「理解確認用の一問一答クイズ」を含める
- 実際の違反事例は抽象化した架空のケースとして扱い、断定的な事実として書かない
```

### 5. 契約書の平易な日本語要約

事業部門の担当者が契約の法的な言い回しを読みこなせない場合、リスクをかみ砕いて説明する下書きとして使う。

```
以下の契約条項を、法律の知識がない事業部門の担当者向けに、
平易な言葉で3行以内に要約してください。
「結局、自社にとって何をしてはいけないか・何のリスクがあるか」を中心に書き、
法律用語を使う場合は必ずかっこ書きで一言説明を加えてください。

条項: (ここに条文を貼付)
```

### 法務特化AIツールと汎用AIの使い分け

| ツール | 位置づけ | 特徴・2026年8月時点の動向 |
|---|---|---|
| LegalOn Cloud(旧LegalForce) | 契約書レビュー・契約管理の国内シェア最大手 | 弁護士監修のレビュー基準を標準搭載。ISMS/ISMSクラウドセキュリティ認証(ISO/IEC 27001・27017)を取得し、入力データを外部AIモデルの学習に使わない方針を明示。2026年に入り、複数ファイルを同時参照するAIエージェント機能(3月)、社内規程等をレビュー対象に広げる「DocumentOn」(3月、まずは景品表示法の誇大広告リスク対応から)、フリーランス新法(2026年1月施行の「特定受託事業者に係る取引の適正化等に関する法律」)への準拠チェック(1月)、契約書の30言語超対応・翻訳レビュー(4月)、電子契約「サイン」機能(8月)を相次いで追加しており、契約審査単体のツールから法務OSへ拡張が続いている。料金は要問い合わせ制 |
| OLGA(旧GVA assist) | 契約書レビューSaaS、法務OS「OLGA」へブランド統合済み | 200種類以上の契約類型のレビュー基準・380種類以上のひな形を提供。料金はアカウント費用制で公表額はなく個別見積り(以前あった「月額7.5万円〜」の目安表示は現在サイト上に見当たらない)。中小企業・フリーランス向けにNDAに限定した無料チェックツール「GVA NDAチェック」は引き続き提供されており、まず試したい場合の入口になる。ITreview Grid Award 2026 SummerでCLM・契約管理・AI契約レビューの3部門でリーダー認定 |
| Harvey | 海外の法律事務所・企業法務向け汎用法務AIエージェント | 2026年3月に約2億ドル(約300億円)を調達し、企業価値110億ドル(約1.6兆円)に到達。同時点で導入組織1,300超、カスタムエージェント2万5,000超、1日あたりクエリ40万件規模まで成長。AmLaw100の大半、500以上の企業内法務部門が導入し、契約分析・デューデリジェンス・訴訟対応まで幅広くカバー。日本でも大手法律事務所がアジア初の独占パートナーとして全社導入するなど普及が進む |
| Robin AI | 契約書レビュー特化の新興ツールとして注目されたが経営破綻 | 2025年末に資金調達に失敗した後に事業が分割され、マネージドサービス部門はScisseroへ売却、エンジニアリング人材は2026年1月にMicrosoftへ移り、Wordの法務AI機能強化に活用される見通し。**法務AI新興ツールは変化が速く、乗り換えコストの高い基盤に据える前にベンダーの継続性も確認する必要がある**という教訓的な事例 |
| ChatGPT / Claude / Gemini(汎用AI) | ドラフト作成・要約・アイデア出しの汎用エージェント | 法務特化ツールほど契約審査の網羅性は保証されないが、社内規程FAQ・研修資料・平易な要約など幅広い用途に安価に使える。機密情報の入力ルールを個別に確認する必要がある |

法務特化ツールは「契約書レビューの網羅性・監査ログ・社内基準との一貫性」を重視する場合に、汎用AIは「ドラフト作成・要約・研修資料など裾野の広い業務」に向く。両者は排他ではなく、契約審査は専用ツール、それ以外の法務タスクは汎用AIという併用が一般的になっている。

## 注意点・よくある誤解

- **法律分野はハルシネーション(事実と異なる情報をもっともらしく生成する現象)のリスクが特に高く、2026年も件数は増え続けている**: スタンフォード大学の研究では、法律に関する質問でChatGPT-4が58%、Llama 2が88%の割合で何らかの法的な幻覚(存在しない判例・誤った判示内容など)を含む回答をしたと報告されている。米国の裁判所命令を追跡する集計では、2026年6月時点で生成AIの幻覚に起因する訴訟上の問題(架空判例の引用など)が世界で1,598件確認されており、2026年だけでもネブラスカ州の弁護士が離婚訴訟の控訴審で63件中57件の引用に問題(架空判例20件を含む)があったとして業務停止処分を受けた例や、2026年第1四半期だけで裁判所が科した制裁金の合計が14万5,000ドルを超えた例が報告されている。使用モデルの種類を問わず起きている問題であり(Claudeを使って生成した架空の判例引用で制裁を受けた事例も報告されている)、「どのAIを使うか」ではなく「AIの調査結果は必ず一次情報(判例データベース・法令原文)で裏取りする」運用を徹底することが唯一の対策になる。詳細は[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md)を参照。
- **AIの出力は「一次ドラフト」であり「最終判断」ではない**: 契約審査AIも汎用AIも、条文パターンの類似性から出力しているだけで、個別取引の背景事情・自社の交渉力・業界の商慣習までは判断できない。契約締結の可否・修正条文の最終確定・重要な法令解釈は、必ず社内弁護士・法務担当者が確認する体制を明文化する。前述のとおり法務省も弁護士法72条との関係で「AIは補助、最終判断は人」という運用を適法性の目安としており、社内ルールをこの線に揃えておくと規制動向の変化にも対応しやすい。
- **契約情報を外部AIに入力する情報漏洩リスクを軽視しない**: 取引先の名称・金額・独自の契約条件は、相手方との秘密保持契約(NDA)上の秘密情報に該当することが多い。汎用AIの無料プランやAPI設定によっては入力内容がモデルの学習に使われる場合があるため、法務部門が最初に「どのAIに、どの機密度の情報まで入力してよいか」をルール化する必要がある。LegalOn Cloudのように「入力データを外部AIモデルの学習に使わない」ことを明示しているサービスを選ぶ、または法人向け・API契約のプラン(学習利用オプトアウトが標準の契約形態)を使うのが基本線になる。個人情報を扱う場合はさらに注意が必要で、個人情報保護委員会は2026年1月に個人情報保護法の次期改正に向けた12項目の方針(課徴金制度の導入、同意規制の見直し、委託先監督の強化など)を示しており、生成AIへの個人情報の入力可否も社内ルールの更新対象として継続的に見直す必要がある。詳しくは[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md)を参照。
- **法務特化AIベンダーの事業継続性も選定基準に入れる**: Robin AIのように資金調達に失敗して事業が分割されるケースが実際に起きている。契約審査の基準・レビュー履歴・ナレッジを蓄積する基盤ツールほど、乗り換えコストが高くなる。ベンダーの資金状況・データのエクスポート可否を事前に確認しておく。
- **「AIが76%活用されている」=「AIが法的判断をしている」ではない**: 日経調査が示す高い活用率も、多くは調査・ドラフト作成・リスク条項の一次抽出といった支援業務での利用であり、最終的な法的責任判断はあくまで人間が担っている前提であることを社内で誤解させないようにする。

## 最初の一歩

直近でレビューした契約書の一部を上記の「契約書レビュー」プロンプトに貼って試し、AIが指摘した条項と自分が気づいていた条項を比較して、見落としがなかったかを確認してみる(社外秘の実データではなく、匿名化した条文やサンプル契約書で試すこと)。
