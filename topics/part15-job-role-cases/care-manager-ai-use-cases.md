# ケアマネジャー(介護支援専門員)における生成AI活用事例

## これは何か

ケアマネジャー(介護支援専門員、要介護者・要支援者のケアプラン(介護サービス計画)を作成し、サービス事業所・医療機関との調整役を担う専門職)の仕事は、訪問介護・訪問看護のような「利用者に直接ケアを提供する」業務ではなく、**アセスメント(利用者の状態・意向の聞き取り調査)、ケアプラン作成、サービス担当者会議の運営、モニタリング(サービス利用後の状況確認)、給付管理(介護報酬の請求管理)**という相談援助・計画作成・書類作成が中心の専門職である。厚生労働省の調査では、居宅ケアマネジャー1人あたりの平均担当件数は令和4年度時点で44.0件に達し、記録・書類作成に多くの時間を取られて利用者と向き合う時間が圧迫されているという声が現場から上がっている。生成AIは、この「アセスメント情報からケアプラン文案を作る」「モニタリング訪問・会議の音声を記録に変換する」「保険者への提出書類を点検する」といった**下書き・下処理**の部分を大きく速くできる一方、ニーズの判定やサービス内容の最終決定という専門職としての判断そのものを代替するものではない。本ページでは、ケアプラン作成支援AI、音声入力によるモニタリング記録・会議録の自動作成、給付管理業務の効率化、多職種連携での使い方を、2026年8月時点の国内事例で整理する。

## 仕組み・背景

ケアマネジメント業務における生成AI活用は、大きく2つの技術要素と、1つの制度的な下地の組み合わせで成り立っている。

1. **生成AI(LLM)による文章生成**: アセスメント結果・利用者の意向・過去のケアプランデータを読み込ませ、長期目標・短期目標・サービス内容といったケアプラン(第1表・第2表)の文案候補、モニタリング記録・支援経過記録・サービス担当者会議録の下書きを生成する。
2. **音声認識・自動文字起こし**: モニタリング訪問時の会話やサービス担当者会議の録音を自動でテキスト化し、そこから要点を抽出して記録フォーマットに整形する。株式会社ウェルモの「ミルモレコーダー」(2024年11月正式リリース)は、地域包括支援センターでの活用事例として、従来1時間かかっていた支援経過記録の作成が5分に短縮されたと報告している。株式会社カナミックネットワークは2026年3月、介護専用クラウドソフトとしては業界初となる「システム内完結型」のAI議事録作成機能をリリースし、ケアマネジャーや居宅介護支援事業所がサービス担当者会議の録音データから議事録ドラフトを自動生成できるようにした。

制度的な下地として、厚生労働省の老人保健事業では2017年度から「AIを活用したケアプラン作成支援の実用化」に向けた調査研究がフェーズ1(2017〜2019年度)・フェーズ2(2020〜2022年度)と続けられ、過去の大量のケアプランデータをAIに学習させ、アセスメント情報を入力すると長期目標・短期目標・サービス内容の候補を提示する仕組みの構築が進められてきた。効果検証は「①業務時間短縮効果」「②業務負担軽減効果」「③新たな視点・観点の獲得」「④ケアプランの説明・合意形成の容易さ」「⑤利用者視点でのケアプランへの納得感・満足度」の5項目で行われており、単純な時短だけでなく「ケアマネの気づきを増やす」「利用者への説明がしやすくなる」効果も評価軸に含まれている点が特徴である。この調査研究は国際社会経済研究所(旧NTTデータ経営研究所)によって2023年度・2025年度も継続されており、まだ全国一律で使える公的な「AIケアプラン」が完成した段階ではなく、実証と民間ツールの実用化が並行して進んでいる段階にある。

もう一つの制度的な基盤が「ケアプランデータ連携システム」(バージョンV4、ケアマネジャーとサービス事業所の間で提供票などのケアプラン関連データをクラウド経由でやり取りする仕組み)で、カイポケ・ケアカルテなど主要な介護記録ソフトが対応している。利用料は当初無料期間が設けられ、その後も令和8年度中(2027年3月)まで無料利用が延長されており、終了後は1事業所あたり年額21,000円(税込)のライセンス料が発生する見込みである。この基盤の上に、AIによる文案生成・要約機能が積み重なっていく構図になっている。

## 使いどころ・使い分け

ケアマネジメント業務は「情報を集めて整理・文章化する」部分と「利用者本人にとって何が最善かを判断する」部分を明確に線引きすることが重要になる。

| 業務 | AI活用の向き不向き | 理由 |
|---|---|---|
| アセスメント情報からのケアプラン文案(第1表・第2表)の下書き生成 | 向く(要専門職の確認) | 過去データのパターンから候補を出す一次ドラフトには有効。長期目標・短期目標・サービス内容の妥当性は必ずケアマネが判断する |
| モニタリング訪問・支援経過記録の音声入力→自動文字起こし・要約 | 向く | 定型フォーマットへの整形は得意。誤変換や聞き取りミスがないか本人が確認する前提 |
| サービス担当者会議録の自動作成 | 向く | 発言内容の要約・論点整理は速い。決定事項・残された論点の確定は主催者(ケアマネ)が最終チェックする |
| 給付管理票・保険者への提出書類の一次点検(記載漏れ・整合性チェック) | 向く(一次チェックのみ) | フォーマット不備やケアプランとの不整合の洗い出しに有効。最終的な提出可否の判断は人が行う |
| 利用者・家族向け説明文書のやさしい日本語化 | 向く | 専門用語の言い換え・平易化は生成AIの得意領域。医療的な判断や解釈を変えていないか確認は必要 |
| 主治医意見書・多職種からの情報の要約 | 向く(共有範囲は要判断) | 大量の医療情報を短時間で要約できる。誰にどこまで共有してよいかの判断(下記「注意点」参照)は人が行う |
| ニーズ・課題の最終判定、ケアプランの目標・サービス内容の最終決定 | 向かない | 利用者・家族の意向、地域資源、価値観など属人的な要素が大きく、専門職の判断が不可欠 |
| サービス種別・事業所の最終選定 | 向かない | 利用者との関係性・信頼形成を伴う意思決定であり、AIの提示はあくまで参考情報にとどめる |
| 虐待の疑い・苦情・事故等センシティブな事案の対応方針決定 | 向かない | 影響が大きく、誤判断のリスクが高い。関係機関との連携含め人が判断する |

判断に迷う場合は、Part 12「[生成AIに向く業務・向かない業務の切り分け](../part12-business-practice/ai-task-suitability.md)」の3チェック(入力が構造化されているか/成果物の良し悪しを基準化できるか/反復回数が多いか)に、ケアマネジメント特有の軸として「利用者本人の意向・尊厳に関わる最終判断かどうか」を4つ目として加えて仕分けるとよい。

## 実務での使い方

### 1. アセスメント情報からのケアプラン文案生成

主要なケアプラン作成支援AIには、次のようなものがある(2026年8月時点)。

| ツール | 提供元 | 特徴 |
|---|---|---|
| PlanMate(ケアプラン作成AI) | NDソフトウェア株式会社 | アセスメント情報を入力するだけで第1表(居宅サービス計画書)・第2表(サービス内容)の文案をAIが自動生成。既存の介護記録ソフトと連携不要で、ブラウザだけで利用できる独立サービス |
| AIケアプラン | BSNアイネット | 過去のケアプランデータを分析し、利用者に適したケアプラン素案を提示 |
| AI予測くん | 日本ケアコミュニケーションズ | アセスメント内容からケアプランの候補を予測・提示するAI機能 |
| 居宅マナ ケアプランAI | 株式会社ライフシフト | カイポケなど既存の介護ソフトと切り替え不要でアドオン的に利用できるケアプラン自動作成AI |

**コピペで使えるプロンプト例(汎用チャットAIでケアプラン文案の下書きを作る場合)**

```
あなたは居宅介護支援事業所のケアマネジャーの下書き作成を補助するアシスタントです。
以下のアセスメント情報から、居宅サービス計画書(第1表・第2表)の文案の"素案"を
作成してください。

# アセスメント情報
- 利用者の基本情報(年齢・要介護度・世帯状況など、個人が特定できない範囲で記載)
- 本人の意向・希望(できるようになりたいこと、続けたい生活習慣など)
- 家族の意向
- 現在のADL(日常生活動作)・IADL(生活関連動作)の状況
- 課題・リスク(転倒歴、服薬管理、認知機能など)

# 出力してほしいもの
1. 総合的な援助の方針(1〜2文)
2. 生活全般の解決すべき課題(ニーズ)の候補(3〜5個、優先順位付き)
3. 各ニーズに対応する長期目標・短期目標の候補
4. 短期目標に対応するサービス内容の候補(サービス種別のみ、事業所名は書かない)

# 条件
- 記載されていない情報を推測で作り出さない。判断材料が不足する場合は
  「情報不足のため要確認」と明記する
- あくまで「たたき台」であることを明示し、最終的な文言・優先順位の決定は
  ケアマネジャー本人が行うことを前提とした出力にする
- 個人が特定できる氏名・住所・被保険者番号などは入力しない前提で書く
```

出てきた文案は必ず「たたき台」として扱い、ニーズの優先順位・目標設定・サービス内容の最終決定は本人が行う。個人情報を含む実際のアセスメントデータは、無料の汎用AIにそのまま入力せず、後述する専用SaaS(法人契約・学習データ非利用が前提のもの)を使うか、個人が特定できない形に加工してから使う。

### 2. モニタリング記録・支援経過記録の音声入力

モニタリング訪問や電話での聞き取り内容を、その場でスマートフォンに録音し、AIで自動文字起こし・要約させる使い方が広がっている。

- **ミルモレコーダー(株式会社ウェルモ、2024年11月正式リリース)**: 音声を自動でテキスト化し、支援経過記録・訪問看護記録・モニタリング記録などのフォーマットに合わせて要約する。地域包括支援センターの活用例として、従来1時間かかっていた支援経過記録の作成が5分に短縮されたと報告されている。
- **音声記録AI(株式会社ワイズマン)**: インカムでの会話を自動文字起こしし、聞き逃した内容の再確認や記録作成のメモ代わりに使える機能を持つ。

**手順の目安**: モニタリング訪問時に利用者の同意を得た上でスマートフォンで録音 → 専用アプリ・SaaSにアップロード → 自動文字起こし → AIが記録フォーマット(訪問日・利用者の様子・サービス利用状況・課題の変化など)に沿って要約案を生成 → ケアマネが内容を確認・修正して記録として確定。

**コピペで使えるプロンプト例(文字起こしテキストからモニタリング記録案を作る)**

```
以下はモニタリング訪問時の会話の文字起こしです。モニタリング記録として
整理してください。

# 出力形式
1. 訪問日・対応者(記載があれば転記、なければ「別途記載」と明記)
2. 利用者の様子・体調の変化(発言内容から読み取れる範囲で)
3. 現在のサービス利用状況とその評価(本人・家族の発言をもとに)
4. ケアプラン上の目標に対する達成状況
5. 新たに生じた課題・気になる点
6. 次回訪問までの対応方針の候補

# 条件
- 発言していない内容を要約に加えない
- 断定できない内容は「〜という趣旨の発言があった」と原文に忠実な書き方にする
- 医学的な判断(病状の評価など)は行わず、必要であれば「主治医への確認が必要」と
  記載する

# 文字起こし
(ここに文字起こしを貼付。氏名や住所などの個人情報は「利用者A」等に置き換えてから貼る)
```

### 3. サービス担当者会議録の自動作成

サービス担当者会議(ケアプランの内容について利用者・家族・サービス提供者・主治医などが集まって検討する会議)の議事録作成は、1件あたり30分〜1時間程度を要するとされる負担の大きい業務である。

- **カナミックネットワークのAI議事録作成機能(2026年3月リリース)**: 介護専用クラウドソフトとして業界初の「システム内完結型」AI議事録機能で、スマートフォンで録音した会議データから介護に特化した議事録ドラフトを自動生成する。同社の介護AIクラウドサービスは、2026年7月に開始したASPIC(一般社団法人日本クラウド産業協会)の「生成AI利用クラウドサービス情報開示認定制度」の第一号認定(認定番号: 生成AI 0001-2607、2026年7月31日認定)を取得しており、データの取り扱いについて第三者機関の認定を受けているという点で選定の目安になる。
- **NotebookLM(Google)の活用**: ケアマネ自身が会議の録音データをNotebookLMに読み込ませ、議題・決定事項・今後のスケジュール・留意事項といった見出しでノート形式に整理する事例も報告されている。無料で使える一方、個人情報の取り扱いは自己責任になるため、氏名等を匿名化してから読み込ませる運用が紹介されている。

**コピペで使えるプロンプト例(会議の文字起こしから議事録案を作る)**

```
以下はサービス担当者会議の文字起こしです。会議録として整理してください。

# 出力形式
1. 開催日・出席者(役割のみ、例:ケアマネジャー・訪問介護事業所・主治医)
2. 検討事項(ケアプランのどの部分について話し合ったか)
3. 各出席者からの意見・提案(発言者の役割ごとに整理)
4. 決定事項
5. 今後の対応・次回までの課題

# 条件
- 発言していない内容を新たに作り出さない
- 出席者の氏名は「〇〇事業所担当者」のように役割表記に置き換える
- 結論が出ていない論点は「継続検討」と明記する

# 文字起こし
(ここに貼付)
```

### 4. 給付管理業務・保険者への提出書類の効率化

給付管理(利用者ごとの介護報酬の請求内容を管理し、国民健康保険団体連合会・保険者に提出する業務)では、給付管理票の記載内容とケアプラン・提供票の内容が一致しているかの点検、過誤請求(誤った請求)が生じた場合の同月過誤の手続きなど、ミスが許されない事務作業が多い。この領域は、AIによる文案生成よりも**記載内容の整合性チェック(一次点検)**での活用が中心になる。

```
以下は今月分の給付管理票案とケアプランの提供票(サービス種別・回数・単位数)です。
記載内容に不整合がないか点検してください。

# 確認してほしい項目
- サービス種別・提供回数がケアプラン(提供票)と給付管理票で一致しているか
- 単位数の計算に誤りがないか(入力データの単価・回数から再計算した結果と比較)
- 前月からの変更点(サービス追加・終了)が正しく反映されているか

# 出力形式
項目 | ケアプラン記載内容 | 給付管理票記載内容 | 不一致の有無・内容

# 条件
- 記載がない項目は「記載なし」と明記し、推測で埋めない
- 数値の再計算過程を示し、AIの計算にも誤りが起こり得ることを前提に、
  最終確認は必ず人が行う

# データ
(ここにケアプランの提供票データと給付管理票案を貼付)
```

同月過誤の提出期限や運用ルールは保険者(市区町村)ごとに異なるため、AIによる一次点検はあくまで見落とし防止のための補助として使い、最終的な提出判断・期限管理は担当者が行う。

### 5. 利用者・家族への説明文書の平易化、多職種連携での情報共有

ケアプランや主治医意見書には専門用語(サービス種別の略称、医療用語など)が多く含まれ、利用者・家族にそのまま渡すと理解しにくい。生成AIで「やさしい日本語」に言い換えた説明資料を作る使い方が広がっている。

```
以下のケアプランの内容を、専門知識のない利用者ご本人・ご家族向けに
わかりやすい説明文に書き換えてください。

# 条件
- 専門用語(サービス種別・介護保険の制度用語など)は必ず一言説明を添える
- 目標やサービス内容の意味(なぜこのサービスが必要か)が伝わるようにする
- 内容(目標・サービス内容・回数など)を勝手に変更・省略しない
- 敬体(です・ます調)で、読み上げても違和感のない自然な文章にする

# ケアプランの内容
(ここに貼付)
```

主治医意見書やLIFE(科学的介護情報システム)のデータなど、多職種で共有される医療情報の要約にもAIは使えるが、こうした情報を**誰に・どこまで共有してよいか**は情報の種類によって配慮が必要になる。厚生労働省の検討会でも、主治医意見書のような医療情報を利用者本人にそのまま共有する場合には、内容によって本人への心理的な影響が生じ得るため、共有する情報の範囲や伝え方を整理すべきだと指摘されている。AIで要約した内容をそのまま関係者全員に流すのではなく、共有先ごとに必要な範囲・表現を人が判断してから渡す運用にする。

## 注意点・よくある誤解

- **個人情報を安易にAIへ入力しない**: 氏名・住所・電話番号・生年月日・被保険者番号・家族構成・緊急連絡先といった利用者を特定できる情報や、病歴・服薬状況・認知症の症状・ADL・経済状況・虐待の疑いといった機微な情報は、無料の汎用AIにそのまま入力しない。介護事業所向けの生成AI利用ガイドラインでは「入れてよい情報は個人を特定できない情報のみ(例: 80代・女性・独居)」「入れてはいけない情報は利用者・職員の氏名/部屋番号/病名・既往歴/要介護度/顔写真/事業所が特定できる情報」といった線引きが推奨されている。法人として利用するツールは、学習データへの非利用が明記された法人向けプラン、または前述のASPIC認定のように第三者機関による情報開示の確認を受けたサービスを選ぶことが望ましい。
- **AIが出したケアプラン文案・要因分析を鵜呑みにしない**: 生成AIは、それらしいが実際のアセスメント内容に基づかない目標やサービス内容を作り出すことがある(ハルシネーション、詳細は「[生成AIのハルシネーションと対策](../part04-risk-security/hallucination-and-countermeasures.md)」を参照)。ニーズの判定・目標設定・サービス内容の最終決定は必ずケアマネジャー本人が行い、AIの出力は「たたき台」以上の位置づけにしない。
- **「AIケアプラン=AIが計画を決める」という誤解**: 厚生労働省の一連の実証研究は、あくまでケアマネジャーが持つ経験・思考をデータとして扱いやすくし、気づきの幅を広げる・説明をしやすくするための「支援」ツールという位置づけで進められている。AIが最終的なケアプランの内容を決定する仕組みではなく、専門職の判断を置き換えるものではない。
- **人手不足を背景にAI導入への期待は大きいが、構造的な担い手不足は解消しない**: 介護支援専門員実務研修受講試験の受験者数は2018年度に約13万人台から6割以上減少し、その後も回復していない。居宅ケアマネジャーの担当件数は逓減制(40人以上になると介護報酬が減算される仕組み)により35人程度が基準とされる一方、令和4年度の平均担当件数は44.0件に達している。AIによる記録・書類作成の効率化は、この構造的な人手不足そのものを解決するものではなく、生まれた時間を利用者との面談・専門的な判断業務に再投資するという位置づけで捉える必要がある。
- **給付管理・保険者提出書類の最終確認は人が行う**: AIによる整合性チェックは見落とし防止に有効だが、単位数の計算やサービス種別の解釈にAI自身が誤りを起こす可能性もある。提出前の最終確認は必ず担当者が行い、AIの点検結果を確定情報として扱わない。

## 最初の一歩

直近のモニタリング訪問またはサービス担当者会議の記録・議事録を1件選び、氏名・住所などの個人情報を「利用者A」のような表記に置き換えたうえで、上記のプロンプト例を汎用AIか使用中の介護記録ソフトのAI機能で試し、出てきた要約と自分が本来まとめる内容を見比べて、書き漏らしや不自然な言い換えがないかを確認してみる。
