# バックオフィス職における生成AI活用

## これは何か

人事・総務・経理・法務といったバックオフィス(管理部門)の仕事は、「規程・過去の書式に沿って、正確に、繰り返し発生する定型文書・定型判断を処理する」業務が多く、生成AIとの相性が良い領域である。一方で、個人情報・契約情報・財務情報など機密性の高いデータを扱うことが多く、マーケティングや企画職以上に「どこまでAIに読み込ませてよいか」「AIの提案をどこまで信用してよいか」の線引きが重要になる。本ページは、人事・総務・経理・法務それぞれの主要業務にどうAIを差し込むかを、コピペで使えるプロンプト例と部門特有の注意点つきで整理する。文章作成・リサーチの一般論は[生成AIによる文章作成・編集の実務活用](../part12-business-practice/ai-writing-and-editing.md)、情報漏洩対策の一般論は[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md)に委ね、本ページはバックオフィス業務への「実装」に絞る。

## 仕組み・背景

バックオフィス業務に生成AIが効きやすいのは、次の性質を持つ仕事が多いためである。

1. **型(フォーマット)が強く決まっている**: 求人票、契約書、規程、経費精算の申請項目など、あらかじめ構成・書式が決まった文書が多く、AIは型に沿った下書きを安定して生成できる。
2. **「一次スクリーニング」と「最終判断」を分けやすい**: 契約書の条文チェック、経費申請の異常検知、問い合わせ対応の一次回答などは、AIが大量の候補・下書きをさばき、人(法務担当者・上長・経理担当者)が最終確認をするという二段構えにしやすい。

帝国データバンクの調査(2026年3月)では、業務で生成AIを活用している企業は34.5%まで増加しており、活用企業のうち86.7%が「業務への効果が出ている」と回答している([帝国データバンク](https://www.tdb.co.jp/report/economic/20260514-genai/))。バックオフィス領域でも、経費申請→規程チェック→承認ルーティング→会計ソフト連携のような一連のワークフローをAIエージェント(複数の処理を自律的に連鎖させて実行する仕組み)が代行する事例が増えており、LINEヤフーは人事・総務領域で面接官トレーニングAIや日程調整の自動化など複数のAIツールを2026年春までに順次運用開始すると発表している([LINEヤフー](https://www.lycorp.co.jp/ja/news/release/020104/))。ただし、いずれも「AIが最終承認・最終判断まで代行する」段階ではなく、下書き・一次チェック・候補出しをAIが担い、規程との整合性確認や最終承認は人が担うという役割分担が現状の主流である。

## 使いどころ・使い分け

### バックオフィス部門別のAI活用マップ

| 部門 | 主なタスク | AIの向き・不向き | 主に使うAI機能 |
|---|---|---|---|
| 人事 | 求人票・JD(職務記述書)作成、面接評価コメントの下書き、社内問い合わせ対応、研修コンテンツ作成、人事評価コメントの下書き | 向く(型のある文章の量産・一次対応)。採用・評価の最終判断や、応募者・従業員の個人情報を伴う判断はAIに委ねない | 通常のチャット、社内FAQボット(RAG) |
| 総務 | 社内規程・マニュアルのドラフト作成、契約書の一次チェック観点整理、議事録作成、備品・施設管理の問い合わせ対応 | 向く(既存文書の要約・言い換え・観点整理)。規程の最終的な解釈・法的な最終判断は法務・専門家に確認 | チャット、社内FAQボット(RAG)、音声議事録機能 |
| 経理・財務 | 経費精算の一次チェック(規程違反・重複・不自然な金額の検知)、月次レポートの下書き、Excel/スプレッドシート業務の効率化 | 向く(定型的な数値チェック・要約)。会計処理の最終判断・監査対応はAIに丸投げしない | チャット、Advanced Data Analysis等のデータ分析機能、経費精算システムのAI機能 |
| 法務 | 契約書レビューの一次スクリーニング(リスク条文の洗い出し)、社内規程・ガイドラインの平易な言い換え、判例・法令のリサーチ補助 | 向く(条文の見落とし防止・大量文書の一次確認)。契約の締結判断や法的助言はAIではなく弁護士・法務専門家が担う(弁護士法との関係に注意、後述) | 契約書レビュー特化AI(リーガルテック)、通常のチャット |

判断の軸は他の職種と同様で、「大量の候補・下書きを作って人が選ぶ・確認する」仕事はAIに任せやすく、「一つの正解を最終確定する」仕事(採用の合否、契約の締結、会計処理の確定、法的な結論)は人が主導し、AIは材料出し・一次チェックに徹する、という切り分けになる。

## 実務での使い方

### 【人事】プロンプト例1: 求人票・JD(職務記述書)の作成

求人票は「誇張しすぎない・事実ベースで書く」ことが応募後のミスマッチを防ぐ観点で重要になる。手元の情報を正確に渡し、AIには構成と言葉選びを任せるのが実務的な使い方。

```
あなたは採用広報の経験が豊富な人事担当者です。以下の情報から求人票の原稿を作成してください。

## 募集職種・部署
[例: 経理担当(正社員)、経営管理部]

## 募集背景
[例: 事業拡大に伴う増員。既存メンバー2名体制の補強]

## 業務内容
[例: 月次・年次決算業務、経費精算チェック、税理士対応]

## 応募条件(必須/歓迎)
[例: 必須: 簿記2級相当の知識、Excel実務経験。歓迎: 上場企業での経理経験]

## 働き方・条件
[例: フレックスタイム制、リモート週2日可、想定年収400〜550万円]

## 出力条件
- 「募集背景」「業務内容」「応募条件」「働き方」「入社後の成長イメージ」の見出しで構成
- 誇張表現(「即戦力なら誰でも活躍できる」等)は避け、渡した情報のみを事実として書く
- 求職者が知りたいであろう「1日の流れ」の項目を1つ追加で提案する
```

JD(職務記述書、職務内容・責任範囲・必要スキルを定義した文書)を先に作っておくと、この求人票プロンプトの「業務内容」「応募条件」欄をそのまま流用できるため、JD→求人票の順で作成すると手戻りが減る。

### 【人事】プロンプト例2: 面接評価コメントの下書き

評価コメントは「合否の判断」そのものをAIにさせるのではなく、面接官がメモした事実を整理して読みやすい文章にする用途に絞るのが安全な使い方。

```
以下は面接官が面接中にとったメモです。このメモの内容のみを使って、
人事評価システムに登録する面接評価コメントの下書きを作成してください。

## 面接メモ
[例: 論理的に話す。前職の実績は具体的な数字で説明できていた。
チームでの役割については聞かれるまで言及なし。逆質問は3つ、うち2つは待遇面。]

## 出力条件
- 「強み」「懸念点」「確認が必要な点」の3項目に整理する
- メモに書かれていない事実を推測や憶測で補わない
- 合否の推奨や点数化は行わず、事実の整理のみに留める
- 表現は中立的にし、性別・年齢・容姿等に関する記述がメモにあっても評価コメントには反映しない
```

「メモに書かれていない事実を補わない」という指定は、[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md)で扱う「AIが文脈から都合のよい情報を作り出す」事故を防ぐために重要であり、採用のような個人の処遇に直結する場面では特に徹底する。

### 【総務】プロンプト例3: 社内規程・マニュアルのドラフト作成

既存規程の改訂や新規程の草案作成は、ゼロから書かせるのではなく「類似の既存規程」を土台に修正させる方が抜け漏れが少ない。

```
あなたは総務・労務に詳しい担当者です。以下の既存規程を土台に、
新しい制度に対応した規程の改訂案を作成してください。

## 既存規程(現行の在宅勤務規程)
[既存規程の本文を貼り付け]

## 変更したい点
[例: 対象者を「入社1年以上」から「入社3か月以上」に緩和、
週の在宅勤務上限を「週2日」から「週3日」に変更]

## 出力条件
- 変更箇所には[変更]の印を付け、変更前と変更後を対比できるようにする
- 条文番号・体裁は既存規程の形式を維持する
- 変更によって既存の他条文(通勤費規程、労働時間管理の条文など)と矛盾が生じないか、
  懸念点があれば末尾に指摘する
```

生成された改訂案は、実際の労務担当者・社会保険労務士による確認を経てから発効させる。特に就業規則に関わる変更は労働基準法上の手続き(意見聴取・届出等)が必要になる場合があるため、AIの下書きはあくまで「たたき台」として扱う。

### 【総務】プロンプト例4: 社内問い合わせ対応(FAQボット)の考え方

総務・人事・経理宛ての「有給休暇の残数は?」「経費精算の締め日は?」といった定型的な問い合わせは、チャットで都度回答するのではなく、社内規程・マニュアルをAIに検索させて自動応答する仕組み([RAG(検索拡張生成)の基本](../part07-data-analysis/rag-basics.md))を作ると効果が大きい。RAGは、AIが回答前に社内文書を検索し、その内容に基づいて答える仕組みで、シナリオ型(想定Q&Aを事前登録する型)のチャットボットに比べて「規程集を横断して答えられる」利点がある。導入は3〜6か月程度の期間を見込み、最初の1〜2か月は問い合わせ削減効果が出にくいが、ナレッジ(参照させる社内文書)が積み上がる4〜6か月目から効果が顕著になる傾向がある。ツール横断では、Microsoft 365環境ならCopilotのSharePoint連携、Google Workspace環境ならGeminiとGoogle Driveの連携、専用ツールを使う場合はDifyやNotebookLMでRAGボットを構築する選択肢がある(構築手順は[RAG(検索拡張生成)の基本](../part07-data-analysis/rag-basics.md)を参照)。

### 【経理・財務】プロンプト例5: 経費精算の一次チェック観点整理

経費精算システムのAI機能(OCR+不正検知)を使わずにチャットAIだけで確認する場合も、「どこを見るべきか」の観点整理にAIを使うと確認漏れを減らせる。

```
あなたは経理担当者です。以下の経費精算申請リストについて、
社内規程に違反する可能性がある項目、重複申請の疑いがある項目、
金額が不自然に高い項目をチェックしてください。

## 経費精算規程の要点
[例: 会食は1人あたり5,000円まで、タクシー利用は22時以降の残業時のみ、
交通費は最短経路のみ承認]

## 申請リスト
[申請日・金額・費目・利用目的等の一覧を貼り付け]

## 出力条件
- 「規程違反の疑い」「重複の疑い」「金額が不自然」の3カテゴリで指摘する
- 断定はせず、「確認が必要」というレベルの指摘に留める
- 規程に明記されていない曖昧なケースは、判断せず「要確認」として一覧化する
```

AIの指摘は「確認すべき候補の洗い出し」であり、最終的な承認・否認の判断は必ず人(経理担当者・上長)が行う。実際の経費精算システム(楽楽精算、マネーフォワード クラウド等)には、AI-OCRによる領収書読み取りと、重複申請・不自然な金額・キックバックの疑いなどを検知するAIエージェント機能が搭載されているものもあり、日常的な一次チェックは業務システム側のAI機能に任せ、チャットAIは規程の解釈や例外ケースの相談に使うという分担も実務的。

### 【経理・財務】プロンプト例6: 月次レポートの下書き

数値データの集計・グラフ化・傾向の言語化は、Advanced Data Analysis等のデータ分析機能([ChatGPTのデータ分析機能(Advanced Data Analysis)の使い方](../part07-data-analysis/chatgpt-advanced-data-analysis.md))にCSV等を読み込ませると効率が良い。

```
アップロードした月次の部門別経費データをもとに、経営会議向けの月次レポートの
下書きを作成してください。

## 出力条件
- 「前月比・前年同月比のサマリー」「増減が大きい費目とその要因の仮説」
  「今後の注意点」の3部構成
- 数値は貼り付けたデータのみを使い、記載のない数値を推測で補わない
- 費目の増減理由はデータから読み取れる相関の言語化に留め、
  因果関係を断定する表現(「〜が原因である」等)は避け、「〜の可能性がある」と表現する
```

「因果関係を断定しない」という指定は重要で、AIが示す増減の「理由」はあくまで一次的な仮説であり、実際の原因は担当者への確認や追加のヒアリングで検証する。

### 【法務】プロンプト例7: 契約書レビューの一次チェック観点整理

```
あなたは契約書レビューの実務に詳しいアシスタントです。
以下の契約書(業務委託契約書)について、当社(受託者側)の立場で
一次チェックの観点を整理してください。

## 契約書本文
[契約書の本文を貼り付け]

## 出力条件
- 「損害賠償の範囲・上限」「契約解除の条件」「知的財産権の帰属」
  「秘密保持義務の範囲・期間」「支払条件」の5観点で、
  当社に不利な条文がないかを指摘する
- 一般的な業務委託契約と比べて特異な条項(通常見られない条項)があれば指摘する
- 法的な結論(この契約が有効か、締結すべきか)は述べず、
  「弁護士・法務担当者への確認が必要な論点」として整理する
```

契約書レビューは、法務省が2023年8月1日に公表したガイドライン「AI等を用いた契約書等関連業務支援サービスの提供と弁護士法第72条との関係について」以降、リーガルテック(法務向けAIツール)の導入が広がった領域だが、後述の注意点にあるとおり、AIによるレビューが弁護士法第72条(非弁行為の禁止)との関係でどこまで許容されるかは個別事情によって判断が分かれるグレーゾーンが残っている。社内でAI契約書レビューツールを導入する場合は、「AIの指摘はあくまで一次チェック・観点整理であり、最終的なレビュー・法的判断は弁護士または社内の法務専門家が行う」という運用を明確にしておく。

### 【法務】プロンプト例8: 社内規程・ガイドラインの平易な言い換え

法務が作成した規程・ガイドラインを従業員向けに分かりやすく言い換える用途は、法務部門の負荷を軽減しやすい。

```
以下の社内規程の条文を、法律の専門知識がない従業員向けに、
平易な言葉で要約してください。

## 規程本文
[規程の条文を貼り付け]

## 出力条件
- 条文の意味を変えずに、専門用語("善管注意義務"等)には一言説明を付ける
- 「やってよいこと」「やってはいけないこと」を箇条書きで対比させる
- 元の条文の法的な効力・解釈が変わるような意訳はしない
- 要約の末尾に「正確な内容は元の規程を確認してください」という注記を必ず付ける
```

## 注意点・よくある誤解

- **個人情報・機密情報の入力ルールを部門ごとに明確にする**: 人事は履歴書・評価情報、経理は取引先の財務情報、法務は契約相手の秘密情報など、バックオフィスが扱う情報はいずれも機密性が高い。無料プランや外部の一般的なチャットAIに実データをそのまま貼り付けず、法人契約プラン(学習利用が既定オフになっているもの)や社内限定のAI環境を使う(詳細は[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md))。
- **「AIの一次チェック」と「最終判断」を混同しない**: 契約書レビュー、経費精算の異常検知、採用の合否評価などは、AIが候補・懸念点を洗い出す一次チェックまでは向いているが、最終的な締結判断・承認・合否決定は必ず人(専門家・責任者)が行う。特に契約書レビューは、法務省のガイドライン(2023年8月1日公表)以降も、AIによるレビューが弁護士法第72条の非弁行為に該当するかは個別事情に応じた判断が必要な領域であり、「AIレビューだけで契約締結を決める」運用は避ける。
- **人事評価・採用でのバイアスと公平性に注意する**: 面接評価コメントや人事評価コメントの下書きにAIを使う場合、性別・年齢・国籍等に関する記述をAIが評価に反映してしまわないよう、プロンプトで明示的に除外を指示する。また、AIが生成した「客観的に見える」コメントも、元になった面接メモ自体に評価者のバイアスが含まれていれば結果は変わらない点に注意する。
- **数値・規程内容のハルシネーションに注意**: 経費規程の上限額や契約書の条項内容をAIが文脈から誤って補完・要約してしまうことがある。規程・契約書のような「一言一句が意味を持つ」文書を扱う際は、必ず元文書と照合し、AIの出力を鵜呑みにしない(詳細は[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md))。
- **社内FAQボットは「作って終わり」ではない**: RAGボットは参照させる社内文書(規程・マニュアル)が古い・整備されていないと誤った回答を返す。導入後も規程改訂のたびに参照元文書を更新する運用体制を決めておかないと、効果が出るまでの3〜6か月を待っても改善しない。

## 最初の一歩

自部門(人事・総務・経理・法務のいずれか)で直近発生した定型業務(求人票作成、経費精算チェック、契約書レビュー、規程改訂のいずれか)を1件選び、本ページのプロンプト例をコピーして実際に試し、AIの下書き・一次チェック結果と自分の確認結果を比べてみる。
