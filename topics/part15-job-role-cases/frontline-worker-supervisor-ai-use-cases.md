# 製造・建設現場の作業員・現場監督における生成AI活用事例

## これは何か

本ページは、工場のライン作業員・設備保全担当、建設現場の職人・現場監督といった**PCではなくスマホしか持たない「現場の人」**が、日々の業務で生成AIをどう使うかを扱う。具体的には、KY活動(危険予知活動、作業前に潜む危険を洗い出す安全ミーティング)のネタ出し、外国人労働者向けの作業指示の多言語化、音声入力による作業日報・施工日誌の作成、設備点検チェックリストの作成・記録、スマホで現場ルールを聞けるAIチャットボットといった、**現場の個人が手を動かしながら使う場面**にフォーカスする。

隣接ページとの境界を先に整理しておく。[生産管理・SCM担当における生成AI活用事例](production-management-scm-ai-use-cases.md)は需要予測・生産計画という**計画・管理側**の話であり、[品質管理・QA職における生成AI活用事例](quality-assurance-ai-use-cases.md)は検査報告書の作成やテスト設計という**QA担当者という職種**の話である。また[建設・不動産における生成AI活用事例](../part14-industry-cases/construction-realestate-ai-use-cases.md)は業界全体の経営・投資判断としての事例集になっている。本ページはこれらのどれとも異なり、**製造ラインの作業員や建設現場の職人・現場監督個人が、その日その場でどうAIを使うか**という一段下のレイヤーを扱う。[店舗・販売スタッフ職における生成AI活用事例](retail-store-staff-ai-use-cases.md)と同じく「PCに向かう時間がほとんどない現場職」という制約を共有する隣接ページなので、あわせて参照するとよい。

## 仕組み・背景

現場作業員・現場監督向けの生成AI活用は、他の職種以上に「使う端末・使う手」の制約が強い。オフィスワーカーはキーボードで長文を打てるが、現場では次のような制約がある。

- **端末はスマホ1台のみ**: 会社支給のノートPCがなく、私物か会社支給のスマホだけで完結させる必要がある
- **手がふさがっている・汚れている・手袋をしている**: 工具を持ったまま、軍手や防護手袋をしたままではタップ入力が難しい
- **文字入力に不慣れなメンバーが多い**: ベテラン職人や年配の作業員、日本語の読み書きに不慣れな外国人材にとって、長文のプロンプトを打つこと自体がハードルになる

この制約から、現場向けの生成AI活用は「**音声で話しかけて、AIが整形する**」という音声ファーストのUXが軸になる。実際、建設業界向けの音声認識大手アドバンスト・メディアは2026年4月、音声認識AI「AmiVoice」と生成AIを組み合わせた建設業界向け基盤「AmiVoice B-Work One」を発表し、今後3年で3,000社・20万ライセンス規模への展開を目指すと発表している。現場でのキーボード・タッチパネル操作の難しさを解消し、音声によるデータ入力・コマンド操作を軸にする狙いだとされる([ITmedia BUILT](https://built.itmedia.co.jp/bt/articles/2604/16/news043.html))。

現場向けの生成AI活用は、大きく3つの系統に分かれる。

1. **汎用チャットAIの音声入力機能を使う「個人利用」型**: ChatGPT・Geminiのスマホアプリのマイクボタンで話しかけ、テキスト化・要約・フォーマット整形をその場でやらせる。導入コストがほぼゼロで今日から始められる一方、社内システムとは連携していないため「下書き」の域を出ない
2. **現場向けに特化した専用ツール型**: 音声認識×生成AIで日報・議事録・点検記録を自動生成する専業サービス(前述のAmiVoice B-Work One、施工管理アプリのAI機能など)、KY活動の提案に特化したAIアプリ(後述)、多言語動画マニュアル・翻訳プラットフォームなど、現場の業務フローに組み込まれた製品
3. **画像認識AI(カメラ)による安全監視**: 現場に設置した固定カメラや作業員のウェアラブルカメラの映像をAIが解析し、ヘルメット未着用・立入禁止エリアへの侵入・不安全な姿勢などをリアルタイムで検知して警告する仕組み。これは生成AIではなく従来型の画像認識・物体検知AIだが、現場の安全管理という文脈では生成AIツールとセットで語られることが多いため、本ページでも扱う

安全管理領域では、AIが過去の作業マニュアルや災害事例を学習し、KY活動での「気づき」を提案する専用アプリの実用化が進んでいる。三菱電機ビルソリューションズは、AWSの生成AI基盤「Amazon Bedrock」を使った危険予知活動支援アプリ「KY-Support」を自社開発し、2026年4月から全社導入を開始した。トライアル現場での検証では、AIによる潜在的リスクの網羅率が9割を超える実効性を確認したとしている(ベンダー公表)([三菱電機ビルソリューションズ プレスリリース](https://www.mebs.co.jp/press/260326.html)、[ITmedia BUILT](https://built.itmedia.co.jp/bt/articles/2604/16/news067.html))。シナモンAIも、独自の高精度RAG(検索拡張生成)技術「Super RAG」を使い、三菱ガス化学と共同で作業に潜む危険を自動サジェストするKY支援システム「MGC-KYAS」を構築し、国内5工場への導入を進めている([PR TIMES](https://prtimes.jp/main/html/rd/p/000000126.000028252.html))。

外国人労働者の多言語対応も現場AI活用の重要な柱である。特定技能・技能実習制度で働く外国人材は製造業・建設業に多く在籍しており、労働災害は言葉の壁が原因のひとつになっている。現場DXプラットフォームのカミナシは、多言語対応の動画マニュアル・研修システム「カミナシ 教育」を提供しており、動画マニュアルや教育コンテンツを13言語に翻訳して閲覧・受講できる([カミナシ プレスリリース](https://corp.kaminashi.jp/news/pr_20250106_3))。厚生労働省も建設業に従事する外国人労働者向けに、英語・中国語・ベトナム語・インドネシア語など10言語以上に対応した教材を公開している([厚生労働省](https://www.mhlw.go.jp/stf/newpage_10973.html))。

## 使いどころ・使い分け

### 業務フェーズ別の活用マップ

製造ライン作業員・建設現場作業員/現場監督の1日の流れに沿って、どこに生成AIが入るかを整理すると次のようになる。

| 業務フェーズ | 頻度 | AIの使いどころ | 向く担当 |
|---|---|---|---|
| 朝礼・KY活動 | 毎日(作業開始前) | 作業内容・天候・過去の災害事例からその日の危険予知ネタ・声かけ項目を提案 | 現場監督・職長 |
| 作業指示の伝達 | 毎日〜随時 | 日本語の作業指示書を外国人作業員向けにやさしい日本語・多言語に変換 | 現場監督・教育担当 |
| 作業中の設備点検 | 定期(始業前点検・巡回点検) | 点検項目チェックリストのたたき台作成、点検結果の音声入力→記録整形 | 作業員・保全担当 |
| 作業中の安全監視 | 常時 | (直接使用は難しいが)カメラ映像からヘルメット未着用・立入禁止エリア侵入をリアルタイム検知 | 現場監督・安全管理者 |
| 疑問点の解消 | 随時 | 現場ルール・過去のトラブル対応をスマホのチャットで質問し即座に回答を得る | 作業員全般 |
| 終業後の日報・日誌作成 | 毎日 | 音声で話した作業内容・進捗を社内フォーマットの作業日報/施工日誌に自動整形 | 作業員・現場監督 |
| ヒヤリハット報告 | 発生時 | 口頭で話した経緯をヒヤリハット報告書の文章に整形 | 作業員・現場監督 |

判断の軸は、「その場で音声を打ち込んで整形するだけで済む業務」か「安全に直結し、専門知識・実データとの照合が要る業務」かで分けるとよい。日報整形やKY活動のネタ出しは汎用チャットAIの音声入力で十分に価値が出るが、カメラによる安全監視や、労災リスクに直結する多言語作業指示の最終確認は専用ツール・専門家の関与が必要な領域になる。

### 使えるツール・構成(汎用チャットAI vs 専用ツール)

| 業務 | 汎用チャットAI(ChatGPT/Gemini等の音声入力)でできる範囲 | 専用ツールが必要な範囲 |
|---|---|---|
| KY活動のネタ出し | 「今日の作業は○○です。注意すべき危険を挙げて」と話しかけて一般的な危険予知項目を出させる | 自社の過去の災害事例・作業マニュアルを学習させた専用AI(KY-Support、MGC-KYASのような社内ナレッジ連携型)による網羅率の高い提案 |
| 作業指示の多言語化 | 短い指示文をその場でやさしい日本語・英語等に翻訳する壁打ち | マニュアル全体の多言語動画化、13言語対応の教育プラットフォーム(カミナシ 教育など)、用語集の一元管理 |
| 作業日報・施工日誌 | スマホの音声入力で話した内容を、指定フォーマットの文章に整形させる | 勤怠・写真・図面データと連携した施工管理アプリのAI機能(音声認識×生成AIの専業基盤) |
| 設備点検チェックリスト | 点検項目リストのたたき台作成、点検結果メモの文章整形 | 台帳・過去データとの自動突合、異常値の自動フラグ付け、写真からの自動採寸 |
| 現場ルールの問い合わせ | 一般的な安全衛生知識についての壁打ち | 自社の現場ルール・過去トラブル事例を学習した専用チャットボット(誤情報を出さないよう社内文書に限定した回答) |
| 安全監視(ヘルメット・立入禁止エリア) | 不可(画像認識・物体検知の技術領域) | AIカメラによるリアルタイム検知・アラート専用システム |
| ヒヤリハット報告 | 口頭の経緯を報告書の文章に整形 | 複数現場のヒヤリハットを横断集計してパターン分析 |

小規模な工事店・工場であれば、まずは無料〜低価格帯の汎用チャットAI(ChatGPTの無料版・Geminiアプリの音声入力機能)で「日報の音声入力」「KY活動のネタ出しの壁打ち」を試すだけでも工数削減の効果が出やすい。外国人材を多数雇用する現場や、複数拠点で安全管理を統一したい企業では、多言語教育プラットフォームやAIカメラ、KY支援アプリといった専用システムへの投資を検討する順番になる。

## 実務での使い方

### 1. KY活動(危険予知活動)のネタ出し

朝礼前に、その日の作業内容をチャットAIに音声で話しかけ、危険予知のポイントを箇条書きで出させる使い方。あくまで「気づきの材料」であり、最終判断は現場責任者が行う前提を崩さない。

**コピペで使えるKY活動ネタ出しプロンプト例**

```
あなたは建設・製造現場の安全管理を支援するアシスタントです。
以下の作業内容について、作業前のKY活動(危険予知活動)で
話し合うべき危険予知項目を、重大度が高い順に5つ、
それぞれ「想定される危険」「具体的な対策・声かけ」の2点セットで
挙げてください。断定的な「安全である」という表現は避け、
現場責任者が最終確認する前提で、気づきの材料として出力してください。

## 作業内容
{{例: 高さ3mの足場での外壁塗装作業、作業員3名、当日は雨天予報}}

## 現場の状況
{{例: 隣接して重機の稼働あり、通路が狭い、新人作業員1名参加 など}}
```

### 2. 外国人作業員向けの作業指示の多言語化

特定技能・技能実習で働く外国人作業員に向けて、日本語の作業指示書をやさしい日本語や多言語に変換する使い方。安全に関わる指示は必ずダブルチェックする(詳細は後述)。

```
以下の作業指示書を、日本語がまだ得意でない外国人作業員にも
伝わるように書き換えてください。次の2パターンで出力してください。

1. 「やさしい日本語」版: 一文を短く、漢字にふりがなを振り、
   専門用語には()で簡単な言い換えを添える
2. {{ベトナム語/英語/インドネシア語など}}への翻訳版

特に「危険」「禁止」「必ず◯◯すること」という安全に関わる
指示は、意味が曖昧にならないよう強調して訳してください。

## 元の作業指示書
{{作業手順・注意事項のテキスト}}
```

### 3. 音声入力による作業日報・施工日誌の作成

現場から事務所に戻らず、その場でスマホに向かって話した内容を、社内フォーマットの作業日報・施工日誌に整形させる使い方。ChatGPT・Geminiのスマホアプリの音声入力(マイクボタン)を使い、話した内容をそのままチャットに貼り付けて整形させる。

```
以下は現場での作業内容を音声で話した内容の文字起こしです。
これを、当社の作業日報フォーマットに沿って整形してください。

## 出力フォーマット
- 作業日/天候/現場名
- 作業内容(箇条書き)
- 人員配置(氏名・役割)
- 進捗状況(予定に対する遅れ・前倒しの有無)
- 安全・特記事項(ヒヤリハット・資材の過不足など)

## 音声入力の文字起こし
{{音声入力でそのまま話した内容をここに貼り付け}}

## 出力時の注意
- 話し言葉のフィラー(「えーっと」「あの」など)は削除する
- 数値(寸法・数量・時刻)は聞き取れる範囲でそのまま転記し、
  不明瞭な箇所は「(要確認)」と明記する
```

### 4. 設備点検チェックリストの作成・点検結果の整形

始業前点検・定期巡回点検のチェックリストのたたき台を作らせ、点検結果は音声で話して記録用の文章に整形させる。手袋をしたままでも音声で完結できるのが利点。

```
以下の設備について、始業前点検で確認すべき項目を
チェックリスト形式(□項目名、で始まる箇条書き)で
15項目以内にまとめてください。異音・異臭・油漏れ・
安全カバーの有無など、目視・聴覚・嗅覚で確認できる
項目を優先してください。

## 設備情報
{{設備名・型式・用途を記載}}

---
(点検後、以下のように音声で結果を話しかけて整形させる)

以下は点検結果を音声で話した内容です。上記チェックリストに
沿って、項目ごとに「異常なし」「要経過観察」「要修理」の
いずれかに分類し、点検記録の文章に整形してください。

{{点検結果を話した文字起こし}}
```

### 5. 現場ルール・手順に関するスマホでの質問応答

作業中に手が空いた瞬間、スマホでチャットAIに現場ルールや一般的な作業手順を質問し、その場で確認する使い方。社内の正式なルールブックとの食い違いがないか確認する運用とセットにする。

```
私は{{製造/建設}}現場の作業員です。以下について、
一般的な安全衛生の考え方・標準的な手順を教えてください。
ただし、当社独自のルールがある場合はそちらが優先されるため、
「一般論としては」という前提を明示した回答にしてください。

## 質問
{{例: 高所作業での安全帯の掛け替えのタイミングは？
   フォークリフトの死角に人がいる場合の合図の出し方は？}}
```

### 6. ヒヤリハット報告書の作成

ヒヤッとした・危なかったと感じた出来事を、その場で音声で話し、報告書の文章に整形させる。記憶が新しいうちに記録できるため、報告のハードルが下がる。

```
以下は現場でのヒヤリハット(事故には至らなかったが
危険を感じた出来事)を音声で話した内容です。
これをもとに、社内のヒヤリハット報告書の形式で整形してください。

## 出力フォーマット
- いつ・どこで・誰が
- 何が起きたか(事実のみ、感情表現は除く)
- なぜ危険だと感じたか
- 今後の再発防止のためのアイデア(任意)

## 音声入力の文字起こし
{{話した内容}}
```

## 注意点・よくある誤解

- **KY活動のAI提案は「気づきの材料」であり最終判断の代わりにはならない**: AIが過去の災害事例から一般論として危険項目を提示しても、その日・その現場固有のリスク(天候・隣接作業・新人の有無など)を踏まえた最終判断は、有資格者・現場責任者が行う。AIの提案をそのまま読み上げるだけのKY活動は「形骸化」を招くと指摘されている
- **多言語翻訳の誤訳は労災に直結する**: 「立入禁止」「必ず着用」といった安全に関わる指示の翻訳を汎用チャットAIに任せきりにすると、ニュアンスの取り違えがそのまま事故につながりかねない。安全関連の翻訳は、母語話者や多言語対応の専用教育プラットフォームでのダブルチェックを経てから現場に展開する
- **音声入力の誤変換は数値の記録ミスにつながる**: 現場は騒音が多く、音声認識の精度が屋内オフィスほど出ないことがある。特に寸法・数量・圧力値といった数値は誤変換されやすいため、日報・点検記録に反映する前に必ず人が読み返して確認する
- **AIカメラによる安全監視は労働者への周知と目的の明確化が必須**: ヘルメット検知・立入禁止エリア検知のためのカメラ映像が、意図せず「監視」として受け取られると現場の反発を招く。安全目的での利用であることを事前に周知し、映像の保管・利用範囲を明確にしておく
- **無料版の汎用チャットAIに図面・仕様・顧客情報を貼り付けない**: 作業日報や点検記録には、取引先名・図面番号・仕様といった機密情報が含まれることがある。個人のスマホの無料版アプリにそのまま貼り付けると、入力内容が学習に使われる設定のままになっている場合があり、情報漏洩リスクになる。[情報漏洩・データ管理](../part04-risk-security/)の考え方に沿って、法人契約のプランを使う・機密情報は伏せ字にするといった運用にする
- **ITに不慣れなベテラン・年配作業員には音声入力から始めてもらう**: テキスト入力を前提にした導入は、キーボードに不慣れな層にとってハードルが高い。「話しかけるだけ」の音声入力から始め、慣れてきたら他の使い方に広げるほうが定着しやすい

## 最初の一歩

明日の作業終了後、事務所に戻る前にスマホのChatGPTかGeminiアプリを開き、音声入力でその日の作業内容を1分ほど話しかけて、上記の作業日報プロンプトで整形させてみる。整った日報が数十秒で出るかどうかを一度体感することが、現場でのAI活用の入り口になる。
