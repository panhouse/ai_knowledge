# 不動産管理(プロパティマネジメント)担当者における生成AI活用事例

## これは何か

本ページは、賃貸管理会社(プロパティマネジメント会社、PM会社)で、オーナー(貸主)から預かった賃貸物件の**日々の運営を代行する担当者**の業務に生成AIをどう組み込むかを扱う。入居者からの設備トラブル・騒音・鍵紛失といった問い合わせ対応、家賃滞納者への督促、空室を埋めるための物件紹介文・SNS投稿の作成、修繕見積もりの比較や業者との連絡、重要事項説明書・賃貸借契約書のチェック補助、クレーム対応記録の要約が主な守備範囲になる。

似た名前の隣接ページとの境界を先に整理しておく。

- **仲介・売買との違い**: 物件をオーナーや買主に紹介し、契約を成立させる「仲介・売買」業務(反響対応、内見案内、重説・契約の締結)は別の職種であり、本ページでは扱わない。契約成立後、その物件を**運営し続ける**業務(入居者対応、賃料回収、原状回復、次の入居者募集)が本ページの範囲である。
- **Part14「ビル管理・ファシリティマネジメント業界」との違い**: [ビル管理・ファシリティマネジメント業界における生成AI活用事例](../part14-industry-cases/facility-management-ai-use-cases.md)は、オフィスビルなど**大規模建物の設備(空調・エレベーター等)を物理的に維持管理する事業者**を業種目線で扱うページで、予知保全・法定点検・清掃警備が中心である。本ページは主に**賃貸マンション・アパートの入居者・オーナーとの間に立つPM担当者個人**の日常業務にフォーカスし、設備の物理的な保守そのものよりも、入居者対応・滞納督促・空室対策・書類チェックといった「人と紙(契約)」に関わる業務を扱う。両者は同じ「不動産の運営」でも見ている対象(建物の設備 vs 入居者・オーナーとのやり取り)が異なるため、実務では相互に参照するとよい。

賃貸管理の現場は、「深夜・休日を問わず発生する入居者からのトラブル連絡」「オーナーへの説明責任」「宅地建物取引業法など法令に基づく書式の正確性」という、他の管理部門とは異なる制約を抱えている。本ページでは、その制約を踏まえた具体的な活用場面とプロンプト例を整理する。

## 仕組み・背景

賃貸管理業務への生成AI活用は、大きく3つの系統に分かれる。

1. **汎用チャットAIをPC・スマホから使う「個人利用」型**: ChatGPT・Gemini・Claudeなどを担当者が個人で開き、督促文面の下書きや物件紹介文の案出し、クレーム対応記録の要約に使う。導入コストがほぼゼロで今日から始められる一方、管理物件のデータベースや管理規約とは連携していないため、あくまで「文章の下書き」としての利用にとどまる。
2. **賃貸管理システムに組み込まれた「業務システム」型**: イタンジ「ITANDI 賃貸管理」やGMO ReTech「GMO賃貸DX 入居者アプリ」のように、入居者アプリ・オーナー向け管理画面と一体化したAI機能。管理物件の契約情報・過去のやり取りと連携するため精度が高いが、導入・契約が必要で担当者個人の裁量では選べないことが多い。
3. **特定業務に特化した専業AIサービス**: 家賃滞納の督促電話を自動化するAIエージェント(Gnox「督促AIエージェント」等)や、重要事項説明書・賃貸借契約書の下書きを自動生成する専業サービス(Paradis「Ai-Smart重説」等)のように、宅建業法や管理規約といった業界固有の知識をあらかじめ組み込んだ縦割り型のツールが2025年後半以降相次いで登場している。

入居者対応の領域では、GMO ReTechが2026年5月、不動産管理会社向け「GMO賃貸DX 入居者アプリ」に生成AIが入居者からの定型的な問い合わせに自動回答する「AIチャット自動返信機能」を追加すると発表し、2026年8月からの提供開始を予定している(GMO ReTech公式発表)。イタンジも2026年3月、「ITANDI 賃貸管理」の入居者システムに、入居者からの問い合わせに対してAIが回答案を提示する「AI入居者対応支援機能」の提供を開始した。マンション管理領域では、GOGEN社の「Chat管理人 Powered by GPT-4」のように、管理規約・設備マニュアル・申請書類をAIに読み込ませ、入居者からの質問に24時間自動応答する専業チャットサービスも先行して普及している。

督促の領域では、Gnoxの「督促AIエージェント」のように、本人確認・交渉・支払約束の取得・SMS送信・入金後の架電停止までを電話AIが一体で行うサービスが登場しており、保証会社・賃貸管理会社向けに提供されている。

書類作成の領域では、Paradis社の「Ai-Smart重説」が、登記簿謄本・重要事項調査報告書・管理規約・図面などをアップロードするとAIが内容を読み取り、重要事項説明書と賃貸借契約書のドラフトを最短10分で作成する仕組みを提供している。ただし重要事項説明書の**説明そのもの**は宅地建物取引士(宅建士)の独占業務であり、AIはあくまで書類の下書き作成を支援する位置づけである点に注意が必要(後述)。

物件紹介文の領域では、汎用チャットAI(ChatGPTやClaude等)に物件の特徴を入力するだけでターゲット層に合わせた紹介文を生成させる使い方が広がっており、ある不動産会社の事例では作成時間を30分から5分に短縮し、反響数が約3倍になったという報告もある(個社の実践例であり、効果は物件・訴求内容によって変動する)。

## 使いどころ・使い分け

### 業務フェーズ別の活用マップ

PM担当者の1日〜1ヶ月の業務の流れに沿って、どこに生成AIが入るかを整理すると次のようになる。

| 業務フェーズ | 頻度 | AIの使いどころ | 向く担当 |
|---|---|---|---|
| 入居者からの問い合わせ対応(設備トラブル・騒音・鍵紛失等) | 常時 | よくある質問への一次回答案の作成、緊急度の切り分け | 入居者対応担当・コールセンター |
| 家賃滞納者への督促 | 毎月(滞納発生時) | 督促文面(電話メモ・書面・メール)の下書き、段階に応じた文面の使い分け | 管理担当・回収担当 |
| 空室対策(物件紹介文・SNS投稿) | 随時(空室発生時) | 物件情報からの紹介文・キャッチコピー案出し、SNS投稿文の作成 | 客付け・マーケティング担当 |
| 修繕見積もりの比較・業者連絡 | 随時(修繕発生時) | 複数見積もりの比較表作成、業者への依頼文・確認文の下書き | 修繕・工事担当 |
| 重要事項説明書・賃貸借契約書のチェック | 契約更新・新規契約時 | 記載漏れ・転記ミスのチェック補助、条文の平易な言い換え | 契約担当・宅建士 |
| クレーム対応記録の要約・エスカレーション判断 | クレーム発生時 | 経緯の要約、社内共有用の記録作成、エスカレーション要否の整理 | 管理担当・SV |
| オーナーへの月次報告 | 月1回 | 収支・空室状況・対応履歴の要約、報告書の文面作成 | 管理担当 |

判断の軸は「文章の下書き・要約で済む業務」か「宅建業法や個人情報が絡み最終判断に法的責任が伴う業務」かで分けるとよい。物件紹介文の案出しや対応記録の要約は汎用チャットAIで十分に価値が出るが、重要事項説明書の内容確定や督促の法的な最終判断は、必ず有資格者・責任者が行う前提を崩さない。

### 使えるツール・構成(汎用チャットAI vs 専用ツール)

| 業務 | 汎用チャットAI(ChatGPT/Gemini/Claude等)でできる範囲 | 専用ツールが必要な範囲 |
|---|---|---|
| 入居者対応チャットボット | よくある質問への回答案を担当者が下書きとして参照 | 入居者アプリ・管理システムと連携した24時間自動応答(GMO賃貸DX「AIチャット自動返信機能」、ITANDI「AI入居者対応支援機能」、Chat管理人など) |
| 家賃滞納督促 | 督促文面(電話トークスクリプト・書面・メール)の下書き | 電話発信・SMS送信・入金確認までを自動化する督促エージェント(Gnox督促AIエージェント等)、保証会社の督促システム |
| 空室対策・物件紹介文/SNS投稿 | 物件の特徴を伝えて紹介文・キャッチコピー案を複数出させる | ポータルサイトへの一括反映、画像からの自動生成、SNS投稿画像の自動作成ツール |
| 修繕見積もり比較・業者連絡 | 複数見積もりの内容をテキスト化して比較表を作らせる、業者への依頼文・確認文の下書き | 修繕履歴のデータベース化、過去案件からの適正価格レンジ提示(専業の修繕管理SaaS) |
| 重要事項説明書・賃貸借契約書チェック | 条文の平易な言い換え、記載項目の抜け漏れの一般的なチェックリスト化 | 登記簿謄本・ハザードマップ情報等を自動取得して重説・契約書のドラフトを一括生成(Ai-Smart重説等)、契約書全般のAIリスクチェック(LegalOn Cloud等) |
| クレーム対応記録・オーナー報告 | 対応経緯の要約、報告書・詫び状の下書き作成 | 複数物件・複数クレームを横断集計してパターン抽出する分析ツール |

小規模の管理会社・個人経営であれば、まずは無料〜低価格帯の汎用チャットAI(ChatGPTの無料版・Gemini等)で「督促文面の下書き」「物件紹介文」「クレーム記録の要約」を試すだけでも工数削減効果が出る。管理戸数が多く入居者アプリやオーナー向けポータルを既に導入している場合は、そのシステムにAI機能が追加されていないかをまず確認し、次に重説作成のような専業ツールへの投資対効果を検討する順番が現実的である。

## 実務での使い方

### 1. 入居者からの問い合わせへの一次回答案の作成

設備トラブル・騒音・鍵紛失など、入居者からのよくある問い合わせに対して、チャットAIに回答案の下書きを作らせ、担当者が内容を確認してから返信する使い方。緊急度の高い連絡(漏水・ガス臭・火災等)は必ず人が即時対応する前提を崩さない。

**コピペで使える入居者対応・回答案作成プロンプト例**

```
あなたは賃貸マンションの管理会社で入居者対応を担当するスタッフです。
以下の入居者からの問い合わせ内容をもとに、返信メールの下書きを
作成してください。

## 入居者からの問い合わせ
{{入居者からのメール・チャット本文をそのまま貼り付け}}

## 出力時の注意
- 緊急性が高い内容(水漏れ、ガス臭、鍵の紛失で室内に入れない等)
  が含まれる場合は、冒頭に「【至急対応】」と明記し、
  管理会社の緊急連絡先へすぐ連絡するよう案内する文言を入れる
- 緊急性が低い内容(騒音の相談、共用部の使い方等)は、
  丁寧語で状況を確認する質問と、対応までの目安の流れを示す
- 個人が特定できる情報(氏名・部屋番号・電話番号)は
  そのまま出力せず、[氏名][部屋番号]のように伏せ字にする
- あくまで下書きであり、送信前に担当者が内容を確認する前提で出力する
```

### 2. 家賃滞納者への督促文面の下書き

滞納の段階(初回の支払い忘れの可能性がある段階、複数月滞納で保証会社連携が必要な段階など)によってトーンを変えた督促文面を、チャットAIに下書きさせる使い方。最終的な法的措置の判断や、督促の実行そのものは担当者・保証会社が行う。

```
あなたは賃貸管理会社で家賃回収を担当するスタッフです。
以下の状況をもとに、入居者宛の督促連絡の文面を作成してください。

## 滞納状況
滞納月数: {{例: 家賃1ヶ月分、支払期日から10日経過}}
これまでの連絡状況: {{例: まだ連絡していない/1回電話したが折り返しがない 等}}
保証会社の有無: {{例: 家賃保証会社△△と契約あり}}

## 出力時の注意
- 支払い忘れの可能性を前提にした、責める表現を避けた丁寧な文面にする
- 支払期限、振込先、連絡先を明記する箇所は[支払期限][振込先]のように
  プレースホルダーで示す
- 滞納が複数月に及ぶ場合の文面案も別パターンとして用意し、
  保証会社への連携や法的措置に触れる際は「担当者・法務部門にご確認のうえ
  ご対応ください」と明記する
- 断定的な法的表現(「即刻退去」「訴訟を起こす」等)は使わない
```

### 3. 空室対策の物件紹介文・SNS投稿文の作成

物件の基本情報・特徴を伝えるだけで、ポータルサイト用の紹介文とSNS投稿用の短文を複数パターン作らせる使い方。写真の魅力を言語化する際は、実際の物件と齟齬がないよう必ず担当者が確認する。

```
以下の賃貸物件の紹介文を、ポータルサイト掲載用(200〜300字)と
Instagram投稿用(100字程度・絵文字少量使用可)の2パターンで、
それぞれ3案ずつ作成してください。

## 物件情報
物件名: {{物件名}}
間取り・広さ: {{例: 1LDK・40㎡}}
賃料・初期費用: {{賃料、管理費、敷金礼金}}
立地・アクセス: {{最寄駅、徒歩分数、周辺環境}}
設備・特徴: {{例: 独立洗面台、宅配ボックス、ペット可 等}}
ターゲット層: {{例: 単身の社会人、カップル、ペット飼育者 等}}

## 出力時の注意
- 誇大広告・おとり広告にあたる表現(実際にない設備、
  根拠のない「最安」「絶対お得」等)は使わない
- 面積・賃料など数値は入力された情報をそのまま使い、AIが推測で
  数値を書き足さない
- ポータルサイト用は物件の特徴を具体的に、SNS用は一目で
  惹きつける短いフレーズを意識する
```

### 4. 修繕見積もりの比較と業者への連絡文作成

複数の業者から届いた見積もりをテキスト化してチャットAIに渡し、比較表の作成と、業者への確認・依頼文の下書きを同時に作らせる使い方。金額の妥当性そのものの判断はAIに委ねず、担当者・専門業者の知見で行う。

```
以下は同じ修繕工事について3社から届いた見積もりの内容です。
これをもとに、
1. 項目別(工事内容・金額・工期)の比較表
2. 金額や工期に差がある項目について、業者に確認すべき質問リスト
3. オーナーへ見積もり内容を説明するための要約文(専門用語を避けた平易な表現)
の3点を作成してください。金額の妥当性そのものについては
断定せず、「他社と比較して差がある点」の指摘にとどめてください。

## 見積もり内容
### A社
{{見積もり内容を貼り付け}}
### B社
{{見積もり内容を貼り付け}}
### C社
{{見積もり内容を貼り付け}}
```

### 5. 重要事項説明書・賃貸借契約書のチェック補助

契約担当者が作成した重要事項説明書・賃貸借契約書のドラフトを、チャットAIに読み込ませて記載漏れの可能性がある項目や、分かりにくい条文をチェックさせる使い方。宅建業法上、重要事項説明書の**説明**は宅地建物取引士の独占業務であり、AIによるチェックはあくまで下書き段階の補助にとどめる。

```
あなたは賃貸借契約書のレビューを補助するアシスタントです。
以下の重要事項説明書のドラフトを確認し、
1. 一般的に記載が必要とされる項目(物件概要、契約期間、
   賃料・敷金礼金、設備、契約解除の条件、原状回復の負担範囲等)のうち、
   記載が見当たらない・不足している可能性がある箇所
2. 入居者にとって分かりにくい可能性がある条文とその平易な言い換え案
3. 前回契約書とこの契約書で金額・条件が食い違っている可能性がある箇所
を指摘してください。法的な有効性の最終判断はできない前提で、
気づいた点をリストアップすることに徹してください。

## 重要事項説明書ドラフト
{{ドラフト本文を貼り付け}}
```

### 6. クレーム対応記録の要約とエスカレーション判断支援

入居者からのクレーム対応の経緯メモを要約し、社内共有用の記録と、上長へのエスカレーションが必要かどうかの判断材料を整理させる使い方。

```
以下は入居者対応で発生したクレームの経緯メモです。
これをもとに、
1. 社内共有用の対応記録(いつ・誰が・何が起き・どう対応したか)
2. エスカレーション(上長・法務・保証会社への連携)が必要と
   考えられる要素の有無とその理由(例: 金銭的な要求がある、
   繰り返しの苦情である、法的な主張が含まれる 等)
3. 次にとるべきアクションの候補
の3点を整理してください。顧客の氏名・連絡先など個人が
特定できる情報は、記録用の出力からは伏せ字([氏名]等)にしてください。

## クレーム対応の経緯メモ
{{対応者が書いた経緯メモ}}
```

## 注意点・よくある誤解

- **入居者・オーナーの個人情報をそのままAIに貼り付けない**: 入居者対応記録、督促連絡、クレーム対応メモには氏名・電話番号・部屋番号・滞納状況といった機微な個人情報が含まれやすい。無料版の汎用チャットAIに生の情報を貼り付けると、入力内容が学習に使われる設定のままになっている場合があり、情報漏洩リスクになる。伏せ字化してから入力する、法人契約のエンタープライズ版(学習に使われない設定のもの)を使うなど、[情報漏洩・データ管理](../part04-risk-security/)の考え方に沿った運用にする
- **重要事項説明書の「説明」は宅建士の独占業務であることを混同しない**: Ai-Smart重説のようなツールはあくまで書類のドラフト作成・記載漏れチェックを支援するものであり、入居者への重要事項説明そのものは宅地建物取引業法上、宅地建物取引士が行わなければならない独占業務である。AIが作った書類をそのまま説明に使う前に、必ず有資格者が内容を確認・修正する
- **貸主・借主どちらか一方に偏った文面にならないよう確認する**: 督促文面や原状回復に関する説明文は、AIが一般的な回答を優先するあまり、貸主・借主どちらかに不利な断定的表現(法的措置の予告、原状回復費用の一方的な確定等)を含んでしまうことがある。管理会社は貸主・借主双方の公平な立場での対応が求められるため、送信前に必ず人が内容を確認する
- **物件紹介文はおとり広告・誇大広告のリスクを避ける**: 空室対策の紹介文・SNS投稿文で、実際にない設備や根拠のない優位性を書いてしまうと、宅地建物取引業法や不当景品類及び不当表示防止法(景品表示法)上の問題になり得る。AIが生成した数値・設備情報が入力情報と一致しているかを必ず確認する
- **修繕見積もりの金額判断はAIに委ねない**: 見積もりの比較表作成や確認事項の洗い出しはAIが得意とする領域だが、「妥当な金額かどうか」の最終判断は、地域の相場や物件の状態を知る担当者・専門業者の知見に委ねる。AIの回答を「相場情報」として鵜呑みにしない
- **専業ツールと汎用チャットAIの役割を混同しない**: GMO賃貸DXやITANDIのAI機能は自社の管理物件データ・契約情報と連携した上で回答するため精度が高いが、汎用チャットAIは管理規約や個々の契約内容を知らない。汎用チャットAIに「この物件の規約は?」と聞いても正確な回答は得られないため、「文章の下書き」用途と「データに基づく回答」用途を切り分けて使う

## 最初の一歩

直近で対応した入居者からの問い合わせ(緊急性の低いもの)を1件選び、上記の「入居者対応・回答案作成プロンプト」にその内容を(個人情報を伏せ字にした上で)貼り付けて、AIが出す下書きがどこまで実際の返信にそのまま使えるか、どこを手直しする必要があるかを一度試してみる。
