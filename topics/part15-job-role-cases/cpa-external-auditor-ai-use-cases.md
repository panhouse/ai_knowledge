# 公認会計士・監査法人職員における生成AI活用事例

## これは何か

公認会計士・監査法人職員は、企業が作成した財務諸表が適正に表示されているかを**外部の独立した第三者**として検証する「会計監査(法定監査・外部監査)」を担う。証憑(しょうひょう、取引の裏付け資料)と会計データの突合、分析的手続(異常な変動の有無を数値から読む手続)、監査調書(実施した手続と結論を記録する文書)の作成など、内部監査と似た「大量の資料を読み込み文章化する」業務が多い一方、**監査対象企業から独立した立場を保つこと(独立性)と、証拠を鵜呑みにしない姿勢(職業的懐疑心)**が業務の根幹にある。生成AIはこの検証・文書化作業を大きく速くできるが、使い方次第でこの根幹そのものを脅かしうる。

本ページは同じ第7章の2ページと明確に切り分ける。**[経理・財務職における生成AI活用事例](finance-accounting-ai-use-cases.md)**は企業が**自社の**帳簿・決算を作る側の業務、**[内部監査職における生成AI活用事例](internal-audit-ai-use-cases.md)**は企業が**自社の**業務・内部統制を社内の立場で点検する業務を扱う。本ページが扱うのは、監査法人(新日本、トーマツ、あずさ、PwC京都監査法人など)に所属する公認会計士が、**契約先である外部の企業**の財務諸表を法定監査・会社法監査として検証する業務であり、監査対象企業からの独立性・客観性という、内部監査にはない固有の制約が常に前提になる。

## 仕組み・背景

会計監査でのAI活用は、大きく3つの層で進んでいる。

1. **監査法人独自のAI搭載監査プラットフォーム**: 各大手監査法人(Big4)は、証憑突合・調書作成・リスク評価を一体化した自社プラットフォームに生成AI・AIエージェント(人が逐一指示しなくても複数ステップの業務をこなすAI)を組み込んでいる。KPMGインターナショナルは2025年に監査プラットフォーム「KPMG Clara」にAIエージェント「KPMG Clara AI Agents」を導入し、経費の証憑突合(vouching)や未記録負債・未払費用の網羅性チェックといった実証手続を自動化した。KPMGの発表では、証憑突合と調書作成にかかる時間が社内計測で35%削減され、グローバルで9万5千人超の監査人が利用対象になったとされる。日本のあずさ監査法人も2026年6月期から段階的に機能を展開する計画を示している。デロイト トーマツは監査・保証プラットフォーム「Deloitte Omnia」に協働型AIエージェントを2026年に導入し、生成AIによる監査調書の事前レビュー(明確性・一貫性のチェックと改善提案)や、業務の文脈に応じたオンデマンドのマイクロラーニング(「チューターモード」)を提供している。EY新日本有限責任監査法人は2026年1月、生成AI組み込みの書類解析システム「Document Intelligence Platform(DIP)」を本格稼働させ、全被監査先3,805社の監査で証憑の読取・会計データとの突合・調書作成までを一貫処理できるようにした。独自の画像解析AIが証憑の不自然な加工の兆候を検知するとアラートを出す機能も持つ。PwCはグローバル共通のデータ分析システム「Halo」で大量データの分析・リスク評価を行い、異常な取引や不正の兆候の早期把握に活用している(2015〜2017年にはH2O.aiと共同開発した「GL.ai」で総勘定元帳の異常検知を試行した実績もある)。
2. **サードパーティの証憑照合・継続的監査ツール**: DataSnipper(Excel上の台帳データと証憑ファイルをAIが自動照合し根拠付きで調書に転記するツール、Big4を含む85カ国60万人超の専門家が利用)やMindBridge AI Auditor(元帳データを継続的・全数分析し、不正・誤謬の兆候をスコアリングするツール)は、Big4が自社プラットフォームに組み込む場合もあれば、準大手・中小監査事務所が単体で契約する場合もある。
3. **汎用チャットAI(ChatGPT/Claude/Geminiなど)**: 会計基準の一次リサーチ、監査手続の説明文のドラフト、英文資料の翻訳といった、監査調書の管理システムに統合されていない周辺業務で使われる。

規制・基準面では、日本公認会計士協会(JICPA)が2024年8月に「テクノロジー委員会研究文書第11号 監査におけるAIの利用に関する研究文書」を公表し、大手監査法人を中心に進むAI利用の実態と、監査人の業務・役割への影響の展望を整理した。国際的にはIAASB(国際監査・保証基準審議会)が、ISA(国際監査基準)315号(リスク評価)における自動化ツール・技法(ATT)の使用に関する非拘束的なFAQ・支援資料や、監査調書の記録方法に関する支援資料を公表しており、AIを含む自動化ツールを使った場合に「何を・どう文書化すべきか」の実務解釈を示している。米国のPCAOB(公開会社会計監視委員会)は2026年半ば時点でAI固有の監査基準をまだ設けていないが、2026年3月の戦略提言募集でAIへの指針整備が主要テーマの一つとなり、電子形式情報の技術支援分析(technology-assisted analysis)に関する基準改正が2026年12月15日以後開始する事業年度から適用される。いずれの基準体も共通して強調するのは、**AIはリスク評価・実証手続の「支援」であり、監査意見の形成という最終判断は監査人に残る**という原則である。

## 使いどころ・使い分け

### 監査プロセスの業務フェーズ別 活用マップ

| 監査フェーズ | AIが担う範囲 | 人(監査人)が必ず担う範囲 |
|---|---|---|
| ①契約受入・独立性検討 | 過去の類似案件・業界リスク情報の一次調査 | 独立性チェックリストの確認、契約可否の最終判断 |
| ②リスク評価・監査計画 | 有価証券報告書・IR資料・業界動向からのリスク要因の洗い出し、重要な会計上の見積りの候補抽出 | 監査上の重要性(materiality)の設定、監査範囲・手続の最終決定 |
| ③内部統制の評価 | 業務記述書・フローチャートのドラフト生成、統制文書と実際の業務プロセスの一次照合 | 統制の整備状況・運用状況の評価結論の確定 |
| ④実証手続(証憑突合・分析的手続) | 証憑と会計データの自動照合、財務指標の期間比較・異常値の一次抽出、差異コメントの下書き | 差異の原因究明、追加手続の要否判断 |
| ⑤サンプリング・不正/異常検知 | 母集団全体からの異常取引・不自然な証憑加工のフラグ立て(継続的監査) | フラグの原因調査、不正・誤謬への該当性の最終判断、不正リスク対応手続の設計 |
| ⑥監査調書の作成・レビュー | 定型フォーマットへの文章化、実施した手続と結果の記述の下書き、調書の明確性・一貫性の事前チェック | 手続の十分性・結論の適切性のレビュー(上位者レビュー含む)、最終承認 |
| ⑦監査報告書作成・意見形成 | 報告書の定型文言・過年度との比較のドラフト | 監査意見の形成そのもの、経営者・監査役等とのディスカッション |

### 汎用チャットAIで足りる範囲と、専用ツールが必要な範囲の切り分け

| 業務 | 汎用チャットAI(ChatGPT/Claude/Gemini等) | 専用の監査プラットフォーム・ツール |
|---|---|---|
| 会計基準・業界動向の一次リサーチ、監査手続説明文の下書き | 十分対応できる(法人向けプランを使用) | – |
| 英文子会社監査資料・海外投資家向け資料の翻訳下訳 | 十分対応できる | – |
| 証憑と会計データの自動照合・母集団全数の異常検知 | 対応できない(調書システムとの統合・証跡確保が前提) | KPMG Clara AI Agents / Deloitte Omnia AI / EY.ai(DIP) / PwC Halo、DataSnipper、MindBridge AI Auditor |
| 監査調書への自動転記・調書レビューの履歴管理 | 対応できない | 監査法人の専用プラットフォーム、DataSnipper |
| 監査事務所全体のリスク管理・品質管理との連携 | 対応できない | 各監査法人の内部システム、AuditBoard等のGRCツール |

判断基準は「その出力を**監査意見の裏付けとしてそのまま監査調書に転記できるか**」。転記できる水準の証跡管理・再現性・アクセス管理を必要とする業務は専用プラットフォーム、リサーチ・下書き・翻訳など監査調書の外側にある業務は汎用チャットAIで十分なことが多い。

## 実務での使い方

### 1. リスク評価・監査計画のドラフト作成(コピペ用プロンプト例)

```
あなたは監査チームのシニアスタッフです。以下のクライアント情報から、
今期の監査計画における重点監査領域(Key Audit Matters候補)のたたき台を
作成してください。

【クライアント概要】(業種・規模・上場区分を記載)
【前期の監査結果】(前期に指摘事項・重要な見積りがあった領域を箇条書きで貼付)
【今期のIR資料・決算短信・有価証券報告書の抜粋】(新規事業、大型投資、
M&A、会計方針の変更などの記載があれば貼付)
【業界動向】(同業他社の会計不正・訂正報告などの外部情報)

【出力形式】
1. 重点監査領域の候補を「発生可能性」「金額的・質的重要性」の2軸で整理した表
2. 各候補について、重点化すべき根拠を1〜2行で
3. 記載内容から判断できない候補には「追加情報・現場ヒアリングが必要」と明記する

【条件】提示された情報にない事実を推測で付け加えない。
```

出てきた案は監査計画の議論のたたき台として使い、重要性の設定・監査範囲の最終決定はエンゲージメント・パートナー(監査責任者)が行う。

### 2. 分析的手続(異常値の一次抽出)のコメント下書き

```
あなたは監査チームのスタッフです。以下は当期・前期の月次財務データ(部門別)です。
分析的手続として、前期比・予算比で大きく変動している項目を抽出し、
監査調書用のコメント初稿を作成してください。

【出力形式】
科目 | 変動額・変動率 | 変動の考えられる要因(仮説) | 追加確認が必要な事項

【条件】
- 変動率が±15%を超える科目のみを対象とする
- 要因は「仮説」であることを明記し、断定しない
- データから読み取れない要因は「クライアントへの質問事項」として別枠にまとめる
- 数値は入力データの値のみを使い、新しい数値を作り出さない

【データ】
(ここに部門別・科目別の財務データを貼付)
```

出力はあくまで「質問事項リスト+仮説」であり、実際の変動要因はクライアントへの質問(inquiry)と裏付け資料の確認を経て監査調書に反映する。

### 3. 監査調書(実施した手続・結果)のドラフト作成

```
以下は実証手続として確認した事実のメモです。監査調書のフォーマットに沿って
整理してください。

【フォーマット】
1. 実施した手続の内容(母集団・サンプル数・抽出方法)
2. 確認した事実(証憑との突合結果)
3. 発見された例外事項(あれば)とその内容
4. 例外事項に対する追加手続の内容(実施済みの場合)
5. 結論(このメモの記載内容から機械的に導ける範囲のみ。最終評価は別途)

【確認した事実メモ】
(ここに実施したチェックの内容を貼付)

【条件】メモに記載のない手続・確認結果を新たに作り出さない。
「十分かつ適切な監査証拠が得られた」といった評価に関わる結論文言は
書かず、「(監査人による評価が必要)」と注記すること
```

### 4. 会計基準の適用可否リサーチ支援

```
あなたは会計基準の調査補助担当です。以下の取引の概要から、関連しそうな
会計基準(企業会計基準、実務対応報告等)の候補を挙げ、確認すべき論点を
整理してください。

【取引の概要】
(新規のリース取引、資産の除却、企業結合など具体的な取引内容を記載)

【出力形式】
1. 関連しそうな会計基準・実務対応報告の候補(名称のみ、条文番号は不明な場合
   「要確認」と明記)
2. 適用にあたって確認すべき論点(箇条書き)
3. 実務上の判断が必要になりそうな箇所

【条件】条文番号・数値基準は自信が持てない場合は断定せず「要原典確認」と
明記する。原典(基準本文)を必ず自分で確認したうえで監査調書に反映すること
```

会計基準の条文番号や数値基準(例: 資産計上の金額基準)はハルシネーション(もっともらしい誤情報の生成)が起きやすい領域であるため、AIの回答は必ず基準本文・実務対応報告の原典で確認してから調書に反映する。

### 5. 不正リスク要因の洗い出し(不正のトライアングルに基づくチェック)

```
あなたは監査チームのスタッフです。以下のクライアント情報から、不正リスク
要因を「動機・圧力」「機会」「姿勢・正当化」の3分類(不正のトライアングル)に
沿って洗い出してください。

【クライアント情報】
(業績動向、経営者の交代、ノルマ・インセンティブ制度、内部統制の状況、
業界内の不正事例など把握している情報を記載)

【出力形式】
分類 | リスク要因 | 該当する根拠(入力情報のどこから読み取れるか)

【条件】入力情報から読み取れない要因を推測で作り出さない。判断に迷う場合は
「要追加調査」と明記する
```

出力は不正リスク対応手続を検討する際の一次材料として使い、実際に不正リスク対応手続を設計・実施するかどうかは監査チーム(必要に応じてフォレンジック専門家)が判断する。

### ツール横断の対応付けと料金の目安(2026年8月時点)

| 用途 | 主なツール | 特徴・料金の目安 |
|---|---|---|
| 証憑突合・調書作成の自動化(自社プラットフォーム) | KPMG Clara AI Agents / Deloitte Omnia AI / EY.ai(Document Intelligence Platform) / PwC Halo | 各監査法人が自前で開発・運用し、外部への単体販売はしていない。監査契約(監査報酬)に組み込まれる形で提供される |
| 証憑ファイルと台帳データの自動照合・調書転記 | DataSnipper | Excelネイティブのプラットフォーム。Start/Accelerate/Elevateの3プラン構成で、AIエージェント機能は上位プランで利用可能。料金は1ユーザーあたり月額$64程度〜(個別見積りが基本)。Big4を含む85カ国60万人超の専門家が利用 |
| 継続的監査・異常検知(取引データの全数分析) | MindBridge AI Auditor | 元帳データを継続的に分析し、リスクスコアの高い取引を自動抽出。準大手・中小監査事務所での導入例もある。料金は個別見積り制 |
| 会計基準リサーチ・報告書ドラフト・翻訳 | ChatGPT Enterprise / Claude for Enterprise / Gemini Enterprise(汎用AI) | 法人向けプラン(学習への非利用が標準)での利用が前提。監査調書に転記する前に必ず人が確認 |

判断基準は「その出力を**監査調書としてそのまま採用できる証跡管理レベル**が必要か」。証跡・アクセス管理・レビュー履歴を要する業務は監査法人の専用プラットフォームまたはDataSnipper等の専用ツール、調書の外側にあるリサーチ・下書きには汎用AIチャットで十分なことが多い。

## 注意点・よくある誤解

- **独立性・自己レビューの阻害要因になりうる使い方をしていないか**: JICPA「倫理規則」は、監査人が独立した立場を保持することを求めており、監査人自身が関与した業務を自ら評価する状況(自己レビュー)は独立性を阻害する要因として整理されている。生成AIを使ってクライアントの会計処理案や開示文言そのものを**作成・提案**し、それを監査チームが自ら検証する形になると、実質的に非監査業務(経営者の判断業務の代行)を監査人が行ったのと同じ構図になりかねない。AIの利用範囲は「監査人が行う検証作業の支援」に限定し、クライアントの財務諸表・開示文言そのものの作成に踏み込まないという線引きを常に意識する。
- **監査対象企業の機密情報を、無料版・個人向けの汎用AIに入力しない**: 公認会計士には公認会計士法上の守秘義務があり、監査調書・証憑・未公表の決算情報を学習利用のある無料プラン・個人向けサービスに入力すると、情報漏洩だけでなく守秘義務違反そのものが問題になる。各監査法人が指定する法人向けプラン・自社プラットフォーム(学習への非利用が契約で担保されたもの)以外への入力は原則禁止という運用ルールを事前に確認する。
- **AIの判断をそのまま監査結論にすると職業的懐疑心の放棄になる**: 「AIが異常なしと判定したから統制は有効」「AIがフラグを立てなかったから不正はない」と機械的に結論づけるのは、監査人自身による批判的な評価を放棄することになる。継続的監査ツールのフラグや生成AIの一次判断は、あくまで調査の出発点であり、原因調査・追加手続・最終判断は監査人が独立して行う。
- **AIツールの判断根拠を文書化しないと、監査証拠として認められないおそれがある**: IAASBのISA315関連の支援資料が示すように、自動化ツール・技法(AIを含む)を使った場合は「どのデータを使い、どういう閾値・ロジックで判定したか」を監査調書に記録しておく必要がある。米国PCAOBの検査でも、AIによる異常検知を使ったのに、アルゴリズムの調整内容・使用データ・偽陽性(実際は問題のない取引をフラグ立てすること)の評価方法を文書化していない事例が指摘されている。AIツールを「ブラックボックスのまま結果だけ使う」運用は、監査証拠としての説明力を欠くリスクがある。
- **ハルシネーション(もっともらしい誤情報の生成)は会計基準の条文番号・数値基準で特に起きやすい**: 存在しない基準番号や、実際とは異なる金額基準・適用時期を自信満々に提示することがある。AIの回答は必ず基準本文・実務対応報告の原典、または社内の技術情報データベースで裏取りしてから調書・報告書に反映する。プロンプトで「確信が持てない場合は断定せず『要確認』と回答する」ことを明記すると誤情報の混入を減らせる。詳細は[生成AIのハルシネーションと対策](../part04-risk-security/hallucination-and-countermeasures.md)を参照。
- **「継続的監査で全数分析ができる」=「サンプリングの手間がなくなる」ではない**: 全数分析ツールは異常の「候補」を大量に洗い出せるが、フラグの多くは偽陽性であり、原因調査・重要性判断という監査人の作業自体は残る。母集団カバレッジの向上と監査人の実作業負荷の軽減は別の話として捉える。

## 最初の一歩

直近の監査調書のうち、分析的手続の差異コメント、または会計基準の一次リサーチのいずれか1件を選び、上記のプロンプトを匿名化した仮のデータで試し、AIの出力のうち「確信を持って書いてよい部分」と「原典・現場確認が必要な部分」を自分で切り分けてみる(監査対象企業の実データ・機密情報はそのまま入力しないこと)。
