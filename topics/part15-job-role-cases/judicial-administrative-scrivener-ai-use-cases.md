# 司法書士・行政書士における生成AI活用事例

## これは何か

司法書士(不動産・法人の登記、裁判所提出書類、成年後見・相続手続の代理)と行政書士(建設業許可・飲食店営業許可などの許認可申請、定款作成、外国人ビザ申請、補助金申請書類の作成)は、いずれも「決まった様式の書類を、依頼者ごとに異なる事実関係に当てはめて正確に作る」ことが業務の中核であり、ドラフト作成・下調べ・定型文面の生成という点で生成AIとの相性が良い。一方でどちらも法律で定められた独占業務(資格者以外が報酬を得て行うと処罰される業務)を担っており、AIの出力をそのまま納品すると、非司法書士行為・無資格者による業務(行政書士法違反)のグレーゾーンに踏み込む・誤った内容を公的機関に提出してしまうといった固有のリスクがある。本ページは、この2つの近接した書類作成系士業について、業務フェーズ別の活用例と共通のリスク境界を整理する。

司法書士・行政書士は法律事務所という業種としての切り口([Part 14 業種別 生成AI活用事例](../part14-industry-cases/professional-services-ai-use-cases.md)の対象)ではなく、資格者本人の業務フローに焦点を当てる点で、事業会社の法務担当者を扱う[法務職における生成AI活用事例](legal-ai-use-cases.md)とも視点が異なる。

## 仕組み・背景

両資格とも、生成AIの使い方は基本的に「大量の定型フォーマットに、ヒアリングで得た事実関係を正確に流し込む」作業の下書き役という位置づけになる。

- **司法書士**: 相続登記(不動産の名義変更)、会社設立・役員変更などの商業登記、裁判所提出書類(訴状・答弁書などの本人訴訟支援書類)を扱う。2024年4月1日に相続登記の申請義務化が施行され、正当な理由なく相続を知ってから3年以内に登記しないと10万円以下の過料の対象になる制度が始まった。この改正では施行日より前に発生していた相続についても2027年3月31日までの登記が義務付けられており、司法書士が対応する相続登記案件は増加傾向にある。案件数増加への対応として、登記原因証明情報や相続関係説明図のたたき台をAIに作らせ、司法書士は事実確認と最終的な申請書チェックに時間を割く、という業務再配分が進んでいる。
- **行政書士**: 建設業許可・飲食店営業許可・産業廃棄物収集運搬業許可などの許認可申請、株式会社・NPO法人などの定款作成、外国人の在留資格(ビザ)申請、各種補助金・助成金の申請書類作成を扱う。許認可の種類ごとに添付書類・様式が細かく決まっており、AI-OCR(画像から文字を読み取るAI)と生成AIを組み合わせて、依頼者から預かった書類の情報を申請書の下書きに自動転記する運用を導入する事務所が増えている。
- **共通の法的背景**: どちらの業務も、資格者以外が報酬を得て行うことを法律で禁止されている(司法書士法73条「非司法書士等の取締り」、行政書士法19条「業務の制限」)。2026年1月1日に施行された改正行政書士法では、行政書士法19条の禁止対象に「他人の依頼を受けいかなる名目によるかを問わず報酬を得て」という文言が加わり、「コンサルティング料」「事務手数料」といった名目であっても、実態が許認可書類の作成であれば無資格者による違法行為とみなされることが明確化された。あわせて、違反時に個人だけでなく所属法人にも罰金刑を科す両罰規定が導入されている。これは「AIが書類の大半を自動生成してくれるなら、無資格のコンサルタントでも代行業を名乗って請け負えるのでは」という発想への牽制であり、AIを使う側(有資格者)にとっても、AI任せの体制がどこまで許容されるかを考えるうえで押さえておくべき改正といえる。

## 使いどころ・使い分け

どちらの資格も「AIに下書きさせてよい範囲」と「有資格者が事実確認・最終判断すべき範囲」の線引きが業務の肝になる。

| 業務フェーズ | 司法書士の活用例 | 行政書士の活用例 | 人が必ず担う範囲 |
|---|---|---|---|
| 受任前のヒアリング整理 | 相続関係(法定相続人・遺産分割の希望)の聞き取りメモをAIに整理させ、必要書類リストの一次案を作成 | 許認可・ビザの要件を満たしそうか、ヒアリング内容から一次チェックリストを作成 | 依頼者の事実関係そのものの確認、受任の可否判断 |
| 書類ドラフト作成 | 登記申請書・登記原因証明情報・相続関係説明図・遺産分割協議書のたたき台生成 | 許可申請書・定款・理由書・事業計画書のたたき台生成、ビザ申請の理由書下書き | 添付書類との整合性確認、最新の法令・様式改正の反映確認、申請書の最終確定 |
| 裁判所提出書類支援 | 本人訴訟支援(簡裁訴訟代理等関係業務は認定司法書士のみ)における訴状・答弁書のひな形提示、事実関係の時系列整理 | (対象外。行政書士は裁判所提出書類の作成不可) | 訴訟方針の判断、認定司法書士の代理権限の範囲内かどうかの確認 |
| 補助金・助成金申請 | (対象外が中心) | 事業計画書・収支計画のたたき台、採択事例を踏まえた記載表現の改善提案 | 数値の裏取り、加点要件の該当性判断、虚偽記載のリスクチェック |
| 顧客向け説明・FAQ対応 | 相続登記の必要書類・流れを一般向けに平易に説明する文面の下書き | 許認可の要件・スケジュールを一般向けに説明する文面の下書き | 個別事案への当てはめ、料金・受任可否の回答 |
| 事務所運営 | 議事録作成、業務日誌、集客用のWeb記事・解決事例記事の下書き | 同左 | 公開前の事実確認、守秘義務に触れる情報が入っていないかの確認 |

使い分けの判断基準は「この書類がそのまま登記所・許認可行政庁・裁判所に提出された場合、誤りがあれば依頼者にどんな不利益が生じるか」。提出書類の内容確定・受任の可否・依頼者への法的な説明は必ず有資格者本人が行い、AIは「下書き作成・事実関係の整理・見落とし防止」の補助役に位置づけるのが実務的な線引きになる。

## 実務での使い方

### 1. 司法書士: 相続登記の登記原因証明情報・相続関係説明図のたたき台作成

```
あなたは司法書士の実務補助者です。以下の相続の事実関係をもとに、
相続関係説明図に記載する内容を整理してください。

【事実関係】
- 被相続人: 氏名、死亡日、最後の住所
- 相続人: 続柄・氏名・生年月日を列挙(配偶者・子など)
- 遺産分割協議の有無: あり/なし
- 対象不動産: 所在・地番・家屋番号

【出力形式】
1. 相続人の関係を家系図的に文章で整理(誰が誰の子か)
2. 法定相続分の一次計算(遺言・遺産分割協議がある場合は考慮しない前提で)
3. 相続関係説明図に記載すべき項目のチェックリスト
4. 戸籍謄本等で確認が必要な事項(離婚歴・養子縁組の有無など)を注記

※ 出力はあくまで下書きであり、戸籍の記載内容と必ず突合して
確定させることを前提とする
```

戸籍・住民票・不動産の内容など個人情報や登記情報そのものは入力せず、氏名や地番は仮名・ダミーの番地に置き換えて試すこと(注意点参照)。

### 2. 行政書士: 建設業許可申請書の骨格作成

```
あなたは行政書士の実務補助者です。以下の条件で、建設業許可(知事許可・一般建設業)
申請の準備チェックリストと、許可申請書に記載する事業内容の文案を作成してください。

【条件】
- 業種区分: (例: 内装仕上工事業)
- 申請区分: 新規
- 経営業務の管理責任者・専任技術者の要件: 満たす前提
- 財産的基礎の要件: 満たす前提

【出力形式】
1. 必要となる添付書類のチェックリスト(登記事項証明書、納税証明書、
   実務経験証明書など、様式番号がわかるものは様式番号も明記)
2. 「事業内容」欄に記載する文案(200字程度)
3. 提出前に必ず最新の都道府県窓口の様式・要件を確認すべき箇所を注記
```

建設業法・許可要件は改正頻度が高い分野のため、AIが提示する要件は必ず提出先の都道府県・国土交通省地方整備局の最新の手引きと突合すること。

### 3. 行政書士: 外国人ビザ申請の理由書下書き

```
以下の事実関係をもとに、在留資格認定証明書交付申請に添付する「理由書」の
下書きを作成してください。

【条件】
- 在留資格: (例: 技術・人文知識・国際業務)
- 申請人の学歴・職歴: (要点を箇条書きで提示)
- 受入企業の事業内容・申請人の従事予定業務:
- 学歴・職歴と従事予定業務の関連性を説明する必要がある

【出力形式】
- です・ます調のフォーマルな文体で400字程度
- 学歴・職歴と業務内容の関連性を明確に説明する構成にする
- 事実として提示していない情報を補って書かない(不明な点は
  「(要確認)」と明記して空欄にする)
```

### 4. 司法書士・行政書士共通: 依頼者向けの平易な説明文の下書き

```
以下の手続きについて、法律の知識がない依頼者向けに、
「何をいつまでに・なぜやる必要があるか」を3行程度で平易に説明する
文面を作成してください。専門用語を使う場合は必ずかっこ書きで一言説明を加える。

手続き: (例: 相続登記の申請義務化、建設業許可の更新手続 など)
```

### 5. 事務所運営: 解決事例記事・議事録の下書き

```
以下の相談内容(個人が特定できないよう抽象化済み)をもとに、
事務所ホームページに掲載する「解決事例」記事の構成案を作成してください。

- 相談の背景(業種・状況を一般化した形で)
- 対応した手続きの流れ
- 依頼者にとってのメリット・所要期間の目安
- 個人・企業が特定される固有名詞・日付・金額の詳細は含めない
```

船井総合研究所の士業向けレポートでは、こうしたWeb記事・解決事例作成・議事録作成へのAI活用によって、事務所によっては関連作業が従来の6分の1程度の時間で済んだ事例が紹介されている(ベンダー公表・個別事例の数値であり、事務所ごとに前提条件が異なる点に注意)。

### ツール・体制の使い分け

| 区分 | 位置づけ | 特徴 |
|---|---|---|
| ChatGPT / Claude / Gemini(汎用AI) | 書類ドラフト・説明文・記事の下書き作成 | 導入コストが低く汎用性が高い。個人情報・登記情報・戸籍情報などの機密データは原則入力しない運用が前提 |
| AI-OCR + 生成AIの組み合わせ | 依頼者から預かった書類(登記簿謄本、決算書、身分証等)の情報を申請書ひな形へ転記 | 手入力の転記ミスを減らせる一方、OCRの読み取り誤りをAIが「もっともらしく」補完してしまうリスクがあるため、原本との突合が必須 |
| 士業向け業務・文書管理システム(クラウド型の事件管理・書類作成支援ソフト) | 様式の一元管理、進捗管理と組み合わせたドラフト生成 | 司法書士・行政書士向けに様式が最初から組み込まれているぶん、法改正への追従や職印・電子署名との連携などの実務対応が汎用AIより速い場合がある。選定時は改正対応のスピードとサポート体制を確認する |

現時点(2026年9月)で、日本司法書士会連合会・日本行政書士会連合会がそれぞれの会員向けに公表した生成AI利用の統一ガイドラインは確認できていない。同じ書類作成系の士業である弁理士については、日本弁理士会が2025年4月に「弁理士業務AI利活用ガイドライン」を公表し、外部AIサービスへの秘密情報入力が守秘義務違反になり得ることなどを明文化している。司法書士・行政書士も同様の守秘義務(司法書士法24条、行政書士法12条)を負っており、統一ガイドラインの有無にかかわらず、各事務所が「AIに何を入力してよいか」を自主的にルール化しておく必要性は変わらない。

## 注意点・よくある誤解

- **非司法書士行為・無資格者の業務(行政書士法違反)の境界を越えない**: 司法書士法73条は資格者以外が報酬を得て登記申請書類の作成・代理を行うことを禁じ、違反すると1年以下の懲役または100万円以下の罰金の対象になる。行政書士法19条も同様に無資格者による官公署提出書類の作成を禁じており、2026年1月1日施行の改正で「いかなる名目によるかを問わず報酬を得て」の文言が加わったことで、名目上は「AIコンサルティング」「書類作成サポート」であっても、実態が許認可書類の作成であれば無資格者は処罰対象になり得ることが明確になった。有資格者自身がAIを使う分には問題ないが、無資格の事務員・外部業者がAIの出力をほぼそのまま依頼者に納品するような運用は、この境界に触れるおそれがあるため、「最終的な書類の内容確定と提出判断は必ず有資格者が行う」運用を事務所内で明文化しておく。
- **依頼者の機密個人情報を安易に入力しない**: 戸籍謄本、住民票、登記情報、マイナンバー、在留カードの記載内容などは機密性の高い個人情報であり、無料プランの汎用AIやセキュリティ設定次第では入力内容がモデルの学習に使われる可能性がある。プロンプトを試す段階では氏名・地番・生年月日をダミーデータに置き換え、実際の依頼者情報を入力する場合は法人向け・API契約など学習利用がオプトアウトされたプランを使うといった社内ルールを先に決めておく。
- **AIが提示する要件・様式は必ず最新のものと突合する**: 建設業許可要件、ビザの在留資格区分、補助金の公募要領などは改正・改訂の頻度が高く、AIの回答は学習データ時点の情報に基づくため、実際の提出前に必ず提出先窓口(法務局、都道府県、地方出入国在留管理局、補助金事務局など)の最新の手引き・様式で裏取りする。
- **AIの出力を「有資格者の判断」の代わりにしない**: AIは条文パターンや過去の記載例の類似性から文章を組み立てているだけで、依頼者固有の事実関係への当てはめ・受任の可否・提出書類の最終的な適法性判断はできない。「ドラフト作成→有資格者が事実確認→修正→提出」という運用フローを崩さないことが、品質面でもコンプライアンス面でも最重要のルールになる。
- **AI-OCRの読み取り誤りをそのまま転記しない**: 手書き書類や古い謄本をAI-OCRで読み取らせる場合、文字認識の誤りがあっても生成AIがもっともらしい文脈で補完してしまうことがある。転記後は必ず原本と突合する。

## 最初の一歩

直近で作成した相続関係説明図または許認可申請の添付書類チェックリストの一部を、氏名・地番などをダミーデータに置き換えたうえで上記のプロンプトに貼って試し、AIが作った下書きと実際に確認すべき事実関係にどれだけ差があるかを確認してみる。
