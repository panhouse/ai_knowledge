# n8n・Make・Zapierの比較と使い分け

## これは何か

「n8n・Make・Zapierはどれも似たような自動化ツールらしいが、結局うちの会社はどれを選べばいいのか」——3ツールそれぞれの個別ページ([n8nの基本](./n8n-basics.md)、[Makeの基本](./make-basics.md)、[Zapierの基本](./zapier-basics.md))には機能・料金の詳細があるが、1本ずつ読んでも横並びでの判断はしにくい。本ページは3ツールの詳細説明を繰り返さず、**同じ軸で並べた比較表と、自社の状況から1つに絞り込むためのチェックリスト**に絞って整理する。

## 仕組み・背景

3ツールとも「トリガー(処理の起点)→アクション(実際の処理)」をビジュアル画面上でつなぐワークフロー自動化ツールという基本構造は共通で、呼び方が違うだけである(n8nは「ノード」、Makeは「モジュール」、Zapierは「ステップ」)。違いが生まれているのは主に次の4点で、これは各ツールの成り立ちの違いに由来する。

- **Zapier**(2011年創業): 最古参のクラウド専業サービス。非エンジニアが迷わず使えることを最優先に設計され、連携アプリ数を積み上げてきた
- **Make**(前身Integromatは2012年創業、2022年に現ブランドへ刷新): ZapierとN8nの中間に位置し、GUI(操作画面)の見やすさとコストのバランスを追求してきた
- **n8n**(2019年創業): OSS(オープンソースソフトウェア)としてスタートし、セルフホスト(自社サーバーでの運用)と技術的な柔軟性を武器にエンジニア・情報システム部門からの支持を広げてきた

この歴史的な立ち位置の違いが、そのまま「料金モデル」「セルフホスト可否」「学習コスト」「AI機能の方向性」の違いに直結している。

## 使いどころ・使い分け

### 横並び比較表(2026年7月時点の目安。詳細な料金プランは各ツールの個別ページを参照)

| 項目 | Zapier | Make | n8n |
|---|---|---|---|
| 立ち位置 | 業界最古参・連携アプリ数最多。非エンジニア向けの決定版 | 中間。GUIの分かりやすさとコストのバランス | OSS・セルフホスト可。エンジニア/技術系チーム向け |
| 料金モデル | タスク課金(アクション実行1回=1タスク) | クレジット課金(標準モジュール実行1回=1クレジットが目安) | 実行課金(ワークフロー1回の実行)。セルフホストなら無料 |
| セルフホスト | 不可(クラウド専用) | 不可(クラウド専用) | 可(無料、要インフラ管理) |
| 学習コストの目安 | 低(非エンジニア向けの直線的なUI) | 低〜中(キャンバス型UIで分岐も視覚化しやすい) | 中〜高(ノードの概念・データ構造の理解が必要) |
| AI機能の方向性 | Zapier Agents(自律型)+Zapier Copilot(自然言語でのZap自動生成)。非エンジニアがGUIだけでAIエージェントを作れる方向に強い | Make AI Agents(自律型、2025年提供開始)。OpenAI/Anthropic/Gemini公式モジュールを柔軟に組み込める | AI AgentノードとLangChain統合。任意のLLM・外部ツールを自由に組み合わせる柔軟性が最も高い |
| 連携アプリ数の目安 | 9,000以上(業界最多クラス) | 3,000以上 | 1,500以上の標準ノード+HTTP Requestノードで公開APIのあるサービスに事実上無制限に接続可 |
| 日本語対応 | 管理画面・公式ドキュメントは英語中心(公式サイトの一部のみ日本語化)。ブラウザ翻訳での運用が実務上の主流 | 同左。管理画面・ドキュメントは英語中心 | 同左。ノード名・ドキュメントは英語中心 |
| エンタープライズ機能 | Team/EnterpriseプランでSAML SSO、ロールベースアクセス制御、接続イベントログ | EnterpriseプランでSSO・SCIM・監査ログ | Businessプラン以上でSAML SSO・Git連携。2FA必須化や監査ログ、外部シークレット管理はEnterpriseプランが必要 |
| 向いている企業規模・ユースケース | 非エンジニア中心の中小企業、部門単位のスモールスタート、対応アプリ数の広さを重視する会社 | 複雑な分岐・データ加工をGUIで組みたい中堅企業、コスト効率と柔軟性を両立したい会社 | エンジニア・情報システム部門がいる会社、セキュリティ・データ主権を重視する会社、実行回数が多くコストを抑えたい会社 |

**注**: 日本語対応について、3ツールとも「管理画面に日本語切り替えの選択肢はない」という点は共通している。一方でメール本文・フォーム回答など**処理するデータそのものが日本語であること自体は3ツールとも問題なく扱える**。困るのは画面や公式ヘルプの言語であって、業務データの言語ではない。

### Difyとの違い(参考)

Difyは「AIチャットボット・RAGアプリを作ること」自体が主目的のAI特化プラットフォームであり、n8n・Make・Zapierとはカテゴリが異なる。「AIの生成・判断そのものが目的ならDify、複数システムをつなぐ自動化の中にAIを1ステップとして組み込みたいならn8n/Make/Zapier」という整理になる。詳細は[Difyとは何か](./dify-basics.md)を参照。

## 実務での使い方

### 「うちの会社ならどれ」判断チェックリスト

以下の質問に順番に答えていくと、候補が絞り込める。

1. **社内にサーバー運用ができるエンジニア・情報システム担当がいるか?**
   - いない → 質問2へ
   - いる → 質問4へ
2. **月あたりの自動化の実行回数・ステップ数は少なめ(数千タスク未満)で、単純な「トリガー→アクション」が中心か?**
   - はい → **Zapier**が第一候補(GUIが最も平易で、情報量・利用者数が多く、詰まっても検索で解決しやすい)
   - いいえ(条件分岐・複数データの集約・繰り返し処理が必要そう) → 質問3へ
3. **コストも抑えつつ、複雑な分岐・データ加工をGUIで組みたいか?**
   - はい → **Make**が第一候補(キャンバス型UIで複雑な分岐を視覚化しやすく、クレジット単価も比較的抑えやすい)
   - どうしても非エンジニアだけで完結させたい → Zapierのまま、複雑な処理は複数のZapに分割して運用する
4. **データを自社サーバー内に置く必要があるか(セキュリティ規定・データ主権・監査要件)?**
   - ある → **n8n(セルフホスト)**一択(3ツールの中で唯一、自社インフラでの運用が無料でできる)
   - 特にない、まずクラウドで試したい → n8n Cloudの無料トライアル、またはMakeで試して比較する
5. **目的が「AIチャットボット・RAG検索アプリを作ること」自体か?**
   - はい → 本比較の対象外。[Difyとは何か](./dify-basics.md)を検討する
   - いいえ(複数システムの連携が主目的でAIはその一部) → 質問1〜4の結果に従う

### 業務シーン別のおすすめ

| 会社・部門の状況 | おすすめ | 理由 |
|---|---|---|
| システム管理者がいない10〜50名規模の会社。初めて業務自動化に挑戦する | Zapier | 直線的なUIで迷いにくく、日本語の解説記事・動画も多いため独学で進めやすい |
| システム管理者はいないが、複数の条件分岐やデータの集計・加工が必要になってきた | Make | GUIの分かりやすさを保ったまま、Zapierより複雑なロジックを組める。クレジット単価もタスク課金より抑えやすいケースが多い |
| エンジニアが在籍し、セキュリティ・データ主権を重視する(顧客データを自社サーバー内に留めたい) | n8n(セルフホスト) | 無料でセルフホストでき、Codeノードでの複雑なロジックや社内システムとの直接連携も自由に書ける |
| 自動化の実行回数(ステップ数)が非常に多く、月額コストを抑えたい | n8n(セルフホスト、または各社の上位プランを実行回数ベースで試算) | n8nは「ワークフロー1回の実行」単位の課金でステップ数に依存しないため、ステップ数の多い複雑なワークフローほど相対的に有利になりやすい |
| すでにZapierかMakeを使っており、AIエージェント機能を強化したい | まず今使っているツールのAIエージェント機能(Zapier AgentsまたはMake AI Agents)を試す | ツールの乗り換えコストの方が、既存ツールの新機能を試すコストより高くつくことが多い |
| 複数部門で用途が違う(営業部門は簡単な通知、開発部門は複雑な社内連携) | 部門ごとに使い分けて併用する(例: 営業・マーケはZapier、基幹系連携はn8nセルフホスト) | 全社を1ツールに統一する必要はない。ワークフローの複雑さと運用者のスキルで使い分ける方が総コストを抑えられる |

## 注意点・よくある誤解

- **課金モデルが違うため単純な「月◯円」比較はできない**: Zapierは「タスク」、Makeは「クレジット」、n8nは「実行(ワークフロー1回)」と課金の単位そのものが異なる。同じ業務フローでも、ステップ数が多いワークフローほどn8nの実行課金が有利になりやすく、逆に単純な2〜3ステップの自動化を大量に回すならタスク/クレジット課金の方が分かりやすいこともある。見積もりは必ず「自社で想定する実行回数・ステップ数」を当てはめて試算する
- **「有名だから」「安いから」で選ぶと後で作り直しになりやすい**: 最初は単純な自動化のつもりでも、業務が育つと条件分岐やデータ加工が複雑化しがちである。将来的な複雑さをある程度見込んで選ばないと、途中でツールを乗り換える手間(ワークフローの作り直し)が発生する
- **日本語UIがないことは3ツール共通の制約**: 「このツールは日本語対応していないから避ける」という比較軸は成立しない。実務ではブラウザの翻訳機能(Google Chromeの「日本語に翻訳」等)を併用するのが前提になる。ただし翻訳機能を有効にしたまま設定を保存すると入力内容が反映されない不具合が起きることがあるため、設定変更時は翻訳をオフにするのが安全
- **併用・段階移行は珍しくない**: 「まずZapierで小さく検証し、複雑になった部分だけn8nのセルフホストに載せ替える」といった段階的な使い方も現実的な選択肢である。最初から1ツールに全賭けする必要はない
- **ロックイン(乗り換えコスト)は軽視できない**: ワークフローが増えるほど、他ツールへの移行は「ゼロから作り直し」に近くなる。特にn8nは学習コストが高い分、いったん構築したワークフロー資産の移行コストも大きくなりやすい
