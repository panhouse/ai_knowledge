# ファインチューニング・RAG・プロンプトの使い分け

## これは何か

「自社の商品知識や社内ルールをAIに反映させたい」と考えたとき、方法は大きく3つある。①プロンプト(AIへの指示文)に情報を直接書く・貼り付ける、②RAG(検索拡張生成。質問のたびに関連資料を検索してAIに読ませる仕組み)、③ファインチューニング(追加学習。モデル自体のパラメータを訓練し直すこと)である。この3つは「AIに何かを教える」という意味では似て見えるが、得意なことも仕組みもコストもまったく違う。選び方を間違えると、高いお金と時間をかけてファインチューニングしたのに「情報が古いままで使い物にならない」といった失敗につながる。

## 仕組み・背景

3つの手法は、AIのどこに情報を持たせるかが違う。

- **プロンプト**: 質問のたびに、必要な情報をその場で文章として渡す方法。モデル自体は一切変化しない。会話ごとに「今回はこれを踏まえて答えて」と都度指示するイメージ。渡せる情報量はコンテキストウィンドウ(AIが一度に読める文章量の上限)に制約される。
- **RAG**: 資料をあらかじめ検索しやすい形(ベクトルデータベースなど)に整理しておき、質問が来るたびに関連箇所だけを自動検索してプロンプトに差し込む方法。仕組みとしては「プロンプトに情報を渡す」ことの自動化・大規模化と言える(詳細は[RAG(検索拡張生成)の基本](../part07-data-analysis/rag-basics.md)を参照)。モデル自体は変化せず、外部の「参考資料」を都度渡している点はプロンプトと同じ。
- **ファインチューニング**: 大量の入力・出力ペアのサンプルをモデルに学習させ、モデルの中身(パラメータ)そのものを調整する方法。LoRA(Low-Rank Adaptation、少ないパラメータだけを追加学習する効率化手法)のような技術で計算コストを抑える手法もあるが、要は「AIの性格や癖そのものを訓練し直す」処理である。学習後は、追加の指示がなくてもその挙動が自動的に出るようになる。

比喩で言えば、プロンプトとRAGは「試験に参考書を持ち込ませる」やり方であり、ファインチューニングは「参考書の内容を暗記させて叩き込む」やり方に近い。参考書を持ち込ませる方式は差し替えが簡単(資料を更新すればすぐ反映される)だが、暗記させる方式は一度覚えさせると忘れさせるのが難しく、覚え直させるにも再学習のコストがかかる。

## 使いどころ・使い分け

3手法を軸ごとに比較すると次のようになる。

| 観点 | プロンプト | RAG | ファインチューニング |
|---|---|---|---|
| 導入の手軽さ | ◎ 誰でもすぐ試せる | 〇 検索基盤の構築が必要(ツール利用なら数十分〜) | △ 学習データ整備・訓練が必要(数日〜) |
| コスト | ◎ 追加コストほぼなし | 〇 検索基盤の運用費が発生 | △ 学習コスト+提供元によっては利用不可 |
| 向いている用途 | ちょっとした指示・少量の背景情報・出力形式の一時指定 | 社内マニュアル・契約書・FAQなど大量かつ頻繁に更新される知識の参照 | 口調・文体・回答フォーマットの矯正、定型業務の型を体に染み込ませる |
| 向かない用途 | 情報量が多い・頻繁に更新される知識 | 「口調を変える」「独特の言い回しを再現する」など振る舞いの矯正 | 新しい事実・最新情報の追加(学習後は更新できず、すぐ陳腐化する) |
| 情報更新への強さ | 都度書き直せば即反映(ただし手間) | ◎ 資料を差し替えるだけで即反映、根拠も明示できる | △ 情報を更新するには再学習が必要。頻繁な更新には不向き |
| ハルシネーション対策 | 効果は限定的 | ◎ 根拠となる資料を示せるため誤情報を減らしやすい | △ 知識の追加には向かず、対策にはならない |

判断の流れは次のように考えるとよい。

1. **まずプロンプトで試す**: 一時的な指示や、数百〜数千字程度の背景情報であれば、まずプロンプトに直接書いて試す。これで十分なら他の手法は不要。
2. **情報量が多い・頻繁に更新される・根拠を示したいならRAG**: 社内マニュアルが数百ページある、毎週情報が更新される、回答の出典を示したい、といった場合はRAGを検討する。
3. **口調や出力形式そのものを矯正したいならファインチューニング**: 「常に自社のブランドトーンで話してほしい」「特定のフォーマットの分類・要約を大量に安定して出したい」など、知識ではなく振る舞いを変えたい場合にファインチューニングを検討する。ただし後述の通り2026年時点では選択肢が限られる。
4. **多くの場合は組み合わせが正解**: 「口調はファインチューニング(または詳細なプロンプトで代替)、最新知識はRAG、細かい当日の指示はプロンプト」のように、3つは排他的ではなく併用が前提になることが多い。

## 実務での使い方

### ケース別の対応表

| やりたいこと | 適した手法 |
|---|---|
| 会議の議事録を「ですます調」で要約してほしい | プロンプト(その都度指示) |
| 自社の全製品マニュアル(数千ページ)から回答してほしい | RAG |
| 問い合わせメールを自社の返信テンプレ・言い回しに寄せて自動生成したい | ファインチューニング、または詳細なプロンプト+例文の提示 |
| 先週更新した最新の価格表を反映して答えてほしい | RAG(頻繁な更新に強い) |
| 特定のフォーマット(JSON形式の分類ラベルなど)を大量・安定して出力させたい | ファインチューニング(または出力例を数個プロンプトに含めるFew-shotプロンプティング) |

### 主要サービスの提供状況(2026年7月時点)

ファインチューニングの提供状況は各社で大きく異なり、変化も速いため導入前に必ず最新情報を確認すること。

- **OpenAI**: 自社サーバーで動かす「Fine-tuning API」を段階的に終了させる方針を2026年5月に発表した。2026年5月7日以降は未経験の組織による新規利用ができず、2026年7月2日以降は60日以上利用実績のない組織も新規の学習ジョブを作成できなくなり、2027年1月6日には既存の利用者も含めて全面的に新規ジョブを作成できなくなる(すでに作成済みのファインチューニング済みモデルの推論自体は、元になったベースモデルが提供終了になるまで継続)。OpenAIは、GPT-5.6のような新しい基盤モデルは指示追従性が高く、プロンプト+RAGの組み合わせで多くの用途をカバーできるとして、ファインチューニングからの移行を推奨している。
- **Anthropic(Claude)**: 自社API単体でのファインチューニングは一般提供されておらず、Amazon Bedrock経由でClaude 3 Haikuなど一部モデルの微調整が可能な形で提供されている(データは利用者のAWS環境内に留まる)。2026年7月時点で新たな自社ホスト型ファインチューニングの提供発表はない。
- **Google(Gemini)**: Vertex AI上でGemini 2.5 Flash-Lite・2.5 Proなどの教師ありチューニング(Supervised Fine-Tuning)機能が提供されている。ただし2026年7月時点でGemini 3系はまだアローリスト(許可リスト)経由の申請制にとどまり、一般提供はされていない。料金・対応モデルは変更されやすいため、導入時はVertex AIの公式料金ページで最新状況を確認する。

このように、2026年時点では「まずファインチューニングありき」で考えるより、「プロンプト→RAG」で解決できないかを先に検討し、それでも足りない場合にのみ提供元の最新のファインチューニング状況を調べる、という順番が現実的である。

### コピペで使える「相談テンプレート」

社内で「うちのケースはどれが向いていますか」を検討する際は、以下を埋めてから議論すると判断がぶれない。

```
## 検討中の案件
- 実現したいこと:
- 参照させたい情報の量(目安): 少量(プロンプトに貼れる) / 中〜大量(資料が数十〜数千ページ)
- その情報はどのくらいの頻度で更新される?: ほぼ変わらない / 月1回程度 / 週次以上
- 変えたいのは「知識」か「振る舞い(口調・形式)」か:
- 回答の根拠(出典)を示す必要があるか: 要 / 不要
- 想定利用者数・頻度:
- 社内で扱えるエンジニアリングリソースの有無:

## 判断結果(上記を踏まえて選択)
□ プロンプトのみで対応
□ RAGを構築
□ ファインチューニングを検討(提供元の対応状況を要確認)
□ 組み合わせ(内訳: )
```

## 注意点・よくある誤解

- **「ファインチューニング=知識を教える手段」という誤解が最も多い**。実際は、ファインチューニングは新しい事実知識を安定して覚えさせる手段としては不向きで、学習していない情報を答えさせようとするとハルシネーション(もっともらしい誤情報)を悪化させることさえある。知識を追加したいなら、まずRAGを検討するべき。
- ファインチューニングが向いているのは、**口調・文体・出力フォーマットのような「振る舞い」を安定させたい場合**である。「常にこの3段落構成で書く」「必ずこの敬語レベルで話す」といった型を大量サンプルで叩き込む用途に向く。
- ファインチューニングした情報は「賞味期限」がある。組織改編や価格改定などで元の情報が古くなっても、モデルは学習時点の内容のまま答え続けてしまう。更新するには再学習が必要で、RAGのように資料を差し替えるだけでは直らない。
- RAGを入れても精度が出ない場合、原因の多くは「検索」側(資料の分割の仕方や検索方法)にある。モデルを変える前に、資料の整理方法を見直す方が効果的なことが多い。
- ファインチューニングの提供状況はサービス提供元の方針変更が激しい分野。本ページのOpenAIの記載のように、ある日突然サービス終了・縮小が発表されることもあるため、依存する前に「継続提供されるか」「代替手段は何か」を必ず確認する。
- 社外秘の情報をプロンプトやRAGの参照元に使う場合は、利用するAIサービスが入力データを学習に再利用しない設定になっているか(法人向けプランやAPI利用など)を必ず確認する。
