# LLMの仕組み:トークン化と次単語予測

## これは何か

ChatGPTやClaude、Geminiなどの LLM(大規模言語モデル)は、文章を人間のような「単語」や「文字」の単位ではなく、**トークン(token)** という独自の単位に分解して処理している。そしてLLMがやっていることの中核は、「これまでの文章の続きとして、次にどのトークンが来そうかを確率的に予測し、それを1つずつ積み重ねて文章を生成する」という驚くほど単純な仕組みである。

このトークンという単位を知らないと、「思ったより料金が高い」「日本語だと途中で回答が切れる」「長い資料を読ませたら前半の指示を忘れられた」といった実務上のトラブルの原因がわからず、対処もできない。トークンはAPI料金の課金単位であり、かつ一度に読み書きできる情報量(コンテキストウィンドウ)の上限を決める単位でもあるため、コスト管理・プロンプト設計の両方に直結する基礎知識になる。

## 仕組み・背景

### トークン化(tokenization)とは

LLMは学習・推論の前処理として、入力された文章を「トークナイザー(tokenizer)」という専用の分割器にかけて、トークンの並びに変換する。トークンは英単語1つのこともあれば、単語の一部(接頭辞・接尾辞)、複数文字の組み合わせ、句読点、絵文字の一部などさまざまで、必ずしも「意味のある1単語」「1文字」とは一致しない。

現在の主要LLMの多くは **BPE(Byte Pair Encoding)** という方式、またはその派生アルゴリズムでトークンの単位を決めている。これは「学習データの中で頻繁に隣り合って出現する文字列のペアを、繰り返し1つのトークンにまとめていく」という統計的な手法で、よく出る単語ほど1トークンにまとまりやすく、まれな単語ほど細かく分割されやすい、という特徴を持つ。

- 英語の目安: OpenAIの公式ヘルプによれば、英語の一般的な文章では **1トークン ≈ 4文字 ≈ 単語の4分の3(0.75語)** 程度になる([OpenAI Help Center](https://help.openai.com/ja-jp/articles/4936856-what-are-tokens-and-how-to-count-them))。
- 日本語の目安: 日本語は英語に比べてトークナイザーとの「相性」が悪く、同じ内容を書いても **英語より多くのトークンを消費する**。CJK言語(中国語・日本語・韓国語)は、同じ内容の英語文と比べて **2〜8倍程度のトークンを消費する**というのが目安として紹介されている([Koukoku.ai Media](https://aikoukoku.jp/basic/token/))。古い・日本語対応が弱いトークナイザーでは、「大規模言語モデル」のような単語がほぼ1文字=1トークンで8トークンに分割されてしまう例もある([みうのAIテックブログ](https://miu-ai-techblog.com/tokenizer_and_bpe/))。GPT-5系が使う o200k系トークナイザーのように多言語・日本語対応を強化したものほど、この非効率は緩和される傾向にある。

### 次単語(次トークン)予測という生成の原理

LLMは、それまでの文章(プロンプト+それまでに生成した部分)を読んで、「次に来る可能性が高いトークン」を語彙全体に対する確率分布として計算する。そこから1つのトークンを選び、文章の末尾に追加し、その一段長くなった文章を再び入力として次のトークンを予測する――これを繰り返すことで、1トークンずつ文章が完成していく(「自己回帰的生成」と呼ばれる仕組み)。

つまりLLMは、文章の「意味」を人間のように理解して答えを組み立てているわけではなく、「学習データに基づく統計的に自然な続き」を高速に積み上げているだけ、という点が重要な特性になる。これが、もっともらしいが事実とは異なる文章(ハルシネーション)が生じる根本的な原因の一つであり、また「同じ質問でも毎回少し違う言い回しの答えが返ってくる」現象(生成のたびに確率的に少し違うトークンが選ばれる)の理由でもある。

### コンテキストウィンドウとの関係

LLMには、一度に読み書きできるトークン数の上限があり、これを **コンテキストウィンドウ(context window)** と呼ぶ。これは「入力(プロンプトや添付資料)+これまでの会話履歴+出力(回答)」を合計したトークン数の上限であり、超えた分は多くのツールで古い会話から順に切り捨てられるか、エラーになる。長文の要約や大量データの読み込みでは、この上限を意識しないと「前半の指示を忘れたような回答」が返ってくる原因になる。

## 使いどころ・使い分け

トークンという概念そのものは常に働いているが、「意識して数える・見積もる」べき場面は限られる。次のような場面では、トークン単位で考える習慣を持つと失敗を避けられる。

| 場面 | トークンを意識すべき理由 |
|---|---|
| 長文の要約・議事録作成 | 元原稿+指示文+出力がコンテキストウィンドウを超えると、後半が読めない/前半を忘れた回答になる |
| 大量データの一括処理(APIバッチ処理など) | 入力トークン数×件数で料金が積み上がる。件数が多いほど事前の見積もりが重要 |
| 長い会話を続けるチャット利用 | 会話が長くなるほど古い発言がウィンドウからあふれて「忘れられる」。指示の再確認が必要になる |
| API利用時のコスト管理 | 料金は「入力トークン数」「出力トークン数」を別々の単価で課金される。プロンプト設計がそのままコストに直結する |
| 多言語コンテンツの制作(日本語⇄英語) | 同じ内容でも日本語は英語よりトークン消費が多く、料金・処理速度・実効コンテキスト量に差が出る |
| RAG(検索拡張生成)やチャンク分割の設計 | 検索して渡す文書の単位をトークン数で区切る必要があり、文字数基準で設計すると想定より大きく/小さくなる |

逆に、単発の短い質問や、資料を貼らない日常的な会話利用では、トークンを意識する必要はほとんどない。

### 2. トークン数を確認する場所(ツール横断)

| ツール | トークン数を確認する場所 |
|---|---|
| OpenAI(ChatGPT/API) | ブラウザの無料ツール [platform.openai.com/tokenizer](https://platform.openai.com/tokenizer) にテキストを貼ると、色分けされたトークン区切りと合計トークン数が即表示される。プログラムから数えたい場合はPythonの `tiktoken` ライブラリを使う |
| Anthropic(Claude/API) | Anthropic Console(console.anthropic.com)の Workbench でプロンプトを入力すると使用トークン数が表示される。API経由では Messages API の `count_tokens` エンドポイントで事前に見積もれる |
| Google(Gemini/API) | Google AI Studio(aistudio.google.com)でプロンプト入力欄の右下にリアルタイムでトークン数が表示される。APIでは `countTokens` メソッドで事前計算できる |

### 3. コピペで使える実例:プロンプトを圧縮してトークン消費を抑える指示文

長文の下書きや資料をそのまま貼ると入力トークンが膨らみやすい。要約させてからやり取りを続けると、以降の会話全体のトークン消費(=コンテキストウィンドウの消費)を抑えられる。

```
以下の文章を、意味・数値・固有名詞を変えずに、
全体の40%程度の長さに要約してください。
見出しや目次、免責事項などの本文以外の要素は除外してください。
```

### 4. 見積もりの考え方(日本語コンテンツの場合)

日本語は英語よりトークン消費が多いため、「文字数」だけで料金や上限を見積もると外れやすい。目安として、日本語の実務文書では英語の同内容と比べて概ね2〜3倍程度、トークナイザーとの相性が悪いモデルではそれ以上のトークンを消費する場合がある([Legalscapeテックブログ](https://tech.legalscape.co.jp/entry/2025/10/28/150459))。1万字の日本語レポートを要約させる場合、正確な数値は必ず上記のトークナイザーで確認したうえで、コンテキストウィンドウの上限(表1)と比較する運用にする。

## 注意点・よくある誤解

- **「1トークン=1文字」ではない**: トークンは文字・単語のどちらとも一致しない可変長の単位。英語では1トークン≈4文字だが、日本語ではモデルによって1文字が2〜3トークンになることもあり、逆に助詞などが1文字1トークン未満にまとまることもある。文字数ベースで料金や上限を見積もると誤差が大きい。
- **「日本語は文字数が少ないからお得」は誤解**: 見た目の文字数が少なくても、トークン単位では英語より多く消費しやすい。多言語対応が進んだモデル(o200k系トークナイザーなど)ほど差は縮まっているが、コスト計算では必ずトークン単位で確認する。
- **コンテキストウィンドウは「記憶」ではない**: 会話が長くなり上限を超えると、多くのツールでは古い発言から自動的に切り捨てられる(要約して圧縮する実装のツールもある)。「さっき言ったのに忘れられた」という現象の多くはこれが原因で、長い会話ではこまめに前提を再掲する、または新しいチャットに切り替えるのが実務的な対処になる。
- **見えない「思考トークン」も課金対象になる**: Claudeの拡張思考(extended thinking)、GPT-5.5のThinkingモード、Geminiの思考モードなどは、回答の前にモデル内部で行う「思考過程」もトークンとして生成しており、画面に表示されなくても出力トークンとして課金される場合がある。想定より料金が高い場合はこの点を確認する。
- **生成は確率的である**: 次トークン予測は毎回同じ結果を保証しない(温度パラメータなどにより変動幅がある)。同じ質問でも言い回しが変わったり、まれに事実と異なる内容が「自然な続き」として生成される(ハルシネーション)のは、この統計的な仕組みに起因する。重要な事実確認は生成結果をそのまま信じず、人が検証する運用を組み合わせる。

## 最初の一歩

[platform.openai.com/tokenizer](https://platform.openai.com/tokenizer) を開き、自分が普段使うプロンプトや日本語の文章を貼り付けて、実際に何トークンになるかを見てみる。同じ内容を英語に訳して貼り比べると、日本語がどれだけ多くトークンを消費するかが体感できる。
