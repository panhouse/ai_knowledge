# トークンとは何か(LLMの処理単位と料金・コンテキストウィンドウの関係)

## これは何か

ChatGPTやClaude、GeminiなどのLLM(大規模言語モデル。大量のテキストを学習して文章を生成するAI)は、人間が読むような「文字」や「単語」の単位でテキストを処理しているわけではない。内部では「トークン」と呼ばれる、文字より大きく単語より細かい単位にテキストを分割してから処理している。このトークンという単位を知らないと、「なぜ長い文章を貼り付けるとエラーになるのか」「なぜ同じような作業でも請求額が違うのか」「なぜ日本語だと英語よりすぐ上限に達するのか」といった、業務で生成AIを使い倒すうえで必ずぶつかる疑問に答えられない。トークンは、LLMの**料金**と**一度に扱える情報量(コンテキストウィンドウ)**の両方に直結する、最も基礎的な計量単位である。

## 仕組み・背景

LLMは文章を「BPE(Byte Pair Encoding)」などの方式で分割してからモデルに入力する。BPEとは、頻繁に一緒に現れる文字の並びを1つの単位(サブワード)としてまとめて登録していく圧縮的な手法で、単語よりも細かく、アルファベット1文字よりも大きい「意味のある文字列の断片」を作り出す。この断片が「トークン」である。

- 目安として、英語の文章では**1トークン ≈ 4文字 ≈ 0.75単語**程度になる(Anthropic公式ドキュメントの目安)。
- 日本語は文字あたりの情報密度が高い(表意文字である漢字を含む)ため、英語よりトークン単価が悪い。おおよそ、ひらがな・カタカナは1文字あたり1〜2トークン、漢字は1文字あたり2〜3トークン程度が目安になる。つまり**同じ内容の文章でも、日本語は英語よりおおむね2〜3倍のトークン数を消費する**。
- トークンへの分割ルール(トークナイザー)はモデル・ベンダーごとに異なる辞書を使っており、同じ文章でもツールが変われば異なるトークン数になる。たとえば「こんにちは」は旧世代のGPT-3のトークナイザーでは6トークンに分割されていたが、GPT-4以降で使われるトークナイザー(cl100k_base / o200k_baseなど)では改善され、1トークンで済むようになった。
- 新しいモデルに切り替えるとトークン数そのものが変わることもある。Anthropicの公式ドキュメントによると、Claude Opus 4.7以降やClaude Sonnet 5などで採用されている新しいトークナイザーは、Claude Sonnet 4.6以前の旧トークナイザーに比べて、**同じテキストでもおよそ30%多いトークン数になる**という注記がある。「モデルを新しくしたら、同じような使い方でも請求額が増えた」という現象は、モデルの性能差だけでなくトークナイザーの違いが原因のことがある。

トークンは実務上、大きく2つの場面に効いてくる。

1. **課金の単位**: API利用料金は「入力トークン数 × 単価 + 出力トークン数 × 単価」で決まる。出力トークンの単価は入力トークンの4〜6倍程度に設定されているのが一般的で、「AIに長い文章を書かせる」作業は「AIに長い文章を読ませる」作業よりも単価あたりのコストが高い。
2. **コンテキストウィンドウ**: モデルが一度の会話・リクエストで同時に読み書きできるトークン数の上限。プロンプト(指示・添付資料)、それまでの会話履歴、AIの出力をすべて足した量がこの上限を超えると、超えた分は処理されないか、古い会話から順に忘れられる。

## 使いどころ・使い分け

トークンを意識すべき代表的な業務シーンと、対応の考え方は次の通り。

| やりたいこと | トークン面での論点 | 対応の方向性 |
|---|---|---|
| 数十〜数百ページの資料をまるごと読ませて要約・質疑応答したい | コンテキストウィンドウが足りるか | コンテキストウィンドウが大きいモデル・プランを選ぶ(下記比較表)。超える場合は資料を分割するか、RAG(検索拡張生成。必要な部分だけを検索して読ませる方式)の利用を検討する |
| 同じ長い指示書・マニュアルを何度も貼り付けて使う | 毎回同じ入力トークン分の料金がかかる | プロンプトキャッシュ(後述)に対応したAPI・ツールを使う |
| 数百〜数千件のテキストを一括で要約・分類したい | 件数分のトークン量で費用が積み上がる | バッチAPI(即時応答が不要なら半額程度)や、安価な小型モデル(Haiku・Flash-Lite・miniシリーズなど)を使う |
| 日本語の長文書類を扱う | 英語の2〜3倍のトークンを消費する前提で見積もる必要がある | コンテキストウィンドウ・予算とも余裕を持って設計する |
| チャットで延々と同じ会話を続けている | 会話履歴も毎回トークンとして数え直されるため、長引くほど1回あたりのコストが増える | 話題が変わったら新しい会話(チャット)を始める |

「なぜかAIが会話の前半の内容を忘れる」「なぜか長文を貼るとエラーになる」という相談は、ほぼ例外なくコンテキストウィンドウの上限に起因する。まずこの表で自分のタスクがどのパターンに当てはまるかを切り分けるとよい。

## 実務での使い方

### トークン数を確認する場所(ツール横断の対応付け)

文章を書く前に「これは何トークンか」を確認できるツールが各社から提供されている。

| 確認したいこと | ChatGPT / OpenAI API | Claude / Anthropic API | Gemini / Google API |
|---|---|---|---|
| トークン数を画面で確認 | 公式Tokenizerツール(platform.openai.com/tokenizer)にテキストを貼り付ける | Claude Console(platform.claude.com)の「Workbench」でプロンプトを組みながら確認 | Google AI Studio(aistudio.google.com)にプロンプトを入力すると画面に表示 |
| プログラムから計測 | `tiktoken` ライブラリ(Python) | API の `count_tokens` エンドポイント | API の `countTokens` メソッド |
| コンテキストウィンドウの確認場所 | モデル一覧ページの「Context window」欄 | 「Context windows」ドキュメントページ | モデル一覧の「Input token limit」欄 |
| 料金の確認場所 | openai.com/api/pricing | platform.claude.com/docs/en/about-claude/pricing | ai.google.dev/gemini-api/docs/pricing |
| 大量処理向けの割引 | Batch API | Batch API(入出力とも50%引) | Batch API(50%引) |
| 繰り返し利用向けの割引 | プロンプトキャッシュ(cached input) | プロンプトキャッシュ(cache read は基本価格の1/10) | コンテキストキャッシュ(最大9割引) |

### コピペで使える実例: 料金の概算方法

見積もりの型はどのツールでも共通で、次の式に当てはめるだけでよい。

```
概算費用 = (入力トークン数 ÷ 1,000,000 × 入力単価)
        + (出力トークン数 ÷ 1,000,000 × 出力単価)
```

Anthropic公式ドキュメントに掲載されている実例(サポート対応チケットの要約)は、そのまま社内稟議の説明にも使える。

> 1件あたり平均約3,700トークンの会話を、Claude Haiku 4.5(入力$1・出力$5/100万トークン)で処理すると、**1万件あたりの概算費用は約37ドル**になる。

社内で「AIで問い合わせ対応を自動要約したらいくらかかるか」と聞かれたら、まずサンプルを1〜2件、実際のツールのトークンカウンターに通して1件あたりのトークン数を測り、この式に単価を当てはめれば、その場で概算できる。

### 主要APIの料金・コンテキストウィンドウ比較(2026年7月時点)

100万トークン(1MTok)あたりの米ドル建て単価と、APIで使えるコンテキストウィンドウ(入力上限)の目安は次の通り。価格・上限は改定が頻繁なため、実際に使う直前に各社公式ページで最新値を確認すること。

| 提供元 | モデル | コンテキストウィンドウ(API) | 入力単価/1MTok | 出力単価/1MTok |
|---|---|---|---|---|
| OpenAI | GPT-5.5 | 約105万(27.2万トークン超は長文加算で$10/$45) | $5 | $30 |
| OpenAI | GPT-4.1 / GPT-4.1 mini | 約100万 | $2 / $0.40 | $8 / $1.60 |
| Anthropic | Claude Opus 4.8 | 100万 | $5 | $25 |
| Anthropic | Claude Sonnet 5(2026年8月末までの導入価格) | 100万 | $2 | $10 |
| Anthropic | Claude Haiku 4.5 | 20万 | $1 | $5 |
| Google | Gemini 3.1 Pro | 約105万(20万トークン超は$4/$18) | $2 | $12 |
| Google | Gemini 3.5 Flash | 100万 | $1.50 | $9 |
| Google | Gemini 2.5 Flash-Lite(最安クラス) | 100万 | $0.10 | $0.40 |

いずれのベンダーも、バッチAPI(非同期処理で料金が半額程度になる)とプロンプトキャッシュ/コンテキストキャッシュ(同じ内容を再送すると大幅割引になる)を用意している。定型的な大量処理では、まずこの2つの割引が使えないかを確認するのが費用最適化の基本になる。

### 消費者向けプラン(ChatGPT / Claude / Gemini アプリ)でのコンテキストウィンドウ

社内の担当者が実際に触るのはAPIよりチャット画面であることが多いが、**同じモデルでもAPI経由とアプリ経由でコンテキストウィンドウが異なる**点に注意したい。たとえばGPT-4.1はAPIでは100万トークンまで扱えるが、ChatGPTアプリではPlus/Teamプランで3.2万トークン、Pro/Enterpriseプランでも12.8万トークンに制限される(モデル・時期により変動)。2026年7月時点のおおよその目安は次の通り。

| ツール | 無料プラン | 標準的な有料プラン | 上位プラン |
|---|---|---|---|
| ChatGPT | 数千〜数万トークン程度(モデルにより変動) | Plus(月額約3,000円): Thinkingモデル選択時は最大25.6万トークン | Pro(月額16,800円/30,000円の2段階): 最大40万トークン、上位ティアではGPT-4.1系で100万トークンにアクセス可 |
| Claude | 20万トークン | Pro(月額$20): モデルにより20万〜100万トークン(Sonnet 5選択時は最大100万) | Max($100/$200): 上限はProと同水準だが、利用できる回数・レートが拡大 |
| Gemini | 約3.2万トークン | Google AI Pro(月額2,900円): 約100万トークン | Ultra(月額14,500円/32,000円の2段階): Gemini 3.1 Ultra選択時は最大200万トークン |

「APIで謳われている上限」と「自分が普段使っているチャット画面での実際の上限」は別物であるため、大きな資料を扱う予定があるなら、契約前にアプリ側のヘルプページで実際の上限を確認するのが確実である。

## 注意点・よくある誤解

- **トークン数は文字数・単語数と一致しない**: 「原稿用紙1枚(400字)」のような感覚で見積もると、特に日本語では実際のトークン数を大きく見誤る。重要な見積もりの前には、必ず実際のテキストをトークンカウンターに通す。
- **同じ文章でもツール・モデルが違えばトークン数も変わる**: 「A社のツールでは収まったのに、B社のツールでは収まらない」という事象は珍しくない。見積もりや比較は必ずツールごとに測り直す。
- **API上の上限とチャットアプリ上の上限は別物**: 前述の通り、同じモデルでもAPIとアプリでコンテキストウィンドウが異なることが多い。カタログスペックだけで「これなら長い資料も読ませられる」と判断しない。
- **出力トークンは入力トークンより高い**: 「要約して」より「詳しく書いて」と頼むほうが、同じ入力でも料金が上がりやすい。定型レポートの自動生成などコストが積み上がりやすい用途では、出力の長さを指定して無駄な出力を減らすのがコツ。
- **コンテキストウィンドウが大きい=常に高精度、ではない**: 大きなコンテキストウィンドウに情報を詰め込みすぎると、モデルが文章の中盤にある情報を見落としやすくなる現象(いわゆる「Lost in the Middle」)が知られている。読ませる資料は必要な範囲に絞り込むほうが、精度と料金の両方で有利なことが多い。
- **チャットの「回数制限」とコンテキストウィンドウは別の仕組み**: ChatGPT・Claude・Geminiのアプリの利用上限は、単純なメッセージ数ではなく処理量(トークン数や計算量)を組み合わせて計算されていることが多い。長い会話を続けたり、大きな資料を何度も貼り付けたりすると、体感より早く利用上限に達することがある。

## 最初の一歩

自分が普段AIに貼り付けている文章(メール1通や社内資料の1ページなど)を、OpenAIの公式Tokenizerツール(platform.openai.com/tokenizer)にコピペしてみて、実際に何トークンになるかを確認してみる。「これくらいの分量でこれくらいのトークン数になるのか」という肌感覚を1つ持っておくと、以降の見積もりが格段にしやすくなる。
