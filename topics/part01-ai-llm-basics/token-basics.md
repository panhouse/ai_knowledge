# トークンとは何か(仕組みと数え方)

## これは何か

ChatGPTやClaudeのAPI料金は「1000文字あたりいくら」ではなく「100万トークンあたりいくら」で決まる。文字数の感覚でコストや入力可能な文章量を見積もると、特に日本語では想定より高額になったり、長文を貼り付けた途端に上限エラーに遭遇したりする。トークン(token)とは、AIモデルがテキストを処理する際の最小の処理単位のことで、API料金と、一度に扱える文章量の上限(コンテキストウィンドウ)は、どちらもこのトークン数で決まる。文字数・単語数とは別物の数え方だと押さえておくことが、実務での最初のつまずきを防ぐ。

## 仕組み・背景

LLM(大規模言語モデル)は文章をそのまま読んでいるわけではない。入力されたテキストは、まず「トークナイザー」と呼ばれる仕組みによって細かい単位(トークン)に分解され、それぞれが数値ID に変換されてからモデルに渡される。トークンは1文字とも1単語とも限らず、よく使われる文字列のかたまり(サブワード)単位で区切られる。たとえば英語の "tokenization" は "token" と "ization" のように2〜3個のトークンに分割されることが多い。

英語はこの分割方式と相性が良く、OpenAIは公式ヘルプで「英語テキストでは、1トークン ≈ 4文字 ≈ 0.75単語(100トークン ≈ 75単語)」という目安を示している。

一方、日本語・中国語・韓国語(CJK言語)は、学習データもトークナイザーも英語中心に最適化されていることが多く、同じ内容を表すのに英語より多くのトークンを消費しやすい。ひらがな・カタカナ・漢字が混在する日本語は1文字が1〜2トークン程度になることが多く、複数の技術系メディアの実測・解説記事でも「日本語は英語に比べて2〜8倍程度のトークン数を消費する」という報告がある。「同じ内容でも日本語で書く方がコストが高く、コンテキストウィンドウも早く埋まりやすい」という前提を持っておくと、料金試算や長文業務の判断がしやすくなる。

## 使いどころ・使い分け

トークンを意識すべき場面は主に2つある。

| 場面 | トークンが効いてくる理由 |
|---|---|
| API・従量課金サービスのコスト試算 | 料金は「入力トークン数 × 単価 + 出力トークン数 × 単価」で決まる。日本語は英語よりトークン消費が多いため、同じ処理内容でも日本語業務の方が割高になりやすい |
| 長文の要約・大量資料の読み込み | モデルごとに「コンテキストウィンドウ」という上限トークン数があり、これを超えると入力できない、または古い会話内容が押し出される。システムプロンプト・会話履歴・添付資料・生成される出力まで、すべて合算でカウントされる点に注意 |

主要モデルのコンテキストウィンドウの目安(2026年7月時点。モデルの世代交代が頻繁なため、契約・設計前に必ず各社公式ドキュメントで確認すること):

| モデル | コンテキストウィンドウ |
|---|---|
| GPT-5.5(OpenAI API) | 100万トークン(Codex上の利用では40万トークン) |
| Claude Sonnet 5 / Claude Opus 4.6以降 | 100万トークン(標準、追加設定不要) |
| Claude Sonnet 4.5など旧世代Claude | 20万トークン |
| Gemini 3 Pro | 100万トークン |
| Gemini 3 Flash | 20万トークン |

コンテキストウィンドウは大きいほど良いとは限らない。上限が大きいモデルほど料金も上がりやすく、また関係の薄い情報まで大量に詰め込むと回答の精度がかえって落ちる「コンテキスト腐敗(context rot)」と呼ばれる現象も指摘されている。必要な範囲の情報だけを絞って渡す方が、コストと精度の両面で有利になることが多い。

## 実務での使い方

### トークン数を実際に確認する方法

- **OpenAI Tokenizer(Web版)**: `platform.openai.com/tokenizer` にテキストを貼り付けると、トークンへの分割結果と合計トークン数がその場で表示される。日本語テキストを試しに貼ってみると、文字数よりトークン数の方が多くなることが体感できる
- **tiktoken(Python/JavaScript向けライブラリ)**: OpenAIが公開しているオープンソースのトークナイザー。プログラムから大量テキストのトークン数を事前計算したいとき(例: バッチ処理前のコスト試算)に使う
- **Claude APIのトークンカウント機能**: Messages APIには、実際に送信する前にトークン数だけを見積もれる仕組みが用意されている。長い資料を送る前に、コンテキストウィンドウに収まるかを事前チェックできる
- **簡易的な手計算の目安**: 正確な値はツールでの確認が必要だが、ざっくり見積もるなら「日本語の文字数 ÷ 1.5〜2」程度をトークン数の目安にすると大きく外れにくい(英語は「文字数 ÷ 4」が目安)

### 料金体系のイメージ(2026年7月時点。必ず各社公式のPricingページで最終確認すること)

| モデル | 入力(100万トークンあたり) | 出力(100万トークンあたり) |
|---|---|---|
| GPT-5.5(OpenAI API) | 5ドル程度 | 30ドル程度 |
| Claude Sonnet 5(2026年8月末までの導入価格) | 2ドル | 10ドル |
| Claude Sonnet 5(通常価格) | 3ドル | 15ドル |
| Claude Opus 4.8 | 5ドル | 25ドル |

出力トークンの方が入力トークンより高い単価に設定されているのが各社共通のパターンで、「読ませるだけ」より「書かせる」方がコストがかかる。長い要約や記事の量産などでは、出力量を絞る工夫(箇条書き指定、文字数上限の明示など)がコスト削減に直結する。

### ツール横断の対応付け

| 概念 | OpenAI | Anthropic(Claude) | Google(Gemini) |
|---|---|---|---|
| トークン数の事前確認 | Tokenizer(Web)、tiktokenライブラリ | Messages APIのトークンカウント機能 | Vertex AI / AI StudioのcountTokens機能 |
| コンテキストウィンドウの呼び方 | Context window | Context window | コンテキストウィンドウ(トークン上限) |

## 注意点・よくある誤解

- **「1文字=1トークン」ではない**: 特に日本語は1文字が1〜2トークンになることが多く、英語の感覚(4文字≈1トークン)で見積もるとコスト・上限を読み違える
- **コンテキストウィンドウは「入力+出力」の合計で管理される**: 長い質問をして、かつ長い回答を求めると、想定より早く上限に達する。会話が続くチャットでは、それまでの全履歴も毎回カウントされ直す点に注意
- **上限に空きがあっても詰め込みすぎると精度が落ちることがある**: 無関係な情報を大量に含めると回答の精度が下がる場合がある(コンテキスト腐敗)。必要な情報を絞って渡す方が安全
- **料金・コンテキストウィンドウの数値は非常に頻繁に改定される**: モデルの世代交代のたびに変わるため、本ページの数値はあくまで執筆時点の目安。契約・実装前に必ず各社の公式ドキュメントを確認する
- **日本語のトークン効率はモデル・世代によって差がある**: 同じ日本語テキストでも、トークナイザーの設計によって消費トークン数は異なる。複数モデルを比較検討する際は、実際に同じテキストを各社のトークナイザーに通して比べるのが確実

## 最初の一歩

`platform.openai.com/tokenizer` を開き、業務でよく使う日本語の文章(メール1通分など)を貼り付けて、文字数とトークン数がどれくらい違うかを一度確認してみる。
