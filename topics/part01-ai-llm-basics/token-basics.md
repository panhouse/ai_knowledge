# トークンとは何か

## これは何か

「思ったより早く長文チャットが打ち切られた」「API料金が想定より高い」——これらの原因はたいてい**トークン**にある。トークンとは、LLM(大規模言語モデル)が文章を処理する際の最小単位で、日本語の「文字数」や英語の「単語数」とは一致しない。LLMの利用上限(コンテキストウィンドウ)も、API・法人向けサービスの料金も、すべて「文字数」ではなく「トークン数」で決まるため、この単位を理解していないと利用量やコストの見積もりを大きく外す。

## 仕組み・背景

LLMは人間のように文章をそのまま読むのではなく、あらかじめ文章を**トークン**という細かい単位に分割(トークナイズ)してから数値として処理する。分割には**BPE(Byte Pair Encoding)**という手法がよく使われる。これは大量の文章データの中で頻繁に一緒に現れる文字の並びを1つの単位としてまとめていく、圧縮に近い考え方のアルゴリズムで、モデルごとに「どの文字の並びを1トークンとするか」という辞書(語彙)を学習時に作っている。

このトークン化のルールと辞書のセットを**トークナイザー**と呼ぶ。トークナイザーはモデルの提供元・モデル世代ごとに異なるため、まったく同じ文章でもGPT・Claude・Geminiでトークン数は変わるし、同じ提供元でもモデルの世代が変わればトークン数が変わることがある。たとえばAnthropicは2026年にOpus 4.7以降・Sonnet 5などで新しいトークナイザーに切り替えており、同じ文章でも旧トークナイザー(Sonnet 4.6以前)に比べて**約30%多いトークン数**になると公式に明記している。つまり「同じ文章=同じコスト」とは限らない。

もう1つ重要な概念が**コンテキストウィンドウ**(context window)で、LLMが一度の処理で読み書きできるトークン数の上限を指す。会話履歴・アップロードした資料・システムプロンプト(AIへの指示文)・出力すべてを合計したトークン数がこの上限を超えると、古いやり取りが自動的に切り捨てられたり要約されたりし、モデルによってはエラーになる。長い会話を続けると「さっき伝えた設定を忘れられた」という現象が起きるのは、多くの場合このコンテキストウィンドウの上限に達したことが原因である。

## 使いどころ・使い分け

トークンを意識すべき度合いは、利用シーンによって大きく異なる。

| 利用シーン | トークンを意識すべき度合い | 理由 |
|---|---|---|
| ChatGPT・Claude・GeminiをWebのチャット画面で使う | 低い(ただし長時間の会話では注意) | 課金はプラン定額制で、トークン単価は表に出ない。ただしコンテキストウィンドウの上限自体は存在する |
| API・従量課金サービスを開発・運用する | 高い | 入力・出力トークン数に単価を掛けた金額がそのまま請求額になる |
| 長文の資料(契約書・議事録・コードベース)をまとめて読み込ませる | 高い | 資料全体のトークン数がコンテキストウィンドウに収まるかを事前に見積もる必要がある |
| プロンプト(AIへの指示文)を設計する | 中〜高 | 冗長な指示文はトークン数=コストと応答速度に直結する |

判断基準としては、「定額のチャット画面で短いやり取りをする」だけならトークンを意識しなくても大きな問題は起きにくい。一方で、「大量の資料を読み込ませる」「APIで自動処理を組む」「法人契約で費用対効果を検証する」場面では、トークン数の見積もりが必須になる。

## 実務での使い方

### 主要モデルのコンテキストウィンドウとAPI料金(2026年7月5日時点)

API利用時は、モデルごとに公表されているコンテキストウィンドウ(上限トークン数)と、入力・出力それぞれのトークン単価を確認する。以下は主要なフラッグシップモデルの目安。

| モデル(API) | コンテキストウィンドウ | 料金(入力/出力、100万トークンあたり) | 備考 |
|---|---|---|---|
| OpenAI GPT-5.5 | 約100万トークン(Codex利用時は40万トークン) | $5 / $30 | 入力27.2万トークンを超える部分は入力2倍・出力1.5倍の料金になる |
| Anthropic Claude Sonnet 5 | 100万トークン(標準料金内) | $2 / $10(2026年8月31日まで の導入価格。9月1日以降は$3 / $15) | 90万トークンのリクエストも9千トークンと同じ単価。1Mトークン全域で均一料金 |
| Anthropic Claude Opus 4.8 | 100万トークン(標準料金内) | $5 / $25 | 最上位モデル。高速化オプション「Fast mode」は$10 / $50(プレビュー) |
| Google Gemini 3.1 Pro | 100万トークン | $2 / $12(入力20万トークン以下)、$4 / $18(20万トークン超過分) | 長い入力ほど単価が上がる階層方式 |
| Google Gemini 3.1 Ultra | 200万トークン | 記事執筆時点で価格の公式一次情報を確認できず(要問い合わせ・要最新確認) | 2026年4月投入。現時点で主要モデルの中では最大級のコンテキストウィンドウ |

Web版のChatGPT・Claude.ai・Gemini(消費者向けチャット画面)では、上記のようなトークン単価は表に出てこない。月額定額プランの中でメッセージ数・利用回数として抽象化されているため、プラン比較は料金プランのページを参照するのがよい(→[ChatGPTのプラン比較](../part02-chatgpt-basics/chatgpt-plan-comparison.md))。ただしコンテキストウィンドウの制約自体はチャット画面でも変わらず存在しており、長い会話では過去の内容が薄れていく。

Microsoft 365 Copilotのように企業向けにライセンス提供されるツールでは、トークンという言葉自体が前面に出ないことが多い。Copilotの従量課金(Pay-As-You-Go)は「メッセージ」や「Copilot Credits」という独自単位で計測され、その裏側でモデルの入力・出力トークン数やツール呼び出し回数がクレジット消費量に変換される仕組みになっている。

### コピペで使える実例: 自分の文章のトークン数を確認する

1. ブラウザで [platform.openai.com/tokenizer](https://platform.openai.com/tokenizer) を開く(アカウント登録不要)
2. 確認したい文章を貼り付ける(例: 社内で使っているプロンプトのテンプレート、要約させたい資料の一部など)
3. 画面下に表示される「Tokens」の数値が実際のトークン数。文字数(Characters)とあわせて表示されるので、その文章が「文字数の何倍のトークン数になるか」を体感できる
4. Claude・Gemini用の目安が欲しい場合は、Anthropic ConsoleのToken Count API、またはGoogle AI StudioのCount Tokens機能でも同様に確認できる(モデルごとにトークナイザーが異なるため、正確な数字が欲しい場合は使うモデルのツールで数える)

### なぜ日本語は英語よりトークン数が多くなるのか

英語は単語やその接頭辞・接尾辞単位でまとまった1トークンになりやすく、Anthropicの公式FAQでも「英語では1トークン≈4文字、または0.75単語」が目安とされている。一方で日本語は、BPEの学習データに占める割合が英語より少ないため効率よくまとめられず、1文字が複数バイト・複数トークンに分割されやすい。実務者による検証記事でも、同じ内容の文章で日本語は英語のおおむね2倍程度のトークン数になるという報告がある。つまり「原稿用紙1枚(400字)なら大体〇〇トークン」という感覚は英語基準の目安をそのまま日本語に当てはめると外れる。長文の日本語資料をAPIで処理する場合は、文字数ベースの見積もりよりも、実際にトークナイザーツールに通して確認する方が確実である。

## 注意点・よくある誤解

- **「文字数」と「トークン数」は別物**: 「〇〇文字以内で」とAIに指示しても、AI自身が生成の途中で正確な文字数を数えているわけではない(トークン単位で生成しているため)。文字数ぴったりの指定はズレが出やすいと理解しておく。
- **料金は入力と出力で単価が違う**: 上の表の通り、多くのモデルで出力トークンは入力トークンの4〜6倍程度の単価になっている。「要約させる」ように入力が長く出力が短いタスクはコストを抑えやすく、「長文を生成させる」タスクはコストが膨らみやすい。
- **同じ文章でもモデルが変わればトークン数もコストも変わる**: モデル移行(バージョンアップ)の際、トークナイザーが変わっていると同じプロンプトでも消費トークン数・料金が変わることがある。Anthropicの新トークナイザー(旧比+約30%)はその代表例。API運用でコストを厳密に管理している場合は、モデル切り替え時に必ず実測し直す。
- **コンテキストウィンドウ=会話の「賢さ」ではない**: コンテキストウィンドウが大きいほど大量の資料を読み込ませられるが、モデルが長い文脈の中の情報を漏れなく正確に扱えるとは限らない(文脈が長くなるほど関連情報を見落とすリスクが増える傾向がある)。「上限に収まるか」と「その中身をきちんと踏まえた回答が返ってくるか」は別の問題として扱う。
- **ツール呼び出し(Function Calling)や添付ファイルもトークンを消費する**: チャットに画像やファイルを添付したり、AIエージェントがツールを呼び出したりする際の定義文・実行結果も入力トークンとしてカウントされる(→[Function Callingの基本](../part08-api-development/function-calling-basics.md))。想定外にコストが増えたときは、こうした「見えないトークン消費」も疑う。

## 最初の一歩

自分が普段使っているプロンプトや資料の一部を、[platform.openai.com/tokenizer](https://platform.openai.com/tokenizer) に貼り付けて、文字数とトークン数の比率を一度確認してみる。特に日本語の文章がどれくらい「文字数より多いトークン数」になるかを体感しておくと、API利用時のコスト感覚や長文資料を扱う際の見積もりが立てやすくなる。
