# 画像・PDFの読み取り活用(Vision入力)の基本

## これは何か

Vision入力とは、ChatGPT・Gemini・Claude・CopilotといったチャットAIに、写真・スキャンPDF・手書きメモの画像をそのまま渡し、「何が書かれているか」「何が写っているか」を読み取らせる使い方のこと。従来、紙の書類をテキスト化するには専用のOCR(光学文字認識)ソフトが必要だったが、今のチャットAIは文章と同じ感覚で画像を「見て」内容を理解できる(マルチモーダルLLM、文章・画像・音声など複数の種類の情報を同時に扱える大規模言語モデル)。これにより、領収書の山を1枚ずつスキャン設定するような手間をかけずに、「この画像から日付と金額を抜き出して」と話しかけるだけで済むようになった。一方で、専用OCRと同じ感覚で使うと痛い目に遭う場面もあり、両者の違いを知らないまま使うと「読み取れたはずの数字が実は間違っていた」という事故につながる。

## 仕組み・背景

### 従来型OCRとVision入力(LLMによる画像読解)の違い

[認識系AIの応用](../part01-ai-basics/recognition-ai-applications.md)で扱った通り、従来型OCRは「画像のどこに文字ブロックがあるかを検出し、文字の形をパターン認識でテキストに変換する」専用技術で、文字を1文字ずつ正確に拾うことに特化している。これに対し、ChatGPTやGeminiなどのVision入力は、画像全体を大規模言語モデル(LLM)に読み込ませ、文字の形だけでなく「これは領収書らしい」「この欄は合計金額らしい」といった文脈・意味まで踏まえて解釈する。

この違いが実務上の得意・不得意を分ける。

| | 従来型OCR(専用OCRソフト・AI-OCR) | Vision入力(チャットAIのマルチモーダル機能) |
|---|---|---|
| 得意なこと | 定型帳票からの1文字単位の正確な抽出、大量件数の一括バッチ処理 | フォーマットが毎回違う書類の意味理解、「この中から〇〇だけ抜き出して」といった柔軟な指示、複数言語・手書きの雑多な内容の要約 |
| 不得意なこと | レイアウトが崩れた自由帳票、文脈を踏まえた解釈 | 桁数の多い数字を1文字も間違えずに転記すること(もっともらしい数字に「読み替えて」しまうことがある) |
| 処理単位 | 1枚ずつ高速・低コストで大量処理する設計 | チャット1回あたりの枚数・サイズに上限があり、大量一括処理には不向き |
| 出力 | 文字列(座標情報付きの場合もある) | 自然文・要約・構造化データ(表形式やJSON)への加工まで一気にこなせる |

つまり「大量の定型帳票を高速・正確に流し込みたい」なら専用OCR(AI-OCRを含む)、「毎回フォーマットが違う書類を読ませて意味まで解釈させたい・その場で少量をサッと処理したい」ならVision入力、という住み分けになる。2026年時点では、専用OCRで文字を抽出した後にLLMへ渡して意味解釈・分類させる「OCR+LLM」のハイブリッド構成も、会計ソフトなどの現場で広がっている。

### Vision入力の技術的な仕組み(使いこなしに必要な範囲)

画像はモデル内部でいくつかの小さなタイル(断片)に分割され、それぞれが「トークン」(AIが処理する文章・画像の最小単位)に変換されてテキストと同じ土俵で処理される。画像の解像度が高い・枚数が多いほど消費するトークン数が増え、料金や1回あたりの処理量の上限に影響する。PDFの場合、多くのツールは「PDF内の各ページを画像として1枚ずつ読み込む」処理を裏側で行っており、スキャンPDF(文字情報を持たず画像として保存されたPDF)もテキストPDF(文字情報を持つPDF)も同じVision入力の経路で扱われる。

## 使いどころ・使い分け

### 精度が出やすいケース

- 活字(印刷文字)で、コントラストがはっきりしている書類(コンビニのレシート、請求書、契約書のスキャン)
- 解像度が十分高く、傾き・影・反射が少ない写真
- 定型フォーマット(領収書・請求書・免許証など、項目の位置がある程度決まっている書類)
- 短い手書きメモで、文字が大きく丁寧に書かれているもの

### 精度が出にくいケース

- 崩し字・走り書きの手書き(特に日本語の手書き文字、殴り書きのメモ)
- 低解像度・ピンボケ・暗い写真、感熱紙レシートの退色・かすれ
- 表組みが複雑で罫線が入り組んだ帳票(セルの対応関係を誤認しやすい)
- 桁数の多い数字列(電話番号・金額・伝票番号など。「8」と「6」、「0」と「D」のような読み違いが起きやすい)
- 複数ページ・複数書類が1枚の画像に混在している場合(どの数字がどの項目に属するか混同しやすい)

### 業務での使い分けの目安

| 場面 | 向いている方法 |
|---|---|
| 月数千枚規模の定型請求書を機械的に処理したい | 専用AI-OCR([経理・財務職における生成AI活用事例](../part15-job-role-cases/finance-accounting-ai-use-cases.md)参照)を軸に、例外処理だけVision入力で補う |
| 出張精算で数枚の領収書をその場でサッと処理したい | チャットAIのVision入力で十分(この後のプロンプト例を参照) |
| 手書きの会議メモ・ホワイトボードの写真をテキスト化したい | Vision入力が得意(ただし崩し字は誤読前提で人が確認) |
| 契約書・免許証など1文字の誤りが重大な結果を招く書類 | Vision入力で下書きを作り、原本と人が必ず突き合わせる(桁数の多い数字は特に要注意) |
| 大量の資料を検索・横断参照したい | Vision入力そのものではなく[RAG(検索拡張生成)の基本](rag-basics.md)、資料をAIが扱いやすい形に整える下準備は[AIが扱いやすいデータ形式](ai-friendly-data-formats.md)を参照 |

## 実務での使い方

### 画面の場所(ツール横断の対応)

| ツール | 画像・PDFの追加場所 | 備考 |
|---|---|---|
| ChatGPT | チャット入力欄の「+」ボタン→「写真とファイルを追加」 | スマホアプリではカメラで直接撮影してその場で送信可能 |
| Gemini | チャット入力欄の「+」(ファイルを追加)アイコン、またはGoogleドライブから選択 | ドライブ上のファイルをアップロードし直さずそのまま参照できる |
| Claude | チャット入力欄のクリップ(添付)アイコン | プロジェクト機能に画像・PDFをまとめて格納して繰り返し参照することも可能 |
| Microsoft Copilot | チャット入力欄の「+」(追加)アイコンから「ファイルのアップロード」 | Microsoft 365ライセンス連携時はSharePoint/OneDrive上のファイルも直接参照可能 |

### コピペで使えるプロンプト例

**領収書からの情報抽出(経費精算向け)**

```
添付した領収書の画像から、以下の項目を抽出して表形式で出力してください。

- 発行日
- 発行者(店舗名・会社名)
- 合計金額(税込)
- 適用税率(10%/8%軽減税率など、記載があれば)
- インボイス登録番号(記載があれば、Tから始まる13桁)
- 想定される勘定科目(交際費/旅費交通費/消耗品費など)

読み取りに自信が持てない文字・数字がある場合は、その項目に「要確認」と付記してください。
推測で埋めず、書かれていない項目は空欄にしてください。
```

**手書きメモのテキスト化**

```
添付した手書きメモの画像を、書かれている通りにテキスト化してください。
判読できない文字は「[判読不能]」と表記し、勝手に補完しないでください。
箇条書きになっている場合は箇条書きのまま、文章の場合はそのままの文体で出力してください。
```

**複数枚の請求書を一括で構造化する**

```
添付した複数の請求書画像それぞれについて、「発行元」「請求番号」「請求金額」「支払期限」を
1件ずつ抽出し、CSV形式(1行1件、見出し行あり)で出力してください。
どの画像がどの行に対応するか分かるよう、ファイル順を保ったまま出力してください。
```

### 料金・上限の目安(2026年7月時点)

ツールごとに1メッセージあたりの添付枚数・サイズの上限が異なるため、大量枚数を1回で処理しようとすると上限エラーになりやすい。

| ツール | 1メッセージあたりの上限(目安) | 画像サイズ上限 | 備考 |
|---|---|---|---|
| ChatGPT(Plus/Go以上) | 添付ファイル最大10〜20個程度(プラン・時期により変動) | 画像1枚あたり最大20MB程度 | 無料版は1日あたりの画像アップロード枚数に制限あり([マネーフォワード クラウド](https://biz.moneyforward.com/ai/basic/3309/)) |
| Claude(全プラン共通) | 1メッセージあたり最大5ファイル程度 | 1ファイルあたり数十MB程度(プロジェクト機能では上限が別設定になる場合あり) | 無料/Pro/Maxでサイズ・枚数の基本仕様は同じ([ネタメモ](https://netamemo.com/claude-file-upload-limit/)) |
| Gemini(有料プラン) | 1プロンプトあたり最大10個程度のファイル | 1ファイルあたり最大2GB程度(動画含む) | 無料プランは動画時間などに別途制限([note: ヒロ](https://note.com/hiro_seki/n/nc21a801cf718)) |
| Microsoft Copilot | Microsoft 365ライセンス連携時は1ファイル最大10MB程度・1日あたりの総量に上限 | ライセンスなしの場合はさらに小さい制限(1MB程度)になる場合あり | 長い資料は事前に分割・要約してから読み込ませることが推奨される([Saiteki AI](https://saiteki-ai.com/basics/ai-tool/microsoft-copilot/microsoft-copilot-chat-files/)) |

個人向けプランの月額料金はChatGPT Plus・Claude Pro・Google AI Proがいずれも概ね月20ドル前後(Geminiは日本円建てで月2,900円程度)で横並びになっており、Vision入力自体に追加料金がかかることは基本的にない。ただし画像・PDFの枚数や解像度が多いほど消費するトークン量(処理量の単位)が増えるため、API経由で大量処理する場合は従量課金が積み上がる点に注意する。上限値・料金は変更が頻繁なため、大量処理を計画する際は必ず各社の最新のヘルプページで確認すること。

## 注意点・よくある誤解

- **「読み取れた」=「合っている」ではない**: LLMは文脈から「もっともらしい」文字・数字を補って答えることがあり、崩れた文字や潰れた数字を、実際とは違う尤もらしい値に読み替えてしまうことがある(ハルシネーション、もっともらしい誤情報を生成する現象、の画像版)。金額・日付・番号など数値が絡む項目は、必ず元の画像と目視で突き合わせる
- **大量の帳票を機械的に流し込みたいなら専用OCR(AI-OCR)が本命**: チャットAIのVision入力は1メッセージあたりの枚数上限が数枚〜十数枚程度と少なく、月数千枚規模の処理には向かない。大量処理は会計ソフトのAI-OCR機能などの専用ツールに任せ、チャットAIは例外対応・柔軟な読み替えが必要な少量案件に使い分けるのが実務的
- **手書きは活字より格段に精度が落ちる**: 特に崩し字・走り書きの日本語手書きは誤読が多い。重要な手書きメモは、AIに一次変換させた後、必ず人が原本と読み合わせる
- **解像度・撮影環境が精度を大きく左右する**: 暗い場所での撮影、斜めからの撮影、感熱紙レシートの退色は誤読の主因になる。正面から明るい場所で撮る、可能ならスキャナーを使う、といった一手間で精度は大きく改善する
- **個人情報・機密情報が写り込んだ画像の扱いに注意**: 領収書には氏名・カード番号の一部、社内資料の写真には機密情報が写り込むことがある。無料プランなど学習利用に同意した設定でアップロードすると、AIの学習データに使われる可能性がある。各ツールのデータ保護設定は[Gemini・Claude・Copilotの初期設定とデータ利用オプトアウト比較](../part03-ai-chat-tools/ai-chat-tools-privacy-and-setup-comparison.md)を参照して確認する
- **経理・財務の現場適用は専用ページを参照**: 領収書処理の具体的な業務フロー・仕訳への落とし込み・数値検証の勘所は[経理・財務職における生成AI活用事例](../part15-job-role-cases/finance-accounting-ai-use-cases.md)に詳しい

## 最初の一歩

手元の領収書を1枚スマホで撮影し、ChatGPT・Gemini・Claudeのいずれかに添付して上記の「領収書からの情報抽出」プロンプトを試し、出力された金額・日付が原本と一致するか目視で確認してみる。
