# 社内AI利用ガイドラインの作り方

## これは何か

「情報漏洩に気をつける」「著作権に注意する」と個々のリスクを知っていても、それが従業員一人ひとりの判断に委ねられたままだと、部署やメンバーによって対応がバラバラになり、結局は「怖いから使わない」か「何も気にせず使う」の両極に振れやすい。社内AI利用ガイドラインは、こうした個別のリスク対策を「自社ではこう運用する」という一本の社内規程にまとめ、全社員が同じ基準で判断できるようにする文書。ゼロから条文を書き起こす必要はなく、経済産業省・総務省や日本ディープラーニング協会(JDLA)が無料公開しているひな形を土台に、自社の実態に合わせて肉付けしていくのが最短ルートになる。

## 仕組み・背景

社内AI利用ガイドラインの位置づけを整理するには、参照する公的な資料が「誰向けに」「どのくらい完成された形で」書かれているかを見分けるとわかりやすい。2026年7月時点で主に参照される3つの資料は、次のように役割が異なる。

- **AI事業者ガイドライン(経済産業省・総務省)**: AIの開発者・提供者・利用者すべてを対象にした、国の考え方を示す包括的な指針。2024年4月の初版公表以降改訂が重ねられ、2026年3月31日公表の第1.2版が最新。本文は原則論が中心で、そのままコピーして社内規程にできる条文集ではない。ただし別添として「チェックリスト」「ワークシート」(別添7)が付属し、自社のAI利用・ガバナンス状況を項目ごとに自己点検し、不足している規程項目を洗い出すための実務ツールとして使える
- **生成AIの利用ガイドライン(JDLA、第1.1版・2023年10月公開)**: 「利用する従業員が守るべき条項」の形で最初から書かれた、社内規程にそのまま転用しやすいひな形。「簡易解説付き」版と「条項のみ」版があり、Word形式でダウンロードして社名や社内ルールに合わせて書き換えるだけで下書きが作れる。2024年2月には画像生成に特化した別冊(画像編)も追加されている。中小企業やAI利用ガイドラインを初めて作る企業の出発点として最も実務的
- **テキスト生成AIの導入・運用ガイドライン(IPA、2024年7月更新)**: 情報システム部門・セキュリティ担当者向けに、導入検討からルール整備・運用・監視までのライフサイクルで整理された資料。セキュリティリスクの評価やチェック項目が手厚く、情シス主導でガイドラインを整備する場合の実務書として参照しやすい

これら3つはどれも「これだけ読めば完成」というものではなく、AI事業者ガイドラインで大枠の考え方と抜け漏れ確認、JDLA版で条文の下書き、IPA版でセキュリティ面の肉付けをする、という組み合わせで使うのが実務的。

## 使いどころ・使い分け

どの資料を起点にするかは、自社の状況によって変わる。

| 状況 | 起点にすべき資料 | 理由 |
|---|---|---|
| 初めてガイドラインを作る中小企業・法務専任者がいない | JDLA「生成AIの利用ガイドライン」 | 条文形式で最初から書かれており、自社名・自社ルールに置き換えるだけで下書きが完成する |
| 情シス・セキュリティ部門が主導して整備する | IPA「テキスト生成AIの導入・運用ガイドライン」 | 導入〜運用のライフサイクルとセキュリティ観点のチェック項目が充実している |
| 官公庁の考え方に沿っていることを説明できる体制にしたい、上場企業・規制業種 | AI事業者ガイドライン(経済産業省・総務省)のチェックリスト・ワークシート(別添7) | 国の指針との対応関係を自己点検・説明できる形になる |
| 既にガイドラインがあり、AIエージェントなど新機能への対応を追加したい | AI事業者ガイドライン第1.2版(Human-in-the-Loopの考え方) | 第1.2版でAIエージェント・フィジカルAIの取り扱いが新たに整理されている |

いずれの場合も、これらの資料は「外部の規制・リスクをどう理解するか」(→[生成AIの規制・ガバナンス動向](./ai-regulation-and-governance-trends.md))や「情報漏洩をどう技術的・運用的に防ぐか」(→[生成AI利用における情報漏洩対策](./information-leakage-prevention.md))を踏まえた上で、それらを**1つの社内規程として束ねる工程**の材料として使う。

## 実務での使い方

### ガイドラインに盛り込むべき項目

社内AI利用ガイドラインとして最低限カバーすべき項目は、次の7つに整理できる。

| 項目 | 盛り込む内容 |
|---|---|
| 対象範囲 | どの部署・役職・雇用形態(社員/派遣/業務委託)が対象か、どのAIツール・サービスが対象か |
| 利用可否の基準 | 会社が許可したツール・法人契約のみ利用可とするか、個人アカウントでの業務利用を明確に禁止するか |
| 入力禁止情報 | 個人情報、顧客の機密情報、未公開の契約条件・決算情報、他社の著作物・機密資料など、AIに入力してはいけない情報の具体例 |
| 生成物の検証責任 | AIの出力(文章・画像・コード)を対外公開・意思決定に使う前に、内容の正確性や著作権侵害の可能性を人間が確認する義務と、その確認担当者 |
| 著作権・法的リスクの扱い | 生成物の商用利用・対外公開時の確認フロー、既存作品への依拠が疑われる場合の対応(詳細は[生成AIの著作権リスクと実務での注意点](./copyright-risks-in-generative-ai.md)を参照) |
| 承認・申請フロー | 新しいAIツールを部署で導入したい場合の申請先、高リスク用途(採用選考・与信審査など)で使う場合の事前レビュー要否 |
| 教育・研修と違反対応 | 利用開始前の研修受講を必須にするか、違反時の対応(注意・懲戒等)、相談・問い合わせ窓口 |

### 公的テンプレートの入手先とカスタマイズの流れ

1. **JDLA「生成AIの利用ガイドライン」をダウンロードする**: [JDLA公式サイトの資料室](https://www.jdla.org/document/)から「生成AIの利用ガイドライン【条項のみ】(第1.1版)」または解説付き版をWord形式で取得する。画像生成を業務で使う場合は「生成AIの利用ガイドライン(画像編)」も併せて入手する
2. **自社の実態に合わせて条文を書き換える**: 「会社名」「対象ツール名(ChatGPT/Gemini/Copilot/Claude等、自社が契約しているもの)」「入力禁止情報の具体例」を自社の業種・取扱データに合わせて差し替える。ひな形の条文をそのまま丸写しにすると、実際には使っていないリスク(例: 自社が画像生成AIを使っていないのに画像編の条項を残す)が混在して読みにくくなるため、不要な条項は削る
3. **AI事業者ガイドラインのチェックリスト・ワークシート(別添7)で抜け漏れを確認する**: [経済産業省「AI事業者ガイドライン」掲載ページ](https://www.meti.go.jp/shingikai/mono_info_service/ai_shakai_jisso/20260331_report.html)から第1.2版の別添(チェックリスト・ワークシート)を入手し、下書きした社内規程がどの項目をカバーできているかを自己点検する。ワークシートは全項目を採用する必要はなく、自社の事業内容・AI利用実態に合う項目だけを選んで使ってよいとされている
4. **セキュリティ面をIPAガイドラインで補強する**: 情シス主導で整備する場合は、[IPA「テキスト生成AIの導入・運用ガイドライン」](https://www.ipa.go.jp/jinzai/ics/core_human_resource/final_project/2024/generative-ai-guideline.html)の導入〜運用のライフサイクルに沿って、アクセス管理・ログ管理・監査の項目を追加する
5. **法務・経営層の承認を得て正式な社内規程として発行する**: 就業規則や情報セキュリティ規程など既存の社内規程との整合性を確認し、正式な社内文書として承認・発行する

### コピペで使えるガイドライン骨子(見出し例)

ゼロから作る場合の目次のたたき台。JDLAのひな形を条文レベルの下書きとして使い、この骨子で章立てを整理すると全体像が組みやすい。

```markdown
# 〇〇株式会社 生成AI利用ガイドライン

1. 目的
2. 適用範囲(対象者・対象ツール)
3. 利用可能なAIツール一覧(法人契約のみ/個人契約禁止)
4. 入力してはならない情報
   4.1 個人情報・顧客情報
   4.2 未公開の経営情報・契約条件
   4.3 他社の機密情報・著作物
5. 生成物の取り扱い
   5.1 対外公開・商用利用前の確認義務
   5.2 著作権侵害リスクへの対応
   5.3 事実確認(ハルシネーション対策)の義務
6. 禁止行為
7. 新規ツール導入・高リスク用途利用時の申請フロー
8. 教育・研修
9. 違反時の対応
10. 問い合わせ・相談窓口
11. 改定履歴
```

### 社内への浸透のさせ方

ガイドラインは発行して終わりではなく、以下の運用があってはじめて機能する。

- **研修をセットにする**: ガイドラインの配布だけでは読まれないことが多いため、利用開始前に短時間の研修(15〜30分程度でよい)を必須化し、入力禁止情報や生成物確認義務を具体例つきで説明する
- **Q&A・相談窓口を明確にする**: 「これは入力していいか」「この画像は公開していいか」を迷ったときに聞ける窓口(情シス・法務・専用チャット等)を明示する。窓口がないと、判断に迷った従業員が黙って個人アカウントで使う「シャドーAI」化を招きやすい
- **違反時の対応をあらかじめ決めておく**: 悪質な情報漏洩と、ルールを知らずに軽微な逸脱をしてしまった場合を分けて対応レベルを決めておくと、運用時の判断がぶれない
- **定期的に見直す**: 新しいAIツールの追加、AIエージェントのような新機能の登場、規制動向の変化(→[生成AIの規制・ガバナンス動向](./ai-regulation-and-governance-trends.md))に応じて、最低でも年1回は内容を見直す

## 注意点・よくある誤解

- **禁止事項の羅列だけでは浸透しない**: 「〜してはいけない」ばかりのガイドラインは読まれず守られにくい。「なぜ禁止か」「どうすればよいか(代替手段・相談先)」を併記すると実効性が上がる
- **ひな形をそのまま使うと自社の実態とズレる**: JDLAのひな形は汎用的に書かれているため、自社が契約していないツールの条項や、業種特有の機密情報(医療情報、金融情報など)への言及が抜けている場合がある。必ず自社の業務内容に合わせて加筆・削除する
- **一度作ったら終わりではない**: AI事業者ガイドラインのように参照元自体が改訂され続けている(2024年4月の初版から2026年3月の第1.2版まで複数回改訂)ため、社内規程も追随して更新する前提で運用する
- **技術的対策・法的リスク対応とは役割が異なる**: このページはガイドラインという「文書」をどう作り、どう運用に乗せるかを扱う。入力データの学習利用防止やSSO統一といった技術的対策は[生成AI利用における情報漏洩対策](./information-leakage-prevention.md)、著作権侵害の判断基準は[生成AIの著作権リスクと実務での注意点](./copyright-risks-in-generative-ai.md)、EU AI Actなど外部規制の動向把握は[生成AIの規制・ガバナンス動向](./ai-regulation-and-governance-trends.md)がそれぞれ担当する。社内ガイドラインはこれら3つの内容を「自社の規程」として一本化する役割を持つ

## 最初の一歩

[JDLA公式サイトの資料室](https://www.jdla.org/document/)から「生成AIの利用ガイドライン」をダウンロードし、自社が契約しているAIツール名と入力禁止情報の具体例に書き換えた下書きを1枚作ってみる。
