# Tree of Thought(ToT)プロンプティング

## これは何か

新規事業の進め方、価格戦略、システム移行の方式など「複数のやり方があり得て、どれが正解か自明ではない」問題をAIに相談すると、[Chain-of-Thought(CoT)](chain-of-thought-prompting.md)で筋道立てて考えさせても、最初に思いついた1本の道筋をそのまま押し通してしまい、実は途中で選択肢を間違えていた、ということが起きる。Tree of Thought(ToT、「思考の木」)プロンプティングとは、AIに1本の答えをいきなり出させるのではなく、複数の異なるアプローチを枝分かれさせて並べ、それぞれの長所・短所を自己採点させたうえで、最も筋の良い案を選ばせる(あるいは良いところを合成させる)手法である。人間が重要な意思決定の前に「案A・案B・案Cを並べて比較検討する」のと同じ発想をAIにやらせる、と考えるとわかりやすい。

## 仕組み・背景

2023年にPrinceton大学とGoogle DeepMindの研究チームが発表した論文"Tree of Thoughts: Deliberate Problem Solving with Large Language Models"がこの手法の原型だ。CoTがモデルに「1本道の途中式」を書かせる手法だったのに対し、ToTは思考の各ステップを木構造のノード(節)として扱い、各ノードから複数の分岐(思考の候補)を生成し、モデル自身に(あるいは別の評価ステップに)各分岐の見込みを採点させ、有望な分岐だけを残して次のステップに進み、行き詰まった分岐は途中で切り捨てて(バックトラック)別の枝に戻る、という探索アルゴリズムとして提案された。論文の実験では、24点パズル(4つの数字を四則演算で24にするゲーム)においてGPT-4のCoTプロンプトの成功率が4%だったのに対し、ToT(幅優先探索)を使うと74%まで跳ね上がったと報告されている。

ただし、この論文の本来のToTは「候補生成→評価→探索」をプログラムのループとして実装するものであり、Pythonコードでモデルへの複数回のAPI呼び出しを制御する仕組みが前提になっている。チャット画面に1回プロンプトを打ち込むだけのビジネスパーソンが再現できるのは、この探索アルゴリズムそのものではなく、「複数の案を出させる→自己評価させる→選ばせる」という考え方のエッセンスを1つのプロンプトに凝縮した簡易版だ。これを実務では「プロンプト版ToT」「疑似ToT」などと呼ぶ。本ページで紹介する実例もすべてこの簡易版であり、コードや専用ツールは不要である。

## 使いどころ・使い分け

ToTが効くのは「唯一の正解がなく、複数のアプローチが並立し得て、それぞれにトレードオフがある」問題に限られる。単純な事実質問や、答えが1本道で決まる計算問題にToTを使っても、CoTと大差ない答えが出るうえに手間とコストだけが増える。

| タスクの性質 | 向いている手法 | 具体例 |
|---|---|---|
| 答えが1本道で決まる計算・条件判定 | CoT | 割引計算、契約条項の該当判定 |
| 複数の妥当なアプローチがあり比較検討が必要 | ToT | 新規事業の参入方式の選定、価格改定シナリオの比較、システム移行方式(一括切替 vs 段階移行)の検討 |
| 制約が絡み合うパズル的な問題 | ToT | 人員シフトの組み方、複数拠点への予算配分、日程調整の最適化 |
| 外部情報の取得や実際の操作を伴う問題 | ReAct | 最新の競合価格を調べてから比較表を作る、社内システムを検索しながら回答する |
| 形式・トーンを揃えたいだけの単純作業 | Zero-shot/Few-shot | メール文面の整形、要約のトーン統一 |

もう一段大事な判断軸は「2023年当時ほどToTの効果に期待しすぎない」ことだ。ToTが提案された2023年は、モデルが内部で多段階の探索をしていなかったため、プロンプト側で明示的に「複数案→評価→選択」の型を与える効果が大きかった。しかし2025〜2026年にかけて主流になったOpenAI o-series/GPT-5系「Thinking」、Anthropic Claudeの拡張思考(extended thinking)、Google Geminiの「Thinking」モデルは、ユーザーに見えない内部処理として既に複数の解法候補を試し、行き詰まれば別の道筋に戻る、という探索を自動でやっている。そのため、これらの推論モデルに対してプロンプトでToTの型を重ねて指示しても、純粋な数学・コーディングのような「唯一の正解がある」タスクでは、素のモデルに任せた方が同等かそれ以上の精度をより低コストで出せることが多いというのが2026年時点での実務的な見立てだ。

一方で、次のような場面ではプロンプト版ToTは今も価値がある。

- **比較検討の過程自体を人間が見て選びたい場合**: 推論モデルの内部思考は要約されて見えにくいが、ToTは分岐そのものをテキストとして出力させるため、「なぜその案を選んだか」を人間が検証・修正しやすい
- **複数案を意思決定者に提示する資料が欲しい場合**: 経営会議・企画書のように、そもそも「複数案の比較表」という成果物が必要な業務
- **モデルが1つの思い込みに固執しやすいテーマ**: ブレインストーミング的に強制的に視点を分散させたい場合

## 実務での使い方

### コピペで使える実例: 1プロンプト完結型ToT

論文のような多段階の探索を再現する必要はない。次のように「案を3つ出す→自己評価させる→選ばせる」を1回のプロンプトに詰め込むだけで、簡易ToTとして機能する。

```
あなたは経営戦略のアドバイザーです。以下のお題について、
Tree of Thoughtsの考え方で検討してください。

【お題】
[ここに検討したいテーマを書く]
例)地方都市で実店舗を1店舗運営している当社が、
   来期に売上を伸ばすための施策を検討したい。予算は500万円。

【手順】
1. 互いに毛色が異なる案を3つ提示してください(似た方向性の案を並べない)
2. それぞれの案について、以下の観点で自己評価してください
   - 前提条件(成立するために必要な条件)
   - メリット
   - デメリット・リスク
   - 実現の難易度(高・中・低)
   - 成功確率の見立て(高・中・低とその理由)
3. 3案の評価を踏まえて、最も推奨する案を1つ選び、理由を説明してください
   (2案の良いところを組み合わせた第4の折衷案を提案してもかまいません)
4. 最後に、選んだ案を実行する場合の最初の3ステップを箇条書きで示してください
```

### コピペで使える実例: 審査員役を分離するパターン

自己評価だけだと「自分が出した案を自分でひいき目に採点してしまう」バイアスが起きやすい。案を出す役と評価する役を明示的に分けて2段階でやり取りすると、より辛口で実用的な評価になりやすい。

```
# 1回目のプロンプト(案出し)
以下のお題について、方向性が明確に異なるアプローチを3つ提案してください。
それぞれ200字程度で概要のみ示し、評価やおすすめの言及はまだしないでください。

[お題]

# 2回目のプロンプト(評価・選定)
あなたは辛口の審査員です。先ほど出た3つの案それぞれについて、
「実行可能性」「必要な予算・期間」「失敗した場合の損失の大きさ」の3観点で
10点満点の点数を付け、最も点数の高い案を1つ選んで理由を述べてください。
点数が僅差の場合は、両案の良いところを合成した代替案を提示してもかまいません。
```

### モデル別の使い分け目安(2026年7月時点)

| モデル・モード | プロンプト版ToTの効果 | 理由 |
|---|---|---|
| ChatGPTの「Instant」、Claudeの拡張思考オフ、Geminiの「Fast」 | 有効 | 内部で複数案の探索を自動でしないため、プロンプト側で型を与える価値が大きい |
| ChatGPTの「Thinking」、Claudeの拡張思考オン、Geminiの「Thinking」「Pro」 | 数学・コーディングなど正解が1つの問題では効果が薄い/むしろ冗長化。戦略立案・複数案提示など「比較の過程」自体が成果物になる問題では依然有効 | 内部で既に多段探索をしているため上乗せ効果が小さいが、比較表という「見える形」を明示的に要求する価値は残る |

料金面では、ToTは「3案×評価×選定」を1回のプロンプトでまとめて生成させるため、通常のCoTより出力トークン数が数倍に増えやすい。推論モデルと組み合わせるとさらに思考トークンが加算されるため、重要な意思決定に絞って使い、日常的な定型業務には使わないのがコスト管理上の基本になる。

## 注意点・よくある誤解

- **「ToT=常にCoTより高精度」ではない**: 2023年の論文はパズル的な探索タスクでの結果であり、唯一の正解がある事実確認や単純計算にToTを使っても精度は上がらず、トークン消費と待ち時間だけが増える
- **推論モデルへの「二重がけ」に注意**: Claudeの拡張思考やChatGPTのThinkingなど、既に内部で多段推論をしているモデルにプロンプト版ToTを重ねても、上乗せ効果は限定的なことが多い。まずはモデル任せで試し、「比較表という成果物」が必要な場合にだけ明示的なToT型を使う
- **案が3つとも似た方向性になりやすい**: 「毛色が異なる案を」と明示しないと、AIは似たり寄ったりの案を3つ並べるだけになりがちで、比較検討の意味が薄れる
- **自己評価は自分の案に甘くなりがち**: 1回のプロンプトで「案出し→評価」を両方やらせると、出した案を無理に肯定する評価になることがある。重要な判断では、案出しと評価を別プロンプト・別ターンに分ける、あるいは「あえて否定的な立場から評価して」と指示すると精度が上がる
- **本物のToT(探索アルゴリズム)と混同しない**: 論文本来のToTは複数回のAPI呼び出しとコードによる探索制御を伴う実装であり、チャット画面での1発プロンプトはあくまで簡易的な模倣である。過大な期待をせず「発想の幅を広げる補助」として使うのが実務的な位置づけ

## 最初の一歩

次に「複数のやり方が考えられて迷っている」業務課題(施策の選定、進め方の比較など)が出てきたら、上のコピペ例の【お題】部分だけ差し替えて実行し、AIが出した3案の比較表をそのまま会議資料の叩き台に使ってみるとよい。
