# ロール(役割)プロンプティング

## これは何か

ロール(役割)プロンプティングとは、プロンプトの冒頭で「あなたは熟練の経営コンサルタントです」「厳しい編集者として振る舞ってください」のように、AIに特定の立場・専門性・人格(ペルソナ)を与えてから本題を頼む手法。「同じ質問をしても、当たり障りのない一般論しか返ってこない」「回答の口調や視点が毎回バラバラで、狙った切り口が出てこない」というときに使うと、回答の視点・語彙・厳しさのレベルが狙った方向に寄りやすくなる。ChatGPT・Gemini・Claudeのどれでも、追加のプロンプト文だけで使える最も手軽な精度調整テクニックの一つ。

## 仕組み・背景

LLM(大規模言語モデル)は、インターネット上の膨大なテキスト(専門家のブログ、業界の記事、Q&Aサイトの回答など)を学習しており、それぞれの立場・専門分野に特有の語彙・視点・文体のパターンを内部に持っている。「あなたは○○です」という一文は、その中から関連するパターンを呼び出すための"条件付け"のスイッチのように働く。たとえば「弁護士として」と指定すると、リスクや契約条文への言及が増え、「コピーライターとして」と指定すると、キャッチーな言い回しや短い文が増える、といった具合に出力の傾向が変わる。

ここで重要なのは、ロールプロンプティングは**システムプロンプト(カスタム指示)そのものではなく、その中に入れる"材料の一つ"**だという点。システムプロンプトやカスタム指示は「口調」「出力形式」「守ってほしい制約」「背景情報」など会話全体に効く設定をまとめて入れる器であり、ロール設定(「誰として振る舞うか」)はその一項目に過ぎない。両者を混同すると、「ロールさえ設定すれば万能」という誤解につながりやすい。実務では、ロール設定は次の2通りの使い方がある。

- **一回限りの指定**: そのメッセージの中だけで「〇〇として、以下を確認して」と書く。単発の相談・下書き作成に向く
- **永続的な指定**: システムプロンプト(APIの`system`パラメータ)やカスタム指示、Projects/Gemの指示欄に書き、会話全体・毎回の利用で効かせる。定型業務の繰り返しに向く

なお、2025年以降の複数の研究では、ロールプロンプティングの効果は一様ではないことが確認されている。文章のトーン調整・ブレインストーミング・レビューの視点出しなど「観点や語り口を変えたいタスク」では効果が出やすい一方、事実確認・数値計算・コード生成など「正確性そのもの」が問われるタスクでは、専門家ペルソナを与えても精度が上がらない、むしろ下がるケースがあることが指摘されている(arXiv「Prompting Science Report 4: Playing Pretend: Expert Personas Don't Improve Factual Accuracy」)。ロールプロンプトは"魔法の精度向上ボタン"ではなく、"視点・トーンを操作するダイヤル"だと理解しておくとよい。

## 使いどころ・使い分け

| 目的 | ロールプロンプティングの効果 | 使い方の目安 |
|---|---|---|
| 文章の推敲・トーン調整(顧客向けメール、プレスリリース等) | 効果が出やすい | 「厳しい校閲者として」「顧客対応10年のベテランとして」等を明示 |
| ブレインストーミング・アイデア出し | 効果が出やすい | 「複数の異なる立場(財務・営業・法務)から意見を出して」のように立場を複数指定すると視点が広がる |
| レビュー・チェックの観点出し(コードレビュー、提案書レビュー等) | 効果が出やすい | 「〇〇の観点で厳しくレビューして」と、役割+チェック観点をセットで書く |
| 事実確認・数値計算・厳密なコード生成 | 効果は限定的、逆効果のこともある | 役割設定よりも、参照資料を渡す・出力形式を指定する・検証手順(「根拠を明示して」等)を指示する方が効果的 |
| 一度きりの相談 | 一回限りの指定で十分 | メッセージ本文の冒頭に役割を書く |
| 毎回同じ役割で使う定型業務 | 永続設定にする | カスタム指示・Projects・GPTs・Gemに保存する(詳細は後述) |

判断に迷ったら、「このタスクで欲しいのは"視点・語り口の違い"か、"事実としての正しさ"か」を自問するとよい。前者ならロールプロンプトが効きやすく、後者なら役割設定よりも情報の与え方・検証手順のほうが重要になる。

## 実務での使い方

### コピペで使える役割プロンプト例

以下はそのままメッセージ欄に貼り付けて、末尾に自分の実際の文章・コード・状況を続けて使える例。

**1. 文章のレビュー(顧客向けメール・提案書など)**

```
あなたは、大手出版社で20年校閲を担当してきた厳しい編集者です。
以下の文章を、①誤字脱字、②論理の飛躍、③読み手(多忙な決裁者)にとって
分かりにくい表現、の3つの観点でチェックし、指摘箇所と改善案を
箇条書きで示してください。良い点があれば最後に1行だけ触れてください。

[ここにレビューしてほしい文章を貼り付け]
```

**2. ブレインストーミング(新規事業・企画のアイデア出し)**

```
あなたはスタートアップ支援を専門とする経営コンサルタントです。
以下の事業アイデアについて、①市場性、②収益モデル、③実現の難易度
の3つの軸で、賛成派と懐疑派それぞれの視点から意見を出してください。
最後に、次の一歩として検証すべき仮説を1つ提案してください。

事業アイデア: [ここに概要を記入]
```

**3. コードレビュー**

```
あなたは、大規模なWebサービスの保守を10年担当してきたシニアエンジニアです。
以下のコードを、①バグ・例外処理の漏れ、②可読性、③パフォーマンス、
の観点でレビューしてください。指摘は「重要度: 高/中/低」を付けて
箇条書きにし、修正案のコードも示してください。

[ここにコードを貼り付け]
```

**4. 交渉準備(価格交渉・契約条件の想定問答)**

```
あなたは、購買・調達を専門とする百戦錬磨の交渉担当者です。
これから私は取引先(あなた)に価格改定を提案します。
あなたの立場で、想定される反論・値引き要求・条件闘争のポイントを
5つ挙げ、それぞれに対する私の返答案も一緒に考えてください。

提案内容: [ここに交渉したい内容を記入]
```

**5. 顧客対応メールの下書き**

```
あなたは、クレーム対応を専門とするカスタマーサポートのベテランです。
以下の顧客からの問い合わせに対し、①謝罪、②状況説明、③今後の対応、
の順で、丁寧だが事務的になりすぎないトーンの返信メールを作成してください。
文字数は300字程度でお願いします。

顧客からの問い合わせ: [ここに内容を貼り付け]
```

### 「一回限り」と「永続設定」の置き場所(ツール横断)

同じロール設定でも、毎回使うなら都度貼り付けるのではなく、各ツールの「永続的な指示」欄に保存しておくと効率的。2026年7月時点の主なツールでの対応は次の通り。

| ツール | 一回限りのロール指定 | 永続的に保存する場所 |
|---|---|---|
| ChatGPT | メッセージ本文の冒頭に役割を書く | 画面左下のアカウントアイコン→「パーソナライズ」→「カスタム指示」の「自分について」「回答してほしい方法」欄(各1,500文字まで、無料プラン含む全プランで利用可) |
| GPTs(ChatGPTのカスタムAI) | (GPTs自体が特定タスク専用なので通常は永続設定側で使う) | GPT作成画面(「GPTを作成」)の「Instructions(指示)」欄。Plus以上のプランが必要 |
| Gemini | メッセージ本文の冒頭に役割を書く | gemini.google.com→左メニュー「Gemを表示」→「Gemを作成」の指示欄。Google公式はペルソナ・タスク・コンテキスト・出力形式の4要素を含めることを推奨 |
| Claude | メッセージ本文の冒頭に役割を書く(APIなら`system`パラメータ) | claude.aiの「Projects」を作成し、「カスタム指示」欄に記載(Pro以上のプランが必要) |
| Microsoft 365 Copilot | メッセージ本文の冒頭に役割を書く | 個人設定(「Copilotに自分について知ってほしいこと」欄)、または Copilot Studio でエージェントを作成しその指示欄に記載 |

いずれのツールも「役割」単体ではなく、「役割+口調+出力形式+守ってほしい制約」をまとめてカスタム指示に書き込むのが実務上のコツ。役割だけを書いて満足せず、[プロンプトの基本構成要素](./prompt-basic-structure.md)にある他の要素(タスク・文脈・出力形式)と組み合わせること。

## 注意点・よくある誤解

- **「役割を与える=本物の専門知識を持つ」わけではない**: 「弁護士として」と指定しても、AIが法律の専門家になるわけではなく、モデルが元々持っている知識の範囲内で"専門家らしい語り口"になるだけ。事実誤認や古い情報のリスクは役割設定の有無に関わらず残るため、契約書レビューや税務判断など正確性が問われる場面では、必ず人間(有資格者)による確認を挟む
- **過度に凝ったペルソナ設定は逆効果になりうる**: 「架空の経歴」「性格設定」などを長々と書き込むと、トークン(文字量に応じた処理コスト)を消費するだけでなく、モデルの注意がペルソナの設定文自体に向いてしまい、本来のタスク指示への追従が甘くなることがある。役割の記述は「肩書き+専門性+期待する視点」程度の1〜2文に留め、あとは具体的なタスク指示に文字数を使う方が効果的
- **正確性が必要なタスクでは効果が限定的、時に悪化することもある**: 数値計算・コーディング・事実確認では、専門家ペルソナを付けても精度が上がらない、むしろ下がったという実験結果が報告されている。こうしたタスクでは、役割設定よりも「参照資料を渡す」「途中の計算過程を書かせる」「出典を明示させる」といった手法を優先する
- **他の手法と組み合わせるときは指示の矛盾に注意**: 役割設定([Zero-shot・Few-shot・Chain-of-Thoughtプロンプティング](./chain-of-thought-prompting.md)のようなCoT(段階的に考えさせる手法)や、Few-shot(お手本例を示す手法)、出力形式の指定と組み合わせるのは有効だが、「簡潔な回答を好む編集者として」と指示しつつ「詳細な手順を6ステップで」のように矛盾する条件を重ねると、モデルはどちらを優先すべきか迷い、出力が不安定になる。役割・トーン・出力形式の指示が互いに矛盾していないか、書き終えたら一度読み返す

## 最初の一歩

今使っている定型業務のプロンプト(メール下書き、レビュー依頼など)を1つ選び、冒頭に「あなたは〇〇の専門家です」という1文を追加して、追加前後で回答の質を比べてみる。
