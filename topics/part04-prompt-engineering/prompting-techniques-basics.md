# Zero-shot・Few-shot・Chain-of-Thoughtプロンプティング

## これは何か

同じAIに同じような依頼をしても、出力形式がバラバラだったり、計算や論理が絡む問題で急に間違えたりすることがある。これは「頼み方の型」を知らないために起きる。生成AIへの指示の仕方には、大きく3段階の型がある。

- **Zero-shot(ゼロショット、事例なし)**: お手本を見せず、タスクの説明だけで答えさせる、最も基本的な頼み方
- **Few-shot(フューショット、少数事例)**: 望む入出力の例を2〜5個ほど添えて、形式やトーンを真似させる頼み方
- **Chain-of-Thought(チェーン・オブ・ソート、CoT、思考の連鎖)**: いきなり結論を出させず、「順を追って考えてから答えて」と指示し、計算や論理の精度を上げる頼み方

この3つは「シンプルな依頼→形式を揃えたい依頼→計算・論理が絡む依頼」という具合に、タスクの難しさに応じて使い分ける道具箱だと考えるとよい。ただし2026年時点では、後述の通りCoTの位置づけがモデルの世代によって変わってきている点に注意が必要である。

## 仕組み・背景

### Zero-shot(事例なし)

タスクの指示だけを与える、いわば「一発勝負」の頼み方。大規模言語モデルは大量の文章を学習しているため、簡単な分類・要約・翻訳などは例を見せなくても十分にこなせることが多い。プロンプトの基本構成要素([プロンプトの基本構成要素](prompt-basic-structure.md)参照)がきちんと書けていれば、日常業務の大半はZero-shotで足りる。

### Few-shot(少数事例)

タスクの指示に加えて、「入力→望ましい出力」のペアを2〜5個ほどプロンプト内に埋め込む方法。AIは例示された入出力のパターンから「今回何を求められているか」を推測して真似るため、以下のようなケースで特に効果を発揮する。

- 出力フォーマットを厳密に揃えたい(JSON構造、見出しの粒度、箇条書きの文字数など)
- 分類のカテゴリ分け(問い合わせの種類分け、感情分析のラベル付けなど)を、自社独自のカテゴリ定義に沿って行いたい
- 特定のトーン・文体(会社らしい言い回し、ブランドボイス)を再現したい

Few-shotは「口で説明しにくいニュアンス」を例示で伝える方法だと理解すると使いどころが掴みやすい。

### Chain-of-Thought(思考の連鎖)

「ステップバイステップで考えてから答えてください」のように、結論を出す前に途中の思考過程を書き出させる手法。2022年にGoogleの研究者らが発表した論文で、算数の文章題や論理パズルのような複数ステップの推論が必要なタスクにおいて、この一言を加えるだけで正答率が大きく向上することが示され、一気に広まった。理屈としては、AIは文章を一語ずつ予測して生成するため、途中式や論拠を先に言語化させることで、いきなり答えだけを出すよりも計算・論理の誤りが混入しにくくなる、という考え方である。

**ただし2026年時点では、この「明示的なCoT指示」の重要性はモデルの種類によって大きく変わってきている。**

- OpenAIのo1・o3系やGPT-5の推論(reasoning)モード、Anthropic Claudeのextended thinking(拡張思考)モード、Googleの Gemini のthinkingモードなど、いわゆる「推論モデル」は、ユーザーが指示しなくても内部で自動的に段階的な思考(内部CoT)を行ってから回答を生成するよう訓練されている。OpenAIは公式のreasoning best practicesガイドで、こうした推論モデルに対しては「ステップバイステップで考えて」「理由を説明して」といった明示的なCoT指示や過剰なFew-shot例を加えないよう推奨しており、o1-miniのような一部モデルではCoT指示を加えるとむしろ性能が落ちる例も報告されている。Anthropicも同様に、extended thinkingを有効にしている場合は明示的なCoT指示を外し、高レベルな指示にとどめるよう案内している。
- 一方で、軽量・高速モデル(推論モードを使わない従来型のモデルや、コスト優先で使う小型モデル)には、明示的なCoT指示は依然として有効である。こうしたモデルは内部で自動的に段階的思考をしないため、「順を追って考えて」の一言が今でも精度を底上げする。

つまり「CoTという考え方自体」は今も有効だが、「CoTを自分で指示する必要があるか」はモデル次第、というのが2026年半ば時点の実務上の結論である。

## 使いどころ・使い分け

| 技法 | 適した場面 | 具体例 |
|---|---|---|
| Zero-shot | 一般的な知識で答えられる単純なタスク、時間をかけずにまず試したいとき | 「この文章を3行で要約して」「この英文を自然な日本語に訳して」 |
| Few-shot | 出力の形式・粒度・トーンを厳密に揃えたい、自社独自の分類基準がある | 問い合わせメールを自社のカテゴリ(「返品」「不具合」「使い方」等)に分類する、決算資料の言い回しに合わせて文章を書く |
| Chain-of-Thought | 計算・条件分岐・複数ステップの論理が絡む、途中経過を検算したい(非推論モデル・軽量モデル利用時に特に有効) | 割引後の見積金額の計算、複数条件がある契約書の適用可否判定、スケジュールの矛盾チェック |

判断の流れとしては、まずZero-shotで試し、①形式やトーンが揃わなければFew-shotで例を足す、②計算や条件判定で間違いが目立つならCoTで思考過程を出させる、という順で足していくのが実務的である。なお、GPT-5やClaudeのExtended thinkingなど推論モードを使っている場合は、②のCoT指示は基本的に不要(むしろ冗長になりうる)なので、まずは推論モードのオン/オフを確認してから対応する。

## 実務での使い方

### コピペで使える例1: Few-shotで問い合わせメールを分類する

カスタマーサポートの問い合わせメールを、自社のカテゴリに沿って一定の形式で分類したい場合の例。例をいくつか見せることで、Zero-shotでは表記が揺れがちな出力形式・カテゴリ名を安定させられる。

```
あなたはカスタマーサポートの一次仕分け担当です。
届いた問い合わせメールを読み、以下の3つのカテゴリのいずれかに分類し、
「カテゴリ」と「理由(1行)」をこの形式で出力してください。

【カテゴリ】返品・交換 / 不具合報告 / 使い方の質問

---
例1
入力: 「先週届いた商品のサイズが合わなかったので、Mサイズに交換したいです」
出力: カテゴリ: 返品・交換 / 理由: サイズ違いによる交換希望のため

例2
入力: 「電源を入れても画面が真っ暗のまま何も表示されません」
出力: カテゴリ: 不具合報告 / 理由: 動作不良の申告のため

例3
入力: 「アプリの通知をオフにする設定はどこにありますか」
出力: カテゴリ: 使い方の質問 / 理由: 操作方法の問い合わせのため
---

【分類対象】
「注文したはずの商品が2週間経っても届きません。追跡番号もメールに記載がないのですが」
```

このように業務でよく使う分類パターンを2〜3例ストックしておき、対象の問い合わせ文だけ差し替えれば、都度使い回せるテンプレートになる。

### コピペで使える例2: Chain-of-Thoughtで見積計算を検算させる

条件が複数絡む金額計算や割引適用など、間違えると実害が出る計算をチェックしたいときの例。非推論モデル(GPT-4o系、Claude Haiku系、Geminiの非thinkingモデルなど)や、電卓代わりに素早く使いたい軽量モデルで特に効果を発揮する。

```
以下の条件で請求額を計算してください。
先に計算の手順を1ステップずつ書き出し、
途中式を示したうえで、最後に「合計金額: ◯◯円」の形式で結論だけをもう一度書いてください。

【条件】
- 商品単価: 12,000円、数量: 8個
- 数量が5個以上の場合、商品代金全体に10%の数量割引が適用される
- 送料は一律1,200円(割引対象外)
- 割引後の金額に対して消費税10%を加算する

ステップバイステップで考えてから答えてください。
```

※GPT-5のreasoningモードやClaudeのExtended thinkingなど、推論モードを使っている場合は最後の「ステップバイステップで考えてから答えてください」は基本的に不要(内部で自動的に行われるため)。まず出力に途中式が自然に含まれるか試し、含まれない・精度が不安なときだけ明示的なCoT指示を足すとよい。

### ツール横断の対応付け(2026年7月時点)

| 概念 | 主なツールでの扱い |
|---|---|
| Zero-shot / Few-shot | すべてのチャットAIで、プロンプト本文に直接書き込めば追加設定なしで使える |
| CoT(明示的指示) | 非推論モードのChatGPT(GPT-4o系など)、Claude(Sonnet/Haikuの非thinking利用時)、Geminiの非thinkingモデルで有効 |
| 内部CoT(自動) | ChatGPTの推論モデル(o系・GPT-5のreasoningモード)、Claudeの「Extended thinking(拡張思考)」、Geminiの「thinking」モデルが自動で実行。UI上ではモデル選択や「Thinking」トグルで切り替える |

## 注意点・よくある誤解

- **Few-shotの例は多いほど良いわけではない**: 目安は3〜5例。それ以上増やすと、モデルが例のパターンに過剰に引っ張られたり、プロンプトが長くなって肝心の指示がぼやけたりする。3つの多様な良い例の方が、10個の似たような例より効く。
- **推論モデルに明示的なCoT指示を重ねると逆効果になることがある**: OpenAIは公式ガイドでo1系・GPT-5のreasoningモードに対して「ステップバイステップで考えて」等の指示を避けるよう案内しており、性能が落ちる例も報告されている。まず素のZero-shot/Few-shotで試し、精度が足りない場合のみCoT指示を足す、という順番が安全。
- **CoTで出力される「思考過程」を鵜呑みにしない**: 途中式や理由づけが表示されても、それが実際の内部処理を正確に反映しているとは限らない。特に金額計算や法的判断など実害のある場面では、最終結論を人が検算・確認するプロセスを省略しない。
- **Few-shotの例に機密情報の実データをそのまま使わない**: 例として社内の実際の顧客名・金額などを貼り付けると、それ自体が情報漏えいリスクになる。ダミーデータに置き換えてから使う。
- **「Zero-shotで十分か」を確認せずにいきなり凝った例を作り込まない**: シンプルな依頼にFew-shotやCoTを盛り込むと、かえって回りくどい出力になることがある。困りごとが実際に起きてから技法を足す方が効率的。

## 最初の一歩

日常的に使っているプロンプトを1つ選び、望ましい入出力のペアを2つだけ書き加えて(Few-shot化して)、同じ依頼をもう一度投げてみる。出力形式やトーンがどれだけ安定するかを比べてみるとよい。
