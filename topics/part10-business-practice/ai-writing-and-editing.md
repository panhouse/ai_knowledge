# ChatGPTを使った文章作成・編集のコツ

## これは何か

ChatGPTにメールや議事録、提案書の下書きを頼んでも、「なんとなく正しいが、そのままは使えない」文章しか出てこないことが多い。これは指示に「誰宛か」「どんな文体か」「どのくらいの長さか」「どんな形式か」が入っていないために起きる。業務文書の作成・編集でChatGPT(やClaude、Geminiなど他の生成AI)を使いこなすコツは、①依頼段階でトーン・読み手・長さ・フォーマットを明示すること、②できあがった文章を校正・推敲・要約・翻訳などの「編集プロンプト」で仕上げること、③自分らしい文体を学習させて毎回の指示を減らすこと、の3点に尽きる。

## 仕組み・背景

ChatGPTのような大規模言語モデル(LLM)は、指示文(プロンプト)に含まれる情報だけを手がかりに次に続く単語を予測して文章を生成する。プロンプトに「誰に」「何のために」「どんな形で」という条件が書かれていなければ、モデルは学習データの中でもっとも「平均的」な書き方を選ぶ。その結果、当たり障りのない敬語文や、箇条書きと段落が混在した読みにくい構成になりやすい。

逆に、プロンプトに以下の4要素を入れると出力の質が大きく変わることが、プロンプトエンジニアリング(AIへの指示文を設計する技術)の実務でよく知られている。

- **トーン(文体)**: 「丁寧なビジネス文体」「カジュアルだが失礼のない社内向け」など
- **読み手**: 「取引先の部長」「同じ部署の若手メンバー」など、相手の立場・前提知識
- **長さ**: 「3行以内」「A4半分程度」など具体的な目安
- **フォーマット**: 「見出し+箇条書き」「表形式」「メールの本文のみ(件名・宛名も含む)」など

プロンプトの型そのものについては[プロンプトの基本構成要素](../part04-prompt-engineering/prompt-basic-structure.md)で詳しく扱っているので、まずそちらで型を身につけ、本ページでは文章作成・編集に特化した実践パターンを扱う。

もう一つの背景として、2026年時点の主要ツールは「チャットで頼んで一括生成」から「文書を横に並べて対話的に編集する」方式へ進化している。ChatGPTの「Canvas」、Geminiの「Canvas」、Claudeの「Artifacts/Projects」はいずれも、生成した文章をその場でハイライトし、「この段落だけ短く」「もっと丁寧な言い回しに」と部分修正できる編集パネルを備える。一括生成で満足せず、こうした編集機能で「叩き台を磨き上げる」工程を前提にすると、成果物の質が安定する。

## 使いどころ・使い分け

生成AIを使うべき場面と、人が最初から書くべき場面を分けるとムダが減る。

| 業務シーン | AIに向く度合い | 理由・使い方 |
|---|---|---|
| 定型メール(依頼・お礼・催促) | 高い | 型が決まっているため、トーンと要件を渡せば一発で使えるレベルになりやすい |
| 議事録・要点整理 | 高い | 発言メモや録音の文字起こしを渡して要約・構造化させるのが得意 |
| 社内報告書・週報 | 高い | 事実(数字・進捗)は自分で用意し、体裁の整形をAIに任せる |
| 提案書・企画書の骨子 | 中程度 | 構成案・叩き台作りには強いが、独自の分析や競合優位性の核心部分は人が詰める |
| 謝罪文・クレーム対応文 | 低〜中程度 | 事実確認と責任の取り方は人が判断すべきで、AIには表現の調整だけを任せる |
| 契約書・法的拘束力のある文書 | 低い | コンプライアンス上のリスクが高く、必ず法務・専門家のレビューが前提になる |

判断基準は「事実確認と最終判断の責任は誰が負うか」で考えるとよい。AIに任せるのは表現・構成・体裁であり、事実そのものの正しさや対外的な責任は最後まで人が持つ、という切り分けが安全である(詳しくは[生成AIに向く業務・向かない業務の切り分け](ai-task-suitability.md)を参照)。

## 実務での使い方

### 1. 依頼段階:トーン・読み手・長さ・フォーマットを必ず入れる

以下のようにテンプレート化して使うと、毎回の指示のブレがなくなる。

```
あなたは経験豊富なビジネス文書のライターです。
以下の条件で[文書の種類]を作成してください。

【読み手】○○様(取引先の担当部長、初対面/面識あり)
【目的】○○
【トーン】丁寧だが堅すぎない、社外向けの標準的な敬語
【長さ】○行程度(または「メール1画面に収まる長さ」)
【フォーマット】件名+本文(挨拶→要点→依頼内容→締めの順)
【必ず入れる情報】○○、○○

伝えたい内容の要点:
- ○○
- ○○
```

### 2. 業務シーン別プロンプト例(コピペ可)

**例1: 取引先へのお詫び・スケジュール変更依頼メール**

```
あなたはビジネスメール作成のプロです。以下の状況で、取引先に送るメールの
件名と本文を作成してください。

状況: 発注いただいた資材の納期が、部材調達の遅れにより1週間遅延する見込み
読み手: 発注元の購買担当者(面識あり、これまで良好な関係)
トーン: 丁寧で誠実、言い訳がましくならないように
長さ: 本文150〜200字程度
フォーマット: 件名/宛名/本文(お詫び→理由を簡潔に→新しい納期→今後の対応)/署名欄は[署名]のままにする

必ず入れる情報:
- 新しい納期: ○月○日
- 代替案として一部先行納品が可能なこと
```

**例2: 会議の文字起こし・メモから議事録を作成**

```
以下は会議中に取ったメモ(発言の断片)です。これを議事録の形式に整理してください。

出力フォーマット:
1. 会議名・日時・参加者(不明な項目は「未記入」と表示)
2. 決定事項(箇条書き、3行以内で1項目)
3. ToDo(担当者・期限をわかる範囲で明記。不明な場合は「(要確認)」と付記)
4. 次回までの懸案事項

注意事項:
- 憶測で発言者や数値を補わないこと。メモにない情報は「(要確認)」と記載する
- 敬体(です・ます調)で統一する

メモ:
[ここに文字起こし・メモを貼る]
```

**例3: 社内向け提案書の骨子(アウトライン)作成**

```
新規ツール導入(生成AIの業務利用拡大)についての社内提案書の骨子を作成してください。

読み手: 部長・情報システム部門(コスト対効果と運用リスクを重視する層)
目的: 稟議に進める前段階の検討材料として、まず骨子レベルの合意を得たい
トーン: 客観的・簡潔、感情的な表現は避ける
フォーマット: 見出し+箇条書き。各見出しに2〜3行の要点メモを添える
構成: 背景/課題/提案内容/期待効果(数値化できるものは仮の数値でよいと明記)/
      コスト・リスク/導入スケジュール(案)

現状わかっている情報:
- ○○
- ○○
※骨子作成の段階なので、詳細な数値やデータは後で自分が補うことを前提にしてください
```

### 3. 既存の文章を編集させる:校正・推敲・トーン変更・要約・翻訳

一括生成よりも「元の文章を渡して直させる」使い方の頻度が高い業務では、以下のパターンが有効。

- **校正(誤字脱字・文法)**
  ```
  以下の文章の誤字脱字・文法・表記ゆれ(半角/全角、送り仮名など)だけを修正してください。
  内容や言い回し、文体は変更しないでください。修正箇所は変更前→変更後の形で別途リストアップしてください。

  [文章を貼る]
  ```
- **推敲(冗長さ・わかりやすさの改善)**
  ```
  以下の文章を、意味を変えずにもっと簡潔で伝わりやすい文章に推敲してください。
  一文が長い箇所は分割し、同じ内容の繰り返しは削除してください。

  [文章を貼る]
  ```
- **トーン変更**
  ```
  以下の文章を、[社内向けのカジュアルな文体/社外向けの丁寧なビジネス文体/
  役員向けの格式高い文体]に書き換えてください。内容と結論は変えないでください。

  [文章を貼る]
  ```
- **要約**
  ```
  以下の文章を、[3行/1段落/50字]で要約してください。
  数値や固有名詞は削らずに残してください。

  [文章を貼る]
  ```
- **翻訳(意訳よりニュアンス重視)**
  ```
  以下の日本語のビジネスメールを、[英語/中国語]の同業種・同レベルのビジネス文書として
  自然な表現に翻訳してください。直訳ではなく、相手国のビジネス習慣に合った言い回しに
  調整してください。文化的に不自然になる比喩表現があれば別途指摘してください。

  [文章を貼る]
  ```

### 4. ツール横断の対応付け(編集パネル機能)

| やりたいこと | ChatGPT | Gemini | Claude |
|---|---|---|---|
| 文書を横に並べて対話的に編集 | Canvas(チャット画面の右にパネル表示。ハイライト選択→編集指示) | Canvas(Gemini アプリ内で起動。クイック編集メニューに「長さを変更」「トーンを変更」あり) | Artifacts(生成物をパネル表示。会話で修正指示を継続) |
| 文体・話し方を毎回指定せず固定する | 設定→パーソナライズ→カスタム指示(Custom Instructions) | Gemini アプリの「設定」→「カスタム指示」に近い項目 | プロジェクトの「カスタム指示」欄、またはプロジェクトの「Knowledge(ナレッジ)」に文体ガイドを登録 |
| 過去のやり取りから好みを覚えさせる | 設定→パーソナライズ→メモリ | Geminiアプリのパーソナライズ機能(過去のやり取りを踏まえた応答) | プロジェクトのナレッジに過去の文章サンプルをアップロードして参照させる |

(Canvasの提供範囲やUI名称は各社のアップデートで変わるため、実際の設定画面の文言は都度確認すること)

### 5. 自分らしい文章を書かせる:カスタム指示・メモリ・スタイルガイドの活用

「AIが書いた感が出る」文章を避けるには、自分の過去の文章を学習させる仕組みを使う。

1. **カスタム指示に文体ルールを書く**(ChatGPTなら設定→パーソナライズ→カスタム指示)
   ```
   ## 私について
   BtoB向けSaaS企業のマーケティング担当。顧客・社内両方にメールを書く機会が多い。

   ## 文章の書き方の好み
   - 一文は60字以内を目安に短く区切る
   - 結論を先に書き、理由・詳細は後に続ける(結論優先)
   - 「させていただく」の多用は避け、「いたします」「します」で言い切る
   - 絵文字・過度な感嘆符は使わない
   - 箇条書きを使う場合は「・」ではなく「-」を使う
   ```
2. **過去に自分が書いた文章のサンプルを3〜5本読み込ませ、スタイルを抽出させる**
   ```
   以下は私が過去に書いたメール・報告書のサンプルです。
   これらの文章に共通する文体上の特徴(語彙、文の長さ、敬語のレベル、
   構成の型など)を分析し、「私の文体ガイド」として箇条書きでまとめてください。

   [サンプル1]
   [サンプル2]
   [サンプル3]
   ```
   出てきた文体ガイドをカスタム指示やプロジェクトのナレッジに登録しておけば、以後は毎回そのスタイルで生成される。
3. **プロジェクト/GPT機能を使って業務別に指示を分ける**
   ChatGPTの「マイGPT」やClaudeの「プロジェクト」を業務ごと(社外向けメール用/社内報告用など)に分けて作成し、それぞれのカスタム指示欄に上記の文体ガイドと業務特有のルール(署名フォーマットなど)を登録すると、都度の指示が不要になる。

## 注意点・よくある誤解

- **生成された文章をそのまま送らない**: AIが書いた文章には、不自然な言い回し(「〜することが可能です」の多用など機械的な表現)、実在しない制度名・法令名、実際とは異なる社内用語が混じることがある。特に社外に出す文書は、送信前に必ず人が事実確認と読み通しを行う工程を挟む。生成AIは「誤るもの」という前提を運用ルールとして明文化し、重要な意思決定・対外文書・契約・法務判断など高リスク領域では、レビューを通らない生成物は外部に出さない、という運用が推奨されている。
- **コンプライアンス表現の誤りに注意**: 「絶対に」「必ず効果が出ます」といった誇大表現、景品表示法や薬機法などに抵触しうる言い回しをAIが自然に生成してしまうことがある。業種特有の禁止表現・必須の免責文言は、プロンプトの段階で明示的に禁止・指定しておくか、送信前チェックリストで拾う。
- **機密情報の入力に注意**: 校正や要約のために社内文書をそのまま貼り付けると、取引先名・未公表の数値などの機密情報が外部サービスに送信される。法人向けプラン(入力データを学習に利用しない設定のもの)の利用や、機密情報を伏せ字にしてから貼るなどの工夫が必要。
- **「要約させる」と情報が抜け落ちる**: 数値や固有名詞、条件(期限・金額など)は要約時に削られやすい。プロンプトで「数値・固有名詞は必ず残す」と明示するか、要約後に元文章と数値を照合する。
- **トーン変更だけでは信頼性は上がらない**: 文体を丁寧にしても、内容の正確性は保証されない。トーン変更・推敲は「表現の調整」であり、事実確認とは別工程であることを忘れない。
- **カスタム指示・メモリは万能ではない**: カスタム指示やメモリに登録した内容も、長文の生成では途中で反映が薄れることがある。重要な文書では、生成後に「文体ガイドの通りになっているか」を目で確認する。

## 最初の一歩

次にAIにメールや報告書を書かせるとき、依頼文の中に「読み手」「トーン」「長さ」「フォーマット」の4項目を必ず一言ずつ入れて試してみる。それだけで出力の使い勝手が大きく変わることを体感できる。
