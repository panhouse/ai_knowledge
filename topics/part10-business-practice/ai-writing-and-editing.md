# 生成AIによる文章作成・編集の実務

## これは何か

ビジネスメール、報告書、提案書、議事録、社内文書のトーン調整など、日々の「文章を書く・直す」業務は生成AIが最も得意とする領域のひとつである。ゼロから文面を考える時間や、硬い文章を柔らかく直す作業、長い会議の録音・メモを整形する手間を、AIに下書きさせて人が仕上げる形に置き換えられる。ただし「何でも丸投げできる」わけではなく、下書き作成・推敲・要約は非常に強い一方、交渉の機微や法的な文言は人の判断が欠かせない。どのタスクをどこまで任せるかの見極めが、実務で品質を落とさずに時短する鍵になる。

## 仕組み・背景

生成AI(大規模言語モデル)は、大量の文章から「自然な文の続き方」を学習しており、既存の文章を別の形に変換する作業(要約する、トーンを変える、体裁を整える)を得意とする。入力された文章という「手がかり」があるほど、出力は元の情報に忠実になりやすい。

逆に、手がかりが少ない「ゼロから何かを生み出す」依頼では、AIは学習データにありがちなパターン(当たり障りのない言い回し、抽象的な美辞麗句)で空白を埋めようとする。これが、AIが書いた文章が「それっぽいが中身が薄い」「AI臭い」と感じられる原因であり、具体的な事実や固有名詞を与えていない箇所ほど、もっともらしい嘘(ハルシネーション)で埋められるリスクも高まる。つまり「編集・要約が得意で、情報の乏しい創作が苦手」という特性は、AIの動作原理そのものに由来する。

## 使いどころ・使い分け

| タスク | AIの得意度 | 理由・注意点 |
|---|---|---|
| 白紙からの下書き作成(メール・報告書・提案書) | ◎(ブリーフ次第) | 誰に・何を・どんなトーンで伝えるかという「ブリーフ」が明確なら高品質。ブリーフが曖昧だと当たり障りのない一般論になる |
| 既存文章の推敲・トーン調整(硬い→柔らかい、口語→敬語など) | ◎ | 最も得意な領域。「直す」対象がすでにあるため、事実を捏造するリスクが低い |
| 長文資料・会議の録音/メモの要約 | ◎ | 大量の非構造化テキストから要点を抜き出す作業はAIの得意分野。ただし数値の抜き出しは原文照合が必要 |
| 交渉文言・クレーム対応など機微なニュアンスが要る文章 | △ | 力関係や過去の経緯を踏まえた「言葉の選び方」は文脈情報が不足しがちで、AI任せにすると失礼・不用意な表現が混じることがある。ドラフトは使いつつ最終文言は人が調整する |
| 契約書・法的拘束力のある文言 | × | 誤った言い回し1つが法的リスクになりうる。ドラフトの叩き台までは有用だが、最終チェックは必ず法務・専門家が行う |
| 特定の社内文体・過去の資料のトーンに厳密に合わせる | △→◎(要例示) | 指示だけで「弊社らしい文体」を再現するのは難しい。過去の文書を2〜3例示す(few-shotプロンプティング、[Zero-shot/Few-shotプロンプティング](../part04-prompt-engineering/zero-shot-and-few-shot-prompting.md)参照)ことで精度が大きく上がる |

タスクを「AIに向くか」で仕分ける一般的な考え方は[生成AIに向く業務・向かない業務の切り分け](./ai-task-suitability.md)を参照。文章作成・編集はこの中でも特に「AIに向く」側に寄っているタスク群だが、上表の△・×に当たる部分は個別に人の目を入れる前提で使う。

## 実務での使い方

### コピペで使えるテンプレート1: 業務メールの下書き(役割・相手・トーン・制約)

```
あなたは[役割: 例 "取引先対応を担当する営業担当者"]です。

【背景】
[状況を2〜3行で: 例 "先方から納期を1週間前倒ししてほしいという相談があった。
社内調整は可能だが、追加の人員コストが発生するため、有償対応になる旨を伝えたい"]

【宛先・関係性】
[例: 取引先の窓口担当者。長年の付き合いがあり、カジュアルすぎない丁寧な関係"]

【伝えたいこと(要点を箇条書きで)】
- [要点1: 例 "前倒し自体は対応可能"]
- [要点2: 例 "追加費用として◯万円が発生する"]
- [要点3: 例 "今週中に可否の返事がほしい"]

【トーン・制約】
- 文字数: [例 300〜400文字]
- トーン: [例 丁寧だが率直、遠回しにしすぎない]
- NG表現: [例 過度な謝罪表現は不要]

【出力形式】
件名と本文を分けて、そのままメールに貼り付けられる形式で出力してください。
```

### コピペで使えるテンプレート2: 箇条書きメモ→正式な議事録

```
以下は会議中に取ったメモ(箇条書き・話し言葉混じり)です。
これを正式な議事録の形式に整えてください。

【会議情報】
- 会議名: [例 "第3回 新商品企画会議"]
- 日時: [例 "2026年7月5日 14:00-15:00"]
- 参加者: [例 "山田(進行)、佐藤、鈴木"]

【メモ】
[ここに箇条書きメモや発言の走り書きを貼り付ける]

【出力ルール】
- 「決定事項」「懸案事項(ToDo・担当者・期限)」「次回までの宿題」の3セクションに分ける
- 発言は要約し、話し言葉(「〜っすね」等)は正式な書き言葉に直す
- メモに書かれていない数値や決定事項を勝手に補わない。不明な点は「(要確認)」と明記する
```

### コピペで使えるテンプレート3: 文章のリライト(簡潔・フォーマル・柔らかいトーンなど)

```
以下の文章を、[指示: 例 "同じ内容を保ったまま、3分の2程度の文字数に圧縮し、
より丁寧なビジネス敬語に書き直して"]ください。

【元の文章】
[ここに直したい文章を貼り付ける]

【守ってほしい条件】
- 事実関係・数値は変更しない
- 元の文章にない情報を新たに付け加えない
- [その他の指示: 例 "箇条書きは維持する" "結論を先に述べる"]
```

### 「役割」を与えるとトーンが揃う

プロンプトの冒頭で「あなたは丁寧なカスタマーサポート担当です」のように役割(ロール)を与えると、AIは語彙選択や敬語の丁寧度、謝罪表現の頻度などをその役割に合わせて調整する。役割に加えて「誰に向けて」「何のために」書くのかという相手・目的の情報を添えると、さらにトーンが安定する。この「役割・目的・相手」を含めたプロンプトの型は[プロンプトの基本構成要素](../part04-prompt-engineering/prompt-basic-structure.md)で扱っているRACE・CO-STARのフレームワークと同じ考え方であり、文章作成・編集でも土台として使える。

### ツール横断の対応付け(2026年7月時点)

| ツール | 該当機能 | 特徴・設定場所 |
|---|---|---|
| ChatGPT | ライティングブロック(旧Canvas) | 2026年5月のGPT-5.5系モデルへの刷新に伴い、従来の左右分割ウィンドウ形式から、チャット画面内に直接展開される「ライティングブロック」に変更。ブロックをクリックして編集案の依頼、文章量の調整、読解レベルの変更などのショートカットを使える |
| Google Docs(Gemini) | 「ヘルプ ミー ライト(Help me write)」/文体を合わせる | 画面下部のバーやサイドパネルからGeminiに指示を出し、文書内の編集や新規ドラフト生成が可能。「文体を合わせる(Match writing style)」機能で、既存文書の書式・トーンを再現できる |
| Microsoft Word(Copilot) | Copilot in Word | 指示文を入力するだけで空白ページからドラフトを生成。既存のファイル・メール・会議記録を最大20アイテムまで参照して文書を生成できる |
| Microsoft Outlook(Copilot) | 返信の下書き作成・要約 | 受信メールの要約、返信メールの下書き、長いスレッドの要点抽出に対応。メール本文からCopilot Chatへ文脈を渡すこともできる |

## 注意点・よくある誤解

- **具体性がないと「AI臭い」文章になる**: 固有名詞・数値・エピソードなど具体的な情報を与えずに書かせると、当たり障りのない一般論で埋められがちになる。「弊社の強みを書いて」ではなく、実際の実績・数値・エピソードをプロンプトに含めることで、読み手に刺さる文章になる。
- **書いていない事実を勝手に補われることがある**: 背景情報が足りない部分を、AIがもっともらしい数値や固有名詞で埋めてしまうことがある(ハルシネーション)。特に金額・日付・固有名詞は、AIの出力を鵜呑みにせず必ず原文・事実と突き合わせる。詳しくは[生成AIのハルシネーション対策](../part03-risk-security/hallucination-countermeasures.md)を参照。
- **外部向け・法的意味を持つ文章は必ず人が最終確認する**: 顧客向けメール、プレスリリース、契約に関わる文言などは、AIのドラフトをそのまま送らず、事実誤認・失礼な表現・法的リスクがないかを人が最終チェックしてから送付・公開する。
- **社外秘の情報を貼り付けて下書きさせるリスク**: 実在の顧客名・未公表の数値・契約条件などをそのままプロンプトに入力すると、利用するサービスの設定次第では情報が外部に渡るリスクがある。入力前に匿名化する、法人向け契約(学習に使われない設定)のツールを使うなど、[生成AI利用における情報漏洩対策](../part03-risk-security/information-leakage-prevention.md)に沿った運用が必要。

## 最初の一歩

自分が繰り返し書いているメールの型を1つ選び(例: 見積回答、催促、お詫び)、本ページのテンプレート1を参考に「役割・背景・相手・トーン・制約」を埋めた自分専用のプロンプトを1つ作ってみる。うまくいったら、ChatGPTのカスタム指示やGeminiのGemなどに保存し、次回から使い回せるようにする。
