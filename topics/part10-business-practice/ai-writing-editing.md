# 生成AIによる文章作成・編集の実践

## これは何か

[生成AIに向く業務・向かない業務の切り分け](ai-task-suitability.md)で見た通り、文章作成は生成AIが最も得意とする業務のひとつである。しかし「得意だと知っている」ことと「実際に業務時間を削れる形で使いこなせる」ことの間には距離がある。メールの返信文を毎回ゼロから考える、議事録の走り書きを清書する、長文レポートを要約して上司に共有する——こうした日常的な文章作業は、プロンプトの型さえ押さえれば大きく時短できる。本ページは、文章の「作成」「校正・リライト」「要約」という3つの代表的な場面ごとに、そのままコピペして使えるプロンプト例と実務のコツをまとめる。

## 仕組み・背景

生成AI(大規模言語モデル、LLM)は「次にくる自然な単語・文章」を予測する仕組みで動いており、文法的に整った・自然な流れの文章を作ることを最も得意とする。ビジネス文書の多くは「型」がある程度決まっている(挨拶→要件→依頼→結び、といった構成)ため、この「自然な文章を続ける」能力と相性がよい。

一方で、LLMは学習データに含まれる典型的な表現に引っ張られやすいため、AIに丸投げした文章は「文法的には正しいが、没個性で無難」になりやすいという傾向が研究でも指摘されている。米コーネル大学の研究では、AIで推敲した文章は「文法的には優れているがスタイルは画一的」で、レビュアーから「安全」「平板」「見分けがつかない」と評されたと報告されている。文章作成は生成AIの得意分野ではあるが、「独自性」「説得力」「その人らしさ」が求められる部分は依然として人間の仕事として残る、という前提を持っておくとよい。

## 使いどころ・使い分け

文章まわりのタスクは大きく3種類に分かれ、それぞれプロンプトの組み立て方が異なる。

| ユースケース | 何をAIにやらせるか | プロンプトで重視すること |
|---|---|---|
| **ドラフト生成**(ゼロから書かせる) | 何もない状態から初稿を作らせる | 役割・背景・要点・トーン・出力形式を具体的に与える(曖昧だと当たり障りのない文章になる) |
| **校正・リライト・トーン調整**(既存の文章を直す) | 手元にある文章を直させる | 元の文章をそのまま渡し、「何を変えたいか」(誤字脱字/敬語レベル/読み手)だけをピンポイントで指示する。直してほしくない部分(固有名詞・数値・結論)は明示的に「変えないで」と伝える |
| **要約**(短くする) | 長文を短くまとめさせる | 出力の長さ・粒度(行数/文字数)・構成(箇条書きか段落か)を数値で指定する。「簡潔に」だけでは長さが安定しない |

代表的なタスク例と、それぞれの得意度・コツは次の通り。

| タスク | 得意度 | コツ |
|---|---|---|
| 業務メールの作成・返信案 | ◎ | 「立場」「伝えたい要点」「元メール」の3点を渡すと精度が上がる |
| 社内向け報告書・議事録の整形 | ◎ | 走り書き・文字起こしを渡し、決定事項/ToDo/期限で構造化させる |
| ブログ記事・プレスリリースのドラフト | ○ | 対外公開物は「たたき台」として使い、最終的な事実確認・文体調整は人間が行う |
| 企画書の文章化 | ○ | 箇条書きのメモを渡し、清書・肉付けさせる(ゼロから企画を考えさせるのではなく) |
| 文章の校正・トーン調整 | ◎ | 「誰向けか」(社外/社内/目上)を明示すると敬語レベルが安定する |
| 要約 | ◎ | 行数・文字数・箇条書きか段落かを数値で指定する |
| 翻訳・多言語化 | ◎ | 直訳ではなく「読み手」を指定すると自然な訳文になる(社内資料向け/顧客向けなど) |
| キャッチコピー・タイトル案出し | ○ | 「複数案を出させて選ぶ」用途に向く。1発で正解を出させようとしない |

## 実務での使い方

### コピペで使える実例1: ビジネスメールの返信案

```
以下のメールに対して、丁寧だが簡潔なビジネスメールで返信案を作成してください。

【私の立場】プロジェクトの発注元企業の担当者
【伝えたい要点】
- 納期を1週間延ばしてほしいという依頼は受け入れる
- ただし、次回以降は早めの相談をお願いしたい
- 追加費用は発生しない前提で進めたい

【元メールの本文】
(ここに相手からのメール本文を貼り付ける)

【出力形式】
件名と本文を分けて、そのままメールに貼り付けられる形式で出力してください。
```

「立場」「要点」「元メール」の3点を渡すのが基本形。要点を箇条書きで渡すと、AIが勝手に話を盛ったり要点を落としたりする事故が減る。

### コピペで使える実例2: 議事録の整形

```
以下は会議中に取ったメモ(走り書き)です。読みやすい議事録の形式に整えてください。

【出力形式】
- 見出し: 会議名・日時・参加者(メモから読み取れる範囲でよい)
- 「決定事項」「未決事項」「ToDo(担当者・期限つき)」の3つの箇条書きセクションに分ける
- 話し言葉は書き言葉に直すが、数値・固有名詞・結論はメモの内容を変えないこと
- メモに書かれていない情報を推測で補わないこと

【メモ本文】
(ここに走り書き・文字起こしを貼り付ける)
```

「メモにない情報を補わない」の一文は、ハルシネーション(もっともらしい誤情報の生成。詳細は[ハルシネーションの仕組みと対策](../part03-risk-security/hallucination-countermeasures.md)を参照)を防ぐために重要。議事録は決定事項の証跡になる文書なので、AIが気を利かせて補完した内容が紛れ込むと後で困る。

### コピペで使える実例3: 校正・トーン調整

```
以下の文章を、社外のお客様向けに丁寧な言葉遣いに直してください。
誤字脱字も修正してください。

【条件】
- 結論や数値、固有名詞は変更しないこと
- 過度にへりくだった表現にはしないこと(丁寧さと簡潔さのバランスを取る)
- 修正箇所が分かるよう、変更点を簡単に補足してください

【文章】
(ここに直したい文章を貼り付ける)
```

「誰向けに直すか」(社外のお客様/社内の上司/カジュアルな同僚向けなど)を必ず書く。これを省くと、AIは無難な「当たり障りのない丁寧語」に寄せがちで、意図した距離感にならないことが多い。

### コピペで使える実例4: 長文の要約

```
以下の文章を、箇条書き3行で要約してください。
それぞれ1行40文字程度、結論から書いてください。
数値やデータが含まれる場合は要約に残してください。

【文章】
(ここに要約したい長文を貼り付ける)
```

「3行で」「40文字程度で」のように長さを数値で指定するのがコツ。「簡潔に」「短めに」だけでは、AIが出す分量が毎回ぶれる。

### 応用: 翻訳・多言語化とキャッチコピー案出し

翻訳は「直訳」ではなく「読み手」を指定すると自然な訳文になる。

```
以下の日本語の文章を英語に翻訳してください。
読み手は海外拠点の非日本語ネイティブの同僚です。
直訳ではなく、ビジネスメールとして自然な英語表現にしてください。
社内特有の略語(例: ○○)は、初出時に簡単な説明を加えてください。
```

キャッチコピーやタイトルは、1案に絞らせず複数案を出させて人間が選ぶ使い方が向いている。

```
新商品「(商品名)」のキャッチコピー案を10個出してください。
ターゲットは(想定読者)、トーンは(例: 親しみやすく、専門用語は使わない)。
1案につき20文字以内で、それぞれ狙いを一言添えてください。
```

### コツ: いきなり完成品を求めず、2段階で作らせる

長めの文章(報告書・ブログ記事・企画書など)をいきなり「完成した文章」として書かせると、構成が的外れになったときの手戻りが大きい。まず箇条書きの構成案を作らせ、それを確認・修正してから本文を肉付けさせる2段階アプローチが実務的。

```
# ステップ1: まず構成案だけ
「(テーマ)」についてのブログ記事の構成案を、H2見出し5〜7本の箇条書きで
作成してください。本文はまだ書かないでください。

# (構成案を確認・修正した上で)
# ステップ2: 承認した構成案をもとに本文を執筆
先ほどの構成案の通りに、各見出しにつき300文字程度で本文を執筆してください。
```

### 文体・トーンのブレを減らす、社内用語を教えておく

「トーンを指定するとブレが減る」「社内特有の言い回しを事前に教えておく」というのは文章作成全般に効くコツで、プロンプトの型そのものについては[プロンプトの基本構成要素](../part04-prompt-engineering/prompt-basic-structure.md)にまとめている。毎回同じトーン・社内用語を指定するのが面倒な場合は、カスタム指示やプロジェクトの指示に登録しておくと以後自動的に反映される([ChatGPTの初期設定とデータ利用のオプトアウト](../part02-chatgpt-basics/chatgpt-initial-setup-and-opt-out.md)のカスタム指示の記入例を参照)。

### ツール横断の対応付け: 長文を「編集し続ける」ためのワークスペース機能

チャット欄への貼り付け・コピペを繰り返すのではなく、生成した文章そのものを画面上で直接編集したい場合は、各ツールの専用ワークスペース機能が使える。

| ツール | 機能名 | 特徴 |
|---|---|---|
| ChatGPT | Canvas | 生成した文章を右側のパネルで直接編集できる。文字数調整・難易度調整などのワンクリック編集ツールあり |
| Claude | Artifacts | 生成物を独立したパネルに表示。文章そのもののピンポイント編集より、まとまった単位での再生成向き |
| Gemini | Canvas | ドキュメント・スライド・コードを生成し、Google ドキュメント/スライドへ直接書き出せる |
| Microsoft Copilot | Word内のCopilot(下書き機能) | Word文書内で直接ドラフト生成・書き換えを行える |

## 注意点・よくある誤解

- **AIが書いた文章は「無難だが個性がない」傾向がある**: 生成AIは学習データの典型的な表現に寄りやすく、文法的には正しくても画一的・平板になりやすいことが研究で指摘されている。対外的に出す重要な文書(プレスリリース、提案書、ブランドメッセージなど)ほど、AIの初稿をそのまま出さず、人間が個性・説得力を足す推敲工程を挟む。
- **AIが作った文章をそのまま送らない**: 議事録の要約に元のメモにない内容が混ざる、メールの返信案が事実と異なる金額・日付を書いてしまう、といったハルシネーションは文章生成でも起こりうる。特に数値・固有名詞・日付は必ず人間が原文と突き合わせて確認する(詳細は[ハルシネーションの仕組みと対策](../part03-risk-security/hallucination-countermeasures.md))。
- **機密情報を含む文章をそのまま外部サービスに貼り付けるリスク**: 未公開の契約条件、顧客の個人情報、社外秘の企画内容などを含む文章を校正・要約させる際は、利用しているサービスが法人契約か、学習利用オプトアウトが有効かを確認する。詳細は[生成AI利用における情報漏洩対策](../part03-risk-security/information-leakage-prevention.md)を参照。
- **著作権・オリジナリティへの配慮**: AIが生成した文章表現が既存の著作物の言い回しに酷似してしまうことがある。対外公開する文章(記事・広告コピーなど)は、生成後に類似コンテンツがないか軽く確認し、最終的な文章としての権利関係・オリジナリティは自社の責任で担保する。

## 最初の一歩

次に書く定型的なビジネスメールを1通、自分でゼロから書く代わりに、本ページの「実例1」のプロンプトをコピペしてAIに下書きを作らせ、自分は事実確認とトーン調整だけに時間を使ってみる。
