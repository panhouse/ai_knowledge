# 営業職における生成AI活用

## これは何か

営業という仕事は、「商談前の下調べ」「提案書・見積もりの準備」「商談そのもの」「商談後のお礼・フォロー」「CRM/SFA(顧客関係管理・営業支援システム)への入力とパイプライン管理」という一連の業務フローの繰り返しでできている。この一日・一週間のフローのどこにAIを差し込むかが分かっていないと、「メールの下書きだけ」「議事録の要約だけ」という部分的な使い方にとどまり、営業活動全体の時短にはつながらない。Salesforceが2025年8〜9月に営業担当者4,050人を対象に行った調査では、営業組織の87%が何らかの形でAIを利用しており、AIエージェントを導入済みの担当者は54%、2027年までに導入予定の担当者を合わせると9割近くに達する。本ページは、汎用チャットAIによる文章作成のコツ([生成AIによる文章作成・編集の実務活用](../part11-business-practice/ai-writing-and-editing.md)で扱う一般論)ではなく、**営業という職種特有の業務フローに沿って、どのフェーズでどのAIをどう使うか**を整理する。

## 仕組み・背景

営業の現場で使われている「AI」は、実は性質の異なる3種類が併存している。使い分けを誤ると「なぜこのツールでこれができないのか」と混乱しやすいので、まず区別しておく。

1. **汎用チャットAI(ChatGPT・Gemini・Claude等)**: 企業リサーチの壁打ち、提案書・メールの下書き、議事録の要約など、テキスト生成・要約が得意。自社のCRMデータには直接アクセスしないため、顧客情報は基本的に手動でコピペして渡す必要がある(その分、情報漏洩リスクの管理は利用者側の注意が必要)。
2. **SFA/CRM組み込みのAIエージェント(SalesforceのAgentforce/Einstein、HubSpotのBreeze、Microsoft Copilot for Sales等)**: 自社の顧客データ・商談履歴・メール履歴を根拠(グラウンディング)にして動く点が汎用チャットAIとの決定的な違い。案件の次のアクション提案、フォローメールの自動生成、CRMレコードの自動更新、受注確度の予測などを、システムの中に組み込まれた状態で行う。
3. **商談解析(Conversation Intelligence)ツール(海外ではGong・Chorus、国内ではamptalk・MiiTel・ACES Meet・JamRoll等)**: Web会議や電話・対面の商談を録音し、音声認識で文字起こしした上でAIが要約・トピック抽出・トークの良し悪しの分析を行い、その結果をCRM/SFAやSlack・Teamsに自動連携する。商談中〜商談直後の「営業担当が手入力しなくてもCRMが埋まる」体験を作っているのはこのカテゴリのツールである。

この3種類は競合ではなく補完関係にあり、実務では「汎用チャットAIで下調べ・下書きを作り」「商談解析ツールで会話記録とCRM入力を自動化し」「SFA組み込みAIでパイプライン全体の優先順位付けをする」という組み合わせで使われることが多い。

## 使いどころ・使い分け

### 営業の業務フェーズ別 AI活用マップ

| フェーズ | やること | 向いているAIの種類 | 具体例 |
|---|---|---|---|
| ① 商談準備 | 企業リサーチ、想定される経営課題の仮説出し、想定質問の洗い出し | 汎用チャットAI(Deep Research機能) | ChatGPT/Gemini/ClaudeのDeep Research([生成AIによる情報収集・リサーチの実務活用](../part11-business-practice/ai-research-and-information-gathering.md)参照)、Web検索連携チャット |
| ② 提案書・見積もりのたたき台作成 | 課題整理→提案内容→効果→価格の骨子作成 | 汎用チャットAI | ChatGPT/Gemini/Claude、Copilot in Word。文章としての磨き込みは[生成AIによる文章作成・編集の実務活用](../part11-business-practice/ai-writing-and-editing.md)の校正テンプレートに委ねる |
| ③ 商談中 | 会話の自動文字起こし、トークスクリプト・製品情報のリアルタイム表示 | 商談解析ツール | amptalk、MiiTel、Gong、Zoom AI Companion等のリアルタイム文字起こし |
| ④ 商談直後 | 議事録の要約、決定事項・懸念点・ネクストアクションの抽出 | 商談解析ツール、汎用チャットAI | amptalk/MiiTelの自動要約、または録音の文字起こしをChatGPT等に貼って要約 |
| ⑤ フォロー | お礼メール・フォローメールの下書き、送信タイミングの提案 | 汎用チャットAI、SFA組み込みAI | Salesforce Agentforce/Einsteinのメール自動生成、HubSpot Breeze、ChatGPT/Gemini/Claude |
| ⑥ CRM入力・パイプライン管理 | 商談内容のCRM自動反映、案件の優先度付け・受注確度予測 | SFA組み込みAI、商談解析ツール | Salesforce Einstein Forecasting、Microsoft Copilot for SalesのVoice to CRM notes、amptalkのCRM自動連携 |
| ⑦ 育成・トークの改善 | 商談前のロールプレイ練習、過去商談のトーク分析によるフィードバック | 商談解析ツール、AIロープレツール | amptalk coach、アバトレ、生成AIによる「AIが営業役・利用者が顧客役」のリバースロープレ |

判断の目安は、「その場面で参照すべき情報が自社の顧客・商談データそのものか」「一般的な文章生成・リサーチで足りるか」の2点。前者ならSFA組み込みAIや商談解析ツール、後者なら汎用チャットAIが向く。

### 使うべきでない場面

- **値引き幅・契約条件の最終的な着地点の決定**: AIは選択肢や相場観の提示までにとどめ、最終判断は営業担当・上長が行う([生成AIに向く業務・向かない業務の切り分け](../part11-business-practice/ai-task-suitability.md)の「個人の人生や企業の命運に直結する最終判断」に該当)
- **重要顧客とのクレーム対応・関係修復が必要な場面**: 相手との関係史や力関係の機微をAIは把握できないため、AIには下書きまでを任せ、言葉選びは人が行う
- **競合の非公開情報や、入手経路が不透明な情報を使った提案**: Deep Research系機能はあくまで公開Web情報が対象であり、それ以上の裏取りが必要な場面では使わない

## 実務での使い方

### コピペで使えるプロンプト1: 商談準備リサーチ(初回商談前)

汎用チャットAIのDeep Research機能(使い方の詳細は[生成AIによる情報収集・リサーチの実務活用](../part11-business-practice/ai-research-and-information-gathering.md)を参照)に投げる、営業の初回商談向けのプロンプト例。

```
あなたはBtoB営業のリサーチ担当です。以下の条件で商談準備リサーチを行ってください。

【商談相手】株式会社(企業名)、業種は(業種)、従業員規模は(規模)
【商談の位置づけ】初回商談(先方の課題感はまだヒアリングできていない)
【調べてほしい項目】
  1. 直近1〜2年の事業内容の変化(新規事業、決算発表、プレスリリースの傾向)
  2. 同業他社と比較した特徴・強み
  3. 公開情報から推測できる経営課題の仮説を3つ(根拠となる情報源も明記)
  4. 想定される決裁フロー・部門構成(IR資料・採用ページ等から推測できる範囲で)
【アウトプット形式】
  - 上記を箇条書きでまとめ、最後に「初回商談で聞くべき質問」を5つ提案
  - すべての主張に出典URLを付ける
【注意】
  - 推測と事実を明確に区別して書く
  - 情報が見つからない項目は「不明」と明記し、無理に埋めない
```

出てきた「経営課題の仮説」と「聞くべき質問」は、そのまま商談前の一次情報として使わず、後述の注意点に従って自分でも一次情報(IR資料・プレスリリース原文)を確認してから商談に臨む。

### コピペで使えるプロンプト2: 提案書の骨子作成

いきなり完成した提案書を書かせるのではなく、まず骨子(構成案)だけを作らせ、確認してから肉付けさせる方が手戻りが少ない(2段階アプローチの考え方は[生成AIによる文章作成・編集の実務活用](../part11-business-practice/ai-writing-and-editing.md)も参照)。

```
以下の情報をもとに、提案書の骨子(見出しと各見出しの要点箇条書き)を作成してください。
本文はまだ書かないでください。

【顧客企業】(企業名)、業種(業種)
【ヒアリングで分かった課題】
- (例: 受注後の事務処理に営業担当の工数がかかりすぎている)
- (例: 商談化率が低く、リード対応が後手に回っている)
【自社が提供できる価値】
- (自社サービス・製品の特徴を箇条書きで)
【提案の温度感】(例: 初回提案。まずは課題の言語化と概算費用感の提示にとどめる)
【構成の希望】
- 現状課題の整理 → 提案内容 → 導入後の効果イメージ → 価格・スケジュール という流れ
- 各見出しにつき3〜5個の箇条書き要点のみ(本文はまだ不要)
```

骨子を確認・修正したら、「先ほどの骨子の通りに、各見出しにつき200〜300文字で本文を執筆してください」と続けて本文を生成させる。

### コピペで使えるプロンプト3: 商談後のフォローメール

```
以下の商談メモをもとに、フォローメールの下書きを作成してください。

【私の立場】(自社名)の営業担当
【商談日時・相手】(日時)、(先方担当者名・役職)
【商談で話した内容】
- (箇条書きで要点)
【先方が示した懸念・保留点】
- (例: 予算確保が来期になる可能性)
【こちらから提示した次のアクション】
- (例: 概算見積もりを1週間以内に送付する)
【トーン】丁寧だが事務的になりすぎない、次の約束を明確にする

【出力形式】
件名と本文を分け、最後に「次回アクションと期限」を1行で明記してください。
```

### コピペで使えるプロンプト4: 議事録・商談録音からのネクストアクション抽出

商談解析ツールの自動要約を使わない場合や、汎用チャットAIで代用したい場合のプロンプト。営業特有の項目(決裁者・予算・導入時期・懸念点)を明示的に指定するのがコツ。

```
以下は商談の文字起こし(または走り書きメモ)です。営業の商談記録として整理してください。

【出力形式】
- 「決定事項」「先方の懸念・保留点」「ネクストアクション(担当者・期限つき)」の3セクション
- 加えて、分かる範囲で以下をそれぞれ1行でまとめる
  - 決裁者・関係者(誰が最終判断者か)
  - 想定予算感
  - 想定導入時期
  - 競合検討の有無
- メモ・文字起こしに書かれていない情報は推測で補わず「不明」と書く

【文字起こし・メモ本文】
(ここに貼り付ける)
```

「書かれていない情報を推測で補わない」という一文は、ハルシネーション(もっともらしい誤情報の生成、詳細は[ハルシネーションとは何か・対策](../part04-risk-security/hallucination-and-countermeasures.md))を防ぐために重要。商談記録は「言った/言っていない」が後でトラブルの種になりやすい文書なので、AIが気を利かせて補完した内容を鵜呑みにしないこと。

### ツール横断の対応付け(2026年7月時点)

| ツール | AI機能名 | できること | 主な設定・起動場所 |
|---|---|---|---|
| Salesforce | Agentforce / Einstein(旧Einstein Copilot) | 自然言語での顧客データ照会、メール・フォローアップ文の自動生成、CRMレコードの自動更新、受注確度予測(Prediction Builder) | Salesforce内のAgentforce Studio、Einsteinメニュー |
| HubSpot | Breeze(Copilot・Agents・Intelligence) | 案件サマリー生成、見込み客への自動アプローチ(Prospecting Agent)、CRMデータの補完 | HubSpotメニュー内のBreeze |
| Microsoft | Copilot for Sales(Dynamics 365 Sales/Outlook・Teams連携) | 商談前ブリーフィングの自動作成、CRMレコードとの自動リンク、音声でCRMメモを残す「Voice to CRM notes」 | Outlook/Teamsのサイドパネル |
| 国内の商談解析(Conversation Intelligence) | amptalk、MiiTel、ACES Meet、JamRoll 等 | Web会議・電話・対面商談の自動文字起こし・要約、CRM/SFA(Salesforce・HubSpot等)への自動入力、トーク分析 | 各ツールの録音連携設定、SFA連携設定 |
| AIロールプレイ | amptalk coach、生成AIによるリバースロープレ(AIが営業役、利用者が顧客役)、アバトレ 等 | 商談シナリオ・顧客ペルソナを設定した反復練習、トーク内容へのフィードバック | 各ツールのトレーニングコース作成画面 |

料金感の目安(要問い合わせのものが多いため、必ず最新の公式情報を確認すること): 国内の商談解析ツールはMiiTelが月額5,980円/ユーザーからと比較的安価な部類で、amptalkなど多機能な製品は要問い合わせが多い。SFA組み込みAI(Agentforce・Copilot for Sales等)は既存のSFA/CRM契約への追加ライセンスやクレジット課金となるケースが一般的で、汎用チャットAIの個人契約(月額2,000〜3,000円程度)とは別枠のコストとして予算化する必要がある。

## 注意点・よくある誤解

- **商談の録音・AI解析には同意と社内ルールの確認が必要**: 商談解析ツールで顧客との会話を録音・AI解析する場合、相手の同意取得や自社の情報管理規定の順守が前提になる。特に個人情報や機密性の高い商談内容を含む場合は、[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md)を必ず確認する。
- **CRM自動入力は「手間の削減」であって「正しさの保証」ではない**: 商談解析ツールやSFA組み込みAIが自動生成した要約・次のアクション・確度予測は、そのまま鵜呑みにせず、重要な案件ほど営業担当・マネージャーが内容を確認する工程を残す。自動入力の便利さに慣れると、誤って記録された内容が後工程(受注予測・人員配置)に影響することがある。
- **SFA組み込みAIの精度は入力データの質に依存する**: CRMの過去データが不十分・不正確なまま(いわゆる「入力が形骸化したCRM」)AIエージェントを導入しても、期待するような提案精度は出ない。AI導入の前提として、日々の入力の質を上げる(あるいは商談解析ツールで自動入力の比率を上げる)ことが効いてくる。
- **汎用チャットAIに顧客の個人情報・契約条件をそのまま貼り付けない**: 提案書のたたき台作成や議事録整理のために、汎用チャットAI(法人契約でない個人アカウント等)に顧客の個人情報や非公開の契約条件を貼り付けるのは情報漏洩リスクがある。自社が契約しているプラン・利用規約(学習利用の有無など)を確認し、機密度の高い情報はSFA組み込みAIなど自社データが保護される環境で扱う。
- **Deep Research系の商談準備リサーチは「仮説」であって「一次情報」ではない**: プロンプト1で紹介したような企業リサーチの結果は、公開情報からの推測を含む。特に「経営課題の仮説」は、商談で確認すべき仮説として使い、断定的な前提として提案書に書き込まない。
- **AIロールプレイは万能な練習相手ではない**: 想定質問やペルソナの幅は設定次第であり、実際の顧客特有の言い回しやクセまでは再現しきれない。新人の基礎練習や想定問答の洗い出しには有効だが、実商談の対人スキルを完全に代替するものではない。

## 最初の一歩

次の商談を1つ選び、プロンプト1(商談準備リサーチ)またはプロンプト3(フォローメール)のどちらかを実際に使ってみて、出てきた内容のうち数値・固有名詞・経営課題の仮説を1つ、自分で原典(IR資料や商談メモ)と突き合わせて確認する。
