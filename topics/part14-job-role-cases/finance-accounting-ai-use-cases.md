# 経理・財務職における生成AI活用事例

## これは何か

経理・財務の仕事は「請求書・領収書の入力」「経費精算のチェック」「月次レポートの作成」など、フォーマットが決まった反復業務が多い一方、扱う数値を1円でも間違えると決算・税務・取引先への支払いに直結するという特殊性がある。生成AIは前者の「入力・下書き作成」を大きく速くできるが、後者の「確定数値」を鵜呑みにすると重大な誤りにつながる。本ページでは、経理・財務の現場で実際に使われている生成AIの活用場面を、AI-OCR(画像や手書き文字をAIで読み取り、テキストデータに変換する技術)による証憑データ化から、予実差異コメントの下書き、契約書レビュー支援まで具体的に整理し、他の職種以上に強く求められる「数値検証」の勘所をまとめる。

## 仕組み・背景

経理・財務業務における生成AI活用は、大きく2つの技術要素の組み合わせで成り立っている。

1. **AI-OCR**: 紙やPDFの請求書・領収書・レシートを画像認識で読み取り、日付・金額・取引先・税率などの項目を自動抽出する技術。近年はレイアウトが毎回異なる自由帳票でも、生成AIの言語理解を組み合わせることで読み取り精度が向上している(freeeは2026年に「AIおまかせ明細取得」機能のβ提供を開始し、PDF明細から仕訳の元データを自動生成できるようにした)。
2. **生成AI(LLM)による文章・分析支援**: 抽出された構造化データ(表形式の数値)を渡し、予実差異のコメント案、決算説明資料のドラフト、契約書の要約などを言語生成させる。ここでの生成AIの役割はあくまで「下書き作成」であり、数値そのものの正しさを保証する仕組みではない。

さらに2026年に入り、freeeの「freee-mcp」やマネーフォワードの「AI Cowork」のように、AIエージェント(人が逐一指示しなくても複数ステップの業務をこなすAI)が会計ソフトのAPI(MCP、Model Context Protocol=AIが外部サービスを操作するための標準規格)を通じて仕訳登録や請求書発行まで直接実行する動きが出てきている。これにより経理業務は「人が入力し、AIが補助する」段階から「AIが実行し、人が承認・監査する」段階へと軸足が移りつつある。

## 使いどころ・使い分け

経理・財務業務は「入力・整形・下書き」と「最終確定・判断」を明確に線引きすることが最重要になる。

| 業務 | AI活用の向き不向き | 理由 |
|---|---|---|
| 請求書・領収書のデータ化(AI-OCR) | 向く(要人の確認) | 定型項目の抽出は得意。ただし誤読は起こりうるため人の目視確認が前提 |
| 経費精算の異常検知(重複申請・金額の外れ値検出) | 向く | パターン検出は得意で、大量データから怪しい申請を洗い出す一次スクリーニングに有効 |
| 予実差異コメントのドラフト作成 | 向く(下書きのみ) | 数値の傾向を言語化する初稿作成は速いが、原因の特定は現場ヒアリングと人の判断が必要 |
| 契約書・請求書の支払条件レビュー(一次チェック) | 向く(一次チェックのみ) | 支払期日・振込先・違約条項など見落としやすい箇所の洗い出しに有効。最終的な法的判断は法務・上長が行う |
| 財務諸表・IR資料の文章ドラフト、英語資料の翻訳下訳 | 向く(下書き・下訳のみ) | 文章化・翻訳のスピードは大きく向上するが、開示前の数値・文言は必ず人が原本と突合する |
| 確定申告書・税務申告書類の最終数値決定 | 向かない | 税務判断・最終責任は人(経理責任者・税理士)が負うべき領域 |
| 与信審査・取引先の支払能力の最終判断 | 向かない | 個社の事情や交渉経緯など属人的要素が大きく、誤判断の影響が大きい |

判断に迷う場合は、Part 11「[生成AIに向く業務・向かない業務の切り分け](../part11-business-practice/ai-task-suitability.md)」の3チェック(入力が構造化されているか/成果物の良し悪しを基準化できるか/反復回数が多いか)に当てはめて仕分けるとよい。経理・財務ではこれに加えて「誤りが金銭の移動・法定書類に直結するか」を4つ目の判断軸として必ず加える。

## 実務での使い方

### 1. 請求書・領収書のAI-OCRデータ化 → 会計ソフトへの取り込み

主要クラウド会計ソフトは、いずれも証憑画像から仕訳を自動生成する機能を持つ。2026年時点の主な機能は次の通り。

| ソフト | 主なAI機能 | 特徴 |
|---|---|---|
| freee会計 | AIデータ化(領収書・請求書の自動仕訳化)、「AIおまかせ明細取得」(β、PDF明細からの自動抽出)、freee-mcp(AIエージェントからfreeeを直接操作するMCPサーバー、2026年3月OSS公開) | 紙の明細読み込み精度99%以上を謳う。ClaudeなどのAIエージェントから会計・請求書・人事労務など約330本のAPIを直接操作できる |
| マネーフォワード クラウド | クラウド給与・クラウド契約などプロダクトごとのAIエージェント機能、2026年7月提供開始予定の「マネーフォワード AI Cowork」(経費精算・請求書発行・仕訳などを自律的に処理するAIサービス) | AI Coworkは曖昧な指示(例:「今月の経理業務をまとめて処理して」)から複数ステップを自律実行する設計 |
| 弥生会計/やよいの青色申告 | 銀行・カード明細からの勘定科目自動推論、過去仕訳の学習による自動補完、「弥生会計Next」の経営相談チャット(β) | 過度な自動化を前面に出さず、アナログな中小企業の実務に段階的に寄り添う方針を明言している |

**手順の目安(freeeの場合)**: 「取引」→「自動で経理」→ 領収書・請求書の画像またはPDFをアップロード → AIが日付・金額・勘定科目候補を提示 → 内容を確認して「登録」。候補が違う場合は手動修正し、修正結果は次回以降の推測精度向上に反映される。

### 2. 予実差異コメントのドラフト作成(コピペ用プロンプト例)

月次・四半期の予実管理表をAIに渡し、差異コメントの初稿を作らせる。ChatGPTやClaude、Copilotなど表データを読み込めるチャットAIで利用できる。

```
あなたは経理財務部門のアナリストです。以下の部門別予実データ(予算・実績・差異額・差異率)を基に、
経営会議で報告する「予実差異コメント」の初稿を作成してください。

# 条件
- 差異率が±10%を超える科目のみコメント対象とする
- 各科目について「差異の方向(増減)」「推定される要因」「次月の見通し」の3点を1〜2文で簡潔に書く
- 数値はすべて入力データの値をそのまま使い、新しい数値を作らない・推測で数値を補わない
- 要因が入力データから読み取れない場合は「要因は現場ヒアリングが必要」と明記する

# データ
[ここに部門別予実データの表をCSVまたはテキストで貼り付け]
```

出てきたコメント案は、あくまで「叩き台」として扱い、要因の部分は必ず担当部門にヒアリングして裏取りしてから経営会議資料に反映する。

### 3. 契約書・請求書の支払条件チェック(コピペ用プロンプト例)

```
あなたは経理部門の契約書チェック担当です。以下の契約書(または請求書)の本文から、
支払いに関わる条件を漏れなく抽出し、表形式でまとめてください。

# 抽出項目
- 支払期日(締め日・支払サイト)
- 振込先口座情報の記載有無
- 支払金額(税込・税抜の別)
- 違約金・遅延損害金の条項の有無と内容
- 自動更新条項の有無と解約予告期限
- 通常の取引条件と異なる特記事項

# 出力形式
項目名 | 契約書に記載の内容 | 気になる点(あれば)

# 注意
- 記載がない項目は「記載なし」と明記し、存在しない条件を推測して埋めない
- 金額・日付は契約書の原文の表記をそのまま引用する
```

抽出結果は一次チェックの土台として使い、最終判断(締結可否・法的リスク)は法務担当・上長の確認を必ず挟む。

### 4. 決算・IR資料の文章ドラフトと英文資料の翻訳

決算説明資料や海外投資家向けIR資料では、生成AIは「数値から文章を作る」「日本語から英語(またはその逆)に翻訳する」下訳・下書き作業に向く。ただし、財務数値そのものは開示前に原本(決算書・試算表)と必ず突き合わせる。翻訳では専門用語(例: 売掛金=accounts receivable、繰延税金資産=deferred tax assets)の対訳統一のため、社内の対訳集や用語集をプロンプトに含めて渡すと表記ゆれを防げる。

### 5. 電子帳簿保存法・インボイス制度への対応で気をつけたいこと

- **電子帳簿保存法**(電子データで受け取った請求書等を一定要件で保存することを義務付ける法律)の観点では、AI-OCRの読み取り結果は「保存用の確定データ」ではなく「仕訳・保存のための下書き候補」として扱う。誤読(日付の取り違え、税率の誤認識、登録番号の一部欠落など)は珍しくないため、確認者・修正手順・修正履歴の残し方を業務ルールとして事前に定めておく。スキャン時の解像度は200〜300dpiが目安とされる。
- **インボイス制度**(適格請求書等保存方式)では、請求書に記載された「適格請求書発行事業者の登録番号」が有効かどうかの確認が必要になる。AI-OCRで登録番号を読み取り、国税庁の「適格請求書発行事業者公表サイト」の情報と突き合わせて有効性を判定する仕組みを持つサービスも増えている(例: LayerXの「バクラクビジネスカード」による登録番号自動判定)。

## 注意点・よくある誤解

- **経理・財務は「数値のハルシネーション」の被害が特に大きい職種**: 生成AIは、それらしい数値や存在しない取引先名・条項をもっともらしく作り出すことがある(ハルシネーション、詳細は「[生成AIのハルシネーションと対策](../part04-risk-security/hallucination-and-countermeasures.md)」を参照)。他の職種であれば誤りに気づいて直せば済むケースでも、経理・財務では「誤った数値のまま決算・申告・支払いが進んでしまう」実害に直結する。AIが出した数値・金額・登録番号・条項は、必ず原本(証憑・契約書・会計帳簿)と突き合わせて検証する運用を徹底する。
- **「AI-OCRを入れれば電帳法対応が完了する」は誤解**: ツールが要件を満たしていても、社内の確認フロー・権限設定・保存ルールが整っていなければ、実運用では抜け漏れが発生する。ツール導入と社内ルール整備はセットで進める。
- **プロンプトに機密の財務データ・未公表決算情報を入力するリスク**: 学習利用のオプトアウト設定や、法人向け・エンタープライズプランの利用など、入力データの取り扱いを事前に確認してから利用する。特に未公表の決算情報や人事データを含む場合は、社内規定で利用可否を明確にしておく。
- **自動仕訳の精度は勘定科目・取引パターンによってばらつく**: 銀行明細・クレジットカード明細では推測精度が比較的高い一方、フォーマットが毎回異なる自由記述の請求書や手書き領収書では誤りが増えやすい。精度が低い証憑の種類を把握し、そこは重点的に人の確認を厚くする。

## 最初の一歩

今月受け取った請求書・領収書を1枚選び、使っている会計ソフトのAI-OCR機能(freeeの「自動で経理」、マネーフォワード クラウドの証憑読み取り機能など)で仕訳候補を作らせ、金額・日付・税率が原本と一致しているかを自分の目で確認してみる。
