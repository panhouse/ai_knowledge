# 人事(HR)職における生成AI活用事例

## これは何か

人事(HR)の仕事は、求人票や社内規程、面談記録、サーベイの自由記述回答など「大量の非構造化テキスト」を扱う一方で、応募者・従業員の機微な個人情報を大量に扱う仕事でもある。この2つの性質のせいで、生成AIは「文書のドラフト作成・要約」には非常に強い援軍になる反面、「採否・評価という人の処遇に直結する最終判断」に使うと差別・法令違反のリスクを一気に抱え込む諸刃の剣になる。本ページは、人事業務のどこにどのツールを当てはめると効果的か、逆にどこでは人の最終確認を外してはいけないかを、業務フェーズ別に整理する。

## 仕組み・背景

パーソル総合研究所の「人事白書2025」系の調査では、人事部門の約7割がすでに何らかの業務で生成AIを活用しており、最も多い活用分野は「議事録・会議内容の要約」(4割超)だという結果が出ている。LINEヤフーは2025年7月に全従業員約1.1万人を対象に生成AI活用を事実上の必須業務とする方針を打ち出し、人事総務領域でも採用データ整理支援や面接官トレーニング、日程調整の自動化など2026年春までに10件のAIツールを順次投入すると発表している。人事業務における生成AI活用は、もはや一部の先進企業の実験ではなく、業務プロセスの標準装備になりつつある段階にある。

技術的には、人事領域のAI活用は大きく2系統に分かれる。

- **汎用チャットAI(ChatGPT/Gemini/Claude/Copilot)によるドラフト生成**: 求人票・面接質問・評価コメントなど、その場でプロンプトを与えて文章を作らせる使い方
- **社内データに基づくRAG(Retrieval Augmented Generation、検索拡張生成。社内文書を検索してから回答を生成する仕組み)チャットボット**: 就業規則・福利厚生・給与規程など、社内の一次情報を参照させて従業員からの問い合わせに答えさせる使い方。SmartHRの「AIアシスタント」やMicrosoft 365 Copilotの「従業員セルフサービスエージェント」がこの型に当たる

どちらの系統でも、人事データは個人情報保護法・職業安定法上の制約を受けるため、「何を入力してよいか」「誰が最終判断するか」を業務設計の段階で決めておく必要がある。

## 使いどころ・使い分け

**生成AIの関与度で見た人事業務の仕分け**

| 関与度 | 業務例 | 理由 |
|---|---|---|
| AIにドラフトを作らせてよい(人が確認・編集して確定) | 求人票・JD(職務記述書)、面接質問案、オンボーディング資料、評価コメントの下書き、サーベイ自由記述の要約 | 誤りがあっても人のレビューで補正でき、最終責任は人事担当者に残る |
| AIは一次対応のみ、複雑案件は人にエスカレーション | 就業規則・福利厚生に関する社内問い合わせ | RAGで一次情報を参照させれば正答率は上がるが、個別事情の判断は人が必要 |
| AIを判断材料の整理に限定し、最終判断は必ず人が行う | 応募書類のスクリーニング、人事評価の確定、懲戒・退職勧奨などの重い決定 | 採否・処遇という「個人の人生に直結する最終判断」にAIを使うと、差別的スクリーニングや職業安定法違反のリスクが生じる |

判断基準はシンプルで、「AIの出力をそのまま処遇に反映してよいか」で線を引く。反映してよいのはせいぜい「一次スクリーニングで明らかに要件を満たさない応募を除外候補として提示する」程度までで、不合格・低評価の最終確定にAI出力を単独で使うことは避けるべきとされている。

## 実務での使い方

### 1. 求人票・JD(職務記述書)のドラフト作成

ChatGPT・Gemini・Claude・Microsoft 365 Copilot(Word)のいずれでも同じ要領で使える。Copilot in Wordは求人広告や職務記述書の作成、応募者ごとのスカウトメール個別化にも使われている。

```
あなたは採用担当の人事です。以下の条件で求人票のドラフトを作成してください。

【募集職種】法人営業(既存顧客深耕・新規開拓)
【必須要件】法人営業経験3年以上、Excelでの数値管理経験
【歓迎要件】SaaS業界での営業経験、チームリード経験
【弊社の特徴】従業員150名のBtoB SaaS企業、リモート可、フレックス制度あり
【トーン】堅すぎず、若手にも読みやすい文体

出力構成: 仕事内容 / 必須要件 / 歓迎要件 / 働き方・制度 / メッセージ(3行程度)
性別・年齢・国籍・家族構成など、職業安定法上使用してはいけない属性に触れる表現がないか
最後にセルフチェックして指摘してください。
```

### 2. 応募書類スクリーニングの「補助」

**方針**: 合否判定そのものをAIに丸投げしない。「応募要件との突合を整理させ、最終判断は人が行う」使い方にとどめる。氏名・性別・生年月日・出身地・写真など、選考基準に含めてはいけない属性はプロンプトに含めない、または匿名化してから投入する。

```
以下は職務要件と、匿名化した応募者の職務経歴(氏名・性別・生年月日等は削除済み)です。
評価や優劣の判定はせず、「職務要件に対して、経歴のどこが合致し、どこが情報不足か」を
箇条書きで整理してください。合否の推奨や点数化はしないでください。

【職務要件】
(必須要件・歓迎要件を貼り付け)

【応募者の職務経歴(匿名化済み)】
(職務経歴書のテキストを貼り付け)
```

### 3. 面接質問の生成

Microsoft 365 Copilotには職務内容から質問と模範解答の観点を生成する「インタビュー質問アシスタント」テンプレートが用意されている。ChatGPT等でも同様のプロンプトで代替できる。

```
以下の職務要件をもとに、一次面接用の質問を8問作成してください。
・経験の事実確認(行動面接的な質問)を4問
・入社後の再現性を確認する質問を2問
・カルチャーフィットを確認する質問を2問
質問ごとに「何を見極めたいか」の意図を1行で添えてください。
年齢・家族状況・結婚予定・信条など、職業安定法上尋ねてはいけない事項は
質問案に含めないでください。

【職務要件】(貼り付け)
```

### 4. オンボーディング資料の作成

入社者向けのウェルカムガイド、初週のスケジュール表、よくある質問集の初稿をChatGPT/Geminiで作成し、実際の社内制度と突き合わせて人事が修正する運用が一般的。既存の資料をアップロードして「新入社員向けにトーンをやわらかく書き換えて」と指示すると初稿の手直しが速い。

### 5. 社内規程Q&Aチャットボット(RAG)

就業規則・福利厚生・経費精算ルールなどの問い合わせ対応は、汎用チャットAIに丸投げするとハルシネーション(事実と異なる内容をもっともらしく生成する現象)のリスクが高いため、社内文書を参照させるRAG型の仕組みが向く。

- **SmartHR「AIアシスタント」**: 管理部門がアップロードした就業規則・マニュアル等を参照し、従業員からの問い合わせにチャット形式で自動回答する機能。導入企業では問い合わせ件数の約2割削減効果が報告されている
- **Microsoft 365 Copilotの従業員セルフサービスエージェント**: Copilot Studioでカスタマイズし、福利厚生・給与・休暇申請などの問い合わせに対応させる
- **自社構築のRAGチャットボット**: Difyなどのノーコードツールで就業規則PDFを読み込ませ、自社専用のQ&Aボットを構築するケースもある(構築方法はPart 10「ノーコード・ローコード開発」、RAGの精度改善はPart 7「RAGの精度改善と基盤」を参照)

### 6. 1on1メモ・人事評価コメントのドラフト支援

カオナビは2025年12月に「AI目標・評価アシスト」機能を提供開始し、SMART原則([S]pecific・[M]easurable・[A]chievable・[R]elevant・[T]ime-bound)に沿った目標設定案の提示や、過去の評価データを踏まえた評価コメント案の生成を行う。同社は2025年2月にも人材データベースの記述内容を生成AIが要約する機能を先行提供している。HRBrainも同様にタレントマネジメント領域でのAI機能を展開している。汎用チャットAIで代替する場合は、1on1の音声メモやメモ書きを要約させ、評価コメントの「たたき台」を作らせた上で、最終的な評価点・コメントは評価者自身が確定する運用が基本になる。

### 7. 従業員サーベイの自由記述分析

エンゲージメントサーベイの自由記述回答は、件数が多いと目視での傾向把握が難しい。ChatGPT/Gemini/Claudeに回答テキストをまとめて読み込ませ、トピックごとの分類と代表的なコメントの抽出をさせると、経営報告用のサマリー作成が大幅に短縮できる。

```
以下は従業員満足度調査の自由記述回答(全120件)です。
1. ポジティブ/ネガティブ/中立に分類し、件数を集計
2. ネガティブ回答を「制度」「人間関係」「業務量」「評価」などのカテゴリに分類
3. 各カテゴリの代表的なコメントを1〜2件、個人が特定できない形で引用
4. 経営会議向けに3行でエグゼクティブサマリーを作成

【回答データ】(貼り付け)
```

### 8. 多言語対応(就業規則・社内文書の翻訳)

外国籍社員向けに就業規則・入社時案内を翻訳する用途は、DeepL翻訳や各チャットAIの翻訳機能が実務でよく使われる。法的拘束力のある文書(雇用契約書、就業規則の正式版)は機械翻訳のみで確定せず、専門家によるチェックを挟むのが原則。

### ツール横断の対応表

| やりたいこと | 主に使うツール |
|---|---|
| 求人票・面接質問・評価コメントのドラフト | ChatGPT / Gemini / Claude / Microsoft 365 Copilot(Word・Loop) |
| 社内規程・福利厚生のQ&A自動応答 | SmartHR AIアシスタント、Microsoft 365 Copilot 従業員セルフサービスエージェント、Dify等での自社RAG構築 |
| 目標設定・評価コメント支援、人材データ要約 | カオナビ「AI目標・評価アシスト」「プロファイルブック要約」、HRBrain のAI機能 |
| 議事録・1on1メモの要約 | ChatGPT / Gemini / Claude / Copilot(Teams議事録要約) |
| 多言語翻訳 | DeepL、各チャットAIの翻訳機能 |

## 注意点・よくある誤解

- **候補者の個人情報の取り扱いが最大の落とし穴**: 職業安定法第5条の5および厚生労働省の関連指針では、人種・民族・社会的身分・本籍・思想信条・労働組合への加入状況など「社会的差別の原因となるおそれのある事項」の収集を原則禁止している。生成AIに応募書類をそのまま読み込ませる際、こうした情報が本文中(出身校の記載から地域が推測できる等)に含まれていないか注意する
- **AIによる自動不採用判定は避ける**: 厚生労働省の職業紹介事業者向けの運用要領は、AIレコメンド機能を設計する際に性別・国籍などを学習データから除外し、バイアスの発生有無を定期的に検証・是正することを求めている。過去に海外の大手企業で、過去10年分の採用データで学習した書類選考AIが女性応募者を系統的に低く評価してしまい、運用を停止した事例もある。自社の過去データにも同種の偏りが含まれている可能性を前提に、AIの提示結果を鵜呑みにしない
- **「最終判断はAIに一任しない」を業務ルールとして明文化する**: 採否・評価・懲戒などの重い決定は、AIの提案を参考情報として扱い、必ず人が最終確認・決定する。判断根拠(なぜ不合格にしたか)を人が説明できる状態を保つことが、後の紛争リスクを下げる
- **無料版・個人契約の生成AIに候補者データを入力しない**: 応募者の履歴書・職務経歴書は個人情報であり、法人契約でオプトアウト設定(入力データを学習に使わない設定)が確認できていないツールに投入すると情報漏洩リスクを負う(詳細はPart 4「生成AI利用における情報漏洩対策」を参照)
- **ハルシネーションによる誤情報**: 社内規程Q&Aボットを汎用チャットAIだけで作ると、存在しない休暇制度や誤った手当額をもっともらしく回答することがある。必ず一次情報を参照させるRAG構成にし、回答に出典(規程の該当箇所)を表示させる
- **AI利用の事前告知**: 選考プロセスにAIを利用していることを応募者に案内していない企業も多いが、透明性確保の観点から利用範囲を明示しておくことが望ましいとされている

## 最初の一歩

まずは個人情報を含まない業務から着手する。今書く予定の求人票か、直近のサーベイ自由記述の要約のどちらかを選び、上記のプロンプト例をコピーして自社の情報に差し替えて試してみる。
