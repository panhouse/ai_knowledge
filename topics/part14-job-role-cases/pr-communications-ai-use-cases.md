# 広報・PR職における生成AI活用事例

## これは何か

広報・PR職の仕事は、プレスリリースの執筆、記者への売り込み(ピッチ)、報道のモニタリング、社内外への情報発信、そして有事の際の危機管理広報まで、「型のある文章を素早く大量に作る」業務と「一つの言葉のミスが会社の信用を左右する」業務の両方を抱えている点が特徴である。前者は生成AIとの相性が非常によく、後者は逆にAIに任せすぎると重大な事故につながる。本ページは、[マーケティング職における生成AI活用](./marketing-ai-use-cases.md)が広告・SNS運用・需要創出を扱うのに対し、プレスリリース・メディアリレーションズ・危機管理広報・IR/社内コミュニケーションという「対外的な信頼構築」を担う広報・PR職に絞って、どこまでAIに任せてよく、どこから先は人が主導すべきかを整理する。

## 仕組み・背景

広報・PR業務に生成AIが浸透している背景には、次の3つの要因がある。

1. **プレスリリースは型が決まっている文章**: タイトル・サブタイトル・リード文・本文・会社概要という構成がほぼ様式化されており、AIが型に沿ったドラフトを安定して生成しやすい。国内の調査では、広報部門の生成AI導入率は37.2%に達しているとされ、世界のPR企業でも4分の1以上がプレスリリース作成にAIを導入している([renue、2026年版](https://renue.co.jp/posts/pr-ai-press-release-sns-media-guide-2026))。
2. **配信プラットフォーム自体がAI機能を組み込み始めている**: 国内最大手の配信サービスPR TIMESは新エディターに「AIアシスタント機能」を実装し、入力した本文の情報からタイトル・サブタイトル・リード文を提案する仕組みを提供している。入力データは暗号化され、AIの学習には使用されない設計になっている([syncAD](https://syncad.jp/news/63193/)、[PR TIMES MAGAZINE](https://prtimes.jp/magazine/pr-generative-ai/))。海外でもメディアデータベース大手のMuck Rackが「Media List Agent」というAIエージェントを2026年2月に投入し、ピッチ内容から関連性の高い記者を最大50名まで自動抽出する機能を提供している(ベータ期間中の実績としてピッチの開封率・クリック率が平均10%向上)([The PR Net](https://theprnet.com/news/42304)、[GlobeNewswire](https://www.globenewswire.com/news-release/2026/02/02/3230434/0/en/muck-rack-launches-media-list-agent-to-power-smarter-pitching.html))。同社の「2026年ジャーナリズム実態調査」では、記者の82%がすでに何らかの形でAIを業務利用しているという結果も出ており、書き手側だけでなく受け手側(記者)のAI利用も前提に置く必要がある段階に来ている([GlobeNewswire](https://www.globenewswire.com/news-release/2026/03/19/3259178/0/en/Muck-Rack-s-2026-State-of-Journalism-Report-Finds-82-of-Journalists-Use-AI.html))。
3. **一方で「対外的な最終責任」は変わらない**: プレスリリースの数値誤りや、記者会見・声明文での不用意な発言は、社名で報道される。広報・PR職がAIに求めるのは「下書きの高速化」であって、「対外発表の最終判断の代行」ではない、という一線は他職種以上に強く意識されている(詳細は「注意点」を参照)。

## 使いどころ・使い分け

### 広報・PR業務フェーズ別のAI活用マップ

| 業務 | AIの向き・不向き | 人が最終確認すべき理由 |
|---|---|---|
| プレスリリースのドラフト作成 | 向く(型のある文章の量産・タイトル案の複数出し) | 数値・固有名詞の誤り、事実誤認のチェックは必須 |
| メディアリスト作成・記者の切り口分析 | 向く(大量の過去記事からの傾向抽出) | 実際のリレーション構築・関係性の判断は人が担う |
| 想定問答(Q&A)集の作成 | 向く(想定される質問の網羅的な洗い出し) | 実際の回答方針・トーンの最終決定は広報責任者が行う |
| メディアモニタリング・クリッピングの要約 | 向く(大量記事の感情分析・トピック分類) | 「何が重要な報道か」の評価判断は人が行う |
| 社内報・IR資料・スピーチ原稿のドラフト | 向く(構成案・下書きの高速化) | トーン・登壇者本人の言葉としての自然さは人の調整が必須 |
| 危機管理広報(声明文・一次対応案) | **限定的にのみ活用**(選択肢の洗い出し・トーン比較まで) | 最終文言・公表タイミング・法的リスク判断は経営層・広報責任者・法務が必ず主導 |

判断の軸は、「間違っていても後で人が直せるか」「公表した瞬間に取り返しがつかないか」の2択である。プレスリリースの初稿やQ&A案は前者に当たるため積極的にAIへ任せてよいが、危機管理広報の最終文言は後者に当たるため、AIはあくまで「材料出し・叩き台」までに限定する。

### マーケティング部門との役割分担(すみ分け)

広報・PR職とマーケティング部門は、どちらも生成AIで文章・SNS投稿を作る点で業務が重なって見えるが、目的と評価軸が異なる。

| 観点 | 広報・PR(本ページ) | マーケティング([詳細](./marketing-ai-use-cases.md)) |
|---|---|---|
| 主な目的 | 報道・第三者からの評価(アーンドメディア)の獲得、企業の信頼構築 | 広告・自社発信(ペイド/オウンドメディア)による需要創出・販売促進 |
| 主な成果指標 | 掲載件数・メディア露出の質、レピュテーション | クリック率・コンバージョン率・売上への貢献 |
| 主な素材 | プレスリリース、記者向け資料、危機管理時の声明文 | 広告コピー、SNS投稿、メルマガ、記事構成案 |
| AIに求める役割 | 型に沿った正確な情報発信の下書き高速化 | 複数案の大量生成によるA/Bテストの母数確保 |

自社のSNS公式アカウントが「販促目的の投稿」なのか「企業としての公式見解・危機対応の発信」なのかによって、担当部門とAI活用の慎重度が変わる点を社内で共有しておくとよい。

## 実務での使い方

### プロンプト例1: プレスリリースのドラフト作成

プレスリリースは「タイトル→リード文→本文→会社概要」という型が明確なため、情報を過不足なく与えれば高い精度の初稿が得られる。

```
あなたは経験豊富な広報担当者です。以下の情報をもとに、プレスリリースのドラフトを作成してください。

## 発表内容
[例: 中小企業向け経費精算SaaS「〇〇」が、生成AIによる領収書自動仕訳機能を提供開始]

## 発表の背景・狙い
[例: 経理担当者の入力作業を月間20時間削減することを目指す]

## 訴求したい数値・実績(事実のみ記載。憶測で数値を作らないこと)
[例: 既存機能利用者へのアンケートでは入力時間が平均40%削減]

## 出力構成
- タイトル(30〜40字、要点が一目でわかるもの)を3案
- サブタイトル
- リード文(誰が・何を・いつから・なぜ、を100字程度で)
- 本文(見出し2〜3本、背景→機能詳細→今後の展望の順)
- 会社概要欄のプレースホルダー

## 注意事項
- 本文中の数値・固有名詞は、上記に記載した情報のみを用い、憶測で補完しないこと
- 誇大表現(「業界初」「日本一」等の客観的根拠が必要な表現)は使わず、使う場合は根拠情報が必要な旨を注記すること
```

「憶測で数値を補完しない」という指示は必須。プレスリリースは事実誤認がそのまま社外に出る文書であり、[ハルシネーションの仕組みと対策](../part04-risk-security/hallucination-and-countermeasures.md)で扱う「もっともらしい誤り」のリスクが特に高い業務である。

### プロンプト例2: 想定問答(Q&A)集の作成

記者会見や取材対応の前に、想定される質問と回答の方向性を洗い出す用途はAIの得意分野。ただし「回答そのもの」を鵜呑みにせず、回答方針の材料として使う。

```
あなたは危機管理広報・メディアトレーニングの専門家です。
以下の発表内容について、記者会見・取材で想定される質問を作成してください。

## 発表内容
[貼り付け]

## 出力条件
- 想定質問を15問(好意的な質問5問、厳しい・突っ込んだ質問7問、
  規制・法令に関わる質問3問に分類)
- 各質問について「なぜ記者がこの質問をするか」の意図を一言添える
- 回答の「方向性」のみを箇条書きで示し、そのまま読み上げられる完成文は作らないこと
  (最終的な回答文言は広報責任者・法務が確定するため)
```

最後の「完成文は作らない」という縛りが重要で、AIに回答の"答え"まで作らせると、広報責任者が精査せずそのまま読み上げてしまうリスクがある。あえて「方向性止まり」にすることで、人の最終判断を挟む工程を強制的に残す。

### プロンプト例3: メディアモニタリング結果の要約

自社・競合に関する報道が多い時期は、クリッピングされた記事群をAIに読み込ませて傾向を要約させると、週次レポート作成の時間を大幅に圧縮できる。

```
以下は今週の自社・競合に関する報道クリッピング(合計40本)です。
1. 自社関連の報道をポジティブ/ネガティブ/中立に分類し件数を集計
2. ネガティブ報道があれば、指摘されている論点を要約
3. 競合の報道で目立つトピックを3つ抽出
4. 経営層向けに5行で今週のサマリーを作成(数値の断定は避け、「傾向として」という表現を使う)

【クリッピング記事本文】(貼り付け)
```

「傾向として」という表現を明示的に指示すると、AIが少数の記事から過度に断定的な結論(例:「炎上している」)を出すのを防げる。実際の海外PRツールでも、Muck Rackが60万以上のニュースソースを対象に日次で350万本超の記事をモニタリングする規模のサービスを展開しており、生成AIによる要約はこうした大量データ処理と組み合わせて使われる方向に進んでいる([Muck Rack](https://muckrack.com/))。

### プロンプト例4: 危機管理広報における声明文の「一次対応案」(取り扱い厳重注意)

危機管理広報でAIを使う場合は、「最終文言の作成」ではなく「初動の選択肢を人が漏れなく検討するための壁打ち相手」という位置づけに限定する。

```
あなたは危機管理広報のアドバイザーです。以下の状況について、
社内の初動対応(声明を出すかどうかの判断、社内共有の範囲、一次対応の選択肢)を
整理するための材料を提示してください。声明文の確定稿は作成しないでください。

## 状況
[事実関係を可能な限り正確に記載。未確定情報は「未確認」と明記]

## 求める出力
1. この状況で企業が取りうる初動対応の選択肢を3〜4パターン(即時声明/情報収集優先/沈黙 等)
2. それぞれの選択肢のメリット・リスク
3. 社内で早急に確認すべき事実関係のチェックリスト
4. 声明を出す場合に、一般的にトーンとして避けるべき表現(言い訳に聞こえる表現、責任の所在を曖昧にする表現 等)の類型

## 厳守事項
- 具体的な声明文・お詫び文の確定稿は作成しないこと
- 未確認の事実を断定的に記載しないこと
```

この使い方は「経験豊富な社外顧問に壁打ちしてもらう」感覚に近い。実際、AIが危機管理広報の相談相手になりうるという考え方は、過去の炎上事例や広報のセオリーに基づく整理をAIが高速に行える点に価値があるとする指摘もある一方で([note記事](https://note.com/muzuyasa/n/n3960234a68f6))、最終的な声明の文言・公表タイミング・法的リスクの判断は、広報責任者・経営層・法務が必ず主導するという原則は動かない。

### プロンプト例5: 社内報・スピーチ原稿・登壇資料のドラフト

社内報の記事、経営層のスピーチ原稿、登壇資料の構成案も、広報・PR職の日常業務としてAIの高速化効果が大きい領域。

```
以下のテーマで、社内報向けの記事構成案を作成してください。
本文はまだ書かず、見出しと各見出しで触れる要点のみを示してください。

## テーマ
[例: 新オフィス移転の狙いと従業員へのメリット]

## 想定読者・トーン
[例: 全従業員向け、堅すぎず前向きなトーン]

## 出力条件
- 見出し4〜5本(背景→変化点→従業員への影響→今後のスケジュール、の流れ)
- 経営層のメッセージを引用する場合の想定文言案を1つ(仮のプレースホルダーとして)
```

スピーチ原稿・登壇資料についても同様に、まず構成案を作らせてから本文を書かせる2段階アプローチが手戻りを減らす(考え方は[生成AIによる文章作成・編集の実務活用](../part11-business-practice/ai-writing-and-editing.md)と共通)。ただし登壇者本人の言葉遣い・エピソードを反映させる仕上げ工程は必ず人(広報担当者と登壇者本人)が行う。AIが作った初稿をそのまま読み上げても、聴衆の心が動くかどうかはAIには分からない、という指摘は実務でもよく言われる点である([AI総合研究所](https://www.ai-souken.com/article/writing-speeches-with-chatgpt))。

### プロンプト例6: IR資料・決算説明資料の想定Q&A

IR(投資家向け広報)領域では、決算短信・有価証券報告書をもとに想定質問と回答案を自動生成する専用サービスも登場している。国内では「exaBase IRアシスタント」が決算説明会の想定Q&Aを決算短信・有報から自動生成するサービスとして2025年3月時点で導入100社超、時価総額1兆円超企業の約15%をカバーしていると報告されている。ニーズウェルの「FSGen」は決算短信・有報・決算説明資料のドラフト自動生成、「IR Hub」は適時開示文書のドラフト作成と翻訳を提供している([AI革命株式会社メディア](https://ai-revolution.co.jp/media/ai-in-ir/)、[IT Leaders](https://it.impress.co.jp/articles/-/25437))。汎用チャットAIで代替する場合は、決算短信・有報のテキストを読み込ませ、「アナリストが聞きそうな質問」を洗い出させるプロンプト例2と同様の使い方になる。

### ツール横断の対応表

| やりたいこと | 主に使うツール |
|---|---|
| プレスリリースのタイトル・リード文提案 | PR TIMES新エディターの「AIアシスタント機能」、汎用チャットAI(ChatGPT/Gemini/Claude) |
| メディアリスト作成・記者マッチング | Muck Rack「Media List Agent」、Cision(バックエンドのAI分類) |
| メディアモニタリング・クリッピング要約 | 電通PRコンサルティング等のPR会社モニタリングサービス、汎用チャットAIによる要約 |
| IR資料・決算Q&A作成 | exaBase IRアシスタント、FSGen、IR Hub |
| プレスリリース評価・添削 | プレスリリース特化型AIサービス(例: 「広報AI」による掲載されやすさの自動採点) |
| 社内報・スピーチ原稿・登壇資料のドラフト | 汎用チャットAI(ChatGPT/Gemini/Claude/Copilot) |

料金は各社ツールで大きく異なる(専用SaaSは月額数万円〜のプラン制が一般的、汎用チャットAIは既存の法人契約枠内で追加コストなく使えることが多い)ため、まずは既存の法人契約チャットAIでプロンプトを試し、専用ツールは記者データベースの規模やIR特化機能が必要になった段階で検討するのが実務的な順序になる。

## 注意点・よくある誤解

- **危機管理広報でAIに「最終文言」を書かせない**: 声明文・お詫び文の確定稿をAIにそのまま作らせ、精査なく公表してしまうと、事実誤認や不用意な表現が会社の信用問題に直結する。AIは「選択肢の洗い出し」「チェックリスト作成」までにとどめ、最終文言は広報責任者・経営層・法務が必ず作成・確認する体制を、平時のうちに社内ルールとして明文化しておく。
- **事実誤認・数値のハルシネーションはプレスリリースで特に重い**: 対外発表文書に誤った数値・日付・固有名詞が入ると訂正リリースを出す事態になりかねない。「与えた情報のみを使い、憶測で補完しない」という指示を毎回入れ、公開前に必ず一次情報と突き合わせる(詳細は[ハルシネーションの仕組みと対策](../part04-risk-security/hallucination-and-countermeasures.md))。
- **未公表の決算情報・M&A情報をAIに入力しない**: 適時開示前の財務情報や人事情報を無料版・個人契約の生成AIに入力すると、インサイダー情報の漏洩リスクや学習データへの取り込みリスクを負う。法人契約でオプトアウト設定(入力データを学習に使わない設定)が確認できているツールに限定する(詳細は[生成AI利用における情報漏洩対策](../part04-risk-security/information-leakage-prevention.md))。
- **AIが誇大表現・断定表現を作りがちな点に注意**: 「業界初」「圧倒的な」といった客観的根拠が必要な表現をAIが自然に生成することがある。景品表示法・薬機法などの表示規制に抵触しないか、公開前に必ず人がチェックする。
- **記者・読者側のAI利用も前提に置く**: 記者自身が生成AIで報道内容を検討する時代になりつつあり(海外調査では記者の8割超が業務でAIを利用)、プレスリリースの構成が明確で引用しやすい(数値・定義が整理されている)ほど、AI経由でも正確に取り上げられやすくなる可能性がある。この点はコンテンツマーケティングにおけるLLMO(大規模言語モデル最適化)の考え方とも重なる(詳細は[マーケティング職における生成AI活用](./marketing-ai-use-cases.md))。
- **マーケティング部門との役割の混同に注意**: 同じSNSアカウントでも「販促目的の投稿」と「企業としての公式見解」は性質が異なる。特に危機対応時の発信は広報部門が主導すべきで、マーケティング部門のAI活用ノウハウ(大量のバリエーション生成)をそのまま危機管理広報に転用しない。

## 最初の一歩

直近で配信予定のプレスリリースを1本選び、プロンプト例1のテンプレートで初稿を作らせてみる。あわせて、まだ作っていなければ「危機管理広報でAIに任せてよい範囲・任せない範囲」を1枚のルールとして社内で言語化し、有事の前に合意しておく。
