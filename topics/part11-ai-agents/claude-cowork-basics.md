# Claude Coworkの基本

## これは何か

Claude Cowork は Anthropic の**非エンジニア向けエージェント**で、
「このフォルダの資料を読んで週次の実績スライドを作って」のように頼むと、
指定したフォルダのファイルを実際に読み書きして、**成果物ファイルを作って返すところまで**進める。

チャットとの違いは、[Claude Code](claude-code-basics.md)と同じ構図である。
チャットは「こう作るといい」と手順を教えてくれるが、実際にExcelを開いて数字を拾い、
スライドに落とす作業は人がやる。Cowork はそこをAIがやる。

Anthropic は Cowork を**「Claude に実際の仕事を渡す場所」**として位置づけており、
Claude Code がソフトウェア開発を対象にするのに対し、Cowork は**調査・分析・資料作成といった
コード以外の知識労働**を対象にしている([Claude Cowork公式](https://claude.com/product/cowork))。
2026年1月に Anthropic Labs のリサーチプレビューとして公開され、4月にデスクトップ(macOS/Windows)で
正式提供、7月にはWeb・モバイル(iOS/Android)にもベータで拡大した。

**2026年9月16日、AnthropicはCoworkを独立した製品として区別するのをやめ、通常のClaudeチャットに
統合すると発表した**(「Claude Cowork and chat are now one Claude」)。これにより「チャットで質問する」か
「Coworkにタスクを渡す」かをユーザーが事前に選ぶ必要がなくなり、**同じ会話の中で、必要に応じて
ファイル操作・複数ステップの作業・スケジュール実行などのエージェント的な振る舞いをClaudeが
自動的に呼び出す**形に変わった。過去のチャット・プロジェクト・Artifacts・接続先(コネクタ)・Skillsは
統合後もそのまま引き継がれる。この統合はProプラン・Maxプランから数週間かけて展開され、
Team・Freeプランは後日、Enterpriseは30日以上前の事前通知を経て順次対応する。
そのため本ページで説明する「フォルダを渡してタスクを任せる」という**使い方・権限設計の考え方は
統合後も変わらず有効**だが、起動の入口が「Coworkを開く」から「通常のClaude(チャット)にそのまま頼む」
に変わりつつある点に注意する。

## 仕組み・背景

### フォルダ単位の権限モデル

Cowork の設計上の要点は、**アクセスできる範囲をユーザーがフォルダとツール単位で明示的に選ぶ**ことである。
選んでいない場所には到達できない。削除操作には明示的な承認が必要とされている。

この「作業場所を切り出して渡す」考え方は、Cowork を安全に使う上での中心になる。
デスクトップ全体やドキュメントフォルダ全体を渡すのではなく、
**案件ごとに作業用フォルダを作り、必要なファイルだけをコピーして渡す**のが実務上の基本形になる。

### Claude Code との違い

| | Claude Cowork | Claude Code |
|---|---|---|
| 対象 | 調査・分析・資料作成などの知識労働 | ソフトウェア開発 |
| 想定ユーザー | 非エンジニア中心 | エンジニア中心 |
| 主な入口 | デスクトップアプリ(Web・モバイルはベータ) | ターミナル、IDE、Web、デスクトップ、Slack |
| 成果物 | 文書・スライド・表・整理されたファイル | コード差分、PR |
| 作業単位 | 指定フォルダ内のファイル | リポジトリ |

同じ「エージェント」だが、**レビューの対象が違う**点が実務上は重要である。
Claude Code は差分を読めば変更が分かる。Cowork の成果物は文書なので、
**中の数字や引用が正しいかを人が確かめるしかない**。

## 使いどころ・使い分け

公式に挙げられている用途は、マーケティング(週次指標のスライド、キャンペーン分析)、
営業準備(CRMやコミュニケーションツールからの商談ブリーフ作成)、
法務(契約書の整理、ポリシーの監査)、および一般的な調査・分析・文書作成である。

### 向く仕事・向かない仕事

| 向く | 向かない |
|---|---|
| 複数ファイルを横断した集計・要約 | 数値の正しさが致命的な確定作業(決算・請求) |
| 決まった型の資料を毎週作る | 型が決まっていない、企画そのものを考える仕事 |
| 大量ファイルのリネーム・分類・整理 | 個人情報・機密情報を含むフォルダ全体の処理 |
| 議事録から報告書・ToDoへの変換 | 社外にそのまま出す文書の最終版作成 |
| 契約書・規程の横断チェック(一次確認) | 法的判断そのもの |

### 判断の目安

[生成AIに向く業務・向かない業務の切り分け](../part12-business-practice/ai-task-suitability.md)の
3チェック(入力が構造化されているか / 良し悪しを基準化できるか / 反復回数が多いか)に加えて、
Cowork では**「間違っていたときに誰がいつ気づくか」**を必ず考える。
週次スライドの数字が違っていても翌週には気づく業務なら任せやすいが、
そのまま社外に出る資料は向かない。

## 実務での使い方

### 始め方

2026年9月のチャット統合が展開されたアカウントでは、Coworkを別アプリとして開く手順は不要になり、
通常のClaude(デスクトップ / claude.ai / モバイル)にそのままタスクを頼めばよい。
統合がまだ届いていないアカウントや、明示的にフォルダ単位の作業範囲を切りたい場合は、
従来どおり次の手順で始める。

1. Claude デスクトップアプリ(macOS / Windows / Linux / ChromeOS)を入れる
2. Cowork(統合後は通常のチャット画面)を開き、**作業させるフォルダを選ぶ**
3. 使わせたい外部ツール(接続先)を選ぶ
4. タスクを自然文で書いて実行し、途中の承認要求に答える

Web版(claude.ai)とモバイル(iOS / Android)は2026年7月にベータで対応し、外出先での指示出しや
進捗確認に使える。クラウド上で動く「リモートセッション」はデバイスがオフラインでも
バックグラウンドで処理が進み、承認が必要になった時点で通知が届く。

### Claude Docs / Slides / Design(2026年9月に統合発表と同時に追加)

チャット統合と同時に、会話の中でそのまま使える文書作成ツールが追加された(いずれも全有料プランでベータ)。

- **Claude Docs**: 会話内でClaudeと一緒に文書を書き進める機能
- **Claude Slides**: 会話内でスライド案を作成し、編集・プレゼン表示・PowerPoint/PDFでのダウンロードができる機能
- **Claude Design**: 従来は単体機能だったビジュアルデザイン作成が、会話内からも呼び出せるようになったもの

これらは資料作成をCoworkの「フォルダに成果物ファイルを書き出す」やり方に頼らず、
チャットの続きとして進められる新しい導線であり、既存の企業テンプレートに厳密に合わせる必要がない
簡易な資料はDocs/Slidesで、既存フォーマットへの厳密な準拠や複数ファイル横断の集計が必要な資料は
従来型のフォルダ単位のエージェントタスクで、と使い分けるとよい。

### コピペで使える依頼文の型

エージェントに任せる依頼は、**成果物の形・使ってよい入力・やってはいけないこと**を明示すると精度が上がる。

```
## お願いしたいこと
`/Users/自分/work/2026-08-週次報告/` の中にある売上CSVと前週の報告書を読んで、
今週分の週次報告書(Markdown)を作ってください。

## 出力してほしいもの
- ファイル名: `週次報告_2026-08-05.md`
- 構成は前週の報告書と完全に同じ見出し・順番にする
- 数字は必ずCSVの値をそのまま使い、計算した場合は計算式も併記する

## 守ってほしいこと
- このフォルダの外のファイルは読まない・書かない
- 既存ファイルは上書きせず、新しいファイルとして作る
- CSVに存在しない数字は「データなし」と書く。推測で埋めない
- 判断に迷ったら作業を止めて質問する
```

**「推測で埋めない」「迷ったら止めて聞く」は毎回入れる。** エージェントは
指示を完遂しようとするため、データが足りないと埋めてしまうことがある。

### 使えるプラン(2026年9月時点)

Cowork 単体の料金はなく、Claude の有料サブスクに含まれる。無料プランでは使えない。

| プラン | 月額 | 目安 |
|---|---|---|
| Pro | $17 | 試用向け。重いタスクを1日数回で上限に達しうる |
| Max 5x / Max 20x | $100 / $200 | 業務で日常的に使う場合 |
| Team | $20/シート | 組織利用の入口 |
| Enterprise | 個別見積 | ロールベースのアクセス制御、チーム単位の支出上限設定が可能 |

**エージェントのタスクは通常のチャットより多くの容量を消費する**と公式に明記されている。
料金・上限は変更されうるため、導入判断時は必ず公式ページで確認する。

### レビューのしかた

| 見るところ | 具体的に |
|---|---|
| 数字 | 出典ファイルの値と一致しているか。合計が合うか |
| 引用・出典 | 実在する資料か。ページ・箇所が正しいか |
| 抜け | 対象ファイルを全部読んだか(処理したファイル一覧を出させる) |
| 副作用 | 意図しないファイルが変更・作成されていないか |

依頼の最後に「**参照したファイル名を一覧で出して**」と付けるだけで、
読み飛ばしの検出がかなり楽になる。

## 注意点・よくある誤解

- **「Cowork」という名前・別アプリの区別は薄れていく。** 2026年9月16日の統合発表以降、
  Coworkは独立した製品ブランドとしてではなく、通常のClaudeチャットの一機能として提供される
  方向に変わった。社内マニュアルに「Coworkを開く」と書いている場合、統合が届いたユーザーには
  該当する画面がなくなっている可能性があるため、展開状況を確認してから案内する
- **フォルダを渡す=中身を全部渡している。** 「関係ないファイルは見ないだろう」と考えず、
  作業用フォルダを切ってコピーする。共有ドライブのルートを渡すのは避ける
- **個人情報・機密情報の扱いは事前に整理する。** 顧客名・口座・契約金額を含むファイルを
  渡す前に、社内ルールと契約上のデータ取り扱い条件を確認する
  ([情報漏洩を防ぐデータ管理](../part04-risk-security/information-leakage-prevention.md))
- **間接プロンプトインジェクション**: 読ませたファイルやWebページに悪意ある指示文が
  埋め込まれていると、それに従う可能性がある。外部から受け取ったファイルを処理する作業では
  特に権限を絞る([プロンプトインジェクションとは何か](../part04-risk-security/prompt-injection-basics.md))
- **「エージェントに任せた」は責任の移転ではない。** 成果物の責任は依頼した人に残る。
  レビューを省く前提の業務設計にはしない
- **上限に当たると作業が中断する。** 締切直前の重要作業を1本のエージェントタスクに
  依存させない

## 最初の一歩

空のフォルダを1つ作り、そこに過去の資料を2〜3個コピーして Cowork に渡し、
「このフォルダの資料を読んで、要点を1枚のMarkdownにまとめて」と頼んでみる。
**書き込み先が隔離されている状態で試す**ことが、権限設計の感覚をつかむ最短路である。
